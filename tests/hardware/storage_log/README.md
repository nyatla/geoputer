# 実機ログ保存の検証

通常ファームウェアとは別の一時テストイメージ。実装のLogWriter / LogFormat / LogFileを無改変で使用し、同じ配線・4MHzで既存SDをマウントする。フォーマットやNVS更新は行わない。

`.geoputer-log-test-<ランダムID>`をSD直下へ新規作成し、その中だけへ試験レコードを書く。64件受付、65件目の拒否、実保存・CRC読戻し、一時停止・再開・停止、同一秒ファイル名の衝突、空セッションを確認する。成功時は作成したファイルとディレクトリを削除し、USBへ`[STORAGE-TEST] PASS`を出力する。失敗時の試験ファイルは診断のため保持する。既存ログやデータセットは変更しない。

共有リングの試験では、保存側をCPUコア0、追加側をsetupの実行コアで動かす。保存対象を固定した直後のSDアクセス区間をセマフォで待機させ、その間に空き枠へ追加し、64件到達後の拒否を確認する。最初は40件を保存中に24件を追加し、次は折り返す50件を保存中に14件を追加する。保存後も後続点を残すことと、最終104件の時刻順・座標・CRC・EOFを実SDから確認する。`[RING-TEST]`に追加処理の最大所要時間を出力する。この待機は試験のために設けたものであり、実媒体I/Oと追加処理の時間的な重なりや、通常運転の最大遅延を計測するものではない。

LogWriterはFatFsの内部バッファも持つため、この試験ではヒープに配置する。通常実装ではStorageTaskのメンバーとして常設する。setupのローカル変数へ置かない。

`PLATFORMIO_CORE_DIR=<Coreの場所> pio run -d tests/hardware/storage_log -e cardputer-adv`でビルドする。書込み前に通常ファームウェアを保持し、試験後は必ず通常ファームウェアへ戻す。試験コードのGPS座標は固定入力であり、実測ログとして扱わない。


## ログビューアの読戻し

同じ試験でLogReaderの一覧・概要・最大10件の読出しを実行する。保存済み90件と未保存14件を分離し、保存後104件になること、共有FILの読出し後も保存できることを確認する。専用ファイルを削除した後、`/logs/`の最新ファイルを読取専用で開き、全レコードを10件ずつ検証する。既存ファイルは変更しない。`[BROWSE-TEST] PASS`と`[BROWSE-EXISTING] PASS`が確認点となる。対象がない場合はEMPTY、既存ファイルの概要を取得できない場合はそのエラーを報告し、全件確認の成功とは扱わない。

検証結果・通常ファームへの復帰状況は[ログビューア検証](../../../doc/検証/ログビューア検証.md)を参照する。
