# Geoputer システム構成設計

文書状態: Draft 0.19
対象機: M5Stack Cardputer ADV（Mesh KitのGNSS使用 / 外付けGPS使用を選択可能）  

## 1. 文書の目的

本書は、Geoputerの機能構成、動作モード、データ、エラー処理および省電力方針を定義する。

製品の目的と利用体験は「[Geoputer コンセプト・利用体験概要設計](01_コンセプト・利用体験概要設計.md)」、対応ハードウェアとバス構成は「[Geoputer ハードウェア詳細設計](03_ハードウェア詳細設計.md)」を参照する。

タスク分割、キュー通信、資源の所有者、処理順序および起動時の連携は「[Geoputer タスク構成設計](06_タスク構成設計.md)」で定義する。本書には同じ実行構造を重複して定義しない。

### 1.1 現在の実装と目標構成

現在はGPS受信、地名検索、GPSログのSD保存、設定とライセンス表示を実装している。ログは起動時STOPPEDで、開始・一時停止・再開・停止と未保存状態の表示に対応する。保存形式と実装・検証の範囲は[測位記録ファイル仕様](07_測位記録ファイル仕様.md)に従う。

以下の機能構成・状態遷移には目標仕様を含む。ログ一覧・概要・測位点の閲覧は実装済みである。領域表示、ログの距離・最高速度の全件集計、外付けGPSへの切替、GNSSの休止・復帰制御は未実装である。現行版はMesh Kit固定で起動後のUART受信を継続し、ログ停止・一時停止では記録だけを止める。STORAGE_ERRORは保存障害を表す概念上の状態とし、実装では記録状態と保存エラーを別に保持する。

## 2. 機能構成

GeoputerはGPS測位、GPSログ、地名検索、領域表示、ログ閲覧および設定機能を提供する。LoRa機能は使用しない。

GPS接続モードはMesh Kitと外付けGPSから選択可能とする。保存済みのモードを起動時に読み、対応する接続プロファイルを使用する。モード変更は再起動時に反映し、測位以降の機能は両モードで共通とする。

記録するのは確定GPSサンプルであり、地名検索結果を各ログ点へ常時付加しない。地名検索と領域表示はユーザーが必要とする時点のFixスナップショットに対して行う。検索中の測位更新で検索対象を変更しない。

画面表示、ログ記録、GNSS測位の状態は独立して管理する。Galuchatや表示の障害でGPS受信とログ記録を停止しない。

### 2.1 保存媒体と設定

| データ | 保存先 | 用途 |
|---|---|---|
| 動作設定、GPS接続モード | 本体内蔵FlashのNVS | 起動時に復元する端末固有の設定 |
| GPSログ | FAT32のmicroSD | 記録・閲覧・PCへの持ち出し |
| Galuchatデータ | FAT32のmicroSD | オフライン地名検索・領域表示 |
| OSS・フォントのライセンス表示データ | ファームウェア内の読取専用データ | SD未挿入でも閲覧できる利用OSSの情報 |

設定の正本はNVSのGeoputer用名前空間`geoputer`へ保存する。全設定に形式バージョンを持たせ、読込み時に形式と値域を検証する。設定が未保存なら初期値を使用し、不正な形式や読込障害は初期値適用とエラーを区別して表示する。NVS全体を自動消去して復旧しない。

設定はユーザーが変更を確定したときに保存し、キーによる候補選択や再描画だけでは書き込まない。RAM上での設定適用、保存要求の受付、NVSへの永続化完了は区別する。GPS接続モードはNVSへ保存した値を再起動時に反映する。

データセット切替対応後は、`01`〜`99`の番号と言語別Wordbookの言語識別子を一組としてNVSへ保存する。初期選択は番号01とINIの既定言語とする。変更はGPSログの停止・未保存データの保存・セッション閉鎖が完了している場合に限定し、候補の検証とNVSへの実保存に成功した後に再起動して反映する。一時停止中や停止処理中は適用せず、検証・保存失敗時も再起動しない。

SD未挿入・マウント失敗・取り外し・フォーマットはNVSの設定を変更せず、設定読込み・保存も妨げない。FAT32の1ファイルは4 GiB未満とする。SDフォーマットはカード上の全データを消去する操作として確認し、設定初期化はGeoputerの設定だけを初期値へ戻す。両者の対象を混同しない。

表示言語は動作設定の先頭に置き、日本語 / Englishを選択する。初期値は日本語とし、Enterで確定後に画面へ反映してNVSへ保存する。設定初期化では言語も初期値へ戻す。旧形式の設定はデータセット以外の項目を引き継ぎ、データセットを01・INIの既定言語へ移行する。形式バージョン1のUI言語は日本語、バージョン2は保存値を使い、次回保存でWordbook言語を含むバージョン3へ移行する。Settingsの主表示は日本語16×16、英語8×16、タイトル・キーガイドは共通の8×8、ライセンス画面は従来の本文・フォント・配置を維持する。

Settingsの入口は動作設定、ストレージ操作、初期化、ライセンス情報の4メニューとし、それぞれの子画面を開く2階層構成とする。項目と操作は[Settings画面](画面・操作/settings/README.md)で定義する。

## 3. 動作モード

### 3.1 BACKGROUND_MODE

描画とバックライトを休止し、キー入力による復帰を監視する通常状態。GNSSとGPSログの状態は独立しており、ロギング中は画面消灯後も測位と記録を継続する。

| 機能 | 状態 |
|---|---|
| GNSS | 記録中・一時停止中はACTIVE、停止中は測位要求に従う |
| GPSログ | STOPPED、PAUSED、STARTING、RECORDING、STORAGE_ERRORを維持 |
| LCD / Backlight | OFF |
| Wi-Fi / BLE | OFF |
| CPU | 必要な処理を失わない範囲で負荷低減 |

### 3.2 VIEW_MODE

画面表示とユーザー操作を行う状態。

| 機能 | 状態 |
|---|---|
| GNSS | 現在位置を必要とする画面、ログ記録中または一時停止中はACTIVE。それ以外は測位要求に従う |
| GPSログ | STOPPED、PAUSED、STARTING、RECORDING、STORAGE_ERRORを維持 |
| LCD / Backlight | ON |
| Galuchat | 必要時のみACTIVE |
| CPU | ACTIVE |

無操作タイムアウトの初期値は15秒とする。タイムアウト時は表示を消し、BACKGROUND_MODEへ戻る。GPSログがSTOPPEDで、ほかに測位要求がなければGNSSもPAUSEへ戻す。

Galuchat検索は独立した動作モードではなく、オンデマンド処理として扱う。

### 3.3 GNSS状態

GNSSの状態は次の2つに限定する。

| 状態 | 意味 |
|---|---|
| PAUSE | 測位を休止し、新しいGPS Fixを生成しない |
| ACTIVE | 測位を行う |

PAUSEからACTIVEへ移行した直後は、最初の有効Fixを得るまで測位待ち状態を表示する。

GNSSをACTIVEにする要求元は次のとおりとする。

- GPSログの開始、継続または一時停止中の測位維持
- Live PlaceまたはPlace Viewでの現在位置取得
- 明示的な診断または実機試験

どの要求元もGNSSを必要としなくなった場合はPAUSEへ戻せる。GNSSのPAUSE / ACTIVEをユーザーへ直接操作させるかどうかは、初期実装では規定しない。

### 3.4 GPSログ状態

| 状態 | 意味 |
|---|---|
| STOPPED | 新しいGPSレコードを追加しない。測位要求がなければGNSS PAUSE |
| PAUSED | 記録セッションを保持して新しいGPSレコードを追加しない。GNSS ACTIVEを維持 |
| STARTING | GNSSをACTIVEへ移行し、有効Fixを待っている |
| RECORDING | 確定GPSサンプルをログへ追加している |
| STORAGE_ERROR | 記録要求中だがSD保存に問題がある |

電源投入時はSTOPPEDとする。

### 3.5 状態間の制約

- GNSSがPAUSEのままGPSログをRECORDINGにしない。
- 記録の一時停止はGNSS ACTIVEを維持し、新しいログ追加だけを止める。
- ログ停止後、ほかに測位要求がなければGNSSをPAUSEへ戻す。
- 画面モードの変更だけではログ状態を変更しない。
- 未保存データの有無とログの停止・一時停止状態は別に表示する。

## 4. GPSデータ

GPSデータは、NMEA文単位ではなく、同一測位時刻の情報を統合した確定サンプルとして扱う。

```cpp
struct GPSFix {
    uint64_t utc_epoch_ms;
    uint32_t received_monotonic_ms;
    double latitude;
    double longitude;
    float altitude_m;
    float speed_kmh;
    float course_deg;
    float hdop;
    uint8_t satellites;
    bool position_valid;
    bool time_valid;
    bool altitude_valid;
    bool speed_valid;
    bool course_valid;
    bool hdop_valid;
    bool satellites_valid;
};
```

上記は設計上のデータモデルであり、保存時の構造体レイアウトではない。UTCは日付を含むミリ秒値とし、各項目の有効性を個別に保持する。

UTCと起動後時間を分離し、GNSS時刻が未確定の状態を表現する。Live Placeの表示時計は最初の有効Fixに含まれるUTC時刻で合わせ、以後は本体の単調増加時刻で進める。表示は日本時間（UTC+9）のHH:MM:SSとし、未取得時は--:--:--とする。Fix喪失や画面切替・消灯で表示時計を消去しない。この段階では初回の時刻合わせのみとし、継続補正・日付表示・再起動をまたぐ保持は導入しない。GPSログの測位UTCは表示時計で置き換えない。

## 5. GPSログ

保存形式は[測位記録ファイル仕様](07_測位記録ファイル仕様.md)に従う。512バイトのヘッダーと32バイトの固定長測位レコードを持つバイナリ形式とし、SDカード直下の`/logs/`へ、日本時間の記録開始日時と衝突回避番号による`YYYYMMDD_HHMMSS_n.gps.dat`ファイルを保存する。

標準形式への変換は[ログエクスポート仕様](10_ログエクスポート仕様.md)に従う。USBモード内で元ログを読み、`/export/<元のファイル名全体>.<形式の拡張子>`へ別ファイルとして出力する。GPX・KML・CSVを順次変換し、内部の記録形式は変更しない。

開始から停止までを1ファイルとし、一時停止・再開および日付変更では同じファイルを継続する。停止後・再起動後の開始は新しいファイルとする。ファイル名は最初の記録対象点で確定し、その日時が不明なら`undated_<session_id>_n.gps.dat`を使用する。後からGPS日時が得られてもリネームしない。

有効な位置を取得したサンプルだけを、初期値1秒、選択肢1・5・10秒の記録間隔で採用する。日時・標高・速度・進行方位・HDOP・衛星数の未取得は項目ごとに表現する。区域変更履歴は測位レコードへ混在させない。

SD保存間隔の初期値は10秒とし、まとめ書きを行う。設定候補は1、5、10、30、60秒とする。未保存レコードは排他付きリングへ64件まで保持し、App上の直接受付APIで追加する。SD処理中も空き枠へ追加でき、保存中の領域も64件に含める。保存対象の固定・成功後の解放は短い排他区間で行い、SD処理中はロックを保持しない。満杯では保存間隔を待たずに書き出す。保存失敗中に新しい点で未保存データを上書きせず、保持できず実際に失った点を欠落として計数する。ログ読出しは最大10件ずつとし、読出しと書込みの直列化はStorageが担当する。ファイルの件数計算、CRC、ランダムアクセス、破損した末尾の扱いは測位記録ファイル仕様に集約する。

## 6. Galuchatデータ

WGSMapSetとGisWordBookは同じデータセットの組を使用する。データはmicroSDへ置き、RAMへの全展開を行わない。

SDカード直下に`dataset`ディレクトリを設け、`/dataset/01/`、`/dataset/02/`のように番号別のディレクトリへデータセットを配置する。各番号ディレクトリには、同じデータセットのWGSMapSetとGisWordBookをまとめて置く。データセット切替への対応では、各ディレクトリ直下の`dataset.ini`に共通のGLCと、言語別のタイトル・短い説明・Wordbookのファイル名を定義する。形式と読取り規則は[データセットメタデータ仕様](08_データセットメタデータ仕様.md)に集約する。

```text
/
├ logs/
├ export/
└ dataset/
   ├ 01/
   └ 02/
```

上記はSDカード内のパスを示す。本体側のマウント先`/sd`を含める場合、`/dataset/01/`は`/sd/dataset/01/`に対応する。

`export`はログエクスポート用であり、初めて出力する際、Storageが必要に応じて作成する。事前のSD準備で必須とするディレクトリではない。

現行実装は各番号ディレクトリのINIで指定したGLC・Wordbookを使用する。同じディレクトリに複数言語のWordbookを置け、指定外のファイルを拡張子から自動選択しない。一覧ではINIだけを読み、選択時に指定GLCと使用対象のWordbookを検証する。解像度・格納範囲・チャンク数はGLCから、文字コードはWordbook内部から取得し、INIへ重複して保持しない。Wordbook・INI・タスク間メッセージ・UIの文字列はUTF-8に統一する。Wordbook内部の`token_encoding`（未指定または空の場合は`text_encoding`）が`utf8`または`utf-8`であることを大文字・小文字を区別せず確認する。未指定・他の文字コードは文字コード異常として拒否し、端末内の変換処理・変換表は持たない。メタデータ不正、指定ファイル不足、区域なし、文字コード異常、読込異常を区別する。

起動では保存済みの番号と言語を復元する。選択先の欠落・不整合・形式不正・文字コード未対応・チャンク上限超過・メモリ不足・読出し失敗は地名機能の使用不可として保持し、通常起動とGPS受信を継続する。地名2行へ原因を表示して逆ジオコーディングを停止し、別データへの自動切替やNVS保存値の書換えは行わない。SDが利用可能ならGPSログは利用でき、記録中にデータセット異常が発生しても記録状態を変更しない。文言・再検証・実装との差は[データセットメタデータ仕様8.3〜8.5節](08_データセットメタデータ仕様.md#83-起動時の復元とエラー)に従う。

| モード | 用途 |
|---|---|
| Municipality | 都道府県・市区町村を軽量に表示 |
| Town / Chome | 町丁・小地域を表示 |
| Integrated | 行政区域から小地域まで一つの階層で表示 |

上表はデータセットの用途の例であり、メタデータ形式の固定選択肢ではない。切替対応後の候補はSD上の番号ディレクトリとINIのタイトルで識別する。

最初のデモではIntegratedを第一候補とし、性能またはデータサイズの問題がある場合はMunicipalityへ切り替える。

用途の固定モードではなく、NVSへ保存した番号と言語で指定されたデータを検索する。データセットが使用可能な場合に限り、Live Place表示中に有効Fixを取得した時点で検索し、以後は新しいGPSサンプルに対して最短5秒間隔で更新する。使用可能時の画面復帰・Fix再取得では検索を更新する。使用不可時は画面復帰・Fix再取得で再試行せず、明示的な適用・SD再マウント・再起動後に検証成功を確認してから検索を再開する。検索対象は検索開始時のFixに固定し、GPS受信自体は継続する。再検索中は表示済みの地名とその地名のFixを保持し、結果確定後に地名・表示座標を同時に更新する。初回だけ検索対象のFixを表示する。Fix喪失時は旧地名と座標を消し、使用可能なら地名欄へWAIT GPS FIXを表示する。データセットが使用不可なら原因2行を維持し、GPS詳細だけを無効値へ戻す。

### 6.1 区域コードの矩形キャッシュ

区域コードは128×128セルの32bit符号なし整数画像としてRAMへ保持する。画像は1枚64KiBとし、各セルへデータセットの区域コードを直接保存する。キャッシュの原点と解像度は使用中のデータセットに対応させる。

取得点がキャッシュ範囲内なら保存済みのコードを返す。初回と範囲外では、SDKと同じ丸め方で整数化した取得点を中心セル(64,64)に置き、原点(ix-64, iy-64)、幅・高さ128の矩形を再読出しする。再構成中に到着したGPS座標で要求の中心を変更しない。

Live PlaceのRG枠はキャッシュの状態を表示する。未準備・無効は暗灰、有効な矩形を保持している間は緑、矩形の再構築中は黄とする。緑は現在のキャッシュが準備済みであることを示し、新しい座標が必ずその範囲内にあるという意味ではない。再構築に成功すると緑へ戻り、失敗・解放で暗灰へ戻る。ヒットごとに点滅させず、GPS Fix喪失や画面切替だけで有効なキャッシュを未準備表示にしない。

隣のSD枠は、ログ・地図・WordBook・ファイルシステム管理を含むSD実アクセス中に青で点灯する。RAM上のキャッシュ参照や記録受付、NVS設定保存だけでは点灯しない。矩形がヒットしても地名キャッシュに未登録の区域コードならWordBookを読むため、RGが緑のままSDが青く点灯することがある。矩形と地名がともにヒットした検索ではSDを読まない。RGには最低点灯時間を設けず最新状態を表示し、SDだけ短いアクセスを最低150ms表示する。配置・赤帯を含む画面仕様は[Live Place画面](画面・操作/live-place/README.md)、通知の契約はタスク構成設計4.5節に従う。

コード0の区域なしもキャッシュし、読込み途中の画像を有効として扱わない。地図が重なる部分は従来の点検索と同じ先の非ゼロ値を優先する。32bitに収まらないコード、確保失敗、読込失敗は検索エラーとする。SD再マウント・取り外し・フォーマットやデータセットの再オープン時には旧キャッシュを解放する。

### 6.2 WordBookの地名キャッシュ

WordBookの検索結果は、区域コードをキーとする16件固定のRAMキャッシュへ保持する。1件は32bit区域コードとUTF-8検証・書式展開済みの表示用地名2行（各64バイト）とし、要求ID、画面世代、GPSの座標・時刻・サンプル番号は含めない。ヒット時も検索結果へ今回の要求をコピーし、古い座標と地名を組み合わせない。Storageがメタデータのdisplay_line1 / display_line2を展開して最終2行を作り、AppはそのままUIへ渡す。

検索は配列を順に確認する。利用順は16バイトのインデックス配列で管理し、使用した項目を先頭へ移す。満杯時は末尾の項目を置き換えるLRUとする。地名データ本体を移動せず、時刻、内部Tick、利用連番による新旧判定は行わない。容量・順序・統計を含むキャッシュは固定長で保持し、動的な拡張を行わない。

ミス時にだけWordBookを読み、UTF-8検証と表示用2行への書式展開がすべて成功した結果を登録する。コード0は地名検索へ渡さず、読出し失敗、UTF-8不正、未測位などのエラー結果を登録しない。SDK内のトークンキャッシュは従来どおり無効とする。

有効期間は同じデータセットのReaderを保持している間とする。矩形の再構築、画面切替、GPS喪失では保持し、SD再マウント・取り外し・フォーマット、Readerの閉鎖・再オープンで消去する。ヒット時は媒体の存在確認も行わず、媒体異常は次の実I/Oまたは明示的な媒体操作で判明する。

RGは引き続き矩形キャッシュの状態だけを表示する。地名キャッシュのヒット・ミスでRGの色を変えず、SDは地図・辞書・ログ等の実I/Oに従う。実装と検証結果は[WordBook地名キャッシュ検証](検証/WordBook地名キャッシュ検証.md)を参照する。

### 6.3 地図チャンク索引とデータセットの利用条件

矩形読出しにはSDKの別クラス`GaluchatWGSMapSet3IndexedReader`を明示的に選択し、RAM上のチャンク索引を使用する。SDKの従来クラス`GaluchatWGSMapSet3Reader`は順次走査のままとする。各チャンクの西端・南端・幅・高さ・ファイル位置を保持し、要求矩形と交差するチャンクだけをファイルから取得する。ESP32の32bit環境では索引本体を1チャンク20バイトと見積もる。 キャッシュ再構築は`readWgsRectWithoutTail()`で最後の必要ブロックまで取得し、後続ブロックの走査とGI01全体長の一致の検証を省く。必要ブロック内部の復号・終端検証は維持する。各チャンクは独立したReaderから読むため、処理後に末尾へ移動せず閉じる。

利用できるデータセットの最大チャンク数は1500とする。1500チャンクは許可し、1501チャンク以上は利用不可とする。データセット選択時の検証でWGSMapSetのチャンク数を確認し、上限超過の場合は全チャンクの索引確保・地図本文の読出し・区域検索へ進まない。01〜99のすべての選択番号で、起動時と明示操作後のデータセット確認に同じ制限を適用する。

上限超過はチャンク数と上限を伴う使用不可の理由としてAppへ返す。候補の選択変更時は対象を適用・保存せず、以前の選択を維持する。使用中データの上限超過・索引確保失敗も欠落等と同じ扱いとし、地名欄へ原因を表示して逆ジオコーディングを停止する。GPS受信と、SDが使用可能な場合のログ記録を継続し、明示操作による再検証成功まで自動で再オープンしない。上限超過・確保失敗を理由に従来の全チャンク逐次探索へ切り替えない。

1500チャンクの索引本体は30000バイト（約29.3KiB）、既存の座標情報からの追加分は18000バイト（約17.6KiB）とする。128×128の画像キャッシュ64KiBは別に必要とし、管理情報やアロケータの消費量はこの見積もりに含めない。

チャンク索引、1500チャンクの上限検証、日英の警告表示を先行実装している。地名欄表示・起動継続・失敗保持と明示的な再検証による検索再開も実装した。選択済みデータセットの起動確認と、一覧・詳細からの切替候補の検証へ適用する。上限・キャッシュ容量・ファイル先読み量・検索間隔等のビルド時設定は`application/Config.h`へ集約する。実装範囲と検証結果は[Galuchat地図索引実装検証](検証/Galuchat地図索引実装検証.md)を参照する。

## 7. エラー状態と機能の利用条件

本節を、起動時・実行中に何が利用できず、どの機能が制約されるかの正本とする。App・UIが動作可能なら通常起動と操作を継続し、必要条件を満たさない機能だけを制約する。GPSの判定基準は有効Fixの有無とし、Fixなしを理由に設定だけの画面へ限定しない。複数の障害がある場合は各制約を重ね、別機能の正常化だけで制約を解除しない。

### 7.1 機能ごとの必要条件

| 機能 | 必要条件 | 不要なもの・補足 |
|---|---|---|
| 現在位置・速度等のGPS情報表示 | 有効GPS Fix。高度・速度・方位等は各項目も有効であること | SD・データセット・NVSへの保存は不要。無効な項目は--とする |
| 現在地の地名更新 | 有効GPS Fix、SD読出し可能、使用中のデータセットの検証成功 | キャッシュヒットで実I/Oがなくても、SD・データセットの使用不可を無視して検索しない |
| GPSログの開始・再開 | 新規開始ではSDが利用可能でセッション準備に成功すること。再開では保持中のセッションが有効であること | 有効Fixとデータセットは受付の前提にしない。次の有効Fixを待つ |
| 新しい測位点のRAM受付とSD保存 | 記録要求が有効、新しい有効GPS Fix、記録間隔の条件。RAM受付には空き枠、永続化にはSD書込み成功が必要 | 地名・Wordbookは不要。RAM受付成功と保存完了を区別する |
| 既存ログの一覧・詳細・測位点の閲覧 | SD読出し可能。一覧は対象のファイル名規則、詳細・測位点は対象ログの読出し・形式検証に従う | 現在のGPS Fix・データセットは不要。ログなしは空一覧、対象の破損は詳細・測位点の要求エラーとして区別する |
| 既存ログの削除 | SD書込み可能、対象が存在し記録・保存・終了処理で保持されていないこと、削除確認済み | 現在のGPS Fix・データセットは不要 |
| 既存ログのエクスポート | USBモードの端末操作状態、元ログを読出し可能、出力先へ書込み可能 | GPSタスク・現在のFix・データセットは不要。PC公開と端末のファイル操作は排他とする |
| 設定表示・編集、SDの状態確認・復旧操作 | App・UIと、操作を実行するStorageが利用可能であること | GPS Fix・データセットは不要。SD利用不可でも設定画面を開けるが、各操作の成否は別に判断する |
| 設定の保存・データセット選択の永続化・動作モード切替 | NVSへの保存成功。選択候補の検証やログ停止等、各操作固有の条件も満たすこと | SD未挿入は通常設定のNVS保存を妨げない。永続化に失敗した切替では再起動しない |
| バージョン情報・ライセンス情報の閲覧 | App・UIが利用可能であること | GPS Fix・SD・データセット・NVSへの保存は不要 |

### 7.2 利用できないものと制約

| 状態 | 制約 | 継続できる機能・動作 |
|---|---|---|
| 有効GPS Fixなし（初期測位待ち、Fix喪失、受信断、UART利用不能を含む） | 現在位置に基づく地名更新と、新しい測位点の追加を行わない | GPS受信が可能なら測位待ちを継続。設定、既存ログの操作、SD操作はそれぞれの必要条件を満たせば利用可能 |
| SD全体が利用不可（未挿入、非FAT32、マウント失敗、取り外し等） | ログの新規開始・実保存・閲覧・削除・エクスポート、データセット読込み・逆ジオコーディングを利用不可とする | GPS情報表示、NVS設定の読込み・保存、バージョン・ライセンス表示、設定からのSD復旧操作を継続 |
| SDの書込み・flushだけが失敗し、読出しは可能 | ログや出力の永続化成功を報告しない。既存の未保存レコードを保持し、空き枠がなくなれば新規RAM受付も失敗する | GPS受信・表示、読出し可能なログの閲覧・地名検索を継続。書込み失敗を媒体全体の利用不能と同一視しない |
| 使用中データセットの欠落・構成／形式不正・文字コード未対応・上限超過・メモリ不足・読出し失敗 | 逆ジオコーディングを停止し、明示再検証まで使用不可を保持する | GPS情報表示、SDが利用可能な場合のGPSログ・既存ログ操作、設定を継続。純粋なデータセット異常でログ操作を禁止しない |
| 保存設定が未保存 | 制約なし。DEFAULTとして初期値を使う | 正常起動。NVSが利用可能なら設定を保存できる |
| 保存設定の形式・値・検査値が不正、または設定の復元失敗 | 保存設定を使用せず、初期値で起動する | GPS・SD・データセットの状態を個別に判定して機能を継続。NVS領域が利用可能なら保存を試行できる |
| NVS自体が利用不可、またはNVSへの保存失敗 | 設定の復元・永続化を成功扱いにしない。動作モード・データセット切替は保存成功前に確定・再起動しない | 起動時は初期値、稼働中は有効なRAM設定で動作。GPS・SDなど独立した機能を継続。NVS全体を自動消去しない |
| UI・描画・Appの必須キュー等を初期化できない | 通常の画面操作を開始できない | シリアルへ初期化失敗を出す。Appが初期化失敗を返した場合は通常処理を開始しない |

SD利用不可とGPS Fixなしが同時に起きた場合は、GPSの現在位置・地名・ログ機能を利用できないが、設定と復旧操作は残す。GPS Fixなしとデータセット異常が同時に起きても、読出し可能な既存ログの閲覧・削除・エクスポートをGPSの状態だけで禁止しない。

### 7.3 GPS Fixと記録状態

UART受信準備の成功（BootのUART OK）と有効Fixの取得は別である。未測位はNO FIX、規定時間の受信断はNO GPSとして区別するが、機能の利用条件ではどちらも「有効Fixなし」として扱う。現在の受信断・Fix失効時間は3秒とする。UART初期化失敗時も現在位置が得られない点は共通であり、無関係な機能を設定だけへ限定しない。

- START / RESUMEの受付完了後はSTARTINGで次の新しい有効Fixを待つ。開始・再開前の古いFixを記録しない。
- RECORDING中にFixを失っても、記録要求・セッションを保持する。新しい測位点の追加だけを止め、利用者のPAUSED操作やSTOPPEDへの遷移と混同しない。
- Fix復帰後は新しい有効サンプルから、設定した記録間隔に従って追加を続ける。未測位区間を架空の点や以前の座標で補わない。
- Fixなしでも一時停止・停止と、すでに受け付けたレコードの保存をGPS Fixの取得待ちにしない。Storageの受付・保存待ちがある場合は既存の終了手順に従う。
- 表示時計は最初の有効Fixで初期化し、その後は単調増加時刻で継続する。Fix喪失だけで時計を消さず、GPSログのUTC時刻を表示時計で補わない。

GNSS PAUSE / ACTIVEは将来のデバイス制御であり、現行版のFix有無による制約に置き換えて使用しない。現在はUART受信を継続し、記録停止・一時停止でもGPSデバイスをOFFにしない。

### 7.4 表示と復旧

Bootの成功・警告・失敗はチェック結果であり、端末全体を停止するかどうかとは分ける。UI・Appが利用可能なら、確認完了後は通常2秒、問題がある場合5秒でLive Placeへ進み、完了後のEnterでも進める。起動時のログ状態はSTOPPEDとし、Fix取得だけで自動記録を開始しない。

SD利用不可・ログ保存失敗・GPSの問題は赤帯へ表示する。データセットだけの異常は地名2行へ原因を表示し、同じ原因を赤帯・上段ERRORへ重複させない。地名欄はSD利用不可、確定したデータセット異常、WAIT GPS FIX、通常の検索中／検索結果の順で優先する。Fix喪失や別機能の復旧でデータセット異常を上書きしない。

GPSは受信・有効Fixの復帰でその制約を解除する。ログ保存エラーは対象の受付・保存状態の回復を確認して解除する。データセットは適用・SD再マウント・再起動を基点とする明示再検証に成功して初めて検索を再開し、SDマウント成功だけで正常扱いにしない。F1によるメンテナンス入口と起動チェックの操作は[Boot画面](画面・操作/boot/README.md)、データセットの原因文言・再検証は[データセットメタデータ仕様8.3〜8.4節](08_データセットメタデータ仕様.md#83-起動時の復元とエラー)に従う。

## 8. 省電力方針

BACKGROUND_MODEでは、LCDバックライト、Wi-Fi、BLEを停止する。GPSログがSTOPPEDで測位要求もない場合はGNSSもPAUSEへ移行する。

GNSSのPAUSEが実際にどの程度消費電力を下げるかは、両GPS接続モードで実測する。初期版では安定動作を優先し、Light SleepはGNSS UART、キー割り込み、SDおよびタイマーとの共存確認後に導入する。

電池寿命は仕様値から推定せず、GNSS PAUSE、GNSS ACTIVE、GPSログ中、VIEW_MODEおよびGaluchat検索中の消費電流を実測する。
