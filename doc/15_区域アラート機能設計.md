# 区域アラート機能設計

2026-10-30の電源切替を外した比較により、間隔を空けた試聴と待機ノイズの改善を確認した。その後の電力管理は[電力管理設計](16_電力管理設計.md)に従う。「しない」は常時有効、「通常」「最大限」はDAC・出力段の待機停止とクロック先行復帰を使用し、以前のコーデック全体の深い停止は行わない。

## 1. 対象と責務

実GPSの現在地が、選択した階層の別区域へ移ったことを音で知らせる。監視対象は選択中データセットのWordbook階層であり、地図上の区域コードだけでなく、その階層までの親子ID列を比較する。同じ文字列でも異なる親を持つ区域は区別する。通知判定のために地名文字列を生成しない。

GPSがFIXし、SD・選択データセット・NVS設定が利用でき、データセットのアラートがONの場合に監視する。表示画面・消灯・ログ記録の開始／停止／一時停止とは独立する。履歴の文字・地図・再生画面でも実GPSを監視し、履歴の座標をアラートに使用しない。起動確認中・メンテナンス・USBモードでは監視しない。SDまたはNVSが利用できない間は無効とし、再生中の通知も停止する。GPS FIX喪失でも通知音を停止する。

Appが設定世代・区域遷移・発音期限を所有し、Storageが設定ファイルと9点の区域取得を担当する。AppはUIの既存バック領域を借りてStorageへ渡し、非同期完了を受けて借用を返却する。表示地名の結果とは区別し、監視結果で表示地名を上書きしない。UIは同期のControlAudioを受け、UIループで音を非同期に進める。アプリケーションのタスク・通信キュー・画像バッファは追加しない。音声ライブラリ内部の再生ワーカーは起動時に生成し、待機中も保持する。

## 2. データセットごとの設定

設定トップの「アラート / Alerts」から次の項目を設定する。左右で直接値を変更し、別項目への移動またはEnterで変更を確定した場合だけSDへ保存する。未変更の値は水色、変更中は黄色で表示し、元の値へ戻した場合は保存しない。変更中のEsc / Delはその行に留まって取消。保存失敗はエラーを表示し、実行中のアラートをOFFにする。既知のSD・データセット・NVS不良、Storage処理中は実行項目を無効表示にする。

| 項目 | 選択肢 | 新規作成時 |
|---|---|---|
| 通知 | OFF / ON | OFF |
| 監視階層 | 1〜Wordbook階層数（最大32） | 1 |
| 判定方式 | 毎回 / 緩和 / 進入確定 | 緩和 |
| 判定幅 | 5 / 10 / 20 / 50 / 100 / 200 m | 20 m |
| 通知音 | 単音 / 二連音 / 上昇音 / 下降音 / チャイム | 二連音 |
| 通知時間 | 1回 / 3 / 5 / 10 / 30秒 / 停止まで | 1回 |
| 試聴 | 選択音を1パターン再生 | 通知OFFでも可能 |
| 再読込 | 選択中データセットの設定をSDから再確認 | 不正ならOFFで再作成 |

音量は「動作設定→音量 / Volume」の1〜5に独立させ、NVSへ保存する。初期値は2。アラートファイルへ音量を複製しない。階層は1が最上位であり、深い階層ではその親を含めて比較する。データセット・Wordbook切替または監視設定の変更後、最初の有効な現在地を無音で基準にする。

## 3. 9点の取得と境界判定

判定幅を中心から各方向への距離とし、中心と東西南北・斜めの8点を使用する。例えば20 mなら東西・南北それぞれ−20、0、+20 mの3×3点である。緯度差へ換算し、経度差は現在緯度のcosで補正する。これは区域判定用の近似であり、測地距離の表示や投影処理ではない。日付変更線は折り返し、極点を越える点・取得不能点は無効とする。全9点が有効で同一階層ID列の場合を「周囲一致」とする。

区域コード取得には既存の128×128コードキャッシュを使用する。同じ区域コードの点は中心のID列を再利用する。別コードでも選択階層までのID列が同じなら同一区域とみなす。9点の処理はStorage内で直列に行う。Storage・UI借用領域が使用中なら最新GPSの処理を後で試み、通知の履歴をキューに積み増さない。GPS更新間隔やSD処理時間より短い越境を全て検出することは保証しない。

| 方式 | 通知条件 | 境界往復の扱い |
|---|---|---|
| 毎回 | 中心の区域が前回から変化 | A→B→Aもそれぞれ通知 |
| 緩和 | 最初の中心A→Bで直ちに通知 | A/B往復を抑制。全9点がAまたはBで連続3秒一致すると再武装。Cへ進んだ場合は別の越境として通知 |
| 進入確定 | 前回確定区域と異なる中心で全9点が一致 | 周辺に旧区域が残る間は通知しない |

取得不能・GPS喪失は越境として扱わず、緩和モードの連続一致時間を中断する。消音操作だけでは基準区域・往復抑制を解除しない。

## 4. 通知の寿命と操作

通知中の最初のキーは消音専用とし、通常の画面操作を実行しない。消灯中なら消音と同時に画面を復帰する。フッターは消音用の白いESCマークだけを表示するが、Delや他のキーでも消音できる。消音後は同じ画面・編集・ダイアログを維持する。

「1回」は1パターンだけを再生し、再生中の追加通知を蓄積しない。時間指定ではパターン間を500 ms空けて繰り返す。再通知は新しいパターンにまとめて指定時間を更新するが、最初の発音開始から60秒の上限を延ばさない。「停止まで」も最大60秒で停止する。試聴は通知のON/OFFに関係なく1パターンとし、同じ消音操作を使用する。

音列と既定波形はROM上の定数を使用する。ドライバ・DMA・音声タスクは起動時に一度初期化して保持し、通知ごとに動的確保しない。Cardputer ADVのES8311の電力制御は選択した省電力レベルに従う。通常・最大限では再生終了・取消後にDACと出力段を待機停止し、通知・試聴時に復帰する。パターン内や繰返しの短い休符では同じ再生セッションを維持する。これはコーデックの低消費電力制御であり、ボードの電源レールを物理切断するものではない。

## 5. SDファイル

各番号ディレクトリに`/dataset/01/_alert.dat`のように保存する。`_alert.tmp`は公開前、`_alert.bak`は置換中の退避にのみ使用する。階層設定を含む全アラート情報はこのファイルで保持し、NVSへ二重保存しない。

64バイト固定、数値はリトルエンディアンとする。

| オフセット | バイト数 | 内容 |
|---|---:|---|
| 0 | 4 | ASCII `RGAL` |
| 4 | 1 | 形式バージョン1 |
| 5 | 1 | レコード長64 |
| 6 | 1 | データセット番号1〜99 |
| 7 | 1 | Wordbook階層数1〜32 |
| 8 | 4 | 選択地図・Wordbookの識別値 |
| 12 | 1 | 通知OFF=0 / ON=1 |
| 13 | 1 | 監視階層1〜階層数 |
| 14 | 1 | 毎回0 / 緩和1 / 進入確定2 |
| 15 | 1 | 判定幅の上表の選択番号0〜5 |
| 16 | 1 | 通知音の上表の選択番号0〜4 |
| 17 | 1 | 通知時間の上表の選択番号0〜5 |
| 18 | 42 | 予約ゼロ |
| 60 | 4 | 先頭60バイトのCRC32（IEEE、反転入出力） |

識別値は検証済み地図索引ヘッダー64バイト、選択言語のWordbook索引ヘッダー128バイトを順にFNV-1a 32bitで集約する。これらには既存の元ファイル名・サイズ・更新情報・ヘッダー識別情報が含まれる。全データのハッシュではなく、索引が検出できない同一属性・同一ヘッダーの破損を追加検出する保証はない。選択Wordbookが変わり識別値が変わった場合も不整合としてOFFへ戻す。

読込みでは長さ・版・識別値・階層数・CRC・予約値・全項目の値域を確認する。欠落ならOFFの初期値を新規保存する。不整合ならエラーを表示し、当該ファイルを消去してOFFで再作成する。読出し・stat・書込み等のI/O失敗ではOFFとエラーにし、読めないファイルを破損と断定して消去しない。ディレクトリを同名ファイルとみなして削除しない。

保存はtmpへ書込み・同期・closeし、再読込み照合後、旧datをbakへ退避、tmpをdatへ公開する。途中失敗はOFFとし、可能なら旧ファイル名へ戻す。主ファイル欠落時にbakやtmpからONを自動復元しない。SDの突然の電源断に対するファイルシステム全体の原子性は保証しない。

## 6. メモリと実装箇所

設定・判定状態は固定長、ファイルレコードとID列の一時領域はスタックを使う。9点取得は既存UI借用領域、ReaderとFILの固定枠、Storageの既存コードキャッシュを共用する。地図用96 KiB、UI境界画像、画面用オフスクリーンを追加しない。正常な9点検索でC++ヒープ確保ゼロをホストで確認する。音声ドライバが起動時に保持する領域と外部FSライブラリ内部の確保は別に扱う。

実装の正本は`application/alarm/`、`Application`の`Alarm.cpp`、`task/storage/alarm/AlarmFile`、`PlaceLookup::observeAlarmInto`、`task/ui/AlarmText`と`hardware/AudioOutput`とする。設定保存はApp→Storageの同期受付と通常の非同期完了通知、音声操作はApp→UIの同期受付とUI内再生で扱う。
