# 区域アラート機能設計

2026-10-30の電源切替を外した比較により、間隔を空けた試聴と待機ノイズの改善を確認した。その後の電力管理は[電力管理設計](16_電力管理設計.md)に従う。「しない」は常時有効、「通常」「最大限」はDAC・出力段の待機停止とクロック先行復帰を使用し、以前のコーデック全体の深い停止は行わない。

## 1. 対象と責務

実GPSの現在地が、選択中データセットの最も細かい区域コードの別区域へ移ったことを音で知らせる。監視階層は指定せず、GLCの区域コード（uint32）を直接比較する。判定にはWordbookの親子ID列・地名文字列を使用しない。区域コード0は未定義として通知せず、基準区域も更新しない。

GPSがFIXし、SD・選択データセット・NVS設定が利用でき、データセットのアラートがONの場合に監視する。表示画面・消灯・ログ記録の開始／停止／一時停止とは独立する。履歴の文字・地図・再生画面でも実GPSを監視し、履歴の座標をアラートに使用しない。起動確認中・メンテナンス・USBモードでは監視しない。SDまたはNVSが利用できない間は無効とし、再生中の通知も停止する。GPS FIX喪失でも通知音を停止する。

Appが設定世代・区域遷移・発音期限を所有し、Storageが設定ファイルと9点の区域取得を担当する。AppはUIの既存バック領域を借りてStorageへ渡し、非同期完了を受けて借用を返却する。表示地名の結果とは区別し、監視結果で表示地名を上書きしない。UIは同期のControlAudioを受け、UIループで音を非同期に進める。アプリケーションのタスク・通信キュー・画像バッファは追加しない。音声ライブラリ内部の再生ワーカーは起動時に生成し、待機中も保持する。

## 2. データセットごとの設定

設定トップの「動作設定」「システム設定」に続く3番目の「アラート / Alerts」から次の項目を設定する。左右で直接値を変更し、別項目への移動またはEnterで変更を確定した場合だけSDへ保存する。未変更の値は水色、変更中は黄色で表示し、元の値へ戻した場合は保存しない。変更中のEsc / Delはその行に留まって取消。保存失敗はエラーを表示し、実行中のアラートをOFFにする。既知のSD・データセット・NVS不良、Storage処理中は実行項目を無効表示にする。

| 項目 | 選択肢 | 新規作成時 |
|---|---|---|
| 通知 | OFF / ON | OFF |
| 区域判定 | 即時 / 標準 / 確定 | 標準 |
| 通知音 | 単音 / 二連音 / 上昇音 / 下降音 / チャイム | 二連音 |
| 通知時間 | 1回 / 3 / 5 / 10 / 30秒 / 停止まで | 1回 |
| 再読込 | 選択中データセットの設定をSDから再確認 | 不正ならOFFで再作成 |

音量は「動作設定→音量 / Volume」の1〜5に独立させ、NVSへ保存する。初期値は2。アラートファイルへ音量を複製しない。監視対象は常に最も細かい区域コードとする。データセット・Wordbook切替または監視設定の変更後、最初の有効な現在地を無音で基準にする。

## 3. セル単位の区域判定

区域判定は、現在地をデータセットの経緯度グリッドへ量子化した1セルと、その隣接8セルを使用する。中心セルの求め方は通常の地名検索と同じ丸め規則とする。標準・確定では整数グリッド座標のX・Yに−1、0、+1を加えた3×3セルを調べ、距離mの指定や緯度に応じたcos補正を行わない。データセットの解像度が異なっても、参照するのは常に隣接セルである。即時では中心セルだけを取得する。

区域コード取得には既存の128×128コードキャッシュを使用する。中心コードと隣接コードを直接比較し、Wordbookを読まない。StorageのPlaceLookupは直前1セルの座標・区域判定方式・取得結果を固定メンバーへ保持し、同じセル・同じ方式なら再取得しない。データセットのclose／再構成時に破棄する。セル移動時も既存区域画像内ならSDへアクセスしない。9セルはStorage内で直列に取得し、別の画像バッファを追加しない。

アラート設定はStorage固定ProfileとAppの既存スナップショットで保持する。ファイル読込みは初期化・データセット再構成・明示的な再読込時、書込みは設定変更・作成修復・版移行時に限る。通常のGPS更新・越境通知では設定ファイルを読まない。区域画像のキャッシュ範囲外でのGLC補充、表示用地名の初回取得、GPSログ保存のSDアクセスは別途発生する。

| 区域判定 | 英語表記 | 通知条件 |
|---|---|---|
| 即時 | Immediate | 中心セルが直前の確定区域と異なれば、その取得結果で通知 |
| 標準 | Standard | 中心セルが別区域であり、中心を含む9セル中7セル以上がその区域なら通知 |
| 確定 | Confirmed | 中心セルが別区域であり、9セルすべてがその区域なら通知 |

標準・確定は条件を満たすまで直前の確定区域を保持する。A→Bが未成立の間に中心がAへ戻っても通知せず、Bへ確定した後にAへ戻る場合にも同じ条件を適用する。独立した判定幅・閾値の設定、3秒の再武装待機、区域ペアの履歴は持たない。設定画面は「区域判定」の一項目で3つの言葉を選択する。

日付変更線の隣接セルは経度を折り返す。極点を越えるセル、区域コード0は一致票へ含めない。取得不能セルがあっても分母を縮めず、標準は7票、確定は9票を必要とする。中心の区域を取得できなければ通知せず、基準区域も更新しない。

起動後やデータセット・監視設定変更後の最初の有効な中心区域は、通知せず基準にする。GPS喪失中も区域変更とみなさず、最後の確定区域を保持する。Storage・UI借用領域が使用中なら最新GPSの処理を後で試み、通知履歴をキューへ積まない。GPS更新間隔やSD処理時間より短い越境の全検出は保証しない。

## 4. 通知の寿命と操作

越境通知中の最初のキーは消音専用とし、通常の画面操作を実行しない。消灯中なら消音と同時に画面を復帰する。フッターは消音用の白いESCマークだけを表示するが、Delや他のキーでも消音できる。消音後は同じ画面・編集・ダイアログを維持する。

独立した試聴項目は設けない。通知音の行で左右により値を切り替えるたび、選択中の候補音を1パターン再生する。通知OFFでも再生する。設定を開いた時、通知音の行を選んだだけの時、Enterで確定する時には再生しない。再生中に別の候補音へ切り替えた場合は、その候補音で再生を置き換える。これは設定操作の音確認であり、越境通知の消音専用キー処理を適用せず、編集中の左右・上下・Enter・Esc等の操作を継続できる。

候補音の再生ではSDへ保存しない。別項目への移動・Enterで変更を確定した時だけ保存し、変更中のEsc / Delでは候補を取り消す。取消で元の音を再生し直さない。音確認には通常の音量・省電力制御を適用し、通知時間の設定にかかわらず1パターンで終わる。

「1回」は1パターンだけを再生し、再生中の追加通知を蓄積しない。時間指定ではパターン間を500 ms空けて繰り返す。再通知は新しいパターンにまとめて指定時間を更新するが、最初の発音開始から60秒の上限を延ばさない。「停止まで」も最大60秒で停止する。通知音変更時の音確認は上記の別処理とする。

音列と既定波形はROM上の定数を使用する。ドライバ・DMA・音声タスクは起動時に一度初期化して保持し、通知ごとに動的確保しない。Cardputer ADVのES8311の電力制御は選択した省電力レベルに従う。通常・最大限では再生終了・取消後にDACと出力段を待機停止し、通知・試聴時に復帰する。パターン内や繰返しの短い休符では同じ再生セッションを維持する。これはコーデックの低消費電力制御であり、ボードの電源レールを物理切断するものではない。

## 5. SDファイル

各番号ディレクトリに`/dataset/01/_alert.dat`のように保存する。`_alert.tmp`は公開前、`_alert.bak`は置換中の退避にのみ使用する。全アラート情報はこのファイルで保持し、NVSへ二重保存しない。

64バイト固定、数値はリトルエンディアンとする。

| オフセット | バイト数 | 内容 |
|---|---:|---|
| 0 | 4 | ASCII `RGAL` |
| 4 | 1 | 形式バージョン3 |
| 5 | 1 | レコード長64 |
| 6 | 1 | データセット番号1〜99 |
| 7 | 1 | Wordbook階層数1〜32 |
| 8 | 4 | 選択地図・Wordbookの識別値 |
| 12 | 1 | 通知OFF=0 / ON=1 |
| 13 | 1 | 予約ゼロ（旧版の監視階層は廃止） |
| 14 | 1 | 区域判定：即時0 / 標準1 / 確定2 |
| 15 | 1 | 予約ゼロ（旧版の判定幅は廃止） |
| 16 | 1 | 通知音の上表の選択番号0〜4 |
| 17 | 1 | 通知時間の上表の選択番号0〜5 |
| 18 | 42 | 予約ゼロ |
| 60 | 4 | 先頭60バイトのCRC32（IEEE、反転入出力） |

識別値は検証済み地図索引ヘッダー64バイト、選択言語のWordbook索引ヘッダー128バイトを順にFNV-1a 32bitで集約する。これらには既存の元ファイル名・サイズ・更新情報・ヘッダー識別情報が含まれる。全データのハッシュではなく、索引が検出できない同一属性・同一ヘッダーの破損を追加検出する保証はない。選択Wordbookが変わり識別値が変わった場合も不整合としてOFFへ戻す。

形式1・2の正常な旧ファイルは、通知ON/OFF・区域判定方式・音・時間を保持して形式3へ移行保存する。形式1は毎回→即時、緩和→標準、進入確定→確定へ読み替える。旧監視階層と旧判定幅は旧版の値域を検証してから破棄し、形式3では該当バイトを予約ゼロとする。Wordbook階層数はデータセットとの整合確認用メタデータとして残し、監視階層の選択には使わない。移行保存失敗はI/Oエラーとし、アラートを利用不能にする。

読込みでは長さ・版・識別値・階層数・CRC・予約値・全項目の値域を確認する。欠落ならOFFの初期値を新規保存する。不整合ならエラーを表示し、当該ファイルを消去してOFFで再作成する。読出し・stat・書込み等のI/O失敗ではOFFとエラーにし、読めないファイルを破損と断定して消去しない。ディレクトリを同名ファイルとみなして削除しない。

保存はtmpへ書込み・同期・closeし、再読込み照合後、旧datをbakへ退避、tmpをdatへ公開する。途中失敗はOFFとし、可能なら旧ファイル名へ戻す。主ファイル欠落時にbakやtmpからONを自動復元しない。SDの突然の電源断に対するファイルシステム全体の原子性は保証しない。

## 6. メモリと実装箇所

設定・判定状態は固定長、ファイルレコードの一時領域はスタックを使う。9点取得は既存UI借用領域、ReaderとFILの固定枠、Storageの既存コードキャッシュを共用する。地図用96 KiB、UI境界画像、画面用オフスクリーンを追加しない。正常な9点検索でC++ヒープ確保ゼロをホストで確認する。音声ドライバが起動時に保持する領域と外部FSライブラリ内部の確保は別に扱う。

実装の正本は`application/alarm/`、`GpsApplication`の`Alarm.cpp`、`task/storage/alarm/AlarmFile`、`PlaceLookup::observeAlarmInto`、`task/ui/AlarmText`と`hardware/AudioOutput`とする。設定保存はApp→Storageの同期受付と通常の非同期完了通知、音声操作はApp→UIの同期受付とUI内再生で扱う。

## 7. ベルの表示

GPSアプリの共通ヘッダーで、SDアイコンの左に12×12のROMビットマップを表示する。選択中データセットの有効なアラート設定がONなら白、実際の越境通知が鳴動中なら黄色とする。OFF・未選択・利用不能時は非表示。GPS未測位でもONの設定は白いベルで示す。通知音候補の試聴は越境通知の鳴動表示に含めない。
