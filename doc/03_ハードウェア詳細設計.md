# Geoputer ハードウェア詳細設計

文書状態: Draft 0.10
対象機: M5Stack Cardputer ADV（Mesh KitのGNSS使用 / 外付けGPS使用を選択可能）  
構成: Cardputer ADV + Cap LoRa-1262のGNSS、またはCardputer ADV + 外付けGPS  

## 1. 文書の目的

本書は、Geoputerで使用する対応ハードウェア、ピン割り当て、共有バス、周辺デバイスの初期化条件およびハードウェア共存試験を定義する。

製品コンセプトと利用体験は「[Geoputer コンセプト・利用体験概要設計](01_コンセプト・利用体験概要設計.md)」、画面と操作は「[Geoputer 画面・操作機能設計](画面・操作/02_画面・操作機能設計.md)」、ソフトウェアの動作モードとバス利用方針は「[Geoputer システム構成設計](04_システム構成設計.md)」を参照する。

## 2. 対応ハードウェアとGPS接続モード

本体はM5Stack Cardputer ADVとする。GPS接続モードは以下の2つから選択可能とする。

| モード | 構成 | 使用するGPS |
|---|---|---|
| Mesh Kit | Cardputer ADV + Cap LoRa-1262 | Cap内蔵GNSS |
| 外付けGPS | Cardputer ADV + 外付けGPS（Mesh Kitの代わりに使用） | 外付けGPS |

LoRa機能は使用しない。Mesh KitモードでもCapの無線機能、RFアンテナスイッチおよび位置送受信は利用対象に含めない。

アンテナ脱落時の送信を抑止するため、GPSロガー・USBストレージの両モードで、`setup()`の最初にNRST（G3）をLOW出力へ固定する。出力ラッチを先に設定してからGPIO pad holdを切り替え、前回起動の保持状態からも安全にリセットへ戻す。NSS（G5）は非選択のHIGHとする。この段階ではLoRaへSPI通信を行わない。

StorageがSD用SPIを初期化し、SDのCS（G12）をHIGHにした後、LoRaをSLEEPへ移す。NRST LOWを1ms以上維持してから解除し、BUSY（G6）のLOWを最大100ms待つ。GetStatus（0xC0）のモードフィールドで現在のSTDBY_RCを確認した場合だけ、SetSleep（0x84、パラメーター0x00）を送る。コマンド結果フィールドは過去の操作結果であり、今回のSetSleepの受付結果として扱わない。起動直後の実機応答0x2Aも、モードがSTDBY_RCならSLEEP要求の対象とする。予約ビット7・0は値を規定しないため判定から除く。SPIは1MHz・mode 0とし、初期化時のこの操作以外にLoRaを選択しない。TX/RX・周波数・PA・RFアンテナスイッチの設定は行わない。

SetSleep後は1ms待ち、BUSY HIGHを確認してからNSS HIGH・NRST HIGHをGPIO pad holdで固定する。NSSの下降によるSLEEP復帰と、NRSTの不用意な変化を防ぐ。SLEEP中の再照会は行わない。応答不正、BUSYタイムアウト、SLEEP後のBUSY不整合、GPIO保持設定の失敗ではNRST LOWのリセット保持へ戻し、GPSとSDの初期化は続ける。新しいタスク・キューは追加せず、Storageだけが共有SPIを使って実行する。設定の省電力ON/OFFには依存せず常に実行する。

これはLoRa内部のcold SLEEPまたはリセット保持による停止であり、物理的な電源OFFではない。[Cap LoRa-1262 V1.1公式回路図](https://m5stack-doc.oss-cn-shenzhen.aliyuncs.com/1208/U214-sche-Cap-LoRa1262_SCH_V1.1_20251029_2025_11_07_22_53_19.pdf)では、PI4IOEのP1にあるSHUT_DOWNは未接続で、LoRa専用電源スイッチはない。P0はRFアンテナスイッチ用であり、電源制御には使わない。[SX1261/2データシート](https://m5stack-doc.oss-cn-shenzhen.aliyuncs.com/1177/DS_SX1261_2_V2-2.pdf)の13.1.1節に従い、SLEEPは設定保持とRTC起床を使わず内部ブロックを停止する。GPSの給電・UART、SD、I2C電源レギュレーターは維持する。SLEEP判定は状態応答とBUSYに基づくもので、電流やRF出力の実測とは区別する。GPIO制御開始前の電源投入・ROMブート中、他ファームウェア、外部故障までの安全を保証するものではない。

GPS接続モードは設定として保存し、再起動時に反映する。選択したモードのGPSだけを初期化する。初期版では他のCardputer世代を対象としない。

## 3. 構成要素

| 区分 | 構成 |
|---|---|
| 本体 | M5Stack Cardputer ADV |
| GPS構成 | Mesh KitモードではCap LoRa-1262、外付けGPSモードでは対応GPS |
| MCU | ESP32-S3FN8、240 MHz、Flash 8 MB |
| 画面 | ST7789V2、240 × 135 px、横向き |
| 入力 | TCA8418接続の56キーキーボード |
| ストレージ | 本体microSD |
| GNSS | Mesh KitモードではATGM336H-6N / AT6668、UART。外付けGPSは対応機種ごとに定義 |
| IMU | BMI270 |
| バッテリー | Cardputer ADV内蔵1750 mAh |

## 4. GPS接続構成

Mesh KitモードではCap LoRa-1262をCardputer ADVのEXT 2.54-14Pへ直接装着し、内蔵GNSSのみ使用する。以下のピン割り当てとUART初期値はMesh Kitモードに適用する。

### 4.1 GNSS接続

| 信号 | ESP32-S3 GPIO | 接続方向 |
|---|---:|---|
| UART TX | G13 | Cardputer ADVからCap側GPS_RX |
| UART RX | G15 | Cap側GPS_TXからCardputer ADV |

GNSS UARTの初期設定は115200 bps、8 data bits、no parity、1 stop bitとする。

GPSログ周期の初期値は1 Hzとする。ログ周期はGNSSモジュールのNMEA出力周期とは別のアプリケーション設定として扱う。

### 4.2 外付けGPS接続

外付けGPSモードでは、Mesh Kitの代わりにCardputer ADVへ外付けGPSを接続する。対応機種、接続端子、電源・信号電圧、UART RX/TXのGPIO、ボーレートおよび休止・復帰方法は、採用するGPSの接続プロファイルで定義する。

外付けGPSの具体的な機種と配線は未確定とし、Mesh Kit用のGPIOと115200 bpsをそのまま適用しない。LCD、キーボードおよびmicroSDと競合しない接続を確認する。NMEAによる測位情報の取得とPAUSE / ACTIVEの制御可否を実機で確認してから対応機種とする。

## 5. 本体周辺デバイス

### 5.1 microSD

| microSD信号 | ESP32-S3 GPIO |
|---|---:|
| CS | G12 |
| MOSI | G14 |
| SCK | G40 |
| MISO | G39 |

microSDはGPSログおよびGaluchatデータの保存先とし、ファイルシステムにFAT32を使用する。1ファイルのサイズは4 GiB未満とする。現在のビルド構成ではexFATを使用しない。

動作設定とGPS接続モードは、本体内蔵FlashのNVSへ保存する。ArduinoのPreferencesを使用し、Geoputer用名前空間を`geoputer`とする。設定の読込み・保存・初期値への復元はSDの接続状態に依存しない。SDカードの取り外し・交換・フォーマットではNVSの設定を変更しない。

### 5.2 LCD

| LCD信号 | ESP32-S3 GPIO |
|---|---:|
| Backlight | G38 |
| Reset | G33 |
| RS / DC | G34 |
| Data | G35 |
| Clock | G36 |
| CS | G37 |

BACKGROUND_MODEではLCDバックライトを消灯する。初期版では表示コントローラー自体のSleep制御より、ログ動作の安定性を優先する。

### 5.3 キーボード、IMU、音声系

G8/G9のI2Cバスは、少なくとも以下のデバイスで共有される。

- TCA8418キーボードコントローラー
- BMI270 IMU
- ES8311音声コーデック

キーボード割り込みにはG11を使用する。初期版ではIMUと音声機能をアプリケーション機能として使用しないが、同一I2Cバス上に存在することを前提にする。

## 6. SPIとストレージアクセス設計

microSD用SPIはBoard層で初期化する。Mesh KitモードでもLoRaドライバーは使用しない。起動時のLoRa SLEEP操作を終えた後は、CapのNSS（G5）をGPIO pad holdで非選択のHIGHに保ち、microSDアクセスでLoRaを起床させない。

microSDのファイルアクセスはStorageTaskへ集約する。GaluchatServiceとLogWriterはその内部で実行し、同じReaderやファイルを他タスクから操作しない。読み込みと書き込みの実行順序はタスク構成設計に従う。

NVSへのアクセスもStorageTaskへ集約し、設定用のタスクやキューを追加しない。NVSとSDの利用可否・エラーは別々に管理する。設定初期化はGeoputerの設定だけを対象とし、NVS全体や他ライブラリの名前空間を消去しない。SDマウント失敗を理由に自動フォーマットを行わず、ユーザーがSettingsのストレージ操作から確認した場合だけFAT32でフォーマットする。

## 7. I2C共有設計

G8/G9のI2Cバスは、本体内蔵デバイスで共有する。

以下を実装条件とする。

- I2CバスはBoard層で一度だけ初期化する。
- 本体の各デバイスドライバーが同じバスを使用する。
- デバイス初期化前にI2Cアドレスの競合がないことを確認する。
- I2C障害が発生してもGNSS UARTとGPSログ処理を停止しない。

## 8. UART設計

選択したGPS接続モードのプロファイルに従ってGNSS専用のHardwareSerialを使用する。USBシリアルのデバッグ出力とGNSS UARTを分離する。

NMEA受信バッファは、SD書き込みや画面描画による一時的な処理遅延を吸収できるサイズに設定する。メイン処理ではUARTを高頻度にdrainし、完全なNMEA行をGPSManagerへ渡す。

UART受信断は次のように区別する。

| 状態 | 判定例 |
|---|---|
| GNSS PAUSE | 測位休止中。受信断とは扱わない |
| GPS受信中 | GNSS ACTIVEで、規定時間内に有効なNMEA行を受信 |
| NO FIX | NMEAは受信しているが位置が無効 |
| NO GPS | GNSS ACTIVEにもかかわらず、規定時間を超えてNMEAを受信していない |

### 8.1 GNSSのPAUSE / ACTIVE

GNSS状態はPAUSEとACTIVEの2状態とし、電源投入時はPAUSEで開始する。

| 状態 | ハードウェア動作 |
|---|---|
| PAUSE | 測位休止を要求し、新しいNMEAとGPS Fixを生成しない |
| ACTIVE | GNSSを通常測位状態へ戻し、UARTからNMEAを受信する |

Mesh KitモードのCap LoRa-1262は、Cardputer ADV側へGNSS UART RX/TXを公開しているが、GNSS専用の電源制御GPIOは公開していない。このため、PAUSEはGNSSモジュールへの給電遮断ではなく、GNSSプロトコルによる測位休止として実装する。

外付けGPSモードでは、採用した機種のプロトコルまたは電源制御に従って休止と復帰を行う。具体的な方法は接続プロファイルで定義する。

UARTを閉じるだけではGNSSモジュールの測位と消費電力が継続する可能性があるため、PAUSE完了とはみなさない。使用する休止コマンド、復帰方法、応答および消費電流を実機で確認する。信頼できる休止方法を確認できない場合は既知のハードウェア制約として記録する。

## 9. 電源と動作モード

### 9.1 BACKGROUND_MODE

| デバイス | 状態 |
|---|---|
| GNSS | GPSログの記録中・一時停止中はACTIVE、停止中は測位要求に従う |
| microSD | 必要時のみ、ログ中はまとめ書き |
| LCD Backlight | OFF |
| Wi-Fi / BLE | OFF |

### 9.2 VIEW_MODE

| デバイス | 状態 |
|---|---|
| GNSS | 現在位置を必要とする画面ではACTIVE、それ以外は要求元に従う |
| microSD | ON |
| LCD Backlight | ON |

### 9.3 省電力評価

GNSS PAUSE中の実消費電力と復帰時間を測定する。Light Sleepは、GNSS状態遷移、キー割り込み、SDおよびタイマーとの共存を実機で確認してから導入する。

電池寿命は次の状態を個別に実測する。

- GNSS PAUSE、画面消灯
- GNSS ACTIVE、GPS捕捉前
- GNSS ACTIVE、GPS捕捉後
- GPSログRECORDING、画面消灯
- VIEW_MODE、通常輝度
- Galuchatファイル読込中

## 10. Board層の責務

対応ハードウェアに関する処理を`board`モジュールへ集約する。

```text
application/
  board/
    board_config.h
    Board.cpp
    Board.h
    SharedBus.cpp
    SharedBus.h
```

Board層は次を担当する。

- 本体GPIOとGPS接続プロファイルの定義
- LCDとキーボードを含むCardputer ADV初期化
- microSD用SPI初期化
- 共有I2C初期化
- 選択したGPS接続モードのGNSS UART初期化
- GNSSのPAUSE / ACTIVE制御
- microSD CSの安全な初期状態設定
- Mesh Kitモードで未使用Cap側SPIデバイスを非選択に維持
- 周辺デバイスの初期化結果管理

各機能モジュールへGPIO番号を直接記述しない。

## 11. 初期化順序

```text
Cardputer ADV基本初期化
 ↓
LCD / keyboard初期化
 ↓
共有I2C初期化
 ↓
microSD用SPI初期化
 ↓
SD CS=HIGH（Mesh KitモードではCap NSS=HIGH）
 ↓
microSDマウント
 ↓
NVSのGeoputer設定領域を準備
 ↓
NVSから設定読込・GPS接続モード選択
 ↓
選択したGPSのGNSS UART初期化
 ↓
GNSS PAUSE
```

Galuchatデータの確認は、このハードウェア初期化後にアプリケーション層が行う。GPSログはSTOPPEDで開始し、GPSログ停止中は、表示などの測位要求がなければGNSSもPAUSEを維持する。一時停止は位置記録だけを止め、GPSデバイスをOFFにせずGNSS ACTIVEを維持する。

microSDのマウントに失敗しても、NVSの準備・設定読込みとGPS初期化を継続する。NVSの準備または読込みに失敗した場合は、エラーを表示してRAM上の初期値で起動する。NVS障害をSDマウント失敗として扱わない。

## 12. エラーの分離

| 障害 | 影響範囲 | 動作方針 |
|---|---|---|
| GNSS UART初期化失敗 | 測位・GPSログ | UIと再初期化操作を継続 |
| microSDマウント失敗 | ログ保存・Galuchat | GPS受信とRAM保持を継続 |
| NVS準備・設定読込失敗 | 設定の復元 | 初期値で起動し、NVSエラーを表示。SD・GPSは個別に初期化 |
| LCD初期化失敗 | UI | デバッグ出力を残し停止扱い |
| キーボード初期化失敗 | 操作 | ロガーを継続しエラー表示 |

一つの周辺デバイスの障害で、無関係なデバイスまで再初期化しない。

## 13. ハードウェア共存試験

開発計画のPhase 1（GPS・Storageの追加とハードウェア共存確認）で、両GPS接続モードについて次を確認する。

1. Mesh Kitモードと外付けGPSモードを選択して起動できる。
2. LCD、キーボード、microSDおよび選択したGPSを初期化できる。
3. 電源投入後、GNSSがPAUSEで開始する。
4. GNSSをPAUSEからACTIVEへ移行し、有効なNMEAとGPS Fixを取得できる。
5. GNSSをACTIVEからPAUSEへ戻し、再度ACTIVEへ復帰できる。
6. PAUSE時とACTIVE時のGPS消費電流を測定し、休止の実効性を確認できる。
7. GNSS NMEAを受信しながらmicroSDへ連続書き込みできる。
8. Mesh Kitモードで未使用のCap側SPIデバイスがmicroSDアクセスへ干渉しない。
9. 外付けGPSの電源、信号電圧およびGPIOが本体周辺デバイスと適合し、競合しない。
10. Galuchatファイル読込中もGNSS UARTの受信データを失わない。
11. キー入力と未使用のIMU・音声系がI2C上で共存する。
12. SDカード未挿入とGPS未接続相当の障害を個別に検出できる。
