# Geoputer データセットメタデータ仕様

文書状態: 採用仕様1.4（ファイル形式バージョン1、異常時の起動継続・表示統一は実装反映済み）

更新日: 2026-10-21

対象: microSD上のGaluchatデータセットに付属するメタデータ

## 1. 目的と適用範囲

本書は、データセットのタイトル、短い説明、使用するGLCおよび言語別Wordbookの対応を定義する。番号ディレクトリごとに小さなテキストファイルを配置し、固定長の行バッファで順次処理できる形式とする。JSONや汎用INIの全機能は使用しない。

解像度、格納範囲、チャンク数はGLCを正本とし、本メタデータへ重複して記載しない。Wordbookの文字コードはWordbook内部のメタデータから判定する。

本書はファイル形式と、データセットの選択・保存・再起動・起動失敗の条件を定義する。タスク通信は同期で受付・非同期で結果通知するDatasetOperationを使用し、NVS保存は設定レコードの形式バージョン3を使用する。タスクの責務は[タスク構成設計](06_タスク構成設計.md)、配置と利用条件は[システム構成設計](04_システム構成設計.md#6-galuchatデータ)に従う。

## 2. 配置とデータセットの単位

SDカード直下の`/dataset/01/`、`/dataset/02/`等の番号ディレクトリを、それぞれ独立したデータセットとする。ディレクトリ名は`01`〜`99`のASCII数字2桁に限定し、`00`、1桁、3桁以上や数字以外を含むディレクトリは候補にしない。各ディレクトリ直下にメタデータ`dataset.ini`を1個、使用する共通のGLCを1個、Wordbookを言語ごとに配置する。

```text
/dataset/
├ 01/
│  ├ dataset.ini
│  ├ municipality.glc
│  ├ municipality-ja.giswordbook
│  └ municipality-en.giswordbook
└ 02/
   ├ dataset.ini
   ├ town.glc
   └ town-ja.giswordbook
```

パスはSDカード内の表記とし、本体のマウント先を含める場合は`/sd/dataset/01/dataset.ini`となる。識別にはディレクトリ名を使い、翻訳や編集によって変わるタイトルを識別子として使用しない。ディレクトリ番号をINI内へ重複して記載しない。

地図とWordbookのファイル名はINIで明示する。拡張子に一致するファイルが別に存在しても、指定されていないファイルを自動選択しない。

## 3. テキストと読取り規則

| 項目 | 規則 |
|---|---|
| 文字コード | UTF-8。BOMなしを基本とし、先頭のUTF-8 BOMは許容する |
| 改行 | LFまたはCRLF。最終行の改行は省略できる |
| 行の長さ | ファイル先頭のBOMと改行を除き最大255バイト。UTF-8の文字数ではなくバイト数で数える |
| 空白 | 行頭・行末、およびキー・値の前後のASCII空白とタブを除去する。値の内部の空白は保持する |
| 空行 | 無視する |
| コメント | 行頭の空白除去後に`#`で始まる行を無視する。行末コメントは扱わない |
| セクション | `[dataset]`または`[言語識別子]`とする。閉じ括弧の後には空白以外を置かない |
| 項目 | 最初の`=`でキーと値を分ける。以後の`=`は値の一部とする |
| 引用・エスケープ | 解釈しない。引用符やバックスラッシュは文字として扱う |
| 複数行の値 | 使用しない。タイトルと説明も各1行とする |
| 大文字・小文字 | セクション名とキー名は区別し、本書の小文字表記を使用する |

最初のセクションより前に項目を置かない。同じセクション名を複数回宣言せず、同一セクションの定義済みキーを重複させない。行長超過、UTF-8の不正なバイト列、NUL、構文に合わない行は不正なメタデータとして扱う。行を切り詰めて解釈しない。

形式バージョン1における未知のキーは無視する。セクションは共通情報と言語情報だけを使用し、任意の独自セクションは設けない。既知項目の意味を変更する場合は形式バージョンを変更する。

読取りは1行ずつ行い、一覧や選択中の表示に必要な項目だけを保持する。全ファイルの読込みや、全言語を動的なツリーへ展開することを前提にしない。行の格納には終端NULを含め256バイトを用意し、改行の処理で行長上限を超えて格納しない。実装時の行長上限は、他の容量設定と同様に`application/Config.h`へ集約する。

## 4. セクションと項目

### 4.1 共通情報 `[dataset]`

| キー | 必須 | 内容 |
|---|---|---|
| `version` | 必須 | 本形式のバージョン。値は`1`とする |
| `map` | 必須 | 使用するGLCのファイル名。拡張子は`.glc`とする |
| `default_language` | 必須 | データセットの既定言語。対応する言語セクションが存在すること |

各値は空にしない。共通情報セクションは1個とし、言語セクションとの記載順序は問わない。

### 4.2 言語情報 `[ja]`、`[en]`等

言語識別子はASCII小文字の英字から始め、小文字英数字のまとまりをハイフンで区切る。`ja`、`en`、`en-us`等を使用できる。空の識別子、先頭・末尾のハイフン、連続するハイフンは使用しない。言語識別子は最大31バイトとし、終端NULを含む32バイトの固定領域で扱う。`dataset`は共通情報のために予約する。

| キー | 必須 | 内容 |
|---|---|---|
| `title` | 必須 | その言語で表示する短いデータセット名。空にしない |
| `description` | 任意 | その言語で表示する短い説明。省略または空の場合は説明なしとする |
| `wordbook` | 必須 | その言語のWordbookのファイル名。拡張子は`.giswordbook`とし、空にしない |
| `display_line1` | 任意 | 地名の1行目の書式。省略時の扱いは5.1節に従う |
| `display_line2` | 任意 | 地名の2行目の書式。空文字も指定できる |

言語セクションは1個以上とする。言語識別子は地名の言語を表し、文字コードを表さない。各言語のWordbookはUTF-8で、共通GLCの区域コードに対応する辞書であることを配布物の条件とする。言語の一致だけで区域コードの対応が保証されたとは扱わない。

`map`と`wordbook`は同じディレクトリ直下のファイル名だけを指定する。絶対パス、サブディレクトリ、`/`・`\`・`:`を含む指定、`.`と`..`は認めない。別の番号ディレクトリのファイルを参照しない。

## 5. 表示と言語の扱い

一覧はディレクトリ番号とタイトルを表示し、説明は詳細表示用に使用する。タイトル・説明はUIの表示言語に一致するセクションを使用し、該当セクションがない場合は`default_language`のセクションを使用する。画面に収まらない文字列はUTF-8の文字境界を保って表示側で省略し、保存内容自体は切り詰めない。

UIの表示言語と、地名取得に使うWordbookの言語は別の情報として扱う。日本語UIで英語地名を表示する組合せも表現できる。データセットを初めて選択した場合は`default_language`を地名用言語の初期値とし、詳細画面で収録されている別の言語へ変更できる。UIの表示言語を変更するだけでは、選択済みのWordbookを変更しない。選択したディレクトリ番号と言語識別子を一組としてNVSへ保存する。

本形式による言語の記載は、端末にその言語のフォントが実装されていることを保証しない。描画可能な文字とレイアウトは画面共通仕様に従う。

### 5.1 地名2行の書式

地名用Wordbookの言語セクションに`display_line1`と`display_line2`を置き、Wordbookから区域コードに対応して取得した文字列配列を2行へ展開する。タイトル・説明とは異なり、書式はUI言語ではなく選択中のWordbook言語に従う。

```ini
[ja]
title=日本・住所
wordbook=address-ja.giswordbook
display_line1=%0 %1%2%3
display_line2=%4%5
```

| 記法 | 展開 |
|---|---|
| `%0`〜`%9` | 0始まりの項目番号。配列の順番をそのまま参照する |
| `%%` | 文字としての`%` |
| その他の文字 | 固定文字として表示する |

項目が空文字、または配列に存在しない場合は空文字を展開する。隣接する固定スペースは自動削除しない。番号は1桁のみとし、`%10`は`%1`と固定文字`0`となる。項目の内容は再解釈せず、そこに含まれる`%`をそのまま表示する。末尾の単独`%`や`%A`などは不正な書式とし、一覧・詳細・適用時のメタデータ検証でエラーにする。使用しない言語の不正書式や同じキーの重複も検出する。行長・UTF-8・前後の空白除去は既存のINI規則に従い、引用符やバックスラッシュでのエスケープは追加しない。

両キーを省略した場合は従来の配置とする。6項目のWordbookでは先頭項目と項目1〜3を1行目へ、項目4・5を2行目へ連結し、それ以外の項目数では先頭項目と残りを1行目にまとめる。先頭項目と残りの行政名がともにある場合だけ間に半角スペースを入れる。N03の5項目で従来表示を明記する例は`display_line1=%0 %1%2%3%4`、`display_line2=`となる。

片方だけ指定した場合は未指定の行を空とする。両方を空文字に指定すれば地名の2行を空表示にできる。上下行を自動的に結合したり、あふれた文字を他方へ送ったりしない。

地名は東雲16×16で表示する。半角スペースU+0020だけは8×16の横8ドット送りとし、全角スペースU+3000は16ドット幅を維持する。1行は232ドット以内とし、展開後の文字幅で判定する。超過する場合はUTF-8の文字境界を保って末尾を`...`へ置き換え、省略記号の48ドットを含めて収める。途中の項目を先に省略しない。書式展開は固定長の行バッファを使い、長い項目や繰返し参照でも連結後の巨大な文字列を確保しない。

Storageが完成した2行を地名キャッシュへ保存し、Appへ値コピーで通知する。Appは再結合せず、そのままUIへ渡す。書式はデータセットを開く際に読み込み、変更はSD上のINIを更新した後に再起動または再マウントして反映する。Readerの再オープン時に旧書式のキャッシュを破棄する。形式バージョンは任意キー追加として1を維持し、NVSの保存形式も変更しない。

## 6. GLC・Wordbookとの役割分担と検証

一覧取得ではINIを読み、全候補のGLC本文や索引を読み込まない。説明とWordbookの対応は必要時にINIを読み直して取得できる。GLCからの情報取得・利用条件の検証は対象の選択時に行う。INIの読取り成功だけを、使用可能判定としない。

| 情報 | 正本と取得方法 |
|---|---|
| タイトル・説明・言語別ファイルの対応 | `dataset.ini` |
| 経度・緯度方向の解像度 | GLCの`unit_inv_x`・`unit_inv_y`。1セルの角度幅はそれぞれ逆数で表す |
| 格納範囲 | GLCの各チャンクの位置・幅・高さから求める。全体の外接矩形にはデータのない隙間を含み得る |
| チャンク数 | GLCから取得し、最大1500チャンクの利用条件を適用する |
| Wordbookの文字コード | Wordbook内部の`token_encoding`、未指定または空の場合は`text_encoding`。`utf8`または`utf-8`のみを大文字・小文字を区別せず受け付ける |

解像度は角度単位であり、固定のメートル値とは扱わない。INIへ範囲・解像度・チャンク数・文字コードを追記しても、それらを本体データの代わりに使用しない。

INI・Wordbook・タスク間メッセージ・UIの文字列はUTF-8に統一し、端末内で文字コードを変換しない。SJIS（CP932）やUTF-16、文字コード未指定のWordbookは文字コード未対応として扱う。UTF-8を宣言したWordbookの不正バイト列は地名読出し時に検出し、地名キャッシュに登録しない。ヘッダー確認時に全地名を走査することは要求しない。

既存のSJIS版Wordbookを使用していたSDカードは、同じGLCに対応するUTF-8版Wordbookを配置し、INIの`wordbook`をそのファイル名に更新する。ファイル名や文字コード宣言だけの変更ではデータ本体を変換できない。GLC・INIの形式バージョンとNVS設定レコードの形式は変更しない。

適用前には指定したGLCと使用対象のWordbookの存在、対応するファイル形式、Wordbookの文字コード、およびGLCのチャンク上限を検証する。指定ファイルが不足している場合に、別のファイルを拡張子で検索して代用しない。

## 7. 異常時の扱いと現行実装との区別

| 状態 | 扱い |
|---|---|
| `dataset.ini`が存在しない、または読み取れない | メタデータを利用できないデータセットとして扱う |
| 構文不正、行長超過、必須項目の不足、セクション・定義済みキーの重複 | 不正なメタデータとして扱う |
| `version`が`1`以外 | 未対応のメタデータ形式として扱う |
| 既定言語のセクションが存在しない | 不正なメタデータとして扱う |
| 指定したGLC・使用対象のWordbookが存在しない | 対象ファイル不足として扱う |
| GLC・Wordbookの形式不正、文字コード未対応、読出し失敗 | 本体データの検証エラーとして扱う |
| GLCが1501チャンク以上 | チャンク上限超過として扱い、地図本文の検索へ進まない |

不正なデータセットを新たな選択値として適用・保存しない。検証失敗時は以前の有効な選択と保存値を維持し、再起動しない。使用中の選択先が起動時または検索中に利用できない場合は、8.3節に従って地名欄へ原因を表示し、逆ジオコーディングを停止して通常起動・GPS受信を継続する。

メタデータ読取り、一覧・詳細・言語選択、停止完了条件、NVS保存後の再起動に加え、8.3〜8.4節の起動継続・地名欄への原因統一・再読込み抑止を実装した。Storageは選択世代と失敗理由を保持し、明示的な再検証が成功した世代だけで使用可能へ戻す。検証範囲は[データセット異常時の起動継続検証](検証/データセット異常時の起動継続検証.md)を参照する。

## 8. 選択・保存・再起動

### 8.1 選択画面

動作設定の「データセット」から番号・タイトルの一覧を開く。上下キーで選択し、Enterで詳細を開く。詳細にはタイトル、説明、GLCから取得した解像度・格納範囲・チャンク数、地名用Wordbookの言語を表示する。地名用言語はUIの表示言語と独立して選択できる。Esc / Delで戻る操作や候補の変更だけでは、使用中のデータとNVSを変更しない。

### 8.2 変更の前提と適用

データセットまたは地名用Wordbookの言語を変更して適用する前に、GPSログの停止が完了していなければならない。一時停止のPAUSEDは停止完了として扱わない。STOPPEDに加え、未保存レコードの保存、保持中の採用点の処理、セッションの閉鎖まで完了していることをAppが確認する。変更のために記録を自動停止せず、条件を満たさなければGPS Loggerで停止するよう表示する。

適用操作は「適用して再起動」として示す。Appが停止完了条件を再確認し、候補のGLCと使用対象のWordbookを検証した後、番号と言語の組をNVSへ保存する。保存要求の受付ではなく、実際の保存成功を確認してから再起動する。保存失敗ではエラーを表示し、再起動や新しいデータの適用を行わない。現在の番号と言語の組に変更がなければ再起動しない。

適用の受付後から検証・保存・再起動までの間は、ログの開始・再開を受け付けない。検証または保存に失敗して適用を取り消した後は、旧データセットのまま通常の操作へ戻す。

新しいデータセットとWordbookは再起動後にオープンする。実行中のReaderやキャッシュを新しいデータへ差し替える方式は採用せず、旧矩形キャッシュ・地名キャッシュを再起動後へ持ち越さない。

### 8.3 起動時の復元とエラー

起動時はNVSから番号と言語の組を復元する。選択値が未保存の場合は番号`01`と、そのINIの`default_language`を初期選択とする。先行版の固定候補値をディレクトリ番号として流用せず、旧形式からの移行時もこの初期選択を使用する。

使用中のデータセットに異常があっても、Bootを確認完了として通常の待ち時間を経てLive Placeへ進む。選択先欠落だけを起動停止にする例外は設けない。GPS受信・設定画面・ログ閲覧など利用可能な機能を継続し、SDが利用可能ならGPSログの開始・記録も許可する。ただし、新しい測位点の追加には有効Fixを必要とし、Fixなしで開始・再開を受け付けた場合は次の有効Fixを待つ。既存ログの操作は現在のFix・データセットを必要としない。複数障害時の機能制約は[システム構成設計7節](04_システム構成設計.md#7-エラー状態と機能の利用条件)に従う。起動時のログ状態は従来どおりSTOPPEDであり、自動記録は開始しない。欠落した番号や言語を別候補へ自動変更せず、NVSの選択値を保持する。

BootではSDとGALUCHAT DATAの各チェック行に原因を示す。Live Placeへ進んだ後は、地名の2行を次表のエラー内容に置き換える。地名欄全体を警告専用画面へ切り替えず、GPS情報・記録状態・操作ガイドを通常どおり残す。対象が未選択の候補である場合の検証失敗はSettings内で表示し、使用中のデータセットのエラーへ転記しない。ただし、検証中にSDそのものの利用不可が判明した場合は、候補固有の失敗ではなく共有媒体の障害として反映する。

| 原因 | 地名1行目（日本語） | 地名2行目（日本語） | 地名1行目（英語） | 地名2行目（英語） |
|---|---|---|---|---|
| 選択番号ディレクトリ、INI、指定GLC、言語セクション、Wordbookの欠落 | データセットが | 見つかりません | DATASET | NOT FOUND |
| INIの構文・必須設定・ファイル対応の不整合、対象の曖昧さ | データセットの | 構成が不正です | DATASET | CONFIG ERROR |
| 未対応のメタデータ形式バージョン | データセットの | 形式に未対応です | DATASET | BAD VERSION |
| GLC・Wordbookの形式不正・破損、INI・GLC・Wordbookの読出し失敗 | 地図データを | 読み込めません | MAP DATA | READ ERROR |
| Wordbookの文字コード未対応 | データセットの | 文字コードが未対応です | WORDBOOK | BAD ENCODING |
| チャンク数が1500を超過 | チャンク数が | 上限を超えています | MAP CHUNKS | OVER LIMIT |
| 地図・索引・辞書・検索用メモリの確保失敗 | 地図読込用の | メモリが不足しています | MAP MEMORY | NOT ENOUGH |
| SD未挿入、非対応ファイルシステム、マウント失敗などで媒体を利用不可 | SDカードが | 利用できません | SD CARD | NOT READY |

Storageは失敗理由を状態として通知し、Appがその理由と使用可否を集約してUIへ渡す。UIは上表の固定文言を描画し、正常な地名結果の書式展開済み2行とは区別する。文言はUIの表示言語で選び、データセットのWordbook・表示書式・文字コード変換に依存させない。フォントと位置は地名欄と共通とし、日本語・英数字とも東雲16×16、半角スペースだけ8×16、1行232px・最大2行とする。表の文言はこの幅内に収める。表示色は白とし、起動時だけ別サイズ・別配置のエラー画面を設けない。選択番号・言語やチャンク実数／上限などの詳細は設定のデータセット画面で確認する。

地名欄の優先順位は、SD利用不可、確定したデータセット異常、FixなしのWAIT GPS FIX、通常のSEARCHING...と検索結果の順とする。異常が確定したら過去の地名とその地名に対応するFixを消去し、以前の地名を現在地として残さない。右側のGPS情報は地名に結び付いた古いFixではなく、最新GPSの有効性に従って更新し、Fix喪失時は--にする。正常な再検索が進行中の地名保持ルールは、異常が確定するまでに限る。

データセットだけの異常は地名欄で示し、同じ原因を赤帯や独立した「使用できません」の警告画面へ重ねて表示しない。ログ保存・SD媒体・GPSの異常は従来の赤帯を使用する。SD自体が利用できない場合は地名欄にSDの原因を出すとともに、ログ保存にも影響する共有障害として赤帯へ反映する。純粋なデータセット異常だけでREC / PAUSE等の記録状態をERRORへ置き換えない。

### 8.4 逆ジオコーディングの停止と再検証

Storageはデータセットの欠落・不整合・形式不正・文字コード未対応・チャンク上限超過・メモリ不足・読出し失敗を使用不可の理由として保持し、Appへ通知する。Appはその選択の逆ジオコーディングを無効にして、SearchPlaceと地図ラスタ要求を投入しない。Storage側でも使用不可の選択に対する検索を受け付けて再オープンしない。正常なGPS通知、Fix再取得、画面復帰、1/2/3の画面切替、通常の検索間隔経過では読込みを繰り返さない。

使用不可となった選択のReader・矩形キャッシュ・地名キャッシュはStorageが安全な区切りで閉鎖・無効化し、RGをUnprepared（暗灰）として通知する。実行中のI/Oを強制中断せず、終了後に解放する。Appはキャッシュ状態を独自に偽装せず、古いデータセット世代の成功・Ready通知で使用不可を解除しない。SDランプはログ等も含めた実アクセス時だけ点灯する。読出し失敗後も区域コード0・空地名を正常結果として公開しない。

再検証は利用者による次の操作を基点とする。

| 明示操作 | 再検証の対象と解除条件 |
|---|---|
| データセット・Wordbook言語の適用 | 候補の検証と保存が成功した場合に、従来の適用・再起動規則で選択を反映する。変更のない同じ選択の適用でも再検証を行い、成功時だけ使用可能へ戻す |
| SD再マウント | マウント成功後、保存された番号・言語を改めて検証する。SDマウント成功だけでは地図の異常を解除しない |
| 再起動、USBモードからロガーへの復帰 | 復元した選択を起動時に検証し、成功した場合だけ使用可能へ戻す |

再検証中は既存の原因表示を保持し、失敗すれば新しい理由へ更新して使用不可を維持する。成功後は次の検索可能な有効Fixで地名を取得し、完了までは過去の別選択の地名を表示しない。データセット適用のログ停止・保存・セッション閉鎖条件は8.2節に従う。SD再マウント等の媒体操作も既存のログ保護条件を維持する。ログ保存の再試行とデータセットの再検証は別であり、保存の再試行をGLC・Wordbookの自動再オープンに使用しない。

Fixなし、データの格納範囲外、区域コード0の未該当は、データセット破損と区別する。これらだけでデータセットを使用不可にせず、有効Fixと通常の更新条件が整えば検索を継続できる。

BootとLive PlaceからのF1メンテナンス経路は維持する。地名欄にデータセット異常が出ている場合も、記録停止・保存・セッション終了後にF1 MAINTを表示して入れる。2による通常の設定画面は記録中も従来どおり利用でき、設定画面へ入るだけで記録を停止しない。読込み自体で異常リセットする場合は、電源投入からF1を保持して地図読込み前に退避する。索引ファイルの保存と設定からの索引再生成は未実装であり、将来追加する際も再検証成功前に使用不可を解除しない。

### 8.5 実装・画像との区別

8.3〜8.4節は2026-10-21にコードへ反映した。欠落専用の起動停止と、上限超過・メモリ不足の全面警告を廃止し、固定の2行表示・Storage側の失敗保持・App側の要求抑止・新旧世代の照合を実装した。日英の新しい画面画像は実装から再生成し、旧専用画面の画像を削除した。過去の検証記録は検証当時の動作を示す。索引ファイルの永続化・再生成は別機能として未実装である。
