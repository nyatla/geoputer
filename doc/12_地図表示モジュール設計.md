# ReverseGeoputer 地図表示モジュール設計

文書状態: 実装仕様 1.0（UI固定画像の貸出しとStorage直接書込み）
更新日: 2026-10-26

対象画面: [地図画面](画面・操作/place-view/README.md)。本書は実装したモジュールの責務、データ形式、所有権と連携を定義する。2キーで地図を表示する。画像生成用の区域コード配列は既存の128×128キャッシュと統合しない。現在地の区域判定・地名検索は既存キャッシュを共用する。

## 1. 分離方針

画像処理と境界画像の形式を`application/map/`へ独立させる。このモジュールはStorageTask、SD、Galuchat、FreeRTOS、GPSのスナップショット、M5GFXに依存しない。入力は区域コードのラスタと座標変換情報、出力は色に依存しない境界画像とする。

モジュールの分離とタスクの分離は別に扱う。初版では画像処理もStorageタスクのジョブから呼び出す。ファイルや区域コードの大きな配列をAppへ転送せず、既存の4タスク・5キューを維持する。画像処理モジュール自身はタスク・キュー・通知・ファイルハンドルを持たない。

## 2. モジュール構成

```text
application/
  map/
    MapTypes.h               座標・矩形・区域コード・処理結果
    ViewportTransform.h      地図中心、表示範囲、格子と画素の変換
    DecimatedViewport.h     現在地を含む間引き格子と入力範囲の計算
    MapFrameReceiver.h      UIの固定画像2枚、貸出し・返却・表示交換
    MapSession.h            画面の間保持する32bit区域コード配列と地理情報
    MapTracking.h           完成画像の座標系でのカーソル位置と追従範囲
    BoundaryImage.h          比較・検証用の動的2bit境界画像
    BoundaryImageView.h      共通の画素参照とUI用固定境界画像
    BoundaryExtractor.h      区域コードからの境界抽出
  task/storage/
    MapBuildJob.h            SessionとUIのbackを借用する読出し・変換ジョブ
    StorageWorkArea.h        MapBuildJobとLogReaderの排他共用
    galuchat/
      MapSource.h/.cpp       選択中データセットと既存Readerへの接続
  task/ui/
    UiRenderer.cpp          drawMapによる境界画像・マーカー・地名・縮尺の表示
  MapView.cpp               Appの追従範囲・バッファ貸出し・取消制御
```

純粋な画像モジュールとMapBuildJobはヘッダー内に実装する。既存の`DiskIndexedMapReader`や地名検索を削除・置換するものではない。

| モジュール | 担当する処理 | 依存先 |
|---|---|---|
| ViewportTransform | 中心と縮尺から必要な格子範囲を計算。画素と地理座標を変換 | MapTypesのみ |
| BoundaryImage | 画像の確保、画素の取得・設定、行単位のコピー | 標準C++とMapTypes |
| BoundaryExtractor | 区域コードのサンプリング、隣接比較、境界種別の出力 | 上記の純粋なデータ型 |
| MapSource | 元ファイル・保存索引・格子単位の取得、区域コードの矩形読出し、生成中心の区域コード取得 | 既存のGaluchat読出し・辞書・データセット管理 |
| MapSession | 表示期間の区域コード配列・地理情報・世代の所有 | 画像モジュールと標準C++ |
| MapBuildJob | SessionとUI backの借用、処理段階、進捗・成否、取消、直接書込み | MapSourceと画像モジュール |
| Application | 要求の発行、更新タイミング、世代管理、StorageとUIの中継 | 既存のタスク通信 |
| MapRenderer | UIの色へ変換して描画。現在地カーソル、現在地の地名、北、縮尺と共通ステータスを重ねる | BoundaryImageの読取参照と既存UI |

MapSourceはStorageタスク専用とする。Readerの取得・破棄、媒体排他、SDランプ、索引の異常判定はこの側で行い、画像モジュールに持ち込まない。SDカードアイコンは地図・辞書等の実アクセスを共通位置で示し、キャッシュの準備状態は表示しない。

## 3. 共通データと座標

`RegionCode`は`uint32_t`とし、0は区域なしを表す。現在のコード範囲検査を継続し、大きな値を切り詰めない。

`RasterView`は、区域コード配列への読取専用参照、格子上の原点、幅・高さ、行間隔と配列長を持つ。原点は西端・南端、xは東向き、yは北向きとする。ポインタは同一タスク内の呼出しにだけ使用し、タスク間キューへ入れない。

planViewportは中心の経緯度、元データの経度・緯度方向の格子単位、作業メモリ上限と表示寸法を受け取る。経度方向の格子1個を表示1画素へ対応させる。北を上とし、＋で1/4→1/2→等倍へ拡大、－で等倍→1/2→1/4へ縮小する。端では循環しない。＋は物理的な=キーをShift・Fnなしでも受け付ける。上下左右キーは倍率変更に使用しない。回転・手動スクロールは含めない。起動時の倍率はConfig.hのMapViewScale（初期値1）で指定する。選択倍率はAppが保持し、他画面との往復では維持するがNVSには保存しない。

`ViewportTransform`はこれらを受けて`ViewportPlan`を作る。Planは表示画素から元の格子への写像、必要な読出し矩形、中心の格子位置とスケール表示用の距離を持つ。緯度に応じて縦横の距離差を補正し、画像と500m等の目盛りに同じ換算を使う。

表示画像の原点は左上、xは右向き、yは下向きとする。240×101の画像内の中心は(120,50)とし、画面上はy=18を加えて(120,68)へ置く。座標の反転・丸めはViewportTransformへ集約する。配列参照は事前に検証した整数格子位置へ限定し、各画素で別の丸め規則を使用しない。

### 間引き縮小

縮小は区域コード画像に対して実行し、その後に等倍と同じ境界抽出を適用する。元解像度の境界を縮小画面へ集約する処理は使用しない。採用位置にない細い区域や境界が消えることは、この最近傍間引きの仕様とする。区域コードの平均化や複数画素の優先選択は行わない。

`Request.scale`は1・2・4を取り、元格子の縦横それぞれscale個おきの画素を保存する。`planDecimatedViewport`は従来の表示用Planと、拡大した元格子の読出し矩形を生成する。間引きの位相を現在地の格子へ合わせ、画面中心(120,50)の元画素は倍率によらず同一にする。保存配列の座標は表示用Planの格子として扱い、その座標差をscale倍すると元格子の位置になる。距離目盛りはscale倍し、緯度による縦横補正は従来のままとする。

アプリ側の`DiskIndexedMapReader::readRectDecimated(target, scale, pixels)`は、元解像度の矩形をSDKへ渡し、出力先のset／setSpanで指定位置だけを採用する。出力寸法は各軸ともceil(target寸法 / scale)で、位相はtargetの西端・南端を基準とする。異なるチャンクでも位相を維持し、同じ採用画素に対する先着非ゼロの合成規則を守る。逆方向・縦方向の区間描画も間引いた位置だけを書き込む。区域コードの値域検査は採用しない位置でも維持する。

1画像につき矩形要求は1回とし、索引走査を帯ごとに繰り返さない。元の大きな区域コード画像や別の縮小前バッファは確保せず、保存するのは縮小後の配列だけである。今回の統計区・緯度の条件では、全倍率で240×83×4＝79,680 Bとなる。中心コードは縮小後の中心から取得して、画像生成時の基準区域の強調にだけ使う。現在地の地名検索には共通のコード面キャッシュを使う。Galuchat本体、索引形式、128×128キャッシュは変更しない。

## 4. 境界画像の保持形式

BoundaryImageは1画素2bit、行優先の形式とする。RGB565やM5GFXのパレット番号は格納しない。

| 値 | 意味 | 初版の表示色 |
|---:|---|---|
| 0 | 背景 | 黒 |
| 1 | 周辺区域の境界 | 灰色 |
| 2 | 画像生成中心の区域の境界 | 白 |
| 3 | 予約。初版では出力しない | 入力時に不正として扱う |

1バイトに左から4画素を格納し、x=0の画素をbit7〜6、x=1をbit5〜4へ置く。行間隔は`ceil(width / 4)`バイトとし、各行末の未使用bitは0とする。画像長は`stride * height`である。240×101では60×101＝6,060バイトとなる。

UIのMapFrameReceiverはFixedBoundaryImageを2枚内包し、各6,060 B、合計12,120 Bを常駐の固定領域に置く。表示中のfrontとStorageへ貸し出すbackは別の配列とし、再確保・解放を行わない。StorageはBoundaryImageViewでbackを参照し、生成用画像を別に所有しない。画素の取得・設定はBoundaryImageViewへ集約する。UIは表示交換時に寸法・貸出しID・予約画素値を検証する。大きな配列を実機タスクのスタックへ置かない。

画像自体には現在地マーカー、文字、方角、縮尺、記録状態、ランプを描かない。これらはUIが重ねるため、時計や電池の更新で境界を再計算する必要はない。

## 5. 境界抽出のインタフェース

画像モジュールの主要操作は次のとおりとする。

```cpp
Error planViewport(double latitude, double longitude, int unit_x, int unit_y,
                   size_t max_bytes, ViewportPlan&, int width = 240, int height = 101);
template<class Image>
Error buildBoundaryRows(const RasterView&, const ViewportPlan&, RegionCode current,
                        unsigned first, unsigned rows, Image&);
```

planViewportはファイルを読まず、必要な格子矩形と座標変換を計算する。buildBoundaryRowsは指定行だけを出力する。処理段階・次の行・キャンセル状態は呼出し側のMapBuildJobが保持し、画像モジュールにはタスク実行の状態を持たせない。

各表示画素で区域コードを最近傍サンプリングし、右・下の表示画素と異なる場合に境界を出す。画像の右端・下端には仮想的な外枠を作らない。比較するいずれかの区域コードが非0のcurrent_regionなら現在区域の境界とし、それ以外は周辺境界とする。ここでcurrent_regionは画像生成時の中心区域であり、カーソルだけの移動では変更しない。中心の区域が0なら白線は生成しない。領域外との境界もこの規則で処理する。

行の分割位置でも次の行のコードを参照し、継ぎ目を作らない。入力ラスタは、指定行とその隣接比較でPlanが要求する全サンプル位置を含む必要がある。範囲外の入力を黒として補って正常完了にせず、呼出し条件の不正として返す。縮小では間引き後の区域コードだけを比較し、間引きで失われた細い区域の境界は補完しない。

画像モジュールの結果は成功、入力不正、未対応の表示範囲、容量不足、メモリ不足などに限定する。SDエラーやデータセットの状態へ直接変換しない。BoundaryExtractorはバッファを追加確保せず、渡された入力と出力だけを使う。

## 6. バッファの所有と貸出し

| データ | 所有者 | 生存期間・利用権 |
|---|---|---|
| 区域コードの入力ラスタ | Storage側の通常地図／ログ地図それぞれのMapSession | 地図表示中。離脱・文字表示への切替・消灯で解放 |
| 境界画像2枚、計12,120 B | UIのMapFrameReceiver | UIの寿命で固定保持。frontはUIだけが読み、貸出し中のbackはStorageだけが読み書きする |
| 要求・貸出しID・取消状態 | Appの共通常駐領域 | 貸出し取得からStorageとUIの返却完了まで。画面用unionの切替で消さない |
| 完了情報・表示情報 | App、Storage、UIの値コピー | 対応する要求・表示の期間 |

AppはUIからbackのアドレス・容量・単調増加する貸出しIDを同期取得し、それをRequestMapへ含める。これはタスク寿命の固定画像に限定した貸出しであり、スタックや画面用unionへの参照を渡す方式ではない。UIは貸出し中のbackを参照・初期化・再貸出ししない。Storageは同時に1件だけ受け付け、指定されたbackへ境界画像を直接生成する。Appは画像本体や行転送用配列を保持しない。

読出し段階では借用backの先頭4KiBを索引用ObservedFileReaderへ渡す。ReaderとFactoryはreadBoundaryMap内だけで使用し、全Readerの破棄・借用返却後に同じbackを境界画像として初期化する。Readerが使用中のジョブ返却・作業領域切替を拒否する。マップ本体の16KiBバッファ、Wordbook用バッファ、FILの所有方法は維持する。借用指定のないReaderは従来どおり自身でバッファを確保する。

StorageWorkAreaはMapBuildJobとLogReaderをstd::variantで排他保持する。LogReaderの結果を返送領域へコピーし、ファイルcloseが成功してから切り替える。MapBuildJobはUI画像への参照と処理状態だけを持ち、ReleaseMap／CancelMapへの成功応答前に画像への参照・Reader借用・書込みを終了する。その応答をAppが取得するまで、UIのbackは返却・表示交換しない。

画面離脱や文字表示への切替では、UIは表示を無効にする一方、未返却の貸出しIDと画像領域は保持する。AppがStorageの取消結果を回収し、その後UIへDiscardMapFrameを送って貸出しを解消する。元の画面がなくなっていても返却できる。文字表示から同じ画面世代の地図表示へ戻った場合も、無効にした旧完成画像は復活させない。古い貸出しIDによる完了・返却は、新しい貸出しへ作用しない。

初版はMapSourceが必要な矩形を一度読み、そのラスタを画像モジュールへ渡す方式とする。表示処理の行分割ごとにDiskIndexedMapReader::readRectを呼ばない。同APIは呼出しごとに索引を走査するため、単純な細分化で索引・ブロックを繰り返し読むことを避ける。

区域コードの入力ラスタは地図専用に確保し、Live Place用128×128キャッシュとは共有しない。地図の読出し・失敗・取消・離脱で既存キャッシュやWordbook LRUを無効化せず。MapSourceは独立したReaderを生成し、画像の生成ではWordbookを検索しない。現在地の地名はメインと共通のPlaceLookupにより取得し、UiData.placeに保持する。PlaceLookupは既存のコード面キャッシュと地名LRUを共有し、formatPlaceLinesでdisplay_line1 / display_line2を展開する。境界変換が終わっても入力ラスタをMapSessionに保持する。完成通知後に生成ジョブの書込み権を返却し、地図表示を離れた時にSessionの入力ラスタを解放する。今回の実装では128キャッシュとの統合・用途切替は行わない。

画像モジュールは全画面の入力保持を要求する形式に依存しない。将来、MapSourceに重複読出しを増やさない分割取得経路を追加した場合も、必要な比較用サンプルを含む参照を渡すことで境界画像の形式とUIを維持できる。

初版の設定値はConfig.hへ集約する。表示寸法と境界画像容量はMapTypes.hの定数とする。

| 項目 | 初期値・上限 |
|---|---:|
| 表示幅・高さ | 240×101 |
| 区域コード作業バッファ上限 | 96KiB |
| 画像変換の1ステップ | 8行 |
| 起動時の間引き倍率MapViewScale | 1（＋・－で1・2・4へ変更可） |
| 境界画像の固定領域 | 6,060 B×2＝12,120 B |

画面例の格子解像度・縮尺では元ラスタは約240×83×4＝79,680バイトとなる。実際の確保量はPlanで計算し、上限を超える表示範囲を拒否する。境界画像の画素部分はUIの固定2枚、計12,120 Bだけを使う。Storageに別の境界画像は置かない。地図未表示時も固定領域は常駐する。既存の128キャッシュ64KiBも保持する。これらにReaderのバッファとオブジェクト、貸出し情報と同期結果の値コピーが加わるため、6,060バイトだけを地図機能全体の必要メモリとはしない。初版の縮尺と作業上限は実機の最大空きブロック・最低空きヒープ・所要時間を測って確定する。

### 地名検索との作業領域共用

地名検索もBeginPlaceSearchで同じ未使用backを借りる。先頭4KiBを索引Reader用、整列後の残りをPlaceResult用とし、地図生成用の貸出しと排他にする。メイン画面でも利用できる。地図表示中はfrontを表示したまま検索し、地名の確定では画像のfront/backを交換しない。Storageの検索終了後にAppがCommitPlaceSearchまたはDiscardPlaceSearchを送り、次の画像生成へ領域を戻す。詳細な通知・画面切替契約は[タスク構成設計](06_タスク構成設計.md)に従う。

## 7. メタデータとタスク通信

画像に対応するFrameInfoは、要求ID、画面世代、データセット世代、画像寸法、中心のFix識別子と座標、強調表示する現在区域コード、縮尺情報を持つ。同じIDの画像とメタデータを1つの完成結果として扱う。UIは表示中画像の生成中心・meters_per_pixelからGPS位置の画面オフセットを計算する。新しいGPS位置を旧画像の中心として扱わない。完成画像の中心から左右上下±32表示画素以内はカーソルだけを移動し、いずれかを超えると新しい現在地を中心に画像を生成する。地図左上は倍率だけを表示し、UPDATING / READINGの黄色い文字は重ねない。地図の240×101画素を背景とし、文字の背景帯は設けない。上部は左に倍率（1/1・1/2・1/4）、その隣に距離目盛り、右端に北方位を置く。下部の地名は1行目8×8、2行目16×16とし、黒い1ドットの縁だけを付けて透過描画する。白い区域は現在の表示点に対応する。生成中心から移動して区域が変わった場合は、保持画像から境界線を再描画する。地名は画像メタデータに含めず、GPSの現在地点の区域に追従する。画像の転送・Commitで地名を上書きしない。カーソルは文字より手前に描き、地図領域の外へは描かない。

タスク間通信は既存方式を使い、次の操作を使用する。同期要求の発行元はAppだけである。

| 方向 | 操作 | 意味 |
|---|---|---|
| App→UI、同期 | BeginMapFrame | backのアドレス・容量・貸出しIDを取得する |
| App→Storage、同期 | RequestMap | 貸出し情報付きの生成要求を受け付ける。生成完了は待たない |
| Storage→App、投機的通知 | MapCompleted | 成否・貸出しID・FrameInfoだけを通知する。満杯時は再試行する |
| App→Storage、同期 | ReleaseMap | 完成した生成ジョブから画像参照・書込み権を返却する |
| App→Storage、同期 | CancelMap | 不要になった生成ジョブを終了し、画像参照・書込み権を返却する |
| App→UI、同期 | CommitMapFrame | Storage返却後のbackを検証し、frontと交換する |
| App→UI、同期 | DiscardMapFrame | Storage返却後、失敗・取消・不要になった貸出しを解消する |
| App→Storage、同期 | CloseMapSession | 対応する表示の区域コード配列を解放する |

ReadMapRows／WriteMapRowsと行転送用配列は廃止する。画像本体をUiData・AppNotificationへ埋め込まず、キューは貸出し記述とメタデータを値コピーする。画像の書込み権は通知と同期応答で順番に受け渡し、複数タスクが同時に同じ配列へアクセスしない。画像本体にミューテックスを掛け続ける方式は使用しない。

同期結果のタイムアウトは要求の取消ではない。結果取得まで待機状態を維持し、新しい同期要求を送らない既存の契約を守る。ReleaseやCancelも、先行する同期要求の戻り値を回収した後に発行する。

Storageは同時に1つの地図ジョブを保持し、完成画像をReleaseまで変更しない。通知がキューへ入らなければ同じ最終結果を保持して再試行する。処理段階はIdle、Reading、Rendering、Completeとし、失敗・取消時は生成ジョブの出力参照を返却し、UIの固定配列自体は解放しない。入力配列の寿命はSessionで管理し、新規読出しの途中結果を有効な画像として扱わない。変換のステップ間では受信処理と必要なログ保存を行う。読出し時間そのものの上限は実測し、64件のログバッファとの共存を確認する。

UIは貸出し中のbackを描かず、常に現在のfrontから時計・地名・カーソル・ダイアログを含むオフスクリーンを再描画する。Appは完成通知を受けた後、先にStorageのReleaseMap成功を回収し、その後UIへCommitMapFrameを送る。UIの交換受付に失敗した場合はDiscardMapFrameで貸出しを返却する。Storageが要求を受け付けなかった場合も、取得済みのUI貸出しは返却する。取消やUI返却が一度失敗した場合は状態を保持して再試行し、先に次の生成を開始しない。

### 倍率変更

UIは＋・－キーからMapScale操作と変更先の倍率を通知し、Appの受付結果を待つ。Appは現在の画面・表示状態と1・2・4の値域を検査してUiData.map.scaleを更新する。未処理の操作を別のキーで上書きせず、上限・下限のキーでは操作を発行しない。

倍率変更は新しい地図要求として扱い、同じGPSサンプルで追従範囲内でも即時に取得する。進行中の古い要求はCancelMapで解放してから新しい要求を出す。完了通知・UI行転送・Commitでは要求倍率を検査し、変更前の倍率が遅れて届いても表示しない。表示中の地図・距離目盛りは新画像のCommitまで保持する。地名は共通の現在地検索結果で独立して更新する。

左上の倍率表示は表示中画像の倍率とする。取得中のREADING / UPDATING文字と変更先倍率は表示せず、新しい完成画像への交換時に倍率を切り替える。未測位やSDエラー中でも倍率選択は保持し、利用可能になった時に選択倍率で生成する。画面消灯中の最初のキーは従来どおり復帰だけを行う。

## 8. 更新と異常時の扱い

地図の中心は完成画像のFixと一致させる。Appは現在の有効Fixが完成画像の中心から±32表示画素を超えた場合に再生成を要求する。範囲内は周期的に再生成しない。範囲はConfig.hのMapCursorRadiusに集約する。受付が競合した場合や失敗後は1秒以上待って再試行する。画像モジュールにタイマーを持たせない。消灯中は要求を取り消し、新規読出しを行わない。再生成中は対応する中心情報とともに前の完成画像を維持し、実I/Oは既存SDランプへ反映する。地図画像自体は平行移動・回転せず、カーソルをGPS更新ごとに動かす。UIのカーソル位置は表示中のFrameInfoから計算し、Appの再生成判定と同じMapTrackingを使用する。GPS喪失時は最後の位置を灰色で保持する。

未測位・データセット未選択・SD利用不能・地図範囲外はApp／UIが表示状態へ反映する。区域コード0は地図領域外や区域なしとして扱い、ファイル破損と同一視しない。画像バッファの確保失敗だけで正常なデータセットの選択を解除しない。地図専用の読出し異常はMAP READ ERRORとして地図画面へ表示し、前の完成画像があれば保持する。地図専用経路の失敗だけで選択や既存キャッシュを変更しない。GPS表示・記録は継続する。原データ範囲外でコード0を取得した場合はNO REGIONとして正常に表示する。

## 現在地の区域判定と画像更新の独立性

左右上下±32表示画素の条件は画像再生成だけに適用する。メイン・地図の両画面で、新しい有効GPS Fixが前回検索済みのデータ格子を離れたらSearchPlaceを要求する。格子番号はデータセットのunit_inv_x / unit_inv_yと、Galuchatと同じ四捨五入で求める。同じ格子内ではSD・コード面・Wordbookの検索を行わず、表示座標だけを更新する。画面世代・データセット・Fix有効性が変われば検索の省略を解除する。

地名検索はStorageの既存PlaceLookupを使い、128×128のコード面キャッシュと16件の地名LRUを増設しない。格子が変わっても面内ならSDを読まずコードを取得できる。地図生成は区域コードの専用入力ラスタだけを持ち、WordbookのReaderを新しく作らない。FrameInfoから地名2行128バイトを除去し、遅い画像の完成で新しい地名が古いものへ戻る経路をなくす。

Appは地名検索要求を画像生成より先に送る。SearchPlaceが未完了の間は新しい画像生成を始めず、画像ジョブが占有中はSearchPlaceを送らない。生成中のGPS通知は引き続き受け、画像ジョブ解放後に最新の座標を検索する。Storageの単一受信キューと従来の結果通知方式は維持する。

## ログ座標による表示

ログの地図表示・リプレイも同じMapSource、MapBuildJob、バッファ貸出し経路とUIの境界線画像を利用する。追加の画像形式や履歴専用キャッシュは作らない。Appはログ閲覧では選択レコードの座標を、通常地図ではライブGPS座標を要求に設定する。UIのカーソル計算も同じ入力を選び、履歴表示に現在のGPS Fixを要求しない。

ログの地図・地名は同じ表示済み点に対応させる。±32表示画素の追従範囲は画像の再生成だけを制御し、地名検索のセル粒度は変えない。ログの点送りに上下左右キーを使用するため、通常地図と同じ＋で拡大・－で縮小する。倍率は1/1・1/2・1/4の端で止まり循環しない。再生と一時停止はPで切り替える。文字表示と地図表示をVで切り替えた場合も選択点を維持する。

ログ画面群は10件のレコードと地図転送用メタデータを同時に必要とするため、AppLogResources内にAppMapResourcesを含める。画面群全体を通常地図用のAppMapResourcesとunionで共用し、キューとUIフレームのサイズは据え置く。軌跡や過去の地図を蓄積せず、離脱時の取消・世代照合・解放は通常地図と同じ経路で行う。

## MapSessionと生成ジョブの分離

元画像は`application/map/MapSession.h`で定義し、32bit区域コード配列・確保容量・格子範囲・表示変換・データセットと画面の世代を所有する。Storage側の画面リソースに通常地図用とログ地図用の独立したSessionを置く。両者の大きな配列は同時に保持せず、前の表示の終了を処理してから次を確保する。24bit化は行わない。

MapBuildJobは受け付けた要求の間だけ対象Sessionを借用する。読出し・境界抽出が終わったらReleaseMapでジョブとUI画像への書込み権を返却し、その後UIへ表示交換を指示する。Sessionは引き続き元画像を保持するが、Storageの処理中条件には含めない。地名検索、ログのRAM受付・SD保存、閲覧要求の受付は通常どおり実行できる。

次の地図取得には保持済みの配列を渡し、確保容量が足りれば上書きする。容量不足時は旧配列を解放してから新しい配列を確保し、旧・新の32bit配列を同時に確保しない。入力の更新開始時点で旧内容を無効にし、失敗・途中取消の配列を有効な地図として再利用しない。UIは既存の完成済み境界画像を表示し、Storageの書込み終了・返却後に交換する。

画面離脱、ログの文字表示への切替、消灯、データセット切替ではAppがCloseMapSessionを送る。生成要求が残る場合は先にCancelMapの同期結果を回収する。CloseMapSessionはSession種別・画面世代・データセット世代を照合し、古い終了要求で別のSessionを解放しない。SDの閉鎖・再設定でもSessionを解放する。

### 保持画像からの区域強調更新

Appは地名検索結果の区域コードを、地名と対応座標とともに保持する。現在の表示点に対応する区域が変わり、完成地図の±32表示画素以内なら、同じ中心・倍率・世代を指定した再描画要求を送る。StorageはSessionの一致を確認して境界抽出だけを実行し、SDやWordbookを読まない。保持画像が無効・別世代ならStaleを返し、Appが通常の再取得に切り替える。

範囲外への移動と倍率変更は、従来どおりSDから取得する。区域判定の頻度、地名更新のセル粒度は下げない。区域の連続確認による遅延切替は導入せず、区域コードの更新に追従する。間引きで消える小区域の境界を新たに復元する処理も含めない。

### 容量と計測

習志野付近・縦横同じ角度刻みでは元画像は240×83×4＝79,680バイト。倍率1/1・1/2・1/4は間引き後の同じ寸法で保持する。確保は必要量とし、以後は保持容量内で再利用する。96KiBを毎回固定確保する方式ではない。既存の128×128コードキャッシュとWordbook LRU、UIの境界画像は維持する。

表示中も地名検索・辞書処理には一時確保があるため、保持中のキャッシュミス・倍率変更・地図更新・ログ地図への切替・退出を実機で計測する。`MapHeapDiagnostics`による段階別の空きヒープ・起動後最小空き・最大連続空き領域を記録する。計測用の仮想移動は独立ビルドにのみ含め、通常版へ自動操作コードを入れない。

実機での区域画像保持・キャッシュミス・解放の計測結果は[地図Sessionと区域画像保持の検証](検証/地図Sessionと区域画像保持の検証.md)に記録する。
