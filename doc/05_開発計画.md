# Geoputer 開発計画

文書状態: Draft 0.32  
対象機: M5Stack Cardputer ADV（Mesh KitのGNSS使用 / 外付けGPS使用を選択可能）  

## 1. 文書の目的

本書は、Geoputer初期版を段階的に実装するための開発順序、各フェーズの作業範囲、完成条件、成果物および実機確認項目を定義する。

## 2. 開発方針

- 一度に全機能を実装せず、各フェーズで動作する成果物を作る。
- 最初にApplicationとUI、フォント表示、メイン画面とSettingsの往復を実装する。その後にGPS・Storageを追加する。
- GPS Loggerとしての安定性を最優先する。
- LoRa機能は使用しない。
- Mesh KitのGNSSを使うモードと、Mesh Kitの代わりに外付けGPSを使うモードを選択可能にする。
- GPSの座標受信を先行確認した後、GNSS制御導入時に電源投入時の初期化とPAUSEへの移行を確認し、GPSログをSTOPPEDで開始する。初期化失敗で実状態が確認できない場合はエラーとして扱う。
- GNSS状態とGPSログ状態を独立して管理する。
- 常時記録系へGaluchatおよびUIの処理を混在させない。
- 既存のGaluchat GIS SDKを改変せず、利用側アプリケーションとして実装する。
- SDK側に不足がある場合は、最初にアプリケーション側Adapterで吸収できるか検討する。
- ハードウェア依存値と初期化処理をBoard層へ集約する。
- 動作設定は本体NVS、GPSログとGaluchatデータはFAT32のmicroSDへ保存する。Storageタスクが両媒体を所有し、SD障害とNVS設定の利用可否を分離する。
- 実行構造はタスク構成設計に従う。Phase 0はApplication・UIの2タスク、Applicationの2キューとUIの1キューで開始する。GPS・Storageの導入後は4タスク・5キューとする。
- 各フェーズ終了時にビルドと実機確認を行い、未確認事項を次フェーズへ持ち越す。

現在の実装到達点は、4タスク・5キュー、Boot・Live Place・MENU・GPS Logger・Settings、GPSの日時・詳細取得、Galuchatの矩形キャッシュ、NVS設定、64件RAMバッファのログ保存と一時停止・再開・停止である。Live Placeは[採用仕様1.3](検証/メインレイアウト1.3検証.md)の住所2行、左右GPSパネル、速度の単位切替・3桁表示に対応する。MENUには実装済みのGPS LoggerとSettingsだけを表示する。Phase 0の2直接遷移はMENUへ置換済み。

各フェーズの作業範囲と完成条件は、後続項目を含む全体計画として保持する。保存、ログ一覧・概要・最大10件単位の読出し・測位点閲覧は実装済み。距離・最高速度の全件集計、GNSS休止制御、外付けGPSへの切替、GIS処理の分割と同期待ち時間の短縮は残作業とする。ログ閲覧の検証は[ログビューア検証](検証/ログビューア検証.md)を参照する。保存の検証は[メイン画面・ログ保存検証](検証/メイン画面・ログ保存検証.md)を参照し、単体試験の成功と通常操作による通し確認の完了を区別する。

## 3. Phase 0：Application・UIとフォント表示

### 3.1 作業範囲

- Cardputer ADV向けビルド基盤とBoardの基本初期化
- LCD、キーボード、共有I2Cの最小限の初期化
- フォントライブラリの選定・導入と、8×8・16×16ドットの描画
- ApplicationTask、UITask、ApplicationQueue、容量1のAppReturnQueue、UIQueue
- 投機的送信、同期要求送信、期限付き結果取得の共通API
- 結果取得タイムアウト後もWAITING_RESULTを保持する1件の同期要求管理
- UIのSetUiScreen / UpdateUiContent / GetUiContentと、UiContentChangedによる操作通知
- UIで未処理確定操作を1件保持し、Appが処理済みaction_idを画面指定へ反映する処理
- Live Placeをメイン画面とするプレースホルダと、Settings画面の枠組み
- メイン画面の2でSettingsへ切り替え、SettingsのEscでメイン画面へ戻る操作

この段階は2画面の表示と遷移を対象とする。メイン画面には地名、ステータス、座標、キーガイドの配置を用意し、未実装の測位・保存情報は`--`や未接続表示で表す。地名の固定表示を使う場合は、習志野市庁舎の所在地を画面確認用の例として使用する。Settingsは初期設定の項目と値、戻るキーを表示する。

Phase 0では起動後にメイン画面を表示する。2はSettingsへの直接遷移とし、主要画面追加後のMENUはPhase 3で実装する。設定の編集・保存、GPS・Storage・Galuchat、Boot画面、画面消灯・復帰は後続フェーズで実装する。

ソースはapplication以下に配置する。ApplicationはArduinoのメインタスクで実行し、UIタスクはtask/ui、タスク基底クラスとキュー・同期通信の共通処理はutilsへ置く。ビルドとPhase 0の操作手順は[Application](../application/README.md)を参照する。

### 3.2 完成条件

- Cardputer ADV向けにビルドでき、実機起動後にメイン画面のプレースホルダを表示できる。
- 240×135 pxの実寸表示で、地名・住所は16×16ドット、その他は8×8ドットになる。地名中の英数字も16×16ドットとし、アンチエイリアスを使わず罫線と文字をドット単位で描画できる。
- 2でSettings画面へ切り替わり、Escでメイン画面へ戻る。同じ往復を繰り返しても入力・表示・同期結果の取得が滞らない。
- 画面遷移はUIの内容更新通知、Appによる操作内容の同期取得、Appからの画面指定を通して行う。UIが独自にトップレベル画面を切り替えない。
- UIの同期結果は指定・データ保持までで返し、描画とキー入力はUIタスク内で進める。Appからの表示更新でUiContentChangedの循環を起こさない。
- 結果未取得で次の同期要求を発行せず、取得タイムアウト後は同じ結果を再取得できる。確定操作を二重実行しない。
- GPS・Storage・Galuchatの実装や実データを前提にせず、フォント表示と2画面の往復を確認できる。

## 4. Phase 1：GPS・Storageの追加とハードウェア共存確認

### 4.1 作業範囲

- Phase 0のApplication・UIへGPSTask、StorageTask、GPSQueue、StorageQueueを追加
- LCD・キーボード・共有I2CとGPS・microSDの共存確認
- microSD用SPIの初期化
- FAT32のmicroSDマウント
- StorageによるNVS設定領域の準備と、SDから独立した設定読込み・保存の基盤
- GPS接続モード（Mesh Kit / 外付けGPS）の選択と接続プロファイル
- 選択したGPSのGNSS UART受信
- GNSS PAUSE / ACTIVE制御

### 4.2 完成条件

- 既存のApplication・UIと合わせて4タスク・5キューで動作し、初期化・状態・GNSS制御の要求と結果を既存の通信APIで扱える。
- GPS・Storageの追加後もメイン画面とSettingsを往復できる。
- 両GPS接続モードで、本体周辺デバイスと選択したGPSを同一ファームウェアから初期化できる。
- 外付けGPSの対応機種、配線、UART設定および休止・復帰方法を確認できる。
- Mesh Kitモードで未使用のCap側SPIデバイスがmicroSDアクセスへ干渉しない。
- 電源投入後、GNSSがPAUSEで開始する。
- PAUSEからACTIVEへ移行してFixを取得し、再びPAUSEへ戻せる。
- PAUSE時とACTIVE時の消費電流を測定できる。
- GNSS NMEAを受信しながらmicroSDへ書き込める。
- 周辺デバイスの初期化失敗を個別に判別できる。
- NVSとSDの準備結果を区別でき、SD未挿入・マウント失敗時もNVS設定を読み書きできる。

### 4.3 GPS座標受信の先行実装

Phase 1はまずGPSだけを追加し、Application・UI・GPSの3タスクと4キューで座標取得を確認する。この段階ではMesh Kitの標準UART接続を固定使用し、起動時に受信を開始する。GPSが確定サンプルと受信状態をAppへ通知し、Appが集約した緯度・経度をUIへ同期送信して表示する。Settings表示中も受信し、未測位や受信断では座標を未取得表示へ戻す。

先行段階の同期操作はUART準備を完了点とするStartGpsReceptionと、座標・受信状態を返すGetGpsStatusとする。InitializeGpsのPAUSE確認とSetGnssStateの休止・復帰制御は、その後に実装・検証する。逆ジオコーディング、設定編集・保存、StorageおよびGPSログは先行段階へ含めない。この段階のソースと確認手順は[Application](../application/README.md)を参照する。

- GPSの同期メッセージ（InitializeGps / SetGnssState / GetGpsStatus）と通知（GpsSampleReady / GpsStatusChanged）の分離

- Storageのセッション・記録境界の検証と保存状態通知

- [測位記録ファイル仕様](07_測位記録ファイル仕様.md)に従う1 Hz固定長バイナリログ
- RMCの日付、標高・速度・進行方位・HDOP・衛星数の取得と項目ごとの有効性管理
- 512バイトヘッダー、32バイト測位レコード、CRC32およびレコード番号による直接読出し
- まとめ書き
- 1記録セッション1ファイルの作成・継続・終了
- GPS、SDおよびバッファ状態表示
- 2のMENUから開くGPS Logger画面の追加と開始・再開・停止操作、Live PlaceのF1一時停止操作

### 5.2 完成条件

- 有効なGPS Fixを取得できる。
- 電源投入時はGPSログがSTOPPEDになる。
- GPSログ開始要求によってGNSSがACTIVEとなり、STARTINGを経てRECORDINGへ移行する。
- 一時停止時は新規レコード追加を止め、保存要求の同期受付後にPAUSEDとなり、GNSS ACTIVEを維持できる。
- 実保存の成否をStorageからの非同期通知で確認できる。
- GPS Loggerから再開・停止を行い、停止時はセッションを終了できる。
- メイン画面の2でMENUを開き、GPS Loggerを選んでEnterで開き、Esc / Delでメイン画面へ戻れる。
- GPS FixをLCDへ表示できる。
- 1 Hzで固定長バイナリへ保存し、指定レコードを直接読み出せる。
- 未取得項目、負座標、日時の日付境界、CRCと不完全な末尾を仕様どおりに扱える。
- 一時停止・再開と日付変更では同じファイルを継続し、停止後・再起動後の開始では新しいファイルを作る。
- 部分書込み・flush失敗の再試行でレコードを二重追記しない。
- 初期値10秒間隔でまとめ書きでき、64件に達したら間隔を待たず書き出せる。
- 保存失敗中の64件を上書きせず、新規受付失敗と実際の欠落を区別できる。
- 受付失敗の同期戻り値と、受付後の保存失敗通知をAppが受け、UIにエラー種別・未保存件数・バッファ使用数/64・欠落件数を表示できる。GPS更新や画面切替でエラーを消さず、対応する回復を確認したときに更新できる。
- Storageが書込み・flushと読出しを直列化し、測位レコードを最大10件ずつ返せる。
- ログ・地図・辞書・媒体操作を含むSD実アクセスの開始・終了をSdAccessChangedでAppへ通知し、UIのSD枠を青く点灯できる。RAM受付・NVS保存と実アクセスを区別し、短いI/Oだけ最低150ms表示する。
- キャッシュのUnprepared / Rebuilding / ReadyをRgCacheStateChangedで通知し、RGを暗灰／黄／緑で表示する。Readyは検索していない間も緑を維持し、GPS喪失やログ保存失敗だけでは消さない。
- SD一時障害時にGPS受信を止めず、RAM容量内でログを保持できる。
- 同一測位時刻のレコードを重複して保存しない。
- キュー投入、RAM取込、SD保存を区別し、セッションごとの未保存・欠落件数を確認できる。
- 保存失敗時に、終了済みセッションの未保存レコードを次のセッションへ混在させない。
- 各タスクからApplicationへ投機的に通知・同期結果を送り、同期要求はApplicationからサブタスクへだけ送れる。
- 投入期限切れの未投入と、投入済み要求の戻り値期限切れを区別できる。
- GPS初期化の同期待ち中にも別種通知をApplicationQueueへ保持し、AppReturnQueueの初期化結果を要求IDで判定できる。
- 同期結果の取得タイムアウト後に同じ結果を再取得し、処理要求を二重に送らない。
- 結果未取得での同期送信と、待機状態なしの結果取得をエラーにできる。
- GPS現状取得は先の同期要求の結果を取得した後に開始できる。
- 戻り値の遅延・期限切れ、記録境界とflushの順序を確認できる。

- SDカード情報・容量表示、再マウント、安全な取り外し、確認操作によるFAT32フォーマット

- 無操作タイムアウト
- GPSログ操作の確認表示、記録状態と未保存状態の表示の整備
- 採用済みLive Placeレイアウトの実装。上段を記録状態・時刻・RG・SD・電池の順とし、GPS詳細を本文へ移し、問題を赤地・白文字で表示

### 6.2 完成条件

- Phase 0の2によるSettingsへの直接遷移をMENUへ置き換え、上下キーとEnterで実装済みの主要画面を選択できる。左右キーはSettingsの値編集だけに使用する。
- ショートカットキーで対象画面を開ける。
- UI内容更新を通知し、Appが同期取得して業務操作を判断できる。
- Appからの表示更新で選択・編集を消去せず、通知・表示更新の循環を起こさない。
- GPS接続モードをNVSへ保存でき、再起動後に選択したGPSを使用できる。
- Settingsの子画面でEscを押すと入口へ戻り、入口でEscを押すとLive Placeへ戻る。編集・確認・カード情報パネルのEscは元の子画面へ戻る。
- Settingsの主表示を日本語16×16・英語8×16、補助表示を8×8とし、表示言語を先頭とする動作設定7項目を4行の表示範囲で選択できる。
- 表示言語の確定で同じ画面へ即時反映し、NVSへ保存・復元できる。旧6項目の設定値を引き継ぎ、ライセンス表示は同じ本文・フォント・画素を維持する。
- Bootは画面・タスクとキュー・NVS設定・SD・GPS UART・Galuchatデータ読出し準備を個別に表示する。GNSS制御導入前はFixを待たず、正常時2秒・警告時5秒の結果表示後または完了後のEnterでLive Placeへ進む。起動チェック中は無操作消灯や画面操作による中断を行わない。
- SDカードの取り外し・交換・フォーマット後も設定を保持し、設定初期化はSDデータや他ライブラリのNVS領域を変更しない。
- SDの再マウント・安全な取り外し・フォーマットは、ログ保存・SD読出し・結果参照の終了を確認して実行する。マウント失敗時に自動フォーマットしない。
- SD未挿入でもライセンス情報を閲覧できる。
- 設定の編集取消と保存受付・実保存完了を区別でき、保存完了は実保存結果の通知後に表示する。
- Logsで保存済みログを選び、Log Detailの読込・集計結果を表示できる。読出し結果をAppが受け、UIへ表示内容を渡せる。
- 画面消灯中の最初のキーでLive Placeへ復帰できる。
- 復帰キーが画面内操作へ引き継がれない。
- 初期値15秒の無操作で画面が消灯する。
- GPSログがRECORDINGの場合は、画面消灯中もログが継続する。
- 一時停止中は画面消灯後もGNSS ACTIVEを維持し、GPSデバイスをOFFにしない。
- GPSログがSTOPPEDで測位要求がない場合は、GNSSがPAUSEへ戻る。

## 7. Phase 4：Galuchat逆ジオコーディング

ファイル読出しの先行段階では`/dataset/01/`を固定使用する。ディレクトリ内のGLCとWordBookを各1ファイル検出し、SDKのファイルReaderを通して地名を検索する。Shift_JIS（CP932）のWordBookはUTF-8へ変換して表示する。検索対象のFixを固定し、Live Place表示中の新しいGPSサンプルに対して最短5秒間隔で更新する。Settings・画面消灯中は新たな検索を開始しない。GNSS制御とデータセット選択は後続段階とし、現在のGPS受信を維持する。

区域コードの矩形キャッシュと、区域コードをキーとする16件のUTF-8地名キャッシュを実装済みとする。地名の置換順は16バイトのインデックス配列で管理するLRUとし、時刻・内部Tickを使用しない。ホストと実ファイルでの検証は[WordBook地名キャッシュ検証](検証/WordBook地名キャッシュ検証.md)を参照する。端末への書込みと実機の速度・SDアクセス・メモリ計測は、そのホスト検証と区別する。

### 7.1 作業範囲

- Storageへの地名検索要求通知と、結果通知のApp・UIへの反映
- [システム構成設計](04_システム構成設計.md)で定義するmicroSDの`/dataset/01/`等の番号ディレクトリから、同じデータセットのWGSMapSetとGisWordBookをオープン
- LatestFixのスナップショット取得
- 座標からRegion Code取得
- 点検索を128×128・32bitの矩形キャッシュで包み、初回・範囲外で取得点を中心に再構成
- Region Codeから地名階層取得
- 復元・UTF-8変換済み地名の16件LRUキャッシュと、Reader閉鎖時の消去
- Live Place画面への地名表示
- Live Place表示時のGNSS ACTIVE要求
- 検索中、Fixなし、データ不在、検索失敗の表示

### 7.2 完成条件

- microSD上のGaluchatデータをRAMへ全展開せず参照できる。
- キャッシュの区域コードが元の点検索と一致し、範囲内では地図読出しを行わない。境界・未設定0・重なり順・読込失敗時の無効化を確認し、実機で再構成時間と最小空きRAMを計測できる。
- 画面復帰時の座標から現在地名を取得できる。
- 矩形と地名がともにヒットした検索ではSDを読まず、地名ヒット時も今回の座標・時刻・要求世代を返せる。
- 地名キャッシュの17件目は最も使われていない項目を置換し、辞書読出し・文字変換の失敗を登録しない。
- GNSSがPAUSEの場合、Live Place表示によってACTIVEへ移行し、新しいFixを取得できる。
- 検索中にGPS Fixが更新されても、開始時の座標で検索を完了できる。
- GPS FixなしとGaluchat検索失敗を区別できる。
- Galuchat処理中もGPSのUART受信を継続し、Storageの処理の区切りで記録追加要求を優先して受け付けられる。
- GPS Logger画面ではGaluchat検索を実行しない。

## 8. Phase 5：Place View

### 8.1 作業範囲

- 現在地点周辺の領域ラスタ取得
- Region Codeごとの決定的な疑似色生成
- 領域境界描画
- 現在位置描画
- 縮尺変更
- 地名表示
- Place View表示中のGNSS ACTIVE要求

### 8.2 完成条件

- 64×64、96×64または128×64の領域ラスタを取得できる。
- 同じRegion Codeを毎回同じ色で描画できる。
- Region Code 0、現在領域、周辺領域を識別できる。
- 現在位置と表示縮尺を確認できる。
- 縮尺変更中も旧表示と更新中状態を表示できる。
- ラスタ取得中もGPSログが継続する。

## 9. Phase 6：省電力最適化

### 9.1 作業範囲

- BACKGROUND_MODEのLCD完全消灯
- GNSS PAUSEの実効性確認
- Wi-FiとBLEの停止確認
- CPU負荷とアイドル処理の調整
- SD書き込み間隔とバッファ容量の調整
- Light Sleepの適用可否確認
- 動作状態別の消費電流測定

### 9.2 完成条件

- BACKGROUND_MODEでLCD、Wi-FiおよびBLEが所定の省電力状態になる。
- GNSS PAUSE時に測位処理とNMEA出力が休止し、ACTIVEへ復帰できる。
- 省電力処理によってGNSS UARTを取りこぼさない。
- 設定したSD flush間隔でログ損失上限を説明できる。
- GNSS PAUSE、GNSS ACTIVE、GPSログ中、VIEW_MODEおよびGaluchat検索中の消費電流を記録できる。
- 実測値から連続動作時間の目安を提示できる。

## 10. 初期版の総合完成条件

1. 電源投入後、GPSログがSTOPPEDで開始し、GPS初期化成功時にGNSSがPAUSEとなる。確認不能な実状態はエラーとして区別する。
2. GPSログ開始要求によりGNSSがACTIVEとなり、有効Fix取得後にログが始まる。
3. GPS Loggerでログ開始・再開・停止、Live PlaceのF1で一時停止を行い、状態を画面で確認できる。
4. GPSログ中は画面消灯状態でも測位と記録が継続する。
5. キー操作で画面が点灯し、現在地名をオフライン表示する。
6. Place Viewで現在位置と周辺の地名領域を表示する。
7. Mesh Kitと外付けGPSの接続モードを選択し、どちらでもGPSログ、地名検索および領域表示を利用できる。
8. GPSログがSTOPPEDで測位要求がなくなるとGNSSがPAUSEへ戻る。
9. 操作を止めると自動的にBACKGROUND_MODEへ戻る。
10. Galuchatでエラーが発生しても、GPSログがRECORDINGなら記録を継続する。
11. SD障害時の保持件数、ログ欠落数および復旧結果を確認できる。
