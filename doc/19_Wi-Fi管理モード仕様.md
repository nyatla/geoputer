# Wi-Fi管理モード仕様

文書状態：基本機能・QR接続・Web日英対応実装仕様 1.3。2026-10-30。

本書はGPSロガー・USBストレージと排他に動作するWi-Fi管理モードを定義する。SoftAP、スマートフォン対応Web画面、単体ファイル操作、テキスト表示・編集を実装した。tgz受信中展開は後続機能として未実装である。モード別の固定資源は[動作モード別メモリ構成設計](18_動作モード別メモリ構成設計.md)に従う。

## 1. 目的と実装順序

Wi-Fi経由でSDカードのファイルを管理し、SDカードを抜かずにデータセットを配置・調整できるようにする。中心機能は、ディレクトリを移動し、その場所でファイルを一つずつアップロード・削除し、ディレクトリを作成・削除できるWebファイルマネージャとする。内容の表示と編集はテキストファイルだけを対象とする。

第1段階として接続・状態表示・基本のファイル操作・テキスト表示と編集を実装した。tgzアップロードと受信中展開は、それらを使えるようにした後の拡張とする。tgzを必須にせず、データセットの配置を単品ファイルのアップロードだけで完結できる構成にする。

本体で設定できる通常の設定項目は、Webでは現在値を表示する。設定画面の全機能をWebへ複製することは初期範囲に含めない。データセット用INIの編集は通常の設定値の変更と区別し、ファイル管理の機能として提供する。

## 2. 起動モードとSDの所有権

GPSロガー、USBストレージ、Wi-Fi管理を排他的な起動モードとして扱う。システム設定のモードでWi-Fi管理を選び、「保存して再起動」で移行する。記録中・一時停止中・セッション閉鎖中・未保存ログあり・Storage処理中は移行を認めず、既存のモード変更と同じ制約・確認を使う。

Wi-Fi管理ではApp・UI・Storageを起動し、WebサービスをStorageのループ上で実行する。HTTPの受信・保存処理とSD操作を同じタスクで直列化し、Web専用のアプリケーションタスク・キューは追加しない。GPS受信・記録・地図表示・区域アラート・LoRa送受信は開始しない。SDはStorageがFAT32としてマウントし、Webブラウザーへファイル操作を提供する。USBのマスストレージ公開は行わず、USB CDCの診断経路は維持する。Wi-Fiドライバー等のシステムタスクは、アプリケーションの役割とは別に扱う。

起動フラグは既存の独立したboot_modeレコードを拡張する。0＝GPSロガー、1＝USBストレージを維持し、2＝Wi-Fi管理とする。通常設定の48バイトレコードへWi-Fi設定を詰め込まない。不正フラグ・読出し失敗は既存どおりGPSロガーへ戻して記録する。Wi-Fi管理中に電源を切った場合、次回も同じモードで起動する。

## 3. 接続方式

初期接続は端末自身をアクセスポイントとするSoftAP方式とする。家庭や施設のルーターを必要とせず、PC・スマートフォンを端末のWi-Fiへ直接接続して使用する。

SSIDはReverseGeoputer-XXXXとし、末尾は端末識別用の値とする。端末ごとに生成したパスワードで接続を保護し、SSIDとパスワードは再起動後も維持する。パスワードはハードウェア乱数から英大文字・数字の16文字を生成し、NVSの既存WAP1レコードへ保存する。パスワードをMACアドレスだけから導出しない。接続先は http://192.168.4.1/ とし、本体画面に実際のURLを表示する。

Web画面のHTML・CSS・JavaScriptはFlashへ収録し、外部CDN・外部フォント・インターネット接続へ依存しない。通常のブラウザーから操作できるようにする。DNS応答とHTTPプローブの転送により、接続後の案内ページを提供する。案内から管理画面へ進めるようにする。自動表示はスマートフォンのOS・設定に依存するため、URL用QRと文字表示を常に併用する。DNS開始に失敗した場合も直接URLでの管理は継続する。既存ルーターへ接続するSTA方式は後続機能とする。

認証・接続設定はNVSの専用レコードへ保存する。初期版は本体に接続情報を表示する方式とし、Webから無認証で接続パスワードや起動フラグを書き換えられる経路を設けない。

## 4. 本体画面

本体は接続案内と処理状態を表示する。ファイル操作そのものはブラウザーで行う。

- 共通ヘッダー：Wi-Fiモードのタイトル、SDアイコン、電池残量。
- 接続情報：SSID、パスワード、URL、接続の有無。
- SD状態：利用可能・未挿入・マウント失敗・I/Oエラー。
- 処理状態：待機、受信中、保存中、削除中などと処理量。
- フッター：終了操作に意味があるEscマークと必要な確定キーを表示する。

ASCIIの接続情報には8×16、通常の日本語表示には東雲16×16を使用する。タイトルとフッターは共通の8×8・ROMキーアイコンに従う。GPS画面への数字ショートカット、GPS操作G、通常モードの画面オフSはWi-Fi画面へ持ち込まない。自動消灯は初期版では行わない。

本体の初期ページはWi-Fi接続用QRとする。SSID・パスワードを含めた標準的なWIFI形式を使い、スマートフォンから接続を承認できるようにする。パスワードの手入力を必須にしない。

| 操作 | 動作 |
| --- | --- |
| 左右 | 接続用QR → 管理画面URL用QR → 文字情報の3ページを循環する |
| R | パスワード再生成の確認を開く。初期選択は取消 |
| Esc／Del | Wi-Fi終了の確認を開く |
| 確認中の左右・Enter | 取消／実行を選んで確定する |

接続用QRを表示中に最初のクライアント接続を検知したらURL用QRへ移る。文字情報などを手動選択している場合は接続状態の更新で勝手にページを変えない。QRの描画領域は100×100ピクセル、整数倍の白黒描画とし、周囲に最低4モジュールの白余白を確保する。日本語・英語の[実画面](画面・操作/wifi/README.md)を参照する。

Rによる再生成は新しいランダムな16文字を保存し、接続を切って同じWi-Fiモードで再起動する。記録モードのフラグへ変更しない。取消では変更せず、保存失敗時は現在の接続とパスワードを維持してエラーを表示する。再生成後は新しい接続用QRで再接続する。スマートフォンに古い認証情報が残る場合は、以前のネットワーク設定を削除して接続し直す。

EscおよびDelは終了確認を開く。待機中はGPSモードへ戻る確認、処理中は「処理を中断して戻る」確認とする。取消を初期選択とし、左右で選択、Enterで確定する。

## 5. Web画面

```text
ReverseGeoputer                         日本語 / English
├ 情報 / Info（初期表示）
│ ├ バージョン・起動モード・SSID・SD状態
│ ├ SD容量・空き容量
│ ├ 選択中のデータセット・辞書言語
│ └ 通常の設定値（表示のみ）・更新
├ ファイル / Files
│ ├ 現在ディレクトリ・親へ戻る・ページ送り
│ ├ サブディレクトリへ移動
│ ├ ファイルを一つアップロード
│ ├ ディレクトリ作成
│ ├ ファイル／ディレクトリ削除
│ └ テキストの内容表示・編集・保存
├ データセット / Datasets
│ └ 準備中 / Coming soon（プレースホルダ）
└ GPSロガーモードへ戻る（共通）
```

上部の3つのボタンで画面を切り替える。初期表示は情報画面とし、ファイル画面を初めて開いたときに一覧を取得する。画面切替だけでは現在のディレクトリやページを初期化せず、取得済みの一覧を再利用する。明示的な更新やファイル操作後は再取得する。転送などの処理中は画面・言語の切替を無効にする。データセット画面は見出しと準備中の表示のみで、専用API呼出しや索引・選択操作は行わない。

情報画面には記録間隔・SD保存間隔・消灯時間・明るさ・端末の表示言語・音量・省電力などの現在値を表示する。「更新」で現在値とSDの空き容量を読み直す。本体で設定できる項目は表示のみとし、Wi-Fiモードで稼働していないGPSの現在位置やFIX状態を現在の測位結果として表示しない。

Webの表示言語は本体の設定とは独立した日本語／英語の選択とする。保存された選択がなければブラウザーの言語が日本語のとき日本語、それ以外は英語を使う。選択は同じオリジンのlocalStorageへ保存し、接続案内ページと管理画面で共有する。保存が利用できなくても、そのページでの言語切替は継続できる。端末のNVSやSDへ保存しない。ラベル・確認・進捗・操作結果をブラウザー側で翻訳し、言語変更のためのAPI通信は行わない。ファイル名・ファイル本文・端末の診断詳細は原文を表示する。

画面はHTML、少量のCSSとJavaScript、Flashに収録する翻訳文字列で構成し、装飾は罫線・文字・必要な状態色に抑える。外部フレームワーク・フォント・通信先は追加しない。ブラウザーの配色設定に従い、PCとスマートフォン双方で使える配置とする。viewportを端末幅に合わせ、操作ボタンは最小44px高、本文入力は16pxとする。PCでは一覧を横方向に並べ、狭い画面では縦に並べる。ファイル名と長いパスは折り返し、320px幅でもページの横スクロールを必要としない。

編集画面は「変更を保存」「閉じる」と変更状態を本文より上に配置し、長い本文は入力欄内でスクロールする。未保存内容の破棄確認と変更時だけ保存可能にする動作を維持する。スマートフォンが「インターネット接続なし」と表示した場合も、このWi-Fiへの接続を維持して利用する。

## 6. ディレクトリとファイルの基本操作

| 操作 | 動作 |
| --- | --- |
| 一覧 | 現在のディレクトリ内の名前・種別・ファイルサイズ・更新日時を表示する。取得できない日時は不明とする |
| 移動 | ディレクトリ名を選ぶとその配下へ移動する。親へ戻る操作と現在位置を表示する |
| ディレクトリ作成 | 現在位置の直下へ入力した名前で作成する。同名がある場合は失敗理由を示す |
| アップロード | 選んだ1ファイルを現在位置の直下へ保存する。保存名と保存先を表示する |
| ファイル削除 | 対象名を示して確認し、確定したファイルを削除する |
| ディレクトリ削除 | 対象名と「内容も含めて削除する」ことを示して確認する。配下を順に削除してから対象を削除する |
| 内容表示 | 対応するテキストファイルだけに表示操作を用意する |
| 編集・保存 | 表示したテキストを編集し、変更内容をそのファイルへ保存する |

一覧は固定件数のページ単位で取得し、端末RAMへディレクトリ全件を保持しない。ファイル数が多くても初期表示と次ページ取得ができるようにする。

ブラウザーでのルートはSDカードのルートとし、端末内部のマウント接頭辞 /sd は操作用のパスに露出させない。ルート自体の削除は認めない。サービスの未完了ファイル・回復管理情報は通常一覧から隠し、通常操作の対象にも認めない。

ディレクトリ削除は逐次処理し、削除対象の全リストをRAMへ作らない。中断やI/O失敗の場合、削除済みの項目は復元せず、処理を停止して原因と現在の一覧を表示する。取消は削除開始前の確認で行い、実行中のキャンセルは以後の削除を止める操作とする。

## 7. 単体アップロード

単体アップロードを初期の転送方式とする。ディレクトリ移動後にファイルを一つ選び、そのディレクトリへ送る。データセット専用形式で包装することは要求しない。GLC・Wordbook・INI・ログ等も、通常のファイルとして扱う。

受信データは小さな固定バッファでStorageへ渡し、SDへ順に書く。ファイル全体を端末RAMに保持しない。転送・保存の同時実行は1操作に制限し、Storageがバッファを使い終わってから再利用する。

受信中は管理用の一時名で書き、本文の受信完了、受信サイズ、書込み・close・同期の成功を確認してから正式名へ変更する。同名ファイルがある場合は上書き確認を行う。転送途中の切断や失敗で、既存ファイルを途中の内容へ置き換えない。置換途中の電源断に備え、旧ファイルの退避と回復情報を残す。管理用ディレクトリ `/.rgp-wifi/` に受信中の `upload`、置換時の `backup`、対象パスと照合値を持つ `transaction` を置く。次回Wi-Fi起動時に回復し、回復情報が不正な場合はファイル操作を無効にして原因を表示する。管理領域は通常一覧・操作から隠し、FATの短縮名による参照も拒否する。

ブラウザーは転送量を表示する。送信量が100%になった時点と、端末側の保存完了を区別し、最終応答を受けてから成功と表示する。接続切断・タイムアウト・容量不足・SD I/O失敗は失敗として表示し、一覧へ反映する。初期版の中断後は最初から送り直す方式とし、バイト位置からの再開は別機能とする。

## 8. テキストの内容表示と編集

テキストファイルだけを内容表示の対象とし、バイナリのプレビュー・画像表示・バイナリエディターは設けない。ファイル一覧にはバイナリも表示し、アップロード・削除の対象にはできる。

初期のテキスト対象は .ini / .txt / .csv / .md / .log / .json とし、全文がUTF-8として有効で、NUL等の不適切な制御文字を含まないものとする。.glc / .giswordbook / .dat / .bin等は内容表示しない。拡張子・サイズ・文字コードで表示できない場合は、その理由を示す。文字コードの自動変換は行わない。

編集本文はブラウザーが保持し、端末は小さなバッファで読み書きする。未変更なら保存操作を無効にし、未保存の変更を残して移動・終了する場合はブラウザーで確認する。

保存には読出し時のファイル識別情報を付ける。読出し後に他の操作で元ファイルが変わっていれば、上書きせず再読込みを案内する。保存は単体アップロードと同じ一時名・置換手順を使う。本文・ファイル名・INIの説明文はHTMLとして実行せず、テキストとして表示する。

## 9. データセット配置との関係

初期段階では利用者が /dataset/01 などのディレクトリを作り、GLC、UTF-8版Wordbook、dataset.iniを個別にアップロードする。INIをWebから表示・編集できることで、参照先・タイトル・説明・表示書式を調整できるようにする。[メタデータ仕様](08_データセットメタデータ仕様.md)と[事前索引仕様](11_データセット事前索引ファイル仕様.md)の形式・上限を変更しない。

ファイル保存の成功を、データセットの利用可能判定と同一視しない。地図・辞書の追加や置換、参照先の変更、索引の削除を行った後は、必要な索引生成・検証を行う。基本のファイル管理を実装する段階では、本体の既存データセット管理から実行できる。Webからのデータセット選択・INI入力補助・索引生成／検証の操作は、基本機能に続く追加機能として整備する。

Wi-Fi終了後のGPS起動では、既存仕様に従って保存済みのデータセットと索引を確認する。使用不能なら原因を表示して未選択へ移し、GPS表示・記録を利用できる状態を維持する。Webから変更したという理由で検証を省略しない。

## 10. 処理の排他・完了・終了

SDに触るファイル操作はStorageが直列に処理する。転送・保存・削除などの実行中は、競合する新規操作を実行せず、処理中であることを表示する。端末画面の状態更新とキャンセル処理は継続する。

WebサービスはStorageが所有し、HTTP要求の受付から完了応答まで同じタスクで処理する。Appは本体UIへの状態反映とモード終了を管理する。状態はStorageが保持し、Appへの投機的通知が落ちた場合は再通知する。受信バイト列やテキスト本文をAppの通知キューへ積まない。

起動時は、UIの初期化完了を確認してからAppがStorageへ同期初期化要求を送る。以後のファイル操作はHTTPの完了応答で成否を返す。本体からの終了はStorageの既存受信キューへ投機的なStopWifi通知、または確認済み再生成のRegenerateWifi通知を送り、転送・削除の処理点で取り込む。結果待ちでAppやUIを停止させず、終了準備が整うまで表示を継続する。

本体またはWebから終了を確定したら、新規操作を停止する。受信中の一時ファイルを閉じて破棄し、保存の確定処理中ならその処理が戻るまで待つ。その後、起動フラグをGPSへ保存し、WebサービスとWi-Fiを停止してAppへ終了準備完了を通知し、再起動する。削除は各項目の処理点で中断し、削除済みの内容は元に戻さない。共有メモリを処理中に別モードへ構築し直さない。

Wi-FiではブラウザーにSDの生セクタを公開しないため、USBドライブの「安全な取り外し」は要求しない。SD未挿入・マウント失敗でも接続案内と終了操作は利用可能とする。保存時のclose・同期・置換に失敗した場合はHTTP操作を失敗とし、起動フラグの保存に失敗した場合は再起動せず本体にエラー状態を表示する。

## 11. 動作モード別メモリ

WifiApplicationは、専用のWifiUiTask・WifiStorageTask、専用通知／同期結果キュー、Appの状態を全て内包する。最上位ApplicationMemoryのunionにはこのアプリ全体を配置する。Wi-Fiの型はGPSの区域キャッシュ・地図・検索器を含まず、起動時にGPS用オブジェクトを構築しない。

Wi-Fi側にはWeb制御状態、DNSサービス、固定の転送バッファ、Storageのファイル作業領域を持たせる。WifiUiTaskは270バイトのQRビット行列・内容キャッシュをタスク所有の固定メンバーとして保持する。QRエンコードの作業はUIの局所スタックで完結し、バージョンを5（接続用）・2（URL用）に制限する。既存の画面バッファへ直接描き、QR用の画面バッファを追加しない。大きな領域はタスクのスタックに置かず、モード領域へ直接構築する。後続の展開・索引保守・テキスト保存で同時に使わない作業領域は、そのモード内でもunion等で排他利用する。

Wi-Fiドライバー・TCP/IP・HTTPライブラリ内部のヒープは別途実測する。unionの未使用部分が自動でシステムヒープへ戻るものとは扱わない。Wi-Fi起動時には、生存する固定資源の末尾以降の安全な範囲だけをシステムヒープへ明示的に追加する。登録範囲・静的寿命・再構築禁止は[動作モード別メモリ構成設計](18_動作モード別メモリ構成設計.md)に従う。初期化後のアプリ側の転送処理は、固定領域と借用により、ファイルサイズに応じたヒープ確保を増やさない方式とする。

- sketch/app/xyz_server/task/ExtractFileSetFromYmodemTask.cpp：受信ストリームと展開処理の接続、受信全体の完了確認。
- src/tar/pipeline/ExtractPipeline.cpp：gzip・tar・出力先ファイルへの逐次書込み。
- src/tar/GUnZipByteStream.h / .cpp：固定辞書と入力バッファを持つgzip展開器。
- src/tar/TarExtractor.h / .cpp：ファイル単位のイベントと、呼出し中だけ有効なpayloadストリーム。

```text
HTTP受信ストリーム
  → gzip展開
  → tar解析
  → 準備用ディレクトリ内の各ファイルへ書込み
```

圧縮アーカイブをSDへいったん保存せず、受信しながら展開する。入力源とファイルI/Oのアダプターを分離し、受信が一時的に止まった状態と正常終端・切断を区別する。Storageが追いつかない場合は受信側を待たせ、受信量に応じてRAMを増やさない。

tar終端だけで成功にしない。展開後の残りパディング、gzipの正常終端・CRC32・ISIZE、HTTP本文の受信完了を確認する。参考コードは設計の参考とし、この完了検証を満たすことを採用条件にする。

データセットのパック投入では、準備用ディレクトリへ展開し、構成検査・索引生成／検証が完了してから正式配置する。ファイル単体の保存成功とは別に「登録完了」を表示する。上書き途中の中断に備えて旧データと回復状態を保持する。パス逸脱、同名重複、非対応のエントリ、容量・サイズ・階層上限違反を拒否する。tar拡張形式やパック内のディレクトリ構成の詳細は、この機能の実装前に追加仕様として確定する。

Webから索引保守を行う際は、GPS用MapSessionの存在を前提とせず、Wi-Fi側の作業領域・Reader・FILを受け取る共通処理として呼べるようにする。

## 13. 実装上限と検証項目

転送サイズ・表示上限・ページ件数・削除階層上限はConfig.hのWifi項目へ集約する。既存のパス・データセット形式の制約は正本に従う。

| 項目 | 実装値・制約 |
| --- | --- |
| 接続方式 | パスワード付きSoftAP |
| AP接続端末 | 1台 |
| 同時ファイル操作 | 1操作 |
| 一覧 | 20件／ページ |
| テキストの表示・編集上限 | 64 KiB |
| 転送作業バッファ | 4 KiB（WebServer内部の受信領域は別） |
| フルパス | UTF-8、終端込み256バイト |
| データセット参照ファイル名 | UTF-8、終端込み128バイト |
| 単体ファイルサイズ | 2,147,483,647バイト以下。WebServerのContent-Lengthが符号付き32 bitのため、FAT32の最大ファイルサイズより小さく制限する。残容量は64 bitで計算する |
| データセット言語数／チャンク数 | 既存の16言語／1500チャンク制限を維持 |

基本機能では、SDなし・容量不足・同名・長い名前・UTF-8・大きなファイル・切断・取消・上書き中断・途中削除・再起動時の回復を確認する。転送サイズに比例してアプリ側のヒープが増えないことと、Wi-Fi稼働中の最小空きヒープ・最大連続空き領域・タスクの残スタックを計測する。

ファイルパスはWeb側だけでなくStorage側でも正規化・範囲検証し、SDのルート外や管理用領域へ書き込ませない。URLデコードの重複、NUL、ドライブ指定、親ディレクトリを使う逸脱を受け付けない。正常な相対パスを連結してから、既存の固定長パス制約を確認する。

後続のtgz機能では、受信境界と圧縮・tar境界が一致しない入力、CRC不一致、途中終端、余分なデータ、不正なパス・サイズ、SD失敗を追加検証する。本文・ファイル名・説明文字列はWeb画面でエスケープし、他サイトからの変更要求を受け付けないようにする。

## 14. 利用手順と検証範囲

1. GPS記録を停止し、本体の「設定 → システム設定 → モード」でWi-Fiを選ぶ。
2. 「保存して再起動」を確定する。
3. スマートフォンで本体の接続用QRを読み取り、接続を承認する。PC等では文字ページのSSID・パスワードを入力してもよい。
4. 接続後の案内から管理画面を開く。案内が表示されなければ、本体のURL用QRまたは文字表示のURLを使う。
5. 作業後はWebの「GPSロガーモードへ戻る」、または本体のEsc／Delによる終了確認を使う。

実装と試験結果は[Wi-Fi管理モードの検証](検証/Wi-Fi管理モードの検証.md)に記録する。ホスト・ブラウザー試験の成功と、実機の電波接続・SD転送の確認は区別する。
