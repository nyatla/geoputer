# Geoputer ログエクスポート仕様

文書状態: 実装仕様 1.1（2026-10-17）。ホスト試験・ファームウェアビルドの結果は[実装検証](検証/ログエクスポート実装検証.md)を参照する。実機での変換・再公開は別途確認する。

## 1. 目的と適用範囲

SDに保存した固定長バイナリのGPSログを、PCの地図表示や解析に利用できる形式へ変換する。内部記録は[測位記録ファイル仕様](07_測位記録ファイル仕様.md)のまま維持し、変換によって元のファイルを変更・削除しない。

エクスポートはUSBストレージモード内の機能とする。PCへ接続した後に書き出し忘れに気付いた場合も、ケーブルを抜いたりGPSロガーモードへ戻ったりせず、端末の画面から対象ログと形式を選択して変換できる。GPSタスク・逆ジオコーディング・ログ記録は起動しない。

本書を、出力先・命名・形式選択・SDの所有権切替・進捗表示の正本とする。起動フラグとモード間の再起動は[起動モード・USBストレージ仕様](09_起動モード・USBストレージ仕様.md)、描画と操作は[USBエクスポート画面](画面・操作/usb-storage/export-proposal/README.md)と対応させる。

## 2. 出力形式

次の3形式に対応し、書き出し時に1種類を選択する。UIのタイトルは形式に依存しない`EXPORT`とする。

| 形式 | 拡張子 | 用途と取り扱う情報 |
|---|---|---|
| GPX 1.1 | `.gpx` | 軌跡の交換。座標・UTC時刻・標高・衛星数・HDOPを標準項目へ格納する。速度と進行方位の拡張は出力しない |
| KML | `.kml` | KML 2.2の地表上の軌跡。2点以上はLineString、1点はPointとし、時刻・標高は出力しない |
| CSV | `.csv` | 表計算・独自解析。元の全測位項目を単位が明示された10列で出力する |

GeoJSONは追加形式の候補とし、初期の形式選択には含めない。形式ごとの出力器を追加できる構造とし、元ログの読出し・検証・進捗・ファイルの開閉は共通化する。

座標系・UTC日時・標高・速度・進行方位・HDOP・衛星数の値と有効性は元レコードを正本とする。欠測値を有効なゼロや端末の現在値で埋めない。GPX 1.1には速度・進行方位の直接の標準項目がないため、そのまま標準要素として出力する設計にはしない。

参照する形式は[GPX 1.1 schema](https://www.topografix.com/GPX/1/1/)、[KML Reference](https://developers.google.com/kml/documentation/kmlreference)、[CSVの共通表現（RFC 4180）](https://www.rfc-editor.org/rfc/rfc4180)とする。GPXの座標はWGS84の緯度・経度を小数7桁、標高はmを小数3桁、HDOPは小数2桁で表す。UTC時刻は`YYYY-MM-DDTHH:MM:SS.sssZ`とし、有効な時刻は1970年〜9999年に限る。欠測の標高・時刻・衛星数・HDOPはタグ自体を省略する。ファイル全体を1つのtrk / trksegへ格納する。

KMLは`clampToGround`とし、座標を`経度,緯度`の順に小数7桁で出力する。GPXの緯度・経度の属性順と混同しない。時刻付き軌跡や標高を利用する場合はGPX、全項目の解析にはCSVを使う。

CSVはUTF-8・BOMなし・CRLF改行で、先頭に次のヘッダーを置く。

```csv
record_index,utc,utc_ms,latitude_deg,longitude_deg,altitude_m,speed_m_s,course_deg,hdop,satellites
```

`record_index`は0始まりの元レコード位置、`utc_ms`はUnix epochからのミリ秒である。座標は小数7桁、標高はmで小数3桁、速度はm/s、進行方位は度、HDOPは小数2桁、衛星数は整数とする。欠測値は空欄とする。出力は元レコードの固定小数点整数から計算し、単精度浮動小数点への復元による精度低下を避ける。

## 3. 出力先とファイル名

出力先はSDカード直下の`/export/`とする。本体でマウント先を含める場合は`/sd/export/`となる。ディレクトリ名は単数形の`export`で固定する。

出力名は、入力ログのファイル名全体へ、選択した形式の小文字拡張子を追加したものとする。元の`.gps.dat`を除去・置換しない。入力名の年月日時分秒・衝突回避番号・`undated`名はそのまま保持し、変換した日時で命名し直さない。

| 入力 | 形式 | 出力 |
|---|---|---|
| `/logs/20261017_093012_0.gps.dat` | GPX | `/export/20261017_093012_0.gps.dat.gpx` |
| 同上 | KML | `/export/20261017_093012_0.gps.dat.kml` |
| 同上 | CSV | `/export/20261017_093012_0.gps.dat.csv` |
| `/logs/undated_0000000000000001_0.gps.dat` | GPX | `/export/undated_0000000000000001_0.gps.dat.gpx` |

同じログの異なる形式は、同じ`export`ディレクトリへ並べて保存する。形式別のサブディレクトリや出力用の連番は追加しない。同名・同形式の既存出力がある場合は変換を拒否し、`OUTPUT ALREADY EXISTS`を表示する。上書きや出力用の別名生成は行わない。再変換する場合はPC側で既存出力を移動または削除する。

`export`がない場合は、Storageが端末操作状態で出力準備を行う際に作成する。作成できない場合は失敗を通知する。現行の元ログ名は最大47バイトであり、3形式とも拡張子追加後は最大51バイトとなる。出力名・パス・UI表示用の領域は元ログ名の領域と区別し、末尾の拡張子を切り捨てない。

## 4. USBモード内のSD所有権

USBストレージモードを、PC公開状態と端末操作状態に分ける。同じカードをPCのファイルシステムと端末のFatFsから同時に操作しない。この状態切替はUSBモード内で行い、NVSの起動モード変更やアプリケーション全体の再起動を伴わない。

| 状態 | SDの所有者 | PCへの公開 | 端末のファイル操作 |
|---|---|---|---|
| PC公開中 | PC | MSCでSD全体を公開 | 行わない |
| 取り外し待機 | PC | 安全な取り外しの完了まで維持 | 行わない |
| ログ・形式選択 | Storage | 停止 | FatFsでログ一覧・情報を読む |
| 変換中 | Storage | 停止 | 元ログを読んで出力ファイルを生成 |
| 公開準備 | Storage | 停止 | 出力の同期・閉鎖とアンマウントを行う |
| 完了 | PC接続時はPC、未接続時は公開待ち | PC接続時は再公開 | 行わない |

端末操作へ移る際は、Storageが新規USBセクタI/Oを止め、実行中のI/Oが終了したことを確認してからFatFsをマウントする。PCへ再公開する際は、開いている全ファイルを閉じ、必要なSD同期とアンマウントを終えてからUSBセクタI/Oを再開する。各画面の表示だけを根拠に排他を成立させない。

USB未接続の判定と、接続中のPCによる安全な取り外しの完了は区別する。アクセスランプの消灯や一定時間I/Oがないことを、安全な取り外し済みの根拠にしない。PCの未送信書込みキャッシュを端末側で同期することはできない。接続状態はTinyUSBの列挙状態で判定し、USBのサスペンドを未接続扱いにしない。ケーブル抜去がスタックへ通知されない場合も安全な取り外し待ちを維持する。

## 5. 操作の流れ

### 5.1 USBメニュー

USB起動時はメニューを表示し、「ログを書き出す」「ロガーへ戻る」を並べる。PC接続・未接続・安全な取り外し済みと、SDの準備状態を表示する。終了確認は起動直後には開かず、メニューからの明示操作で開く。

「ロガーへ戻る」では既存の共通確認を使い、PC公開中でも端末側の終了を選択可能とする。PCでの保存完了後、実行中転送の終了とSD同期を待ち、起動フラグ保存成功後の再起動で通常モードへ復帰する。エクスポートのためにこの項目を経由する必要はない。終了時のPC側の前提は[起動モード・USBストレージ仕様](09_起動モード・USBストレージ仕様.md)に従う。ログ変換のための端末所有への移行では、従来どおりPCの安全な取り外しを待つ。

### 5.2 未接続・安全な取り外し済み

「ログを書き出す」を選ぶと、取り外し案内を省略し、USB公開を停止してログ選択へ進む。対象ログ、出力形式の順に選択し、変換を開始する。

### 5.3 PC公開中

「ログを書き出す」を選ぶと、「PCで安全に取り外し」の案内を中央のウインドウへ表示する。安全な取り外し完了を確認できたら端末操作状態へ移り、ログ選択へ自動的に進む。待機を取り消した場合は元のUSBメニューへ戻る。

ケーブルを抜くことや、GPSロガーモードへ再起動することを手順に含めない。対象ログ、出力形式、変換以降の流れは未接続時と共通とする。

### 5.4 選択・変換・完了

ログ選択には元のファイル名を表示する。Enterで対象を決定すると、GPX・KML・CSVの形式選択を表示する。形式選択のEnterで書き出しを開始し、Esc / Delではログ選択へ戻る。ログ選択から戻る場合はファイルを閉じてUSBの公開準備を行い、USBメニューへ戻る。

変換中は対象ファイル名、選択形式、処理済み件数／総件数、進捗率と進捗バーを表示する。途中でPCに接続されても、変換・ファイル閉鎖・アンマウントが終わるまではSDを公開しない。進捗100%だけで完了とは扱わず、出力の確定と公開準備までを完了処理に含める。

変換開始後の取消は初版では提供せず、完了または失敗まで待機する。

成功時は出力先を表示する。PC接続中ならSDを再公開し、「PCへ公開しました」と表示する。未接続なら「USB接続待ち」と表示し、以後の接続時に公開する。書き出し自体は成功したが公開に失敗した場合は、出力作成済みと公開失敗を区別する。

全画面は240×135ドットとし、見出し・ファイル名・補助情報はASCII 8×8、日本語本文は東雲16×16、ASCII本文は8×16を使う。上下と`;` / `.`で選択し、Enterで決定、Esc / Delで戻る。選択を伴う確認は共通の左右2択とする。USB画面では自動消灯を行わない。

## 6. タスクの責務と通信

Appが、UIの要求とStorageの処理状態を統合して状態遷移を管理する。UIは対象ログ・形式の選択、案内・進捗・結果の描画を担当する。実際のSD所有権切替・ログ読出し・形式変換・ファイルの生成・同期・公開準備はStorageが行う。

AppからStorageへの同期要求は、操作を受け付けたかを返す。変換全体の完了を同期応答まで待たせない。Storageは処理を少量ずつ進め、進捗・成功・失敗を既存のApp通知経路へ投機的に通知する。Appはその内容をUIへ同期要求で反映し、描画はUIタスクが行う。

Appの通知キューと数量1の戻り値キュー、サブタスクの受信キュー各1本という構成を維持する。同期要求の結果回収契約は[タスク構成設計](06_タスク構成設計.md)に従う。エクスポート専用タスクや全ログ分のRAM領域は追加せず、共通の読出し処理と形式別の出力器で順次変換する。進捗は最新状態を保持し、通知混雑で変換済み範囲や最終結果を失わない。

## 7. ファイルの確定と失敗処理

SD未挿入・マウント不可・対象消失・読出し失敗・出力先作成失敗・容量不足・書込みや同期の失敗・再公開失敗を成功として扱わず、App経由でUIへ示す。元ログのヘッダー・レコードの検証は測位記録仕様に従い、破損や不完全な末尾を黙って正常な軌跡へ変換しない。途中の出力を完成ファイルとして表示・公開しない。

書き出し途中は`/export/.<元のファイル名全体>.<拡張子>.part`を排他的に作成する。既存の同名作業ファイルは削除せず、`REMOVE STALE .PART ON PC`として拒否する。正常終了時だけ出力を同期し、入出力ファイルを閉じて、上書きしないリネームで完成名へ確定する。その後、FatFsの解除・ドライバの再初期化・USB再公開を行う。

ヘッダー不正・未対応版・CRC不正・測位値不正・32バイト未満の末尾・0件のログは失敗とする。破損レコードは0始まりの位置を表示する。欠測の任意項目とは区別し、不正部分を読み飛ばして成功扱いにしない。FAT32のファイルサイズ上限を超える出力は中断する。

失敗時は自身が作成した作業ファイルを閉じ、削除を試みる。SD異常などで削除できない場合は`.part`を残してPCから修復できるようにする。既存出力と既存作業ファイルは維持し、元ログを変更しない。ファイルを閉じられない場合は端末所有を保ち、USBの生セクタアクセスを許可せず再試行する。

出力作成済みの状態は変換結果とは別に保持する。出力作成後の再公開失敗は「出力済み・公開失敗」と表示し、生成そのものの失敗と区別する。同期失敗でFatFsが残っている場合は端末所有を維持する。アンマウント後の生ドライバ再初期化に失敗した場合は媒体なしでUSBを接続し、エラー画面からUSBメニュー・ロガー復帰を操作できるようにする。

## 8. 実装・検証の範囲

USBメニュー、取り外し待機、4件単位のログ一覧、形式選択、順次変換、進捗・結果表示、USBモード内でのFatFsマウント／再公開を実装する。Appの同期受付は`UsbExportOperation`、進捗と所有権変化の通知は既存の`UsbStorageChanged`を使用し、キューを追加しない。

変換器はStorageが所有する`task/storage/export/LogExporter`とする。1回の処理で最大10レコードを読み、2048バイトの出力バッファへ書き込み、進捗は200msを目安に集約する。開閉・確定・最終結果の変化は待たずに反映する。これらの値は`application/Config.h`にまとめる。FatFsのファイルオブジェクトと変換用領域はStorageのメンバーへ置き、ログ全体をRAMへ展開しない。

ホスト試験では3形式の別実装による読込み、GPX公式XML Schema検証、欠測・日時・単位・最大名長・既存出力・破損・途中切れを確認する。USBドライバの代替環境ではPC所有中の拒否、繰返しマウント、再接続時の保護、同期失敗後の再試行、実行中I/Oの終了待ちを確認する。実機試験の実施状況は[実装検証](検証/ログエクスポート実装検証.md)へ記録する。
