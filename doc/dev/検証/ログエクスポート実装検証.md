# ログエクスポート実装検証

2026-10-17。[ログエクスポート仕様](../10_ログエクスポート仕様.md)のUSBメニュー、端末内変換とSDの所有権切替を実装した。本書はホスト試験と生成ファームウェアの検証結果を示す。2026-10-18に実機へ書き込み、通常起動を確認した。実SDでの変換と再公開は未実施である。

## 実装範囲

USB起動時はメニューを表示し、PC公開中の書き出し要求だけ安全な取り外しを待つ。Storageが生セクタI/Oを止め、進行中のI/Oの終了後にFatFsへ切り替える。4件単位のログ一覧、GPX・KML・CSVの選択、順次変換、進捗と結果、ファイル閉鎖・同期・アンマウント後のUSB再公開を実装した。USBモード内の切替でGPSを起動したり全体を再起動したりしない。

Appの同期メッセージは受付結果を返し、変換結果は既存の通知へ集約する。専用タスク・キュー・ログ全体のRAM領域は追加しない。変換は1回最大10点、出力バッファ2048バイト、進捗更新200msを目安とする。定数は`application/Config.h`へ配置した。FatFsのファイルオブジェクトとバッファはStorageのメンバーとして保持する。

元ログは読出し専用とし、出力名へ選択形式の拡張子を追加する。同名出力は上書きせず、破損・不完全末尾・0件は失敗とする。作業ファイルの同期・閉鎖後だけ完成名へ確定する。変換開始後の取消は提供しない。

## ホスト試験

`python3 tests/run_native.py`に変換器・USBバックエンド・UI遷移の試験を追加した。C++は警告をエラー扱いとし、未定義動作検出を有効にして実行した。

- 3形式で25点の変換と元ログの不変、1回の処理件数の上限、最長47バイトの元名から51バイトの出力名への保持を確認した。
- PythonのXML・CSV読込みで、GPXの緯度経度、KMLの経度緯度、1点のPointと複数点のLineString、UTC epoch・うるう日・ミリ秒、欠測タグ省略・空欄、標高と速度の単位を確認した。
- GPXは公式`gpx.xsd`を取得し、システムのlibxml2で正常出力を検証した。追加検証の実行方法は`GEOPUTER_GPX_SCHEMA=/tmp/geoputer-gpx-1.1.xsd python3 tests/run_native.py`とする。通常試験は外部通信を必要としない。
- 既存出力と既存`.part`の維持、パス逸脱、不正形式、ヘッダー不正・未対応版、途中のCRC異常、末尾5バイト、0件、途中切詰め、出力サイズ制限、出力先が通常ファイルの場合の中断を確認した。
- USBバックエンドの代替環境では、PC所有中の端末操作と終了の拒否、取り外し後のローカルマウント、生読書きと再接続の抑止、繰返しマウント、同期失敗時の所有権保持と再試行、実行中読出しの終了待ちを確認した。
- アンマウント後の生ドライバ再初期化失敗で媒体を公開せず、ロガー復帰は操作できることを確認した。代替環境は、SDKの`sdcard_unmount`だけではVFS登録が残る動作も再現する。
- USBメニュー、取り外し待機と取消、未接続時の案内省略、形式選択・確定・戻る、変換中の操作抑止、完了と失敗からの復帰を確認した。通常の6件一覧とUSBの4件一覧の往復ページングを併せて確認した。

公式スキーマ: [GPX 1.1 XSD](https://www.topografix.com/GPX/1/1/gpx.xsd)。USBドライバの代替試験はWindowsの実USBプロトコル・SDカードの故障・抜去を再現するものではない。

## 描画

`python3 tools/render_usb_export_proposal.py`で日本語・英語各17状態を実装のUiModel・UiRenderer・UsbRendererから描画した。240×135、4bppと16bppの画素一致、ヘッダーとフッターの罫線、右余白、最大名長と最大件数を検証した。破損・出力済み再公開失敗・SDなし・取り外し済みも含む。[実装画面一覧](../画面・操作/usb-storage/export-proposal/README.md)へ反映した。

`tools/render_log_browser.py`のログ・確認・USB画面と`tools/render_settings_layout.py`の設定・言語・ライセンス画面も描画検証の対象とした。

## ビルドと実機確認

PlatformIOの`cardputer-adv`ビルドは警告・エラーなしで成功した。静的RAMは77,536バイト、Flashは1,125,505バイト。全アプリケーションのオブジェクトが対応ソースより新しいことを確認した。生成物は`.pio/usb-export-firmware.bin`、ファイルサイズは1,125,872バイト、SHA-256は`4ed1940c6f2c61b77442df8a5b835981f373f534858b2ff951349f9a954d7872`である。

ELFの関数入口から確認したスタックフレームは次のとおり。これは個別関数の領域であり、実行時の呼出し全体の最大値ではない。

| 関数 | スタックフレーム |
|---|---:|
| App setScreen / publishUiContent | 2064 B / 2048 B |
| App beginUsb / operateUsbExport | 608 B / 592 B |
| Storage run / stepUsbExport | 960 B / 64 B |
| LogExporter record / step / finish | 192 B / 32 B / 32 B |
| UsbStorage takeLocal / publish | 各48 B |
| UiRenderer drawUsb | 208 B |

Storageの12,288バイト、UIの8192バイトというタスクのスタック設定は維持した。出力バッファやFatFsのファイルオブジェクトを変換関数のローカルへ展開しない。

試験ログは`.pio/usb-export-native.log`、`.pio/usb-export-render.log`、`.pio/usb-export-browser-render.log`、`.pio/usb-export-settings-render.log`、`.pio/usb-export-build-final.log`へ保存する。

これまでの実機ではUSBでのSD公開とPC読書き、GPSロガーへの復帰・USB再進入を確認しているが、それは[USBストレージ実装検証](USBストレージモード実装検証.md)の旧ファームウェアによる結果である。今回の変換器とFatFsへの所有権切替を実機確認済みとは扱わない。

実機試験では、安全な取り外しからログ・形式を選択して変換し、再公開後にPCで生成ファイルを読み込む。続けて異なる形式の変換、同名出力の拒否、選択からの取消、通常モードへの復帰を確認する。PC公開中のリセットや書込みは行わず、先に安全な取り外しを完了する。

## 2026-10-18 実機への書込みと起動

`.pio/usb-export-firmware.bin`（SHA-256 `4ed1940c6f2c61b77442df8a5b835981f373f534858b2ff951349f9a954d7872`）を、MAC `70:af:09:df:46:d0`のCardputerへ書き込んだ。対象の識別と生成物のハッシュを照合し、アプリ領域`0x10000`のみを更新した。esptoolの書込み後ハッシュ検証は成功した。NVS領域とSDは消去していない。

再起動後、USBシリアルCOM3で240×135表示、4タスク・5キュー、保存済み設定の読込み、SDのFAT32認識、GPSのFIX、GaluchatデータのOPEN OKを確認した。選択中データセットは172チャンクである。書込みは`.pio/usb-export-flash.log`、起動ログは`.pio/usb-export-boot.log`へ保存した。

今回の確認は通常モードの起動までとし、USBメニューでの変換操作と生成物の実SD読出しは未確認である。ホストでの変換・所有権試験と区別する。

## 2026-10-18 端末からのUSB終了

PC公開中でも終了ダイアログの終了を選べるように変更した。UIの接続状態更新で終了選択を取り消す処理と、StorageのOS取り外し検知による終了拒否を除いた。実行中転送の終了待ち、転送受付停止、SD同期とNVS保存、成功時の媒体非公開化を行う。同期・保存失敗時は現在のモードと媒体を維持して再試行する。端末がFatFsを保持している間の終了拒否と、エクスポート時の安全な取り外し待機は維持する。

終了確認の補助文は「PCの保存完了後に終了」／「Finish PC saves first」とする。PCでの保存完了が前提であり、PC内の未送信キャッシュを端末から保存させる保証ではない。Windowsのクイック削除の扱いは[Microsoftの説明](https://learn.microsoft.com/en-us/windows/client-management/client-tools/change-default-removal-policy-external-storage-media)に従う。

変更後のホスト試験は`.pio/usb-device-exit-native.log`へ保存した。PC公開中の終了選択、接続状態更新後の選択維持、取り外し通知なしの同期受付、実行中I/Oの終了待ち、終了後の新規I/O拒否、SD同期失敗・NVS保存失敗後の媒体保持と再試行に成功した。既存の3形式変換、GPX公式スキーマ、SD所有権と再マウントの試験も通過した。描画試験は日本語・英語各27状態で成功し、更新した確認画面を既存画像へ反映した。

終了処理修正版のビルドは警告・エラーなしで成功した。静的RAMは77,536バイト、Flashは1,125,441バイト。生成物は`.pio/usb-device-exit-firmware.bin`、SHA-256は`e147e90d308653b8ed0223c8222e9d7f1fe3faef19644f903ef36f83fbdd4b6d`とする。ビルド記録は`.pio/usb-device-exit-build.log`へ保存した。
