# ADVリセット時の押下復元

実施日: 2026-10-23

## 問題と修正

前版には起動時Escを保持してメンテナンスを表示するアプリ処理があったが、ADVのキーボード状態の復元が不十分だった。使用中のM5Cardputer 1.1.1のReaderは、初期化時にFIFOを消去し、割込みコールバックが発生した場合だけ一覧を更新する。リセット前から保持されたキーは、押下イベントが残っていなかったり、新しい割込みエッジがなかったりすると一覧へ現れない可能性がある。

アプリ側にUI所有の`hardware/AdvKeyboardReader`を追加した。起動時にTCA8418を一時的にGPIOモードにし、1列ずつLOW出力・他列入力で7×8の物理状態を読む。行入力は200µsの安定待ち後に2回読み、ラッチ済み値と現在値を区別する。GPIOでの走査中に古いFIFOを上限10件で破棄し、キーパッドへ戻して物理押下をキー一覧へ反映する。通常時はFIFOをポーリングし、重複pressとreleaseを同じ物理キーの状態へ統合する。FIFO溢れでは物理状態を再取得する。I2C失敗では押下を捏造せず、モードの復元を試みて戻る。外部ライブラリ本体は変更していない。

レジスタのGPIO/キーパッド選択・入出力方向・プルアップ、GPIOデータ状態、デバウンスの仕様は[TI TCA8418データシート](https://www.ti.com/lit/ds/symlink/tca8418.pdf)に従う。UIはM5Cardputerの自動キーボード更新を無効にしてReaderを注入し、更新を明示的に1回ずつ実行する。新しいタスクやキューは追加しない。

## 検証

`tests/run_native.py`は成功した。実Readerと電気的マトリクス・FIFOのホストモデルで、物理Escだけが残る空FIFOのウォームリセット、続けて再リセットした場合、全56キーの座標、Esc＋Fn、重複press、release、新しいIRQのないイベント処理、古いラッチ値、無効イベント、FIFO溢れ、I2C失敗とモード復元を確認した。既存のUI・Boot・GPS・ログ・USB等の回帰試験も成功した。

Cardputer ADV向けビルドと実機書込みは成功した。SHA-256とMACを照合し、アプリ領域のみ更新した。通常起動ログで物理走査初期化、NVS設定復元、FAT32、GPS UART、データセット01、Boot Ready、GPS FIXと地名取得を確認した。取得範囲にパニック・Watchdogエラーはない。成果物とログは`.pio/adv-held-key/`へ保存した。

Escを保持してのリセットは、実機での物理キー操作待ちである。ホストの再現試験と実機の保持試験は区別し、確認できるまで実機保持試験を成功扱いにしない。
