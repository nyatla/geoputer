# 選択中データセット情報の統合

更新日: 2026-10-28。

## 所有と保持内容

StorageTaskはSelectedDatasetを1個保持する。選択中のディレクトリ・言語、GLC・保存索引・Wordbookのパス、地名の2行表示書式、検証済みの地図・辞書索引ヘッダー、状態・世代・格子解像度・チャンク数をまとめる。タイトル・説明・利用可能言語の一覧は保持せず、初期化のINI解析結果から必要な値だけを取り込む。

PlaceLookupはこの領域を参照して初期化・検索する。MapSourceも同じ領域を参照する。文字列本体はstd::stringのまま所有し、初期化時の動的確保は許容する。Factoryにはstd::crefで明示的にパスを貸し、Factory側へパスをコピーしない。通常の所有パスを受け取るFactoryコンストラクタとSDK互換APIも維持する。

地名検索のFactory・Readerは従来どおり初期化後も保持し、地図生成のFactory・Readerは要求内で構築・破棄する。地図生成用Factoryは引き続きスタック上に置く。共有するのは選択情報であり、地名用128×128画像と地図画像、処理中のファイル・借用バッファを同じインスタンスにまとめない。

## 初期化と通常動作

1. 初期化時にINIを読み、選択言語・書式・ファイルパスを確定する。
2. GLCと保存索引の対応・構造、Wordbookの対応・文字コードを従来と同じ経路で検証する。
3. 全て成功したらReadyとして公開する。途中失敗時はReaderを破棄し、準備済み情報を無効にして、既存のデータセットエラー処理へ返す。
4. 地図生成ではReadyと世代を確認し、保持済みmap_indexとパスから矩形を読む。INI解析・パス組立て・loadMapによる初期化検証を毎回繰り返さない。

地図のstat・open・索引範囲・ブロック復号など、実アクセス時の異常検出は維持する。INIを起動中に書き換えても通常の地図更新では取り込まず、再初期化を境に反映する。設定画面の一覧・詳細は未選択データセットの閲覧も行うため、従来どおりその対象のINIを読む。表示用DatasetViewは固定長構造体でApp・UIへ渡し、実行中の共有情報を書き換えない。

## 更新と参照の寿命

選択・言語の変更、SDの終了・再マウント、選択中データセットの索引メンテナンスでは、先に地名検索のReaderとFactoryを破棄し、その後に共有パス・ヘッダー・書式を無効化する。再利用する際はINIから初期化し直す。USBモードとの切替でも既存のアンマウント・再起動の境界を使う。

全利用はStorageタスク1本の中で行い、地図の読出し関数が戻ると、パスを借りていた局所Factoryも全て破棄される。UIやAppへ共有文字列のポインタを渡さない。SelectedDatasetはコピー・移動せず、PlaceLookupより後に破棄する。古い世代の地図要求はStaleとなり、以前のデータセットに対する画像を新しい選択へ混ぜない。

## 検証

- N03・estatの1/1、1/2、1/4で、自己所有バッファと借用バッファの区域コード・境界画像が一致した。
- 初期化後にdataset.iniを隠した状態でも地図生成でき、明示的にcloseして再検証すると欠落を検出した。INIと索引を戻して再初期化すると回復し、古い世代の要求は拒否した。
- 借用地図経路のホストC++ new要求サイズ累計は、直前の566 Bから0 Bになった。INI解析とパスコピーを含まなくなった結果であり、実機の全ヒープ使用0を意味しない。ESP32側のFatFsパス変換は一時std::stringを使い、例外処理も別に確保する可能性がある。
- 地名検索のキャッシュ、初期化失敗のラッチ、明示的な選択解除、書式変更、ファイル破損からの復旧と、借用終了時の返却を既存テストで確認した。N03ではSDK点検索と324点を比較し、N03・estatでは各7回の自己所有／借用検索の地名・コード・結果が一致した。
- ファイルReaderの自己所有／借用経路はstdio・FatFs、診断ON/OFFで確認し、通常経路の確保と例外時の返却が従来どおりであることを確認した。

通常版cardputer-advのビルド成功。静的RAMは259,384→259,672 B（288 B増）、Flashは1,239,269→1,238,481 B（788 B減）。SelectedDatasetの型サイズは416 B、既存PlaceLookupから移した領域を除いた差分が常駐領域の増加となる。Reader内の索引ヘッダーの値コピーは維持しており、共有したパスとは保持方法が異なる。この時点では初期化時の文字列確保と地図読出し時のFatFsパス変換が残っていた。後述の借用パス変換により、後者を除去した。実機書込み・実機速度計測は実施していない。


## 地図読出しの借用パス変換

地図生成で貸し出すUI back 6,060 Bのうち、先頭4,096 BはReaderの読出しバッファ、続く512 BはNativePathBufferとしてFatFsパス変換に使う。残り1,452 Bも含めて、読出し終了後には境界画像へ上書きする。MapBuildJob::pathBufferは読出し段階でだけアドレスと容量を返し、配置はstatic_assertで確認する。地名検索の結果領域へ同じ配置を適用しない。

変換は`/sd/`から始まる所有パスを読み、借用先へドライブ番号・コロン・残りのパス・終端NULを直接書く。0〜255のドライブ番号に対応し、UTF-8のバイト列を維持する。指定容量に収まらない、または不正なパスの場合は例外として既存の地図エラーへ返し、ヒープへの代替確保は行わない。statとopenの呼出しが終わると変換結果を上書きでき、ファイルを読む間にパス自体を保持する必要はない。

StorageTask::stepMapからMapSource、局所Factory、ReadFileへ同じ借用先を渡す。Factoryは変換先への参照だけを持ち、配列を追加確保しない。指定がない他用途のFactory・ReadFileは従来の所有パス変換を維持する。

### 正常系の確保の確認範囲

- 地図用の区域コード画像・UIの境界画像・FILは既存の固定領域を利用し、Reader・Factory・復号ワークはスタックまたは値メンバーで保持する。
- ファイル用のFactory経路では、パスのコピー・変換、ReaderとFILの生成、読出しバッファに正常系のC++確保要求を行わない。INI解析も地図更新では行わない。
- FatFs経路を通すホストテストで、借用パス付きFactoryのstat、固定FILのopen、索引／GLC相当の2回の読出しを含むC++ new要求0を確認した。ファイルシステムの代替実装自体が計測へ一時stringを混入させないよう、パスの解釈は非所有ポインタで行い、試験用の記録領域は計測前に予約する。
- 同試験で、変換先の容量ぴったり／1 B不足、ドライブ番号の桁数、UTF-8、不正プレフィックス、UI領域の前後・未使用末尾のガード、open後のパス上書き、stat／open／seek／read失敗時の借用返却を確認した。
- N03・estatの実データ3縮尺で、借用地図読出しのC++ new要求0と区域コード・境界画像の一致を確認した。
- 対象SDKのFatFs設定はCONFIG_FATFS_LFN_STACK／FF_USE_LFN=2であり、長いファイル名の作業域もヒープではなくスタックを使う。Arduino SDの通常読出しとSPI転送の実装には、マウント等の初期化時と異なり都度のmalloc/newを確認していない。

以上は初期化完了後の通常版・正常系の地図生成経路に関する確認である。初期化時の文字列・Factory等の確保、自己所有バッファを選ぶ比較用経路、例外処理は対象を分ける。ホストのC++ new計測はCのmallocを全て追跡するものではなく、実機の全アロケータを使ったトレースは未実施である。

借用パス変換を追加した通常版のビルドも成功した。静的RAMは259,672 Bのまま、Flashは1,238,481→1,239,445 B（964 B増）となる。NativePathBufferの型サイズは8 Bで、Factoryは64→72 Bとなる。地名検索が初期化時に保持するFactory3個も型サイズが各8 B増えるが、パス変換用の配列を常駐領域へ追加したわけではない。今回の確認では実機書込み・実機アロケータのトレースは行っていない。
