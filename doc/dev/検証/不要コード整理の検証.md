# 不要コード整理の検証

実施日: 2026-10-26。地名検索のUI作業域借用を実装・書込みした状態を比較元とし、確認済みの8項目を整理した。既存の未コミット変更は維持し、この作業ではコミットしていない。

## 整理内容

| 項目 | 変更と維持する契約 |
|---|---|
| 1. キーボード内部配列 | 読み出されない3つのprivateなキー位置vectorを削除。公開キー一覧・HID・文字列・修飾キーの一覧、固定最大数、2パスの判定は維持する。 |
| 2. 重複初期化 | FixedBoundaryImageはbind時に配列をクリアせず、地図生成側が索引用の使用終了後に全画像を初期化する。地名結果はUIでオブジェクトを構築し、searchIntoが検索開始時に初期化する。Storageの重複した全体代入と、searchラッパーの重複した値初期化を除いた。エラー時の要求照合情報は維持する。 |
| 3. 終了通知 | StorageCompletionの地名メンバーをPlaceCompletionへ変更。要求、状態、区域コード、DatasetInfoだけを通知し、地名と診断文は借用中のPlaceResultに保持する。データセット確認の通知も同じ型とする。 |
| 4. 未使用API | 呼出し元のないDiskIndexedMapReader::coverageを削除。Galuchatの既存APIや従来Reader経路は変更しない。 |
| 5. 固定番号の状態名 | DATASET 01 / DATASET 01 MISSINGをDATASET READY / DATASET MISSINGへ変更。選択中の番号にかかわらず使える状態名とした。 |
| 6. 診断 | ui-releasedをui-hiddenへ変更。メモリ区間はmap-prepare / map-read / boundary / publishとして直接書込みの実行順に合わせた。過去のtransferを含む測定記録は比較資料として保持する。 |
| 7. ライセンス専用テスト | 分離したUsbRenderer.cppを取り込み、製品と同じローカルM5Cardputer依存へ変更。専用ファームがリンクまで成功することを確認した。 |
| 8. 設計書 | Storage所有の未実装プール案とReadRegionRaster / CancelRequest / ReleaseResultの旧契約を除き、UI貸出し・Storage完了・確定または返却へ統一した。READMEのログ測位点に逆ジオコーディングしないという古い説明も修正した。 |

検索結果の表示用コピーをAppとUIの双方に保持すること、未完了の貸出しを画面遷移・消灯後も保持すること、結果返却失敗時の再試行は維持する。PlaceLookup::search、自己所有Reader、ホスト比較用BoundaryImageとGaluchatの従来経路は用途があるため残した。

## サイズ比較

ESP32-S3の通常ビルドおよび同じXtensaコンパイラによるsizeof確認を使用した。

| 対象 | 変更前 | 変更後 |
|---|---:|---:|
| 常駐RAM（PlatformIO） | 95,040 B | 95,008 B |
| Flash使用量（PlatformIO） | 1,229,761 B | 1,229,221 B |
| 通知用の地名メンバー | PlaceResult 344 B | PlaceCompletion 136 B |
| StorageCompletion | 800 B | 800 B |
| AppNotification | 816 B | 816 B |
| App通知キュー8件のデータ領域 | 6,528 B | 6,528 B |

LogReadReplyが504 Bでunionの最大メンバーのため、地名メンバーを208 B縮めても、通知・キューの大きさと固定長コピー量は変わらない。地名本体のPlaceResultはUIの借用領域に必要なため344 Bのままとする。

キーボードから除いた配列の容量は、既定の最大56キーで(56 + 56 + 8) × sizeof(Point2D_t) = 960 B。これは起動時に確保して保持していたヒープの要求容量であり、allocatorの管理領域を含まない。M5Cardputerグローバルオブジェクトは132 Bから96 Bへ縮小し、配置・整列を含めたファーム全体の常駐RAMは32 B減った。変更後の実機最小空きヒープや最大連続空き領域の比較測定は行っていない。
