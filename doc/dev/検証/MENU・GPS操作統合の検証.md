# MENU・GPS操作統合の検証

> 本文の休止・復帰試験は撤回前ファームウェアの記録である。2026-10-25に休止処理を撤回し、記録停止後もGPS連続受信とした。現行表示の検証結果は末尾に記載する。

確認日: 2026-10-25

## 対象

EscのMENU、数字1/2/3/4/0のメイン・地図・GPS・ログ・設定への直接移動、Sの消灯、GとGPS画面のEnterによる共通操作を検証した。通常起動はGPS受信中・記録停止とし、一時停止と停止を区別する。仕様は[画面・操作機能設計](../画面・操作/02_画面・操作機能設計.md)と[GPS画面](../画面・操作/gps-logger/README.md)を参照する。

## ホストで確認した動作

- `python3 tests/run_native.py`：全既存試験を通過。MENUと数字の行き先、子階層の移動抑止、GPS画面のDel、消灯時の復帰専用キー、共通ダイアログ、SD利用不能時の無効項目、状態更新による旧操作の無効化を含む。
- `python3 tests/run_gps_control.py`：実GpsTaskの待機送信・チェックサム・周期再要求・自動復帰期限待ち・送信失敗・戻り値キュー満杯後の再送・停止をまたぐrevisionとsample_seqを確認。
- `python3 tests/run_logger_app.py`：実ApplicationとUiModel・GpsTask、LogWriterを接続し、開始→新しいFixの記録→一時停止→同じセッションの再開→終了要求受付→GPS停止→新規開始を確認。保存・ファイル閉鎖の非同期完了、ファイル名、開始失敗、古いGPS通知の拒否、元画面への復帰も確認。

実機のUART・RTOS待ちをホストアダプターへ置き換えた試験であり、実機の消費電流・休止を証明するものではない。測位レコードと保存設定のファイル形式は変更していない。

## 描画

`python3 tools/render_navigation.py`で日本語・英語各13シーンを検証した。MENU、GPS詳細、記録中・一時停止中・停止中の問い合わせ、SDなし、待機要求・未確認、未測位、長いファイル名、保存エラーを含む。240×135の実寸、右余白、上下罫線と4bit/RGB565の画素一致を確認した。掲載用GPS画像は既存のファイルを差し替え、MENUの画像を追加した。

`tools/render_live_place_layout.py`と`tools/render_map_view.py`でも共通フッターと地図番号2を更新し、従来の画素・数値境界検証を通過した。日本語の操作は東雲16×16、英語はASCII 8×16、詳細値・タイトル・フッターはASCII 8×8を維持する。

## 実機の操作確認

同じファームウェアで、端末の実キー操作と時刻付きシリアルログを照合した。MENU・GPS画面の表示は利用者の目視でも確認した。

| 項目 | 結果 |
|---|---|
| EscのMENU・3のGPS画面・記録開始 | 利用者が表示と記録開始を確認 |
| 一時停止 | PAUSED、accepted=78。flush後にsaved=78となり、GPSの有効FixとUART受信を継続 |
| 同じセッションの再開 | accepted=78のままSTARTINGへ戻り、その後92件まで保存。欠落0件 |
| 停止・非同期保存終了 | saved=92、buffered=0、closing=0、error=0。ログ状態STOPPEDへ移行 |
| GPS待機 | PCAS12の送信を確認したが、利用者の画面はSLEEP UNCONFIRMED。UART受信も残るため、連続した休止は未確認 |
| 停止からの開始受付・UART受信再開 | 新規セッションの開始とreception resumedを確認。最初の試行は数秒で再停止されたため、Fix・実保存までの復帰は別途確認する |

停止前の約35秒のUART受信量は約826.9バイト/秒、最初の停止直後を除く約35秒は約346.7バイト/秒だった。これは生の受信バイト数であり、有効NMEAの件数や消費電流ではない。停止中はParserへの投入を止めるため、診断のNMEA件数が固定でもモジュールの無出力を証明しない。

現在の2秒待機・自動復帰を繰り返す制御と、コマンド後500ms〜復帰期限300ms前の受信による未確認判定では、復帰に伴う出力と待機に入らない状態を現ログだけでは区別できない。UART受信の減少だけから省電力効果や連続休止を断定しない。休止制御と判定条件は追加検討の対象とする。消費電流は未計測。

操作ログは`.pio/navigation-checks/controls-session.log`、集計は`controls-results.json`へ保持する。停止後のFix・実保存の復帰とSによる消灯・元画面への復帰は、実キー確認の依頼中とする。

## 休止後のFix再取得に関する追加確認

利用者は最初のFix時と同じ場所・向きで試行した。JST 08:59:44.439の開始操作後、UART受信は約1.827秒で再開したが、最初のFixは09:02:09.263（開始から144.824秒後）だった。その後は再びNO FIXとなった。開始後から利用者によるリセットまで、待機コマンドの追加送信は0回だった。

利用者が端末をリセットした後は、09:02:51.708のUART初期化から約2.434秒でFixを取得し、その後も有効Fixが継続した。リセット操作の種類によるGNSSへの電源・信号変化は未確認であり、この差だけでGNSS内部・UART・受信状態処理のどれが原因かは断定しない。

2秒の時間指定待機を繰り返す方式は、安定した休止・復帰として合格にしない。次の切り分けでは休止後と通常起動後の生NMEA（RMC/GGAの有効性、衛星数、HDOP、時刻）とUART初期化経路を比較する。現在のファームウェアに追加の変更は行っていない。数値の集計は`.pio/navigation-checks/fix-recovery-results.json`へ保持する。

## GPS操作の取消項目撤去と初期選択（2026-10-25）

GPS画面のEnterと各画面のGから開く操作メニューは、取消項目を置かずEsc / Delで閉じる。停止中は開始のみ、開始待ち・記録中は停止 / 一時停止、一時停止中は停止 / 再開とする。初期選択は開始 / 一時停止 / 再開とし、移動せずEnterで実行できる。通常の削除・初期化等の確認は取消を初期選択とする仕様を維持する。

`tests/run_native.py`と`tests/run_logger_app.py`で、トップ・子画面からの操作、Esc / Delの取消時に実行要求を作らないこと、Enterによる初期選択の実行、SDなしでの開始禁止、保存処理中の一時的な操作無効化でも停止へ選択が移らないこと、状態変化時の旧操作取消を確認した。共通ダイアログ・USB等を含む回帰試験も成功した。

`tools/render_navigation.py`は日本語・英語各13シーンで成功した。GPS操作の選択数と初期選択、1択の中央配置、表示範囲、上下罫線、4bit / RGB565の一致を確認し、掲載画像を更新した。本変更の実機書込みは未実施とする。

PlatformIOの最終ビルドは成功した。SHA-256は`6d4035874056025cc6530d2b2feafb8746fd6d35803b2f56c7dcdd0678260c21`。生成物と検証ログは`.pio/gps-action-checks/`に保存した。
