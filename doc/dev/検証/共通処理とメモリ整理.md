# 共通処理とメモリ整理

2026-10-24。アプリケーション側の重複処理と常駐メモリを整理した。直前のMONO区間描画のみを採用した構成と比較する。

## 実装

- `utils/Utf8.h`の検証をメタデータと地名処理で共用する。NUL、過長符号化、サロゲート、範囲外コードポイント、途切れたシーケンスの拒否を維持する。
- `task/storage/StoragePath.h`でSDパスの検証とFatFsドライブパスへの変換を行い、Reader・索引・ログ・エクスポートで共用する。ホストでは元のパスを使用する。Readerごとのバッファ補充・seek・短距離skipの方針は変えない。
- WordbookのTT00・TM00でページごとに確保していた対象番号vectorを検索1回の中で再利用する。対象数が分かるトークン集合・断片・出力のvectorは必要件数を予約する。コード順の復元、ソート、重複排除、元データとの照合を維持する。
- 同期戻り値のUI・GPS・Storage・地図転送を共用体へ変更する。送信元と要求種別で有効なメンバーを決め、`prepareSyncReturn`でそのオブジェクトの寿命を開始する。地図行の応答にはStorageスナップショットを付けない。キューの本数・件数、値コピー、遅延応答の必須回収、要求の識別は変えない。
- USBエクスポート変換器をStorageの所有する必要時確保の領域とする。変換開始時に確保し、ファイル閉鎖成功後に解放する。確保失敗は`NOT ENOUGH MEMORY`として再公開へ進む。閉鎖失敗では同じ変換器を保持し、公開操作で再試行する。

地図生成の大きな区域コード領域の常駐化、UI画像の単一バッファ化、タスクスタック・VFS枠の縮小、既存128×128キャッシュとの統合は実施していない。Core・SDKのファイルも変更していない。

## ESP32のサイズ

PlatformIO `cardputer-adv`のリンク結果およびXtensa GDBの型サイズから確認した。

| 対象 | 変更前 | 変更後 |
|---|---:|---:|
| 静的RAM | 81,880 B | 68,904 B |
| Flash | 1,206,561 B | 1,204,089 B |
| SyncReturn | 1,024 B | 624 B |
| 封筒付きReturnMessage | 1,040 B | 640 B |
| StorageTask | 28,736 B | 16,960 B |

静的RAMは12,976 B（約12.7 KiB）、Flashは2,472 B減った。ReturnMessageの縮小は戻り値キュー1件と各サブタスクの保留応答3件で計1,600 Bに相当する。残りの主な差は11,384 Bの変換器の必要時確保とクラスの配置による。

USB変換中は変換器の11,384 Bと関連する文字列・アロケータ管理領域をヒープへ確保するため、変換中の総メモリ削減量は静的RAMの差と一致しない。USB変換前およびGPSモードではこの領域を保持しない。新ファームの空きヒープ、最大連続領域、スタック使用量は実機未計測である。

## 検証

- `python3 tests/run_native.py`成功。UBSan・標準ライブラリ境界検査を含む。同期タイムアウト後の同じ結果の回収、通知との分離、各応答の初期化とキューコピー、地図転送の最終バイトまでの保存、UTF-8、ログ、3形式エクスポート、USB所有権・再公開・同期失敗の再試行を確認した。
- `python3 tests/run_dataset_index.py <N03 8192/10000のGLC> <UTF-8 Wordbook>`成功。実データ25点の地名を従来Readerと比較し、索引の独立検証、部分再生成、破損・入出力失敗を確認した。合成データのTT00・TM00複数ページも確認した。
- `python3 tests/run_observed_reader.py`成功。先読み、skip、seek、範囲端、EOF・エラーとビットストリームの一致を確認した。
- `python3 tests/run_map_files.py <estat 8192/10000のGLC> <UTF-8 Wordbook>`成功。地名は鷺沼二丁目、コード領域79,680 B、出力画像6,060 B。既存128×128キャッシュの独立性を確認した。
- `python3 tests/run_usb_export_lifecycle.py`成功。実際の`UsbExport.cpp`をホスト用ハードウェアアダプターで実行し、変換器の必要時確保、確保失敗時のエラー・再公開、変換結果の保持、クローズ失敗時の領域保持・公開拒否、閉鎖後の解放と再公開失敗からの再試行を確認した。
- ESP32向けPlatformIOビルド成功。今回追加した実装から警告・エラーは出ていない。

USB変換器の障害注入はホストのメモリ確保と`fclose`に対して行った。FatFsの実機障害試験、実機書込み、新ファームの速度計測は実施していない。ホスト試験の地図生成時間はESP32の性能値として扱わない。

ビルド成果物と検証ログは`.pio/memory-refactor/`へ保存する。履歴上のメモリレビューの数値は各レビュー時点の構成に対するものであり、本書を今回の変更の比較値とする。

本変更を含む通常版ファームの書込み、LivePlace・GPS測位・地名取得を確認した。USBエクスポートの実機試験はこの確認には含めない。
