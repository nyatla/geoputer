# ログビューア検証

検証日: 2026年10月16日

その後の操作項目の言語別フォント統一は[UIフォント・設定配置検証](UIフォント・設定配置検証.md)を参照する。

## 1. 実装範囲

MENUにLOGSを追加し、ファイル名一覧（6件単位）、詳細（端点のJST日時・スロット数・サイズ）、測位点（1画面1点）を実装した。Storageは同期で要求を受け付け、実読出し結果を固定長通知へ値コピーする。Appは最大10件・320バイトを保持し、UIへ現在の1点を渡す。結果バッファプール・解放通知は使用しない。

記録中のファイルは保存成功済みの範囲だけをLogWriterと同じFILから読む。詳細取得時の上限を固定し、再読込まで新しい点を含めない。保存用リングへの直接受付は継続し、SD読書きはStorageTaskで直列化する。元ログの修復・削除・切り詰め、距離・最高速度の全件集計、地図・地名の再検索は対象外とする。

## 2. ホスト試験

`python3 tests/run_native.py`が成功した。-Wall / -Wextra / -Werror、UndefinedBehaviorSanitizer、pthreadを使用する。[読出し試験](../../../tests/log_reader_tests.cpp)で次を確認した。

- 18ファイルを6件ずつ前後へ移動し、ファイル名の順序、日時不明名の配置、対象外の名前・ディレクトリの除外を確認した。
- ディレクトリ走査を10項目で区切り、取消と空ディレクトリを処理できた。
- 25件＋末尾5バイトの概要、10件未満の末尾、0件・EOF、範囲外、ファイル縮小・セッション変更、要求件数上限、パストラバーサル拒否を確認した。
- 物理スロット12の破損でバッチを失敗とし、単一読出しで前後の正常点を保持した。CRCが一致しても無効項目の非正規値を拒否し、未対応形式を識別した。
- 記録中ファイルの25件を読める一方、新しいRAMの5件は含めなかった。30件へ保存した後も既存の上限25件を維持し、読出し後の追記・クローズも成功した。
- UiModelのページ移動、読込中の戻る、左右キー無効、キャッシュ境界への移動、末尾での非周回を確認した。

既存のキュー・同期要求、GPS、共有リングと保存復旧、設定、言語、フォント、地名キャッシュ、時計、ライセンス、アクセス表示の試験も成功した。ログは`.pio`配下の一時生成物とは別に、`/tmp/geoputer-viewer-native.log`へ保存した。

## 5. 実SD試験と書込み状況

[専用試験](../../../tests/hardware/storage_log/README.md)へ、記録中の90件・未保存14件の分離、末尾6件・EOF、停止後104件の概要、3ファイルの一覧、および既存ログの読取専用・全件CRC確認を追加した。

初回の専用試験で、ローカルに置いたFatFsのFILがスタックを圧迫し、readTargetからopenReadを呼ぶ経路で例外が発生した。FILをLogReaderの所有領域へ移し、スタック上へ大きな構造体を確保しない形に修正した。修正後にホスト試験と通常・専用ファームのビルドは成功した。

通常画面が起動しないとの申告後、COM6から同じ専用試験のDouble exceptionと再起動の反復を確認した。ログは`.pio/viewer-recovery-before.log`へ保存した。正常アプリが動作している状態ではなく、初回の専用試験ファームが残っていることを確認した。通常ファームへの復旧を優先し、修正版の専用試験はその後の確認とする。

G0による書込み待機への手動復帰後、MAC `70:af:09:df:46:d0`を照合し、4節のSHA-256に一致する修正版の通常ファームをアプリ領域0x10000へ書き戻した。書込み後のハッシュ照合も成功した。30秒の起動ログで240×135、4タスク・5キュー、NVS設定LOADED、SD FAT32、GPS UART、Galuchat OPEN OK、ReadyからLivePlaceへの遷移を確認した。有効Fixを29サンプル受信し、JST補正・地名取得・矩形キャッシュとWordBookのMISS→HITを確認した。観測区間にpanic・assert・再起動はなかった。Storage残スタックは6,964バイト、空きヒープは130,344バイト、最小ヒープは122,500バイトを報告した。ログは`.pio/viewer-normal-boot.log`へ保存した。修正版の専用実SD再試験と通常UIの実キー操作は未確認であり、起動確認の成功とは区別する。初回試験は固有名の試験用ディレクトリだけへ書き込み、既存の`/logs/`・NVS・データセットは変更していない。異常終了で残った試験ディレクトリの自動削除は行っていない。

## 6. 実キー操作の確認手順

1. 消灯中なら任意のキーで復帰する。Live Placeで`2`、下（`.`）を2回、EnterでLOGSへ入る。
2. ファイルをEnterで開き、件数・サイズ・FIRST / LASTを確認する。「測位点を見る」をEnterで開く。
3. 下（`.`）で次、上（`;`）で前へ移動し、10件のキャッシュ境界でも表示を確認する。Esc / Delで詳細、一覧、MENUへ戻る。
4. 記録中も同じ操作を行い、GPS Loggerの保存件数が増えることを確認する。閲覧件数は詳細の再読込を行うまで固定される。

通常UI全体の実キー操作、通常運転での最大受付遅延と残スタック、実機での媒体障害復旧は未確認である。専用試験やホスト描画の成功と区別する。
