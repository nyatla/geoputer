# ログ再生中の地名ちらつき抑制

実施日: 2026-10-29。現行仕様は[ログ閲覧](../画面・操作/log-detail/README.md)を参照する。

## 原因と修正

Application::showCachedPointは次の測位点が別のデータセットセルに入るたびにclearPlacePresentationを呼び、地名2行を消していた。その後、地図や地名の取得が終わるまでの描画で空白が表示される。UIのbeginPlacePresentationには既存の地名を保持する仕組みがあり、点送り側の先行消去がその効果をなくしていた。

有効なデータセットで次の地名を待つ場合は、文字列を消さず状態だけWaitingへ変更する。既存の地名2行・その座標・区域コードをひと組として保持し、新しい結果の確定時に既存のCommitPlaceSearchで差し替える。古い地名の座標を新しい点に付け替えないため、MapViewの座標一致・状態チェックも維持される。

点を通り過ぎて遅れて届いた検索結果は引き続き破棄し、最後に確定した地名を表示し続ける。新ファイル・画面世代変更・データセット変更／未選択、破損レコード等の無効化と、確定した区域なし／エラーの扱いは維持する。再生の待機条件や表示時間は変更しない。

新しいバックバッファ、文字列コピー用領域、キャッシュ、ヒープ確保、永続状態は追加しない。既存のUiData.place等をそのまま使う。

## 検証

- run_logger_app.py成功。別セルの点読出し後、検索待ち、検索開始、古い要求の破棄まで既存地名を保持し、UIスナップショットに空白を渡さないことを確認した。現在の要求が完了すると地名2行・座標・区域コードが更新され、UIにも同じ確定値が反映されることを確認した。記録、ログ閲覧、再生速度・方向、TAB、画面資源、エラー処理の既存試験も成功した。
- 本番UiRendererを使う8ケースの画素試験が成功。文字／地図・日本語／英語・4/16ビット色で、Ready→Waiting→Searchingの地名領域が画素単位で一致し、完了結果では表示が変わることを確認した。比較用の画素配列はホスト試験内だけのもので、ファームには含まれない。
- run_status_icons.pyの既存375描画ケースも成功した。
- cardputer-advビルド成功、変更範囲のgit diff --checkに問題なし。静的RAMは253,972 Bで不変。Flashは直前の1,237,985 Bから1,238,009 Bへ24 B増加した。実行時のヒープ最小値や実処理時間は今回再計測していない。
