# 選択言語と地名書式の固定長化

検証日: 2026-10-28

## 保持方式

App所有のSelectedDatasetでは、選択言語を終端込み32バイト、地名2行の書式をそれぞれ終端込み128バイトへ保持する。書式の有効長はUTF-8で最大127バイトとし、文字数ではなくバイト数で数える。INI解析にも同じPlaceDisplayFormatを使用し、選択情報へ値コピーする。App／Storageの所有・参照関係と寿命は変更しない。

未選択言語の書式も含め、上限超過はメタデータエラーとし、切り詰めない。省略時の従来配置、明示的な空行、%0〜%9と%%の解釈、展開後の画面幅による省略は維持する。PlaceLookup::configureとDatasetIndex::loadMapは言語をstring_viewで受け、固定配列からstd::stringへ変換しない。SelectedDataset内の動的文字列はなくなるが、INI解析結果のタイトル・説明・言語一覧などの一時的な動的確保は残る。INIバージョン、NVS、索引形式、core／SDKは変更しない。

## ESP32向けビルド比較

直前の通常版ELFと変更後のcardputer-advビルドを比較した。

| 項目 | 変更前 | 変更後 | 差 |
|---|---:|---:|---:|
| ファーム静的RAM | 253,532 B | 253,740 B | +208 B |
| Flash | 1,242,717 B | 1,242,305 B | −412 B |
| Application | 217,352 B | 217,560 B | +208 B |
| StorageTask | 174,224 B | 174,224 B | 0 B |
| SelectedDataset | 584 B | 792 B | +208 B |
| PlaceDisplayFormat | 52 B | 257 B | +205 B |

各構造体は内包関係にあるため行を加算しない。固定容量の導入で静的RAMは増える一方、選択情報の文字列保持・コピー・解除のC++ヒープ確保は不要になる。

INI解析結果を局所保持する関数の個別スタックフレームは、readDatasetMetadataが752→944 B、PlaceLookup::openが1,040→1,248 B、maintainDatasetIndexが640→832 B、applyDatasetSelectionが656→864 B、bookSourcesが704→912 Bとなった。DatasetIndex::buildは1,408 B、completeDatasetJobは1,072 Bで変化しない。これらは個別フレームの静的確認であり、呼出し全体のピークや実機ウォーターマークではない。タスクスタック設定は変更していない。

## 検証結果

- 127バイトの書式は2行とも終端付きで保持でき、128バイトの書式は選択／未選択の両言語で拒否する。
- 日本語を含むUTF-8の127／128バイト境界、空行、無効な書式、重複キー、容量超過時に既存値を上書きしないことを確認した。
- 選択言語の31／32バイト境界と、書式の保持・解除を含む選択更新でC++ newが0回であることを確認した。
- N03とestatの実データで従来経路と借用経路の地名結果が一致し、準備済みの通常借用検索もC++ newが0回だった。
- stdio／FatFs両経路で、深さ32・TT／TMページ境界の地名書式処理が成功した。
- 通常ホスト試験、Appの記録・画面遷移・借用管理試験、ESP32向けビルドが成功した。

実行ランナー: run_native.py、run_logger_app.py、run_borrowed_place_files.py、run_wordbook_phases.py。実機への書込み、処理時間比較、実機ヒープ／スタック計測は実施していない。
