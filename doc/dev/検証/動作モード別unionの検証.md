# 動作モード別unionの検証

2026-10-30。仕様は[動作モード別メモリ構成設計](../18_動作モード別メモリ構成設計.md)を参照する。

## 変更内容

GPSとUSBのApp資源・Storage資源を、一つのApplicationModeMemoryへ統合した。AppとStorageの個別unionを二つ並べる構成ではなく、GPS一式とUSB一式の合計サイズを比較する最上位unionである。共通UI・キュー・SPI・設定・返送領域は外側に置いた。

静的Application構築時はモード領域を空にし、NVSのモード選択後に使うメンバーだけを直接構築する。配置のための追加ヒープ確保、大きな一時スタック配列、通信キュー、画像バッファは追加していない。実行中の別モードへの切替は拒否し、既存の保存・再起動を使う。StorageはAppが予約する同じunionを参照し、自身のstorageサブオブジェクトだけを操作する。

USB共通処理からGPS専用資源へ触れないよう、画面遷移・通知・ファイル一覧・再起動準備を整理した。USB一覧ReaderにはGPSのLogWriterを渡さない。既存のUSB LogExporterの遅延確保は維持した。

## 試験

| 試験 | 確認結果 |
| --- | --- |
| tests/run_mode_resources.py | 空の起動状態、一度だけの構築、同一アドレス、別モードへの切替拒否、有効メンバーだけの破棄。実ApplicationとStorageが同じ最上位unionを参照し、選択情報・地図・Readerの借用先が安定すること |
| tests/run_logger_app.py | 既存のGPS記録・一時停止・再開・非同期終了、地図と地名の借用、区域アラート。実USB Appで画面入口・一覧要求・非同期完了・GPS/GIS通知の無視・GPS専用UI要求の拒否・再起動準備 |
| tests/run_map_scale.py | 地図倍率変更、古い完了の拒否、書込み中の取消、Storage終了後のUI借用返却、区域変更時の再描画 |
| tests/run_usb_export_lifecycle.py | 既存の変換器の遅延確保、確保失敗、正常変換、close失敗時の保持、USB再公開の再試行 |
| tests/run_native.py | キュー・UI・設定・GPS・地名・ログ・USB・INI・アラート・音声の通常回帰試験。新しいモード資源試験も標準ランナーへ追加 |

ホスト試験は各既存ランナーのUBSan／ASan設定に従った。実行環境のLeakSanitizer制約があるため、ASAN_OPTIONS=detect_leaks=0を指定した。リーク検出の成功を示す結果ではない。

## 実機向けの固定サイズ

以下は64 bitホストのsizeofではなく、最終ESP32-S3 ELFのDWARF型情報から取得した32 bitターゲットの値である。

| 型・領域 | バイト数 |
| --- | ---: |
| AppGpsResources | 2,776 |
| StorageGpsResources | 172,872 |
| GPS一式 | 175,648 |
| AppUsbResources | 624 |
| StorageUsbResources | 2,408 |
| USB一式 | 3,032 |
| モードunion（タグとアラインメントを含む） | 175,656 |
| Application全体 | 218,392 |

GPS一式＋USB一式の合計を予約せず、大きいGPS一式に管理分を加えた領域を使う。USB起動中の余白を自動的にシステムヒープへ返す方式ではない。今後Wi-Fi用の固定資源を追加する場合は、この予約内へ排他配置できるかをサイズで判断する。
