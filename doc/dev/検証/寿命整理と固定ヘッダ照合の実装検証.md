# 寿命整理と固定ヘッダ照合の実装検証

実施日: 2026-10-26

## 適用内容

以下の3件の寿命整理と、追加指定された固定ヘッダ照合を実装した。消灯時のUI地図画像解放は取り消し、UiModel.cppとMapFrameReceiver.hが変更前と同一であることを照合した。front/backの保持・復帰時の表示は維持する。

1. ObservedFileReaderのバッファをFILより前のメンバーへ配置した。正常時だけでなく、f_open失敗で構築が中断した場合もFIL→バッファの逆順に解放する。借用領域の返却もFILの破棄後になる。
2. LogWriterは保存・close成功後にpath_の容量を解放する。保存失敗・close失敗・未保存データが残る間は再試行用パスを維持する。最後のファイル名は固定のLogSnapshot::nameへ残し、path()は稼働中／再試行中のパスを返す。ヒープ解放はAppとの短いクリティカルセクションの外で行う。
3. ログ画面群を離れたAppは、未完了要求の終端結果を回収してからReleaseLogBrowseを一方向通知する。キュー満杯なら通知を再送する。Storageは終了世代を保持し、未完了読出し・同期結果・完了通知の返送が終わってからcloseとパス解放を実行する。close失敗時は保持して再試行し、古い世代の終了要求では新しいReaderや地図を解放しない。USBのファイル選択から変換へ移る場合も、終了済みReaderのパスを解放する。
4. DatasetIndex.cppの4箇所の16バイト固定ヘッダ照合を、アプリ側FixedHeader.hのchar[16]とstring_viewへ置き換えた。必ず16バイトを読み、最初のNULまでを比較し、後続のパディングを無視する従来の意味を維持する。短い入力の例外と停止位置も維持する。4文字のtagとSDK内部の照合は変更していない。

ReleaseLogBrowseは取消と同じ投機送信であり、同期応答を待つ操作ではない。これにより索引生成等の長い処理の背後で、終了通知のためにAppが待機し続けることを避ける。キュー数・容量、既存メッセージの値、ファイル形式、NVS設定形式は変更しない。Galuchat本体・Core・SDKにも変更を加えていない。

## 検証

- run_storage_work.py：未完了読出しの解放拒否、古い画面世代での解放拒否、close失敗時のパス保持と再試行成功時の容量解放、地図に遅れて届くログ終了の無害化。Writerのclose失敗・再試行ではファイルと最後の名前を保持し、完了後はpath容量を解放する。既存100回の確保なし切替も成功。
- run_borrowed_reader.py：stdio／FatFs模擬バックエンドと診断有効／無効で、読出し・借用・例外時の返却を回帰確認。FatFs模擬のf_open失敗では実際のC++解放順を追跡し、FILが自己所有4KiBバッファより先に解放されることを確認した。
- run_fixed_header.py：SDKの従来関数と比較し、WGSMapSet/3、GisWordBook/0、空文字、16文字のNULなし、誤った先頭、NUL後の非ゼロパディング、0〜15バイトの短い入力を確認。判定・消費位置が一致し、正常照合時のC++確保は0回だった。
- run_native.py：ログの保存・停止後の閲覧・削除・CRCと記録順、UI・GPS・設定・USB等の既存回帰試験。停止済みファイルの検査にはLogSnapshot::nameを用い、空になったpath()をファイル名として扱わない。
- run_logger_app.py：実際のAppとキューで、画面離脱後の終端結果、終了通知のキュー満杯時の再送、戻り値待機なしの送信、画面遷移・地図・リプレイ等を確認。
- run_usb_export_lifecycle.py：ファイル選択・変換・再公開と、確保失敗・close失敗時の保持を確認。
- run_dataset_index.py：実データと人工データによる形式・CRC・再生成・照合・失敗時復旧と、従来Readerとの地名一致を確認。
- PlatformIOの通常ビルドと対象差分の空白検査。

新しい固定ヘッダ試験と借用Reader試験にはASan／UBSanを用いた。LeakSanitizerは実行環境の制約で無効。模擬FatFsと実機確認の範囲は区別する。
