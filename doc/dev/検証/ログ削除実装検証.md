# ログ削除実装検証

更新日: 2026-10-17

## 1. 実装範囲

Live Placeの1/2/3でGPS記録・設定・ログ一覧へ直接移動する版へ、文字キーDによるログ削除を追加した。ログ一覧の案内は`[ENTER] OPEN    [D] DELETE`とし、Esc / Delの戻る操作は維持して画面案内から外した。

確認画面は対象ファイル名を全文表示し、取消を初期選択にする。上下で削除を選んでEnterを押した場合だけ、Appが対象行・一覧の版・確認済みフラグを検証し、DeleteLogをStorageへ要求する。実際の削除はStorageが非同期に行う。記録・一時停止・保存待ち・終了処理でLogWriterが保持する対象は、実行直前にも保護する。

成功後は旧ページ先頭のファイル名を含む側から再取得し、選択行を可能な範囲で維持する。空の末尾ページは直前のページへ戻る。失敗時は一覧と選択行を残し、理由を赤で表示する。削除受付後は完了まで重複操作・画面移動・自動消灯を抑止する。

操作の正本は[ログ一覧画面](../画面・操作/logs/README.md#4-削除)、通信の正本は[タスク構成設計](../06_タスク構成設計.md)とする。

## 3. ファームウェア

PlatformIOのcardputer-advビルドが成功した。静的RAMは53,376 B、Flashは1,072,713 B。既存キューの個数・容量とメッセージサイズは変わらず、UI要求1,544 B、App通知696 B、戻り値344 Bを維持する。

リンク済みELFでcallUi 32 B、setScreen / publishUiContent 1,936 B、readUiSnapshot 1,920 B、readUiContent 128 Bのスタック確保量を確認した。[メニュー遷移時のスタック削減](メニュー遷移リセット修正検証.md)とUIループの相対10ms待機を維持している。

バイナリは`.pio/log-delete-firmware.bin`、試験・描画・ビルドのログは`.pio/log-delete-*.log`に保持する。

## 4. 実機書込みと操作

COM6のCardputer ADV（MAC `70:af:09:df:46:d0`）へアプリ領域0x10000から書き込み、esptoolの照合成功を確認した。書込み時にNVS・SDの内容を変更していない。

通常起動、SDのFAT32マウント、選択済み162チャンクのデータセット、GPS FIX、地名検索を確認した。ユーザー操作で数字3からログ一覧へ入り、一覧取得に成功した。ユーザーから確認・取消の成功回答を受け取り、シリアルログ上でもDeleteの成功通知3回（kind=3、error=0）と、それぞれに続く一覧再取得を確認した。操作後はEsc / DelでLive Placeへ戻り、地名キャッシュの参照を継続している。実機の保持中ログの保護と削除失敗の誘発は行っておらず、それらはホスト試験の結果と区別する。

起動から90秒の連続監視で、スタック保護例外・監視タイマー停止・意図しない再起動は記録されなかった。操作中のApp最小空きスタックは2,556 B、Storage最小空きスタックは5,664 Bだった。書込みログは`.pio/log-delete-flash.log`、起動・操作ログは`.pio/log-delete-boot-operations.log`に保持する。
