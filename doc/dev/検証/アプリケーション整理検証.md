# アプリケーションの冗長処理・診断コード整理の検証

確認日: 2026-10-25。比較元は`bf11379`とし、タスク構成・同期要求と通知の契約、保存設定・測位記録ファイル形式、Galuchat本体のAPIを維持して整理した。

## 変更内容

| 対象 | 結果 |
|---|---|
| 廃止済み操作 | F1/Pの旧キー値、個別Pause/Stopダイアログと描画・確定処理を削除した。入力試験の未割当キーを実際のOtherへ置き換えた |
| 空の処理・未使用引数 | 空のLIVE入力関数、描画の未使用引数、検索スケジュールの時刻引数を除いた。送信メッセージの時刻は維持した |
| 旧描画シナリオ | GPS描画をnavigationツールへ一本化し、log-browserツールの実行されない旧GPS/P操作ケースを除いた。旧一時停止画像4枚と説明も整理した |
| 詳細診断 | ビルド定義REVERSEGEOPUTER_DIAGNOSTICSの初期値を0とし、通常版では詳細なGIS・GPSログ、I/O統計、区間計時、地図のヒープ診断を停止した |
| 維持する通知と時刻 | SD/RGアクセス通知、進捗・タイムアウト・時計、起動結果・状態変化・エラー出力は維持した |
| キー操作可否 | UiModel::keyGuideを入力の方向キー受付とフッター描画の共通の判定とした。選択行数・ライセンスの移動先もUiModelへ集約した |
| 確認の有効性 | updateDialogStateを内容更新時と入力直前の両方から呼ぶ。App・Storageの受付時検証は維持した |
| GPS表示 | GpsPresentationで速度・方位・座標・高度・品質を整形する。LIVEの単位込みの桁制限と、GPS画面のFix待ち中の受信済み品質表示を維持した |
| 画面対応表 | MenuScreensから物理数字キー、遷移先、MENUラベル、フッターの数字を取得する |
| データセット読込み | dataset.iniを必須とし、拡張子探索とその専用の複数ファイル異常を除いた。未設定インスタンスは未選択としてI/Oを行わない。既存の実ファイル試験をINI経路へ移した |
| 計測ツール | 隔離コピー・計測コード挿入・診断設定・背景待ち・ローカル補助ツールの準備を共通化した。再準備時は古い比較用.cppを残さず、過去のログは保持する |
| 比較資料 | baselineと旧縮小比較は測定を再現する資料として保持し、用途をtests/performance/README.mdへ記述した。比較用ライブラリへの変更は生成したコピー内だけで行う |

言語候補が1個だけの場合は、表示されているグレーの左右矢印と同じ判定で入力を受け付けず、内容の変わらない言語変更要求を送らない。言語変更の試験用データには、実メタデータと同じ候補数を設定した。

## ホスト確認

以下の既存試験と準備処理の試験は成功した。対象は実装コードであり、未定義動作サニタイザと警告をエラーとするコンパイルで確認した。

- run_native.py：キュー・同期要求、UI・設定・確認、GPS・地名検索、Boot・JST時計、フォント・ライセンス、RG/SDランプ、バイナリログ回復、USB所有権、書出しファイルの独立したXML/CSV検証。
- run_logger_app.py：実Application・UiModel・GpsTask・LogWriterによる開始・一時停止・再開・停止、非同期閉鎖、失敗、復帰。地図表示中の格子変更、同じ格子の検索省略、地図ジョブと現在地検索の排他。
- run_gps_control.py：連続受信、開始の冪等性、GNSS休止コマンドの送信がないこと、遅れた応答の回収。
- run_observed_reader.py：通常版・診断版の両方、stdio・FatFsの両方。通常版で計時・統計が更新されず、読出し・ビットスキップ・異常検出・SDアクセス通知が動作すること。
- run_place_files.py：N03の実データで324点のキャッシュ・直接参照一致、選択・解除・再選択、未選択・欠落・破損・メモリ不足・文字コード異常、修復後の明示再検証。実際のSJIS辞書の拒否も確認した。
- run_map_files.py：統計区実データで3倍率の間引き結果、区域コードと地名、128×128キャッシュの独立性、画像生成の一時バッファを確認した。
- run_map_scale.py：±32画素の追従と再生成、倍率変更、取消、古い完了通知、転送途中の変更、一括画像交換。
- run_usb_export_lifecycle.py：変換器の遅延確保、メモリ不足、ファイル閉鎖失敗時の保持、再公開の再試行。
- test_benchmark_support.py：通常ソース・設定・測定ログの維持、生成ソースの更新、挿入位置の一意性、診断設定の分離。

全4種類の準備スクリプトを最終ソースで実行し、RAW比較からspan比較へ同じ生成先で切り替えた際に古いRAW比較.cppが残らないことを確認した。生成ソースは通常ソースの代替ではなく、計測時にだけビルドする。
