# Geoputer Application

Application・UI・GPS座標受信・Storageを実装する。ApplicationはArduinoの`setup()` / `loop()`が実行されるメインタスクで動作し、UI・GPS・StorageをFreeRTOSの別タスクとして起動する。GPSがUARTとNMEA解析、StorageがNVS設定とSDを所有し、Appが各タスクの結果・通知を集約してUIへ表示データを渡す。

```text
application/
  main.cpp                 メインタスクの入口
  Application.h/.cpp       全体状態、通知受信、UI・GPS・Storageの同期操作
  ScreenGroup.h            画面群の分類と送信用表示データの準備
  AppScreenResources.h     App専用の地図・ログ作業領域と排他共用
  Config.h                 UI色深度・SD予約枠・チャンク上限・GISキャッシュ・検索周期
  LogBrowser.cpp           一覧・測位点の要求、10件キャッシュ、地図リプレイ
  Settings.h/.cpp          設定の初期値・値域検証・NVSレコード符号化
  BootStatus.h             起動チェックの状態・表示略称・完了判定
  TaskMessages.h           固定長メッセージと同期結果
  task/ui/
    UiTask.h/.cpp          UI受信ループ、キー入力、通知・結果返送
    UiModel.h/.cpp         選択状態、未処理確定操作、画面指定の保持
    UiScreenResources.h    地図・設定・データセット・ライセンス・USBの画面内状態

    UiTypes.h              画面・操作・表示データの値型
    KeyBindings.h          1/2/3/4の画面選択・方向操作と物理キーの対応
    LivePlaceLayout.h      画面の領域・GPS数値と未取得表示
    PlacePresentation.h    Storageの2行住所の受取りと検索中の表示保持

    StorageWorkArea.h       借用画像へ生成する地図ジョブとLogReaderの排他共用
    SettingsStore.h/.cpp   PreferencesによるNVS設定保存・復元

    PlaceSearchFlow.h     App側の検索間隔と未完了要求の管理
    StorageActivity.h      RG状態・SD実I/Oの観測
    log/
      LogWriter.h/.cpp     排他付き64件リング、保存範囲の保持、失敗時の同一位置再試行
```

現在は4タスク・5キューとする。ApplicationQueueは8件、AppReturnQueueは1件、UIQueue・GPSQueue・StorageQueueは各1件。UIは8192バイト・優先度1、GPSは4096バイト・優先度2、Storageは12288バイト・優先度1をスタック容量と優先度の初期値とし、実機で計測して調整する。未取得の同期要求は全体で1件だけとし、結果取得のタイムアウト後も同じ要求を待つ。Appは通知からUIの操作内容を取得し、画面指定と処理済みIDを返す。UIは描画前に同期結果を返し、結果キューが満杯なら完成済みの結果を保持して再投入する。GPSも同じ戻り値キューを使い、返送の再試行中もUART受信を続ける。

同期戻り値の共通ヘッダー・初期状態は`utils/SyncClient.h`の`prepareSyncReturn`で、各タスクが所有する戻り値へ直接設定する。追加の転送用フレームは作らず、満杯時に完成済み結果を保持して再送する方式は維持する。Storageの未処理ジョブは`JobKind`で一種類だけ保持し、設定読出し・地名検索・データセット検査・データセット操作・設定保存や媒体操作を区別する。完了通知は送信できるまで別に保持する。USB移行とデータセット変更で共通するロガー停止条件は`log/LogTypes.h`の`loggerStopped`へ集約し、Appの未受付点・制御操作等の追加条件は各呼出し側で確認する。戻り値のデータは共用体で保持し、`prepareSyncReturn`が送信元と要求種別に対応するメンバーを構築する。`BeginMapFrame`ではUIのback画像の貸出し情報だけを返し、Storage同期応答はストレージ状態を返す。

## ビルド

リポジトリのルートでPlatformIO Coreを使う。

PlatformIOが未導入の場合は、プロジェクト内の仮想環境へ導入する。

```bash
python3 -m venv .venv
.venv/bin/pip install platformio==6.2.0
.venv/bin/pio run -e cardputer-adv
```

PlatformIOがPATHにある場合は次のコマンドでビルドする。

```bash
pio run -e cardputer-adv
```

生成物は`.pio/build/cardputer-adv/firmware.bin`。書き込みには同じ環境で`pio run -e cardputer-adv -t upload`を使用する。書き込み先の接続・識別を確認してから実行する。

## 現在の操作とGPS接続

画面選択はLIVEのEscで開くMENUと、1＝メイン、2＝地図、3＝GPS・記録、4＝ログ一覧、0＝設定の数字ショートカットとする。数字はトップ画面でのみ有効とし、子画面の戻る操作は維持する。Sは消灯、GはGPS画面と共通の操作ダイアログを開く。詳細は[画面・操作機能設計](画面・操作/02_画面・操作機能設計.md)に従う。

通常起動はBootの6項目を確認し、完了後は通常2秒、問題があれば5秒でメインへ進む。Esc長押し・押下のメンテナンス入口は維持する。GPS受信は起動時に開始し、ログは停止とする。Sと無操作タイムアウトは表示だけを消灯し、最初のキーは元の画面への復帰だけに使用する。

GPSロガーモードのSD初期化はカード認識、FAT32マウント、`/sd/geoputer`と`dataset`・`logs`・`export`のディレクトリ確認の順とする。未挿入や読込み障害は警告のまま通常起動を続ける。FAT32でないカードは全消去を明示したフォーマット確認を、基本ディレクトリの欠落は既存ファイルを保持する構成作成確認をBoot上で開く。どちらも取消を初期選択とし、取消後はSD機能を使わず起動を続ける。実行した場合はStorageタスクが処理し、フォーマット時はMBR付きFAT32の作成後に基本ディレクトリを作り、一度再起動する。ディレクトリ確認ではファイル内容を検査せず、データセットの適否は後続のCheckDatasetで判定する。メンテナンス起動は従来どおりこの確認より先に設定画面へ入る。

GとGPS画面のEnterで操作ダイアログを開く。取消項目は置かず、Esc / Delで閉じる。開始待ち・記録中は一時停止、一時停止中は再開、停止中は開始を初期選択にする。左右で選択しEnterで実行する。一時停止はflushしてセッションを維持し、停止はログの保存・終了を要求する。どちらもGPS受信を維持する。開始は新規セッション、再開は同一セッションを次の新しいFixから継続する。GPSの休止・復帰処理は撤回し、起動から連続受信する。

未測位はNO FIX、有効NMEAの受信断とFix失効は3秒で判定する。記録停止はGPS受信・地名・地図の位置更新を止めない。消灯や画面切替だけでは測位・記録を変更しない。GPS画面のLAT/LONは1行に並べ、数値は固定欄の右端へ揃える。各表示のラベルと単位は桁数で移動させない。

接続は[Mesh Kitの標準接続](https://docs.m5stack.com/en/arduino/projects/cap/cap_lora868)を使用し、UART1のRX=G15、TX=G13、115200 bps・8N1とする。受信バッファは2048バイトとし、5ms周期で最大1024バイトを取り出す。GPIOと通信速度は現在の実装では固定であり、設定画面から変更しない。LoRaの送受信は初期化しない。GPS・USBの両モードでsetupの先頭からNRST=G3をLOWに保持し、StorageのSPI初期化後にGetStatusとSetSleep(0)だけを送って内部のcold SLEEPへ移す。成功時はNSS=G5とNRST=G3をHIGHに保持して不用意な復帰を防ぎ、失敗時はリセット保持へ戻す。起動ログは`[LORA] SLEEP`または`[LORA] RESET HELD`とする。個別電源断ではなく、GPSの給電・受信は継続する。

Live Placeのヘッダーには現在時刻を8×8のASCIIでHH:MM:SS表示する。GPSから最初の有効FixとUTC時刻を得た時点でUIの表示時計を合わせ、日本時間（UTC+9）へ変換する。以降はUIタスクの単調増加時刻で進め、GPS受信断・Fix喪失・Settings表示・消灯を経ても継続する。未取得時は--:--:--とし、再起動後は改めてGPS時刻を待つ。この段階は初回の時刻合わせだけを行い、GPSの各受信で時計を再設定しない。ログ用の測位UTCとは独立した表示時計とする。

GPSの同期操作は`StartGpsReception`と`GetGpsStatus`とする。前者の成功はUART受信の準備完了を表し、有効Fixを待たない。GNSSの休止・復帰コマンドや電源状態の確認は行わない。通常起動のメンテナンス受付後から受信し、START前は記録に採用しない。GNSS休止制御は今回の実装対象から外す。

GGAとRMCをチェックサム付きで解析し、GP・GNなどのトーカーに依存せず度分表記を符号付き十進度へ変換する。同一UTC時刻の情報は80msの統合待機または次時刻の到着で1サンプルに確定し、どちらかが無効なら有効位置として扱わない。破損行・範囲外座標は採用しない。受信断やFix喪失では有効フラグと表示座標を消去する。

通知は`GpsSampleReady` / `GpsStatusChanged`としてApplicationQueueへ投機的送信する。満杯時は最新のスナップショットを保持して再試行し、途中の表示更新が統合された件数を数える。現在は画面表示用であり、全サンプル保存の保証は行わない。AppはGPSの共通revisionで古い通知と同期結果を除外し、同期待ち中の通知では表示データの更新予約だけを行う。同期結果の取得後に`UpdateUiContent`を送り、UI自身が描画する。

USBシリアル（115200 bps）には状態変化と有効座標を出力する。5秒ごとの`RX` / `NMEA` / `rejected`は、UART到着・有効行の受信・破損行の切り分けに使用する。`coalesced`は通知待ち中に統合された更新数とする。`NO FIX`が続く場合はGPSアンテナから空が見える場所で測位を確認する。

地名は選択中のWordbook言語と画面で描き分ける。`ja`は東雲16×16（半角スペースのみ8ドット幅）、日本語以外のASCIIは通常AsciiFont8x16とする。Live PlaceのASCII長文は8×8の折返し、地図は1行目8×8・2行目を言語別の16ドット高で省略する。地名表示はUI表示言語とは独立させる。GPS測位待ちは従来の16×16を使う。GPS Logger・ログ詳細の操作項目とSettingsの主表示は、日本語モードを日本語表記の東雲16×16、英語モードをM5GFXのAsciiFont8x16とする。言語名は日本語を16×16、Englishを8×16で表示する。東雲16ドット部分のASCII英数字には全角字形を使い、該当する全角記号がない場合だけ同じ東雲の8×16字形をセル中央へ置く。8×8字形の2倍拡大は行わない。未収録文字は東雲の白四角で表示する。8×8のASCIIはM5GFXの`Font8x8C64`、補助表示の日本語は`lgfxJapanGothic_8`を使用する。描画は1ビット字形から整数座標へ行い、アンチエイリアスを使用しない。東雲の固定ソース・ライセンス・変換手順は[third_party/shinonome](../../third_party/shinonome/README.md)に保持し、`python3 tools/prepare_shinonome.py`でFlash上の読取専用字形表を生成する。

Live Placeの最下段は`⎋SG 12340`とし、現在画面の数字をシアン、ESCを含む通常キーを白で表示する。他のトップも同じ基本キーを表示し、地図には＋・－、ログ一覧にはDと上下矢印、MENU・設定トップには上下矢印を追加する。状態上使えないキーはグレーとする。ログ一覧でファイルを選ぶとプロパティを開き、Enterで文字表示へ進む。プロパティ・文字・地図・統計では1＝文字、2＝地図、3＝統計の直接選択とし、Mの表示メニューは廃止する。現在の表示先の数字はシアンとし、同じ数字では表示や再生を変更しない。PAUSE中は左右1点・上下10点、PLAY中は上下で速度変更・左右で逆／順再生を選択する。B/E先頭末尾、地図ではPで再生・一時停止、＋で拡大・－で縮小とする。地名は閲覧点を共有キャッシュで検索し、ライブGPSと分離する。ログ一覧のDで削除確認を開き、取消を初期選択として削除を実行できる。Delは戻る操作として維持し、一覧の案内はキー名だけとし、Enterに機能がある場所では16×12の枠付き改行キー風マークを表示し、OPEN / DELETE等の説明行は表示しない。ESCは枠内にESCを描いた24×12のROMマークとする。記録・保存・終了処理中の対象はUIとStorageで保護する。Place Viewは2キーで開き、境界線地図を表示する。[Boot画面](画面・操作/boot/README.md)はAppが集約した初期化結果を表示する。通信契約は[タスク構成設計](06_タスク構成設計.md)に従う。

BootのチェックはDISPLAY、TASKS/QUEUES、NVS SETTINGS、SD CARD、GPS UART、GALUCHAT DATAの6項目。NVS設定の未保存はDEFAULTとして正常扱いとし、SD未認識と混同しない。GaluchatはGPS Fixを待たずにCheckDataset通知で保存済み番号・言語のファイル・ヘッダー・辞書形式・文字コードを確認する。設定未保存時・初期化後は未選択とし、GALUCHAT DATAは正常のNONEを表示してデータファイルを開かない。未確認・確認中・成功・警告・失敗を色と記号で区別する。Boot表示中は無操作消灯を行わず、完了前のEnter・数字キー・Delではチェックを中断しない。Escは初期化完了を待たずメンテナンスへ入る。UART OKは受信準備の成功であり、測位成功やGNSS PAUSEを意味しない。

## Galuchatのファイル読出し

FAT32のSDカードの`/geoputer/dataset/<識別名>/`に、`dataset.ini`、WGSMapSet/3（`.glc`）、言語別GisWordBook/0（`.giswordbook`）を配置する。INIのファイル名指定を使い、余分なGLC・辞書があっても自動選択しない。初回は未選択で起動するため、設定→データセット選択→データセットを選択から識別名と言語を選び、「適用する」で即時反映する。選択一覧の先頭にある未選択を確認して、NVSを未選択へ戻せる。未選択でもGPS表示・ログ記録は利用できる。[配置用INI例](../../examples/sd/geoputer/dataset/jp-example/dataset.ini)のファイル名は、実際に配置するファイル名へ合わせる。

データセット切替用の`dataset.ini`は[データセットメタデータ仕様](08_データセットメタデータ仕様.md)で定義する。UTF-8の行単位のINIで、言語別のタイトル・説明・Wordbookと共通のGLCを指定する。解像度・格納範囲・チャンク数はGLCから取得する。切替対応版では実在する識別名と言語を選択し、ログの停止・保存・閉鎖完了後に検証・NVS保存後にReaderを切り替えて即時反映する。起動時に選択先が見つからない場合は原因を通知して未選択へ移し、通常画面へ進む。メタデータの読取りと切替は実装済み。[実装検証](検証/データセット切替実装検証.md)にホスト試験を記録する。UTF-8専用化、メニュー遷移のスタック削減、UIの休止処理を含む修正版を実機へ書込み済み。SD上のINIとファイル名を合わせた後、地名取得に成功した。旧版ではデータセット適用後の再起動と切替先の復元を確認し、最終版で切替済みデータの読出し・MENU・SETTINGS・戻る操作を90秒間監視した。[メニュー遷移修正の検証](検証/メニュー遷移リセット修正検証.md)に結果を記録する。

```text
SDカード直下/
└ geoputer/
  ├ dataset/
  │ └ jp-n03-y2026-1/
  │   ├ dataset.ini
  │   ├ 任意名.glc
  │   └ 任意名.giswordbook
  ├ logs/
  └ export/
```

Wordbookと`dataset.ini`、タスク間メッセージ、UIの文字列はUTF-8として扱う。GW00の任意メタデータや`token_encoding`／`text_encoding`の値でWordbookの利用可否を判定しない。選択済みWordbookの初期化検証はメタデータの長さ・チャンク境界を確認し、内容を読み飛ばして文字列を返さない。実際に読み出した地名が不正なUTF-8なら`ENCODING ERROR`とし、キャッシュへ登録しない。端末内で文字コード変換・自動判定・不明文字への置換は行わない。既存のSDカードでは、同じGLCに対応するUTF-8版Wordbookへ置き換え、INIの`wordbook`をそのファイル名へ変更する。ファイル名やメタデータだけの変更では文字コードを変換できない。[UTF-8統一の検証結果](検証/UTF-8統一検証.md)に実ファイル試験と容量を記録する。

Storageがマウント済みの`/sd`を`FileReadSource`のスコープ付きReaderから読む。アプリ内のFactory互換アダプタと自己確保フォールバックは廃止し、作業領域と固定FILの指定を必須とする。本番の地図・Wordbook・索引・候補確認はFactory経由でReaderを生成しない。SDのファイルシステムは[SD_FatFs](../../third_party/SD_FatFs/README.md)を使用する。`StorageFs.h`がアプリ内のネイティブ型・APIを選び、`StorageCard`がrawドライバ・専用VFS・FatFsの所有とマウントを一括管理する。実機はSD_FatFsに統一し、旧SDKバックエンドへ切り替える比較設定は廃止した。ホストのFatFs試験では専用の偽バックエンドを使用する。標準SDKのグローバルAPIは維持する。ESP32では実際のドライブ番号をファイル情報へ渡し、`/sd/...`を`<drive>:/...`へ変換してFatFsの`f_open`・`f_read`・`f_lseek`・`f_close`・`f_stat`を直接使用する。ホストではstdioを維持する。実際のopen・seek・バッファ補充・closeだけをSDアクセスとして観測し、バッファ内の1バイト参照は対象外にする。先読み量は用途別とし、地図の初期化・矩形取得、索引とWordbookは4KiBを使用する。地図生成と地名検索のGLC・索引・Wordbook ReaderはUIから借りた同じ4KiBを順に使用する。WordBookのSDK内トークンキャッシュは無効とし、データ全体のRAM展開は行わない。スキップがバッファ内なら位置だけを進め、バッファ外に残る距離が`FileReadThroughSkipBytes`以下なら通常のバッファ補充で読み流す。初期値は4096バイトで、0はバッファ外の移動を常にシークで処理する。長い距離はシークを維持し、読み流した後の先読み余剰は次の読出しに再利用する。読み流し専用の追加バッファは確保せず、地図とWordbookの両方に適用する。読み流しでは実際のf_read（ホストはfread）を観測し、RAM上のスキップはI/Oとして数えない。SDKのReaderを基準とする[third_party/galuchat](../../third_party/galuchat/README.md)を使用し、現在はチャンク範囲Readerの試作差分をアプリ内だけに保持する。coreとSDKは変更しない。C++17と例外処理を有効にする。

アプリの`FileReadOptions`でバッファ容量と読み流し閾値を独立して指定する。汎用の既定値はともに4096バイト。容量0はファイルI/Oの前に拒否する。地図・地名検索の`FileReadSource`は検証済みのファイルサイズと読出し設定を保持し、Readerごとの作業バッファは呼出し時だけ渡す。読出し設定はFileReadSourceの構築時に確定する。Readerが生存中の再確保や追加のキャッシュ・索引は行わない。アプリ限定試作では、範囲指定時に先読みバッファをチャンク全体長までに抑え、読出しの補充を指定範囲の末尾までに制限する。現在の矩形取得は4KiBとし、App経由のUI作業領域がある場合は索引Readerの終了後に同じ領域をGLC Readerへ貸す。借用領域のない呼出しは拒否する。[現行GLC読出しバッファ比較](検証/現行GLC読出しバッファ比較.md)に4/8/16KiBの条件と結果を記録する。

FatFsの長距離シークはファイル先頭からの絶対位置で指定し、`f_tell`で到達位置も確認する。読取専用の`f_lseek`はEOFを超える位置を切り詰めて成功する場合があるため、要求位置と異なる場合はエラーとする。読出しは戻りコードと実読出し数を確認し、失敗時やReaderの破棄時にファイルを解放する。バッファ容量・範囲制限・読み流し閾値は従来どおりであり、セクタ境界への整列、DMA化、ファイルの継続利用はこの変更に含めない。[FatFs直結の実機比較](検証/FatFs直結の実機比較.md)に測定条件と結果を記録する。

地図のRLE描画は、アプリ内Galuchatの区間書込みに対応する出力先を使用する。ランを行・列境界で分割し、座標変換とクリップを区間単位で行う。区域コードは既存のuint32画像へ直接書き込み、ゼロ透過と先に得た非ゼロ値の優先を維持する。追加の画像バッファは確保しない。`set`のみを持つ従来の出力先には画素単位の経路を残す。[RLE区間描画の最適化](検証/RLE区間描画の最適化.md)に検証結果を記録する。 単色領域も同じ区間書込みを使用する。能力判定は`HasSpan`へ統一し、RLEは行・列ごとに矩形との交差を判定する従来の区間描画を維持する。事前の範囲除外は試験後に取り下げた。[追加最適化の検証](検証/単色領域の区間描画とRLE範囲除外.md)を参照する。


選択中データセットの実行情報はStorageTaskの固定メンバーSelectedDatasetへまとめ、地名検索と地図読出しはその参照を借りる。Appは本体・参照を持たず、要求・完了通知と必要な状態のスナップショットを扱う。番号は整数0／1〜99、地図名・選択言語の辞書名は各128 B（UTF-8最大127 B＋終端）に保持する。固定ルート`/sd/geoputer/dataset/`、ディレクトリやGLC・索引・Wordbookのフルパスはセッションに保存しない。FileReadSourceは固定ルート・番号・名前への非所有参照から、ファイル操作中だけ256 Bのスタックパスを構成する。初期化時にINIを読み、選択言語・地名書式・検証済みヘッダー・状態と世代を保持し、地図生成時にはINIや初期化検証を繰り返さない。選択言語は終端込み32 B、書式は各行終端込み128 B（UTF-8有効長127 B）で固定保持する。超過書式は未選択言語も含めメタデータエラーとし、切り詰めない。選択情報とINI解析にアプリ側のヒープを使わず、解析の一時情報は局所スタックへ置く。切替・SD再マウント・保守では旧Readerと参照を終了してから同じ領域を更新し、Appは既存の完了通知・スナップショットで結果を反映する。4KiBの読出し領域はUI借用を維持し、パス領域は借りない。設定から別候補を調べる読込みは個別に実行する。名前の制約は[メタデータ仕様](08_データセットメタデータ仕様.md#2-配置とデータセットの単位)を参照する。

WordBookの地名検索はアプリ側のWordBookCacheで包む。32bit区域コードとUTF-8検証・書式展開済みの地名2論理行（各96バイト）を16件まで固定長で保持する。利用順だけを16バイトのインデックス配列で管理するLRUとし、時刻・内部Tickは使わない。ヒット時は辞書読出しとUTF-8検証・整形を省き、ミス時に成功した結果だけを登録する。今回の座標・時刻・要求世代は毎回の要求から結果へ設定する。

地名キャッシュは矩形の再構築・GPS喪失・画面切替では保持し、PlaceLookupのclose、SD媒体操作、Reader再オープンで消去する。矩形と地名がともにヒットした検索ではSDを読まない。RGは従来どおり矩形の状態、SDはログ等も含めた実I/Oを表示する。実装と検証は[WordBook地名キャッシュ検証](検証/WordBook地名キャッシュ検証.md)を参照する。

区域コードの取得は`CachedMapReader`で包み、Storage所有の固定128×128 `uint32_t`画像1枚（64 KiB）を借用し、最初の点検索で内容を読み込む。経度・緯度はSDKと同じ解像度と丸め方で整数座標へ変換する。範囲内は画像の値を返し、初回または範囲外では取得点をセル(64,64)とする矩形をアプリの`DiskIndexedMapReader`で読み直す。保存索引のチャンク情報を1件ずつ読み、対象チャンクの群情報を1件ずつ確認し、必要な群へ直接移動して追加APIの`readRectFromBlockRange()`で復号する。群を持たない16KiB未満のチャンクは既存の`readRectWithoutTail()`を使用する。原点は`(ix-64, iy-64)`、幅・高さは128、範囲の上端は含まない。区域なしのコード0も有効なキャッシュ値とする。

アプリは`DiskIndexedMapReader`を使用し、保存索引から対象チャンクを選ぶ。`MaxDatasetChunks`（1500）は索引読込み前に確認する。SDKの`GaluchatWGSMapSet3IndexedReader`は今回の比較試験の旧方式だけに使用し、製品側でRAMチャンク索引を作らない。従来の`GaluchatWGSMapSet3Reader`と既存APIは変更しない。矩形取得では最後に必要なブロックの処理を完了した時点で停止し、後続ブロックの走査とGI01全体長の一致の検証を省く。必要ブロック内の復号・バイト境界整列・RAWS/LZSSの終端検証は維持する。チャンクごとに独立したReaderを閉じるため、次のチャンクに備えた末尾への移動は行わない。保存チャンク索引と既存の画像キャッシュを使用する。保存ファイル内のブロック群索引も使用し、群ごとに復号範囲を制限する。同じチャンクの複数群はファイルとバッファを使い回し、追加画像は作らない。

読出し先のアダプターは32bitの範囲を検証し、複数地図が重なる場合は先に取得した非ゼロ値を保持する。これによりSDKの点検索の優先順を維持する。SDKの矩形読出しは通常後の非ゼロ値で上書きするため、標準のRasterViewをそのまま使わず、このアダプターへ直接書き込む。64bitの中間画像は作らない。

再構成開始時にキャッシュを無効化し、矩形全体の読出し成功後に原点と有効状態を確定する。途中の読込・確保・コード値域エラーは検索失敗として返し、部分的な画像を参照しない。同じReaderの範囲内では画面復帰後も再利用する。SD再マウント・取り外し・フォーマットおよびReaderの閉鎖時は画像を解放し、別のデータセットへ持ち越さない。BootのCheckDatasetでは画像を確保しない。

Appは`SearchPlace`通知に要求ID・画面世代・Fixのコピーを付ける。Storageは結果を`ReadCompleted` / `ReadFailed`で返す。結果は`StorageReadKind::Place`で設定読出しと区別し、通知キュー満杯時も保持する。新しい検索は未完了要求がない場合だけ行い、メイン・地図の両画面で新しいGPSサンプルのデータ格子が変わったら要求する。5秒の制限は設けず、同じ格子なら検索を省く。Settings表示中と画面消灯中は新しい検索を開始しない。

RGは矩形キャッシュの実状態を示し、未準備は暗灰、構築中は黄、有効な矩形を保持していれば検索間隔中やGPS喪失・画面切替後も緑を維持する。SDはログ・地図・WordBook・媒体操作の実I/Oで青く点灯し、RAM受付・キャッシュ参照・文字変換・NVS保存では点灯しない。状態の正本はStorageで、`RgCacheStateChanged` / `SdAccessChanged`をAppが最新revisionで統合しUIへ渡す。キュー満杯時は最新状態を保持し、表示通知を待ってI/Oを遅らせない。SDだけ最低150ms表示し、同じアクセスIDの再送で再点灯しない。

[メイン画面](画面・操作/live-place/README.md)は採用仕様1.3のレイアウトを実装し、上段に記録状態・JST時刻・RG・SD・電池、本文に東雲16ドットの住所2行、左に大きな速度・進行方位、右にLAT / LON / ALT / SAT、下段に記録時間・64件バッファ、問題発生時は赤地白文字の原因を表示する。電池残量はUIがM5Unifiedから5秒ごとに取得し、取得不能は--%、充電状態が不明なら充電中と表示しない。

地名と表示座標は同じ検索Fixを使う。再検索中は前の表示を保持し、結果確定時に一緒に差し替える。Fix喪失時は旧地名・座標を消し、WAIT GPS FIXを16ドット表示する。キャッシュとSDの実状態はGPS喪失で消去しない。画面世代が古い結果、Fix喪失前の検索結果は適用しない。Storageがdataset.iniのdisplay_line1 / display_line2を展開し、完成した2行をキャッシュ・通知する。Appは再整形しない。Storageは2論理行を各96バイト以内で保持する。Live PlaceはASCII長文を8×8で折り返し、地図画面は1行目を8×8・2行目を言語別の16ドット高で描き、それぞれ表示幅で省略する。

SD未認識、ファイル不足、候補重複、区域なし、文字コード異常、データ読込異常を区別して表示する。SDカードは起動前に挿入する。起動後に挿入・交換した場合はSettingsのストレージ操作で再マウントする。SDデータの異常でGPS受信やNVS設定保存を止めない。

速度・方位の主数値は東雲16ドット、ラベル・速度単位・右側の詳細値はASCII 8ドットとする。SPD / HDGは左上ラベル、左右・上下の均等分割、SPD / HDG間の横線は左端から中央縦線までとする。速度は低速時に整数m/h、1〜100km/h未満は小数1桁km/h、100km/h以上は整数km/hへ切り替える。数字16ドット・小数点の送り幅8ドットで3桁までを収め、単位の位置を固定する。方位はGPSの進行方位を整数度へ丸め、360°は0°とする。ALTはGGAの海抜高度を小数1桁のメートルで表示する。項目ごとの未取得やFix喪失は--にし、HDOPはメイン表示だけから外してGPS取得・ログ記録には残す。

## GPSログの保存

Appは新しい有効Fixを設定間隔で採用し、StorageTask::tryAppendLogを通常の関数として呼ぶ。この関数はAppタスク上で排他付き64件リングへコピーし、受付結果とLogSnapshotを返す。要求・戻り値キューやSD処理の完了を待たず、他の同期要求の結果待ち中にGPS通知を処理する場合も追加できる。成功はRAM受付であり、永続化完了ではない。OpenLogSession / FlushLog / CloseLogSessionは引き続き同期メッセージとする。Storageは満杯・設定時間経過・一時停止・停止で実保存を行う。FatFsのf_sync成功後に保存件数を進め、LogWrittenを通知する。保存失敗はStorageError（Log種別）で通知し、受け付けた全レコードを保持して5秒間隔で同じ位置へ書き直す。

記録間隔は1・5・10秒（初期値1秒）、SD保存間隔は1・5・10・30・60秒（初期値10秒）から設定する。保存期限はバッファが空から非空になった時点を基準に判定する。長いGIS処理の分割は未実装であり、その実行中や先行する結果返送待ちの間もRAMに空きがあれば追加できるが、実保存とキュー経由の制御受付は遅れ得る。

レコード本体は`records[64][32]`、連番は`sample_seqs[64]`に分離し、合計2,304バイトを維持する。Storageは保存対象を固定してからロックを解放し、リングの最大2連続区間を直接writeしてf_syncする。成功時にその対象だけを解放し、保存中に追加された点は残す。失敗時は同じ対象・同じファイル位置を保持して再試行する。保存中の分も64件へ含め、二重バッファやSD保存用の全件スタックコピーは作らない。符号化には32バイトのローカル領域、ヘッダー生成には従来どおり512バイトを使用する。ESP32の排他区間は状態・添字・コピーに限定し、変換・CRC計算・SD・キュー待ちを含めない。

満杯の間の新規受付は失敗とする。Appは未受付の採用点を1件保持して再要求し、その間に保持できなかった新しい採用対象点だけを欠落件数へ加算する。一時停止・停止の確定操作は新規採用を止め、保持中の点が受付済みになってから、その境界のflush / closeを要求する。SD障害が継続して境界が受付不能なら操作はWAITのまま待ち、未保存点を破棄しない。

未受付点の再要求は1秒間隔とする。セッション終了もLogWritten / StorageErrorとStorageSnapshotで通知し、open=false・closing=falseで終了を確認する。終了専用の通知は設けない。ログ保存通知は元の同期要求IDを引き継がず、AppはStorageのrevisionで古い媒体状態を除外し、LogSnapshot自身のrevisionで直接受付後の件数・保存状態が古い通知へ戻らないようにする。終了処理中や未保存データの保持中は、新規セッションを受け付けない。ファイルの作成・seek・書込み・sync・closeの失敗は共通のLogError::Ioとして通知する。

`/geoputer/logs/`へ、最初の採用点のJSTからYYYYMMDD_HHMMSS_n.gps.datを作る。日時不明はundated_<session16桁>_n.gps.datとする。排他的な新規作成で既存ファイルを上書きせず、同じ秒は連番を進める。512バイトヘッダー・32バイト測位レコードをリトルエンディアンとCRC32で符号化する。ファイル形式の正本は[測位記録ファイル仕様](07_測位記録ファイル仕様.md)。有効点のないセッションは空ファイルを作らない。一時停止・再開では同一セッションを継続し、停止後の次回開始は別ファイルにする。

ログの保存・未保存・欠落・最終保存の状態はGPS LOGGERで確認する。ログが開いているか未保存データがある間は、再マウント・取り外し・フォーマットを拒否する。NVS設定の保存は使用できる。ログ一覧・概要・最大10件単位の非同期読出しと閲覧画面は実装済み。距離・最高速度の全件集計、GNSSの休止・復帰制御、長いGIS処理の分割は後続実装とする。GPS通知は最新値へ統合する方式であり、全GNSSサンプルを無条件に保存する保証は行わない。

## 設定・ストレージ・ライセンス

Settingsは動作設定、システム設定、アラート、データセット選択、ストレージ操作、バージョン情報、ライセンス情報の7メニューとし、4行ずつスクロール表示する。項目・値・確認文・カード情報は日本語を東雲16×16、英語をAsciiFont8x16とし、タイトルとライセンス本文はASCIIの8×8ドットとする。GPS状態・キーガイド・短い通知も8×8ドットとする。動作設定は項目名をx=20で左寄せ、値を実描画幅に応じて右端x=236へ右寄せする。4行表示で全7項目へスクロールし、カード容量等はカード情報パネルを開いて表示する。動作設定の先頭に表示言語（日本語 / English、初期値日本語）を置き、表示言語・GPSログ間隔・SD保存間隔・消灯時間・輝度を編集してNVSへ保存できる。表示言語はEnter確定後、Appが適用した時点で同じ画面・選択位置のまま反映する。輝度・消灯時間も即時反映する。ログ間隔はAppのFix採用間隔、SD保存間隔はStorageの未保存データの期限へ反映する。データセット選択は設定トップから識別名一覧、タイトルとWordbook候補を扱うDATASET画面、閲覧専用の詳細、索引保守を開く。システム設定にはモード編集・Mesh Kit固定のGPS接続（外付けGPS未対応）・保存して再起動・初期化を置く。初期化画面から戻るとシステム設定の同じ項目へ戻り、確認後だけ実行する。GPS接続は動作設定から除く。

NVSの名前空間は`geoputer`、キーは`config`。48バイトのレコードへ識別子、形式バージョン3、7項目、Wordbook言語、検査値を保存し、長さ・形式・値域・検査値を検証してから使用する。設定が未保存なら初期値を使用し、不正・読込障害は設定エラーとして表示する。旧バージョン1・2の16バイト設定を読み、他項目を維持してデータセットだけ01・INIの既定言語へ移行する。次の保存でバージョン3へ移行する。保存形式の詳細は[Settings画面仕様](画面・操作/settings/README.md#7-nvsの形式と旧設定の引継ぎ)に従う。SD未挿入でも設定を読み書きできる。SaveSettingsは設定のコピーを保持した時点で同期結果を返し、実保存成功はSettingsWritten、失敗はStorageErrorで通知する。LoadSettingsは通知で要求し、ReadCompleted / ReadFailedで復元結果を返す。完了通知はキュー満杯時も保持して再投入し、実処理を二重実行しない。

SDはLCDと別のSPI（FSPI、SCK=G40、MISO=G39、MOSI=G14、CS=G12）を`Config.h`の`SdSpiHz = 25'000'000`（指定上限25MHz、現行ドライバーの実クロックは20MHz）で使用し、未使用LoRaのNSS=G5をHIGHに保つ。ストレージ操作画面にはカード状態、カード容量、FAT種別、総容量・空き容量、再マウント、安全な取り外し、FAT32フォーマットを用意する。FAT32以外は利用対象外として表示する。SD操作はOperateStorageの同期受付後にStorageが実行し、StorageOperationCompleted / StorageErrorで結果を通知する。

フォーマットは端末上の確認画面で取消からOKへ選び直して確定した場合だけ実行し、カード全体をFAT32の単一ボリュームとして作成する。マウント失敗時の自動フォーマットは行わない。設定初期化も別の確認画面を経てGeoputerの初期値をNVSへ保存する操作とし、SDデータや他ライブラリのNVS領域を消去しない。

ライセンス情報はSDとNVSを使わず、Flash内の本文を上下キーでスクロールして閲覧する。上下キーを押し続けると連続スクロールする。配布元と本文は[ライセンス一覧](../../third_party/licenses/manifest.json)に保持し、`python3 tools/prepare_licenses.py`で29文字幅・9行表示の8ドットASCII本文を再生成する。IPAの許諾文は公式の英語本文を使い、東雲は原文を保存したうえで英訳を掲載する。

## ログ閲覧

各トップ画面の`4`でLOGSを開く。ファイルをEnterで開くと基本情報のみのプロパティを表示し、再度Enterで1点ずつ閲覧できる。上 / `;`が前、下 / `.`が次、Esc / Delが戻る。消灯中の最初のキーは復帰だけに使う。

一覧は6件ずつ、.gps.datを省いた名前とページ番号/総ページ数、選択ファイルのサイズ由来件数を表示する。Enterでプロパティを開き、さらにEnterで文字表示へ進む。2で地図、Pで再生を切り替える。3で統計を明示要求し、Rで再計算する。測位点は保存済みのGPS値を表示し、その座標から通常画面と共通の地名検索を行う。文字表示・地図表示・リプレイを切り替えられる。Appが10件の生レコード320バイトを保持し、UIへ現在の1点を渡す。Storageの同期結果は受付成否だけを返し、読出し結果はトークン・画面世代付きの固定長通知として値コピーする。結果バッファプールと解放通知は使用しない。

記録中の閲覧でもRAM受付を続け、SD読書きはStorageTaskが直列化する。先行分の保存後に取得した保存済み上限を固定し、新しい記録は詳細の「再読込」で反映する。読出しは元ファイルを変更せず、破損点の番号も詰めない。操作と検証範囲は[Logs](画面・操作/logs/README.md)、[詳細・測位点](画面・操作/log-detail/README.md)、[ログビューア検証](検証/ログビューア検証.md)を参照する。

フォントと動作設定の配置変更・検証は[UIフォント・設定配置検証](検証/UIフォント・設定配置検証.md)を参照する。

## Galuchatのリソース設定とチャンク索引

ビルド時のGIS設定は`application/Config.h`へ集約する。`MaxDatasetChunks`は1500（上限を含む）、`MapCacheSide`は128、`FileReadBufferBytes`・`MapInitReadBufferBytes`・`WordBookReadBufferBytes`・`FileReadThroughSkipBytes`は4096、`MapRectReadBufferBytes`・`IndexReadBufferBytes`は4096、検索1回のTT/TM参照先を局所スタックへ置く`WordBookReadPageCacheEntries`は32、地名LRUの`WordBookCacheEntries`は16とする。利用者が画面から変更する設定の候補・初期値は引き続き`Settings.h` / `Settings.cpp`で管理する。

通常起動では保存索引の全体検証と元GLCHの照合を行い、チャンク配列をRAMへ保持しない。矩形検索時は交差するチャンクだけを開く。起動時・Reader再オープン時にチャンク数を確認し、1501以上は保存索引の検証とGI01の読出しへ進まず利用不可とする。逐次探索へ戻さない。上限超過とメモリ確保失敗はGPS更新によって再試行せず、Readerの明示的な閉鎖・SD再マウント後に再確認する。GPS受信とログ記録は継続する。

起動チェックでは`TOO LARGE` / `NO MEMORY`を表示する。起動を継続し、原因を通知して未選択へ移り、逆ジオコーディングを停止する。全面警告を閉じる操作は要求しない。同じ制限を選択済みデータと切替候補へ適用する。`[DATASET]`ログにチャンク数・設定上限・状態を記録する。

## メモリ削減後の描画と通信

`Config.h`の`UiColorDepth = 4`で16色パレットの全画面バッファを使用する。現在の9色・240×135の解像度・字形・一括転送を維持し、RGB565色から番号への変換はUiCanvasに集約する。値16は従来のRGB565参照描画とし、プレビュー生成時に両者のRGBピクセルが一致することを確認する。SDのVFS予約枠は`SdMaxOpenFiles = 3`とする。地図・索引・WordbookのReaderは直接FatFsのFILを使用し、このVFS枠を消費しない。ファイルの所有者は引き続きStorageタスクとする。

キューは用途ごとにUiRequest（1280 B）/ GpsRequest（16 B）/ StorageRequest（144 B）/ AppNotification（816 B）/ ReturnMessage（576 B）を使用する。UI更新以外のキューや結果保持領域へUIデータ全体を予約しない。Appの2キュー・サブタスクの各1キューと件数、同期結果の必須回収、値コピーによる所有権を維持する。各型のサイズは実機向けコンパイラのsizeofで確認する。

実装・実測・検証範囲は[メモリ削減実装検証](検証/メモリ削減実装検証.md)にまとめる。

UiDataのログ閲覧・USBファイル一覧とデータセット画面のデータは、種別付きunionで同じ領域を使う。読取りはbrowse() / datasets()、書込みはeditBrowse() / editDatasets()とし、読取りだけで保持種別を変えない。App・UI・キューはそれぞれ独立した値コピーを所有し、別種別へ移った後の古い完了結果は表示へ反映しない。UiDataは1696 Bから1248 B、UiRequestは1728 Bから1280 Bへ縮小した。変更範囲と検証は[画面専用UIデータの共用検証](検証/画面専用UIデータの共用検証.md)を参照する。

### 画面群の専用リソース

ScreenGroupは共通画面、地図、ログ閲覧、設定、USBに分類する。AppScreenResourcesは地図の転送・生成状態とログの要求・10件キャッシュを種別付きunionで共用する。ログ一覧・詳細・測位点の間では同じリソースを維持し、USBのファイル一覧もログ用の領域を使う。画面を離れた後も必要な要求ID・取消状態は共通の制御状態へ保持する。

Appは既存のUiRequest内で次画面の表示データを準備し、UIが受け付けてから画面群のリソースを切り替える。拒否された場合は元のリソースと画面を維持する。別画面へ移った後の完了通知は現在の作業領域へ書き込まない。UIの地図画像・カーソル、設定・データセット編集・ライセンス位置、USB選択状態はUiScreenResourcesへ集約し、画面切替時に画像を解放して局所状態を初期化する。時計・電池・入力時刻・確定待ち操作は共通状態に残す。

StorageのMapBuildJobとLogReaderはStorageScreenResourcesへまとめ、受付済みジョブの寿命に従う。画面を離れた後も取消・完了まで資源を保持し、結果は値コピーで返す。GPS受信・ログ保存・現在地キャッシュは画面の専用リソースに含めない。静的RAMはこの整理で67,752 Bから67,304 Bへ448 B減り、表示データの共用前69,096 Bからは合計1,792 B減った。詳細は[画面群リソース整理の検証](検証/画面群リソース整理の検証.md)を参照する。

### 起動モードとUSBストレージ

通常モードの設定→システム設定でモードをUSBに編集し、「保存して再起動」で確認すると、Storageが独立したNVSキーboot_modeを保存し、成功通知後にAppが再起動する。記録停止・未保存データの保存・セッション閉鎖が完了していることが必要。USBモードではGPSを起動せず、PC公開中はSDをFatFsへマウントしない。PC公開中でも終了ダイアログの終了を選択できる。PCのコピー・編集・保存を完了して確定すると、実行中I/Oの終了・SD同期・フラグ保存・USB公開停止後に通常モードへ再起動する。Windowsのクイック削除で運用する場合はPCの安全な取り外しを必須としない。PCの未送信キャッシュを端末から同期する機能ではない。

USB-OTG/TinyUSBへ移行し、CDCを手動開始する。アプリケーションログはutils/ConsoleのUSBCDCへ出力し、MSCはUSB起動時だけ登録する。シリアルモニタは115200bps、DTR/RTSとも有効とし、USB Serial/JTAGを使っていた従来のCOM番号から変わる場合がある。NVSのconfigレコード・SD上のログ形式は維持する。[詳細仕様](09_起動モード・USBストレージ仕様.md)。

USBメニューの「ログを書き出す」から、保存済みログをGPX・KML・CSVへ変換できる。[エクスポート仕様](10_ログエクスポート仕様.md)に従う。出力は`/geoputer/export/<元のファイル名全体>.<形式の拡張子>`とする。PC公開中だけ安全な取り外しを待ち、USB公開を止めてFatFs操作へ切り替え、閉鎖・同期・アンマウント後に再公開する。変換はStorageの`task/storage/export/LogExporter`が10点ずつ進め、2048バイトのバッファを使う。変換器は変換開始時だけ確保し、ファイル閉鎖成功後に解放する。確保失敗はエラー表示してUSBを再公開し、閉鎖失敗時は同じ変換器を保持して再試行する。関連定数は`Config.h`に置く。同名出力は上書きせず、破損・不完全末尾・0件のログはエラーとする。変換中の取消は提供しない。実装と試験の範囲は[実装検証](検証/ログエクスポート実装検証.md)を参照する。

ライセンス本文は上下で1行スクロールし、左右キーまたはライセンス閲覧中の`<` / `>`（Shift+, / Shift+.）で前後のソフトウェアの名称行へジャンプする。名称が表示の先頭へ来るようにし、先頭・末尾で折り返さない。`tools/prepare_licenses.py`はマニフェストの掲載項目から本文と先頭位置を同時生成する。

設定の「バージョン情報 / About」ではGeoputerの版・JSTビルド日時・Git情報を確認できる。製品名と版は`Version.h`を正本とし、初回公開版は`0.1.0`、配布タグは`v0.1.0`とする。PlatformIOのpre-build hookがビルドディレクトリの`generated/BuildMetadata.h`へ日時とGitの短縮ハッシュを生成する。未コミット変更は`+dirty`、Gitが取得できない場合は`unknown`と表示する。Enter / Esc / Delで同じメニュー項目へ戻る。ライセンス本文は別の項目として維持する。

## メンテナンス起動

Cardputer ADVではアプリ側の`hardware/AdvKeyboardReader`をUIが所有する。初期化時にGPIOによる物理マトリクス走査で押下状態を復元し、通常時はTCA8418のFIFOをポーリングする。MCUリセット前からキーを保持していてイベントが残っていない場合も検出し、重複pressで状態を二重追加しない。キーボード更新はUIが明示的に1回ずつ実行し、M5Cardputer側の自動更新と重複させない。

キーボードの最大同時押し数は`Keyboard_Class`の構築時に固定する。標準の`M5Cardputer.Keyboard`は全56キーを上限とし、Fn・Shiftなどの修飾キーも含める。キー一覧と状態用の全配列は構築時に容量を確保し、UI動作中は再利用する。上限を超えるpressは保持せず、満杯でもreleaseは処理する。ADV Readerには`maxKeys()`の値を渡し、物理状態の復元・FIFO復旧にも同じ上限を適用する。上限を後から変えるAPIは設けない。

`python3 tests/run_keyboard.py`は同梱ライブラリ本体を使い、上限0・1・3・56、全キー押下での起動、超過・重複press、満杯でのrelease、修飾キー、FIFO復旧を検証する。入力処理中のC++確保・解放が0回であることを検査し、標準版のマトリクスReaderとTCA8418 Readerも対象にする。

Bootの確認中・完了後、および異常表示中のLive PlaceでEsc（物理バッククォート、Fn不要）を押すと、メンテナンス状態で設定画面を開く。電源投入時からの押しっぱなしも保持し、UIはAppへの最初の応答前にキーを走査する。起動時にEscが押されていれば、AppはSD初期化・NVS復元の完了を待たずメンテナンスを表示し、設定復元だけを継続する。復元中の保存操作は無効にする。通常起動には設定読込み後の1500ms受付期間（`config::BootMaintenanceWindowMs`）も残し、GPS・地図の自動初期化前に退避できる。メイン画面のエラー時も、記録と保存の終了後はEscで入れる。通常のEscによる設定操作は継続する。

メンテナンスでは自動位置検索・記録開始・消灯を抑止する。設定入口のEsc / Delは共通の取消／再起動確認となる。設定変更・SD操作・データセット選択・USB切替は既存処理を使う。開始済みのStorage処理は強制中断しないため、読込みでクラッシュする場合は次回起動からEscを保持する。保存索引はデータセットの再適用で生成できる。起動・検索では保存チャンク索引を利用する。独立した再生成・元データ突合は設定トップ→データセット選択から実行する。[Boot仕様](画面・操作/boot/README.md#5-escによるメンテナンス起動)を参照する。

## 障害時の機能制約

[システム構成設計7節](04_システム構成設計.md#7-エラー状態と機能の利用条件)を正本とする。有効GPS Fixなしでは地名更新・新しい測位点の追加だけを止め、設定・SD操作・既存ログの利用は各機能の必要条件で判断する。開始・再開は次の有効Fix待ちとなり、記録中のFix喪失はセッションや記録要求を解除しない。SD利用不可ではログ・地名機能を利用できないが、GPS表示とNVS設定操作を継続する。データセット異常だけなら逆ジオコーディングを停止し、ログは利用可能なSDと有効Fixに従って記録する。

SD全体の利用不可、書込みだけの失敗、NVSの設定復元失敗・保存失敗は別に扱う。ログ閲覧・削除・USBモードでのエクスポートは現在のGPS Fixやデータセットを必要としない。版・ライセンスの表示データはファームウェア内にあり、SD・GPS・NVS保存に依存しない。UI・Appを準備できない初期化失敗だけは通常操作の開始前に停止する。

## データセット異常時の起動継続

[データセットメタデータ仕様8.3〜8.5節](08_データセットメタデータ仕様.md#83-起動時の復元とエラー)に従い、使用中の欠落・破損・文字コード未対応・上限超過・メモリ不足・読出し失敗・SD利用不可では、原因を通知してNVSとRAMを未選択へ移す。地名欄は未選択とし、GPSと利用可能なログ機能を継続する。解除理由はその起動中の診断へ残し、キャッシュ保守後も利用者が改めて選択するまで検索を再開しない。

欠落時の起動停止と上限超過・メモリ不足の全面警告は廃止した。PlaceLookupはすべてのデータセット失敗を保持し、Reader・画像・辞書キャッシュを解放する。明示的なCheckDataset／configureで検証世代を進め、Appは要求IDと世代を照合して古い成功によるエラー解除を防ぐ。Boot・地名欄・再読込み抑止の[検証結果](検証/データセット異常時の起動継続検証.md)を参照する。

## データセット事前索引（生成・チャンク読出し実装済み）

[事前索引ファイル仕様](11_データセット事前索引ファイル仕様.md)に従い、適用・再適用時に`/geoputer/dataset/<識別名>/_mapindex.dat`を生成する。GLCとINIに宣言された全言語のWordbookを収録し、有効な既存領域は再利用する。生成・構造CRC検証・同期・公開後にNVSを保存し、失敗時は旧索引を復元する。生成設定は`Config.h`へ集約する。

データセットの「適用する」は検証・索引確定・NVS保存後にReaderとキャッシュを入れ替え、CheckDatasetの再確認後に検索を再開する。ログ停止・保存・閉鎖完了を必要とするが、再起動は行わない。システム設定のモード候補はUI内で保持し、編集確定や確認取消ではNVSへ書き込まない。

通常起動・明示再検証では索引全体の構造・CRCと元GLCHの識別情報を照合する。索引なし・破損・元GLC不一致はデータセットエラーとし、GPS・SDログは各機能の条件に従って継続する。Escメンテナンスまたは設定のデータセット再適用で生成できる。候補表示は索引を必要とせず、元データを検証する。

`DiskIndexedMapReader`は共通ヘッダーと全体範囲だけを保持する。画像キャッシュのミス時は索引を1回開き、チャンク情報40バイトを順に読む。交差しないチャンクの群情報はskipし、交差するチャンクの群情報16バイトを1件ずつ確認して、必要な群だけ保存位置から復号する。マップ索引領域の末尾で先読みを止め、毎検索の全体CRCは行わない。128×128画像・地名LRUは維持し、画像ヒット時は地図用の索引・GLCを開かない。地名LRUがミスする場合はWordbook用の索引を別に開く。`[INDEX-IO]`と`[INDEX-IO-TIME]`は両方の索引I/Oの合計を記録し、`[READ-IO]`のmap/bookは元GLC・元Wordbookだけを記録する。

ブロック群の途中再開はアプリ内Galuchatの追加APIで実装した。索引ファイル形式は変更せず、既存索引をそのまま使う。WordbookもDiskIndexedWordBookReaderで保存済みTI00・TT00・TM00索引を利用する。選択言語と元Wordbookの識別情報を起動時に照合し、地名キャッシュのミスごとにTI・TT・TMの各索引領域を前方向へ読み、索引Readerを閉じてから対象枝・ページ・断片を直接取得する。TTとTMは各関数内の最大32件の参照先配列を順に使う。1件24 B、ESP32では管理情報込み776 Bで、上限を超えた段階は残りを再走査する。配列を検索間で保持せず、GLC読出しとWordbook読出しを直列化する。Readerと借用指定は例外を含むスコープ終了時に破棄し、全経路で同じUIの4KiBを共用する。Core・SDKへは今回の追加APIを反映していない。前段実装の実機比較は[保存チャンク索引の比較](検証/保存チャンク索引の性能比較.md)、現在の群索引の利用・試験は[保存ブロック群索引の検証](検証/保存ブロック群索引の検証.md)と[保存Wordbook索引の検証](検証/保存Wordbook索引の検証.md)に記す。

保存索引は地図とINIの全地名言語のWordbookを1ファイルへ収録する。適用時は既存索引全体が正常なら書換えず採用し、欠落・不足・不一致・破損があれば全再生成する。設定→データセット選択のキャッシュ再生成・キャッシュ検証で、対象識別名を選び地図と全言語Wordbookを一括処理する。通常起動の軽い確認と、明示操作による元データの全走査突合を区別する。詳細は[データセット事前索引ファイル仕様11節](11_データセット事前索引ファイル仕様.md#11-索引保守と全言語の利用)に従う。

データセットメニューは「データセットを選択」「キャッシュ再生成」「キャッシュ検証」の3項目とする。キャッシュ操作は対象の番号一覧→共通確認→進捗・結果の順に進み、地図と全言語Wordbookを一括処理する。対象を通常利用に適用せずに保守でき、使用中が未選択でも操作できる。既知の実行不能条件は項目をグレーアウトして理由を示し、試行が必要なI/O・破損・不一致などは処理結果で表示する。

使用中のデータセットが欠落・破損・キャッシュ欠落・SD利用不可などで使用不能と判明した場合、StorageはNVSを未選択・空言語へ更新し、Readerとキャッシュを解放する。NVS保存失敗でもRAM上は未選択とし、保存失敗を通知する。原因は5秒間の通知と、その起動中のデータセット設定に残す。新しい候補の検証失敗では現在の有効な選択を維持する。自動解除はGPSの記録状態を変更せず、復旧後も利用者が改めて選択するまで地名検索を再開しない。

## 内部処理の整理

画面の共通処理はUiRenderer::drawとUiModel::keyPressedに残し、Boot・Live Place・GPS Logger・ログ閲覧・設定の描画と入力処理をprivate関数へ分ける。画面指定、世代と操作ID、ダイアログの優先、削除中の操作抑止は共通入口で維持する。描画用スナップショットと設定は参照で渡し、描画関数ごとの再コピーを行わない。

Storageのデータセット操作は受付・完了通知と、選択解除・適用・索引保守を分ける。索引の生成・公開・設定保存・失敗時の復元はDatasetIndexが従来どおり担当する。索引形式の位置と整数入出力はDatasetIndexFormat.hへ集約し、再適用可能エラーの分類はDatasetTypes.hでUIとAppが共有する。タスク・キューとファイル形式は変更しない。

整理内容と変更前後の確認は[内部整理の検証](検証/内部処理整理の検証.md)を参照する。


### 独立した境界地図

トップ画面の2で地図を表示する。画像生成用ラスタは既存の128×128区域キャッシュとは別に確保し、MapSourceが保存索引から専用の矩形を読む。現在地の区域判定と地名はメインと同じPlaceLookup・コード面キャッシュ・地名LRUを使う。画像処理・2bit形式は`application/map/`へ分離し、StorageのMapBuildJobが8行単位で境界画像を生成する。AppがUIの固定backをStorageへ貸し出し、完成通知とStorageの返却確認後にUIへ表示交換を指示する。行単位の画像コピーは行わない。完成地図の中心から左右上下±32表示画素以内ではGPSカーソルだけを移動し、範囲外へ出るか倍率を変更したら即時再生成する。カーソルは地名より手前に描く。白い境界は完成画像の生成区域を示す。地名は最新の現在位置に追従し、地図の生成時点に固定しない。消灯中は新規処理を止める。設定・ログの下位階層からの2による割込みは行わない。

Live Placeの最下段は`⎋SG 12340`。他のトップも同じ基本キーに各画面で使用できるキーを追加する。GPSのENTER / G: CONTROLの説明行は省略する。地図の詳細とメモリ所有権は[地図表示モジュール設計](12_地図表示モジュール設計.md)、ホスト実データ試験は`python3 tests/run_map_files.py <map.glc> <wordbook>`を参照する。地図専用作業バッファの上限96KiB・カーソル追従半径32画素・再試行間隔1000msはConfig.hに集約する。

地図処理の段階別メモリ診断はConfig.hの`MapHeapDiagnostics`で切り替える。初期値は`DetailedDiagnostics`に従い、通常版は無効とする。`[MAP-HEAP]`は現在空き量・起動後最小値・最大連続空きブロックと残スタックを出力する。値の意味と実機結果は[地図生成時の空きヒープ計測](検証/地図生成時の空きヒープ計測.md)を参照する。

共通のUTF-8検証は`utils/Utf8.h`、SDパスからFatFsパスへの変換は`task/storage/StoragePath.h`へ集約する。vectorを返す互換APIでは対象番号用vectorを再利用する。通常の地名検索は固定128件のトークン配列と返却先への直接出力を使用する。[メモリ整理の検証結果](検証/共通処理とメモリ整理.md)。

RAWセルは交差矩形と描画対象行を先に求め、行の描画部分だけで出力座標を加算する。直接値・パレットの選択もセル単位とし、画素ごとの除算・剰余と上下の範囲判定をなくす。行内は横方向だけを判定し、復号箇所を一つに保つ。範囲外の入力も従来どおり復号し、読出し順序と終端検査を維持する。行バッファは追加しない。[RAW行処理の検証](検証/RAW行処理の検証.md)。

地図は240×101画素の全面を使い、倍率（1/1・1/2・1/4）・距離目盛り・北方位・地名を黒い背景帯なしで重ねる。地名1行目は8×8、2行目はWordbook言語が`ja`なら16×16・それ以外のASCIIなら8×16とし、文字周囲の1ドットだけを黒く縁取る。カーソルはこれらより手前に描画する。追加の画像バッファは確保しない。

現在地の地名更新は地図画像の再生成から独立している。コードキャッシュのサイズ比較（128・64・32画素角）と採用理由は[実機検証](検証/区域コードキャッシュと地図地名更新の検証.md)を参照する。


## リファクタリング後の共通処理

画面ショートカット・MENU項目・フッターの数字は`task/ui/ScreenNavigation.h`の`MenuScreens`から取得する。`UiModel::keyGuide()`は上下左右の操作可否とフッター表示の共通の判定を提供し、一覧の端・編集中・処理中・ライセンスのジャンプ位置を描画側で再判定しない。確認ダイアログの有効性は`updateDialogState()`へ集約し、内容更新時と確定入力時の両方で検証する。App・Storageの受付時検証は維持する。

LIVEとGPS画面の数値整形は`GpsPresentation.h`へ集約する。表示位置と単位は描画側で指定し、GPS画面の受信済み品質情報とLIVEのFix喪失時の表示規則を維持する。廃止済みF1/P操作、個別のPause/Stop確認、空のLIVE入力関数は持たない。地名検索のスケジュールは格子とsample_seqで決まり、未使用の周期用時刻引数は持たない。

`PlaceLookup`は指定されたディレクトリの`dataset.ini`を必須とし、拡張子によるGLC・Wordbook探索は行わない。未設定のインスタンスは未選択としてI/Oを行わない。追加ファイルがあってもINIが指すファイルだけを使用し、INI欠落時に別のファイルへフォールバックしない。実ファイル試験もこの経路を使用する。

通常版の診断設定と再現用ベンチマークの準備・保存方法は[パフォーマンス検証ツール](../../tests/performance/README.md)を参照する。計測コード・比較用Galuchatコピーは生成した隔離ディレクトリだけへ配置する。

地図の元画像は`map/MapSession.h`で保持し、Storageの通常地図用・ログ地図用Sessionを分ける。MapBuildJobは処理の間だけSessionを借用し、ReleaseMap後は地名検索・ログ保存を通常どおり処理する。範囲内の区域変更は元画像から境界だけ再生成し、SDを読まない。範囲外・倍率変更では同じ32bit配列を上書きする。離脱・文字表示への切替・消灯時にCloseMapSessionで解放する。

Storageの同期結果・完了通知の未送信データはStorageRepliesの共用体で保持する。索引の読取り専用検証では比較用Sourceのみを確保し、書込み用ファイル・バッファを作らない。ログを1で文字表示へ戻す際はUIの画像表示を無効にする。2枚の固定配列は常駐し、未返却の貸出しはStorageの取消確認後に解消する。


StorageWorkAreaはLogReaderとMapBuildJobをstd::variantで排他保持する。FILはvariantの外に置いたStorage所有の固定2枠へ集約する。地図とログ閲覧は第1枠を借り、地名検索は第2枠を索引・GLC・Wordbookで順に使う。索引の生成・突合・候補GLC調査は最大2枠を借り、3枠目は動的確保せず拒否する。地図の事前確認・索引・GLCは順に同じFILを借り、地図用ReaderはFileReadSourceのwithRange内でスタック上に構築・破棄する。Reader本体とFILのヒープ確保を地図生成経路から除き、SDK互換Factoryと他の処理経路は維持する。UIのMapFrameReceiverは6,060 Bの固定画像を2枚所有する。Appがbackの貸出しを同期取得してStorageへ渡し、MapBuildJobは借用先へ直接生成する。Storageの生成用画像とAppの行転送配列は持たない。MapCompleted後、AppがReleaseMapの成功を回収してからUIへCommitMapFrameを送る。失敗・取消時はStorageの返却確認後にUIへDiscardMapFrameを送る。画面を離れても未返却の貸出しは保持し、完了・取消が遅れても同じ領域を再貸出ししない。未完了の読出し・地図結果は切り替えず、ログ結果の返送領域へのコピー後、ファイルcloseが成功してからReaderを破棄する。MapSessionの区域コード画像とUIの表示・受信画像は共用領域の外に置く。固定FILもジョブ切替で破棄せず、全借用の終了後にStorage所有者が破棄する。切替とclose失敗の試験は`python3 tests/run_storage_work.py`で実行する。メモリ・所要時間の比較は[Storage作業領域共用の検証](検証/Storage作業領域共用の検証.md)を参照する。

地図生成の索引ReaderとGLC Readerは、UIから貸し出されたback画像の先頭4KiBを順に借用する。全Readerが破棄されて借用が解除された後に同じ配列へ境界画像を生成し、両Readerの読出しバッファの動的確保を省く。GLCの先読みは4KiBとし、作業領域またはFIL枠のない読出しは拒否し、自己確保は行わない。`python3 tests/run_borrowed_reader.py`で寿命・排他・例外時の返却を検証し、`run_borrowed_map_files.py <map> <wordbook>`で区域コード・境界画像と要求確保量を比較する。

借用導入前後の空きヒープ・連続空き領域・所要時間は[Reader借用バッファの実機比較](検証/Reader借用バッファの実機比較.md)を参照する。

Wordbook検索は、TT00の対象選択とTM00のトークン選択で同じ番号配列を段階ごとに再利用し、必要件数を予約して容量の過剰な成長を避ける。メタデータの現在セクション名と索引検証の前言語IDは小さなスタック配列に保持する。LogReaderのパス作業用stringは同じReaderの一覧・概要・測位点・削除で容量を再利用する。検索間のWordbook作業領域保持は行わない。[3件の実機比較](検証/3件の小規模メモリ整理の実機比較.md)に確保回数、ピーク、処理時間を記録する。

ログ画面群を離れた際は、Appが終端結果を回収した後にReleaseLogBrowseを一方向通知する。Storageは世代を照合し、読出し・結果返送・closeの終了後に作業領域を再利用可能にする。フルパスは操作時だけスタックへ構成し、LogWriterは正常close後に保持対象の所有を終える。最後のファイル名は状態スナップショットへ残す。消灯時のUI画像保持は従来どおりとする。アプリ側の16バイト固定ヘッダ照合にはFixedHeader.hを用い、文字列の一時確保を行わない。[実装検証](検証/寿命整理と固定ヘッダ照合の実装検証.md)を参照する。


借用領域はMapReadWorkspace（Readerとパス）・PlaceReadWorkspace（Readerと結果）の用途別構造体で配置を定義し、BorrowedLayoutへ容量・アラインメント検証と構築・破棄・型変換を集約する。読出し配列を初期化時にゼロクリアせず、結果だけを初期化する。[整理と性能比較](検証/借用メモリの型付きレイアウト整理.md)を参照する。

地名検索もUIの固定backを作業域として借りる。BeginPlaceSearchでアドレス・容量・貸出しIDを取得し、SearchPlaceへ渡す。先頭にPlaceResult、その後にReader用4KiBとトークン用512Bを配置する。Reader領域を索引・GLC・Wordbookへ順に渡す。Storageの完了通知はメタデータだけとし、AppのprocessPlaceが結果を確認してCommitPlaceSearchまたはDiscardPlaceSearchを送る。通知ハンドラから同期UI要求は送らない。画面離脱・消灯・古いログ点の結果でも処理終了まで貸出しを保持し、返却を確認してから新しい検索・地図生成を許可する。Appの通常表示スナップショットも確定済み結果に揃え、古い地名への巻戻りを防ぐ。地名検索の地図・索引・Wordbookは、Storage所有の`FileReadSource`を参照する。Factoryと`shared_ptr`は保持せず、読出し中だけReaderをスタックに構築する。作業バッファは検索の引数として渡し、保持情報には保存しない。索引Readerを閉じてから本体Readerを開く順序を維持する。アプリ内のFactory互換アダプタは廃止する。SDK本体の汎用APIは変更しない。候補確認も借用バッファ付きのSD Sourceを使う。`tests/run_borrowed_place_files.py <map> <wordbook> ...`で実データの結果一致・確保削減・例外時返却を検証する。

地名検索のUI作業域借用の実装・確保量・実機書込み結果は[検証報告](検証/地名検索のUI作業域借用の検証.md)を参照する。

不要コード・重複初期化・終了通知型・診断と専用テストの整理結果は[不要コード整理の検証](検証/不要コード整理の検証.md)を参照する。

RGの表示を廃止し、全画面共通のSDカードアイコンへ統一した。12×12の48バイト定数パターンをFlashへ置き、右上で暗灰／青を切り替える。USBコールバックの実セクタI/OもStorageが既存のSDアクセス通知へ集約する。[共通仕様](画面・操作/共通ステータスアイコン.md)を参照する。

全画面の共通ヘッダーはSDカード→電池アイコン→残量率の順とし、電池は既存の5秒周期で更新する。READING/LOADING等の単純な読出し文言は省き、SD実アクセス表示へ統合した。削除・保存終了待ち・生成/検証の進捗とエラー表示は維持する。

ログ一覧のサイズ由来件数・ページ表示・直接閲覧とSDアイコン更新は[検証報告](検証/ログ一覧と直接閲覧の検証.md)にまとめる。

## 固定の区域コード領域

StorageTask内のStorageCodeImagesが地名判定用64 KiBと地図用96 KiBを所有し、CachedMapReaderとMapSessionは借用参照を使う。両配列はヒープを使わず、画面の有無にかかわらず予約する。地図用は通常地図/ログ地図で1枚を排他的に使用する。CloseMapSession後も有効な内容を保持し、要求のデータセット世代・緯度経度・倍率等が一致すれば再描画する。容量超過時はエラーを返し、動的確保へ逃げない。詳細は[設計と借用候補](14_Storage固定画像領域と作業領域の設計.md)を参照する。


SD専用化後のFILは552 B、共有2枠は1,112 B。VFSのstdio・stat・ディレクトリ操作も専用版へ接続し、Galuchatの4KiB先読みは維持する。[固定FIL2枠とSD専用FatFsの実機比較](検証/固定FIL2枠とSD専用FatFsの実機比較.md)に静的RAM・実行中ヒープ・処理時間を記録する。

地名検索の通常経路は、UI backの先頭にPlaceResult、その後ろにReader用4 KiBと128件のuint16_t配列2本を置く。TIの階層番号とTMの出力位置は局所スタックで処理し、1階層ずつ返却先へ直接出力する。1行385 Bの返却容量を持つが、表示幅で省略し、満杯の行の後続検索を打ち切る。トークン数128件超過は容量エラーとし、ヒープへ退避しない。Galuchatの既存vector APIは残し、アプリ内の追加APIを使用する。

ログのルートはConfig.hのLogDirectoryをROMから借用する。LogWriterはLogSnapshot::name、LogReaderは要求内のnameを使い、フルパスのstringを保持しない。ファイル操作ごとのTemporaryPathと、512バイトのヘッダー処理をnoinlineの別関数へ分け、スタックの大きな領域を重ねない。保存・close失敗時は同じ名前で再試行し、削除保護はルートと名前を照合する。ホスト用のカスタムルートは呼出し元がReader／Writerの寿命中保持する。

設定からの索引適用・再生成・検証では、StorageIndexLeaseがStorageMapMemoryの96 KiBを地図から保守用へ切り替える。地図の未完了処理・未返却結果・FIL使用中は拒否し、開始時に両MapSessionを無効化して参照を外す。DatasetIndexWorkが4 KiBを2本、座標最大12,000 B、最大16言語の辞書情報表2,756 Bを貸し、成功・失敗後に地図型と参照を再構築する。既存の地図は再生成が必要になる。INI解析は固定出力・局所スタックを使う。索引処理の辞書情報は同じ固定作業領域、進捗言語名・識別子は局所配列へ移し、適用・再生成・検証のアプリ正常経路のC++確保を除去した。借用しないDatasetIndex APIは自己確保する互換経路を維持する。


データセットの一覧・詳細・言語候補はUI backをBeginDatasetReadで借り、StorageがDatasetViewへ直接書く。Appは完了通知を通常ループで回収し、CommitDatasetRead／DiscardDatasetReadで確定・返却する。画面変更や要求の差替えでも書込み終了前に返却せず、Appの通常更新でUI所有の結果を上書きしない。現在言語・件数・位置と候補の再問い合わせは従来どおりとする。

起動時・適用後のCheckDatasetはStorageIndexLeaseで既存96 KiBを一時利用し、Reader用4 KiBを索引・GLC・Wordbookへ順に貸す。占有中はWaitingとして再要求し、選択を解除しない。INI解析は言語上限16の固定出力と局所スタックへ移行し、C++ヒープ確保を行わない。候補確認も同じ96 KiBからバッファを借り、WordBookHeaderReaderで初期化と標準ヘッダー確認を共用する。標準IO等の内部確保は別に扱う。[実装と検証](検証/データセット表示のUI借用と初期化Reader共用.md)を参照する。


INIはreadDatasetMetadataIntoで実行用の固定結果とUIのタイトル・説明の返却先へ出力する。16件の言語IDと行の配列は解析関数内のスタックだけに持ち、初期化はreadSelectionを戻ってからReader確認へ進む。`python3 tests/run_metadata.py`で16/17件・切替・UTF-8省略・異常系とC++動的確保0件を確認する。run_native.pyもこの試験を含む。[INI解析の固定出力とスタック化](検証/INI解析の固定出力とスタック化.md)にメモリ・検証結果を記録する。

索引操作の固定辞書表・スタック・C++確保回数の比較は[索引保守のヒープ除去](検証/索引保守のヒープ除去.md)を参照する。


データセットの詳細・言語候補・適用前確認はStorageIndexLeaseで96 KiBを借り、GLCの4 KiB×2本を使った後にWordbookへ順に貸す。表示結果はUIの借用先、ReaderとWordbookのヘッダー値は局所スタックへ置く。候補確認では保存索引を必要としない。保持中の地図は無効化され、次の地図表示で再生成する。WordBookHeaderReaderは起動時にも共用し、任意メタデータを長さだけ確認して読み飛ばす。SDKの展開関数は再利用するが、SDKのWordbook Readerインスタンス・Factoryを本番で生成しない。INI・ログ・USBエクスポートはそれぞれの既存ファイルI/Oを使う。[検証とReader経路の監査](検証/候補確認のSDReader統一.md)を参照する。

互換・比較用の旧経路を廃止した後の状態と、過去の記録を用いた性能・メモリ確認は[互換経路整理と実機計測](検証/20261029_互換経路整理と実機計測.md)を参照する。通常版は計測後に実機へ書込み済み。

全画面のフッターとESC/Delの文脈別動作は[共通キー操作](画面・操作/共通キー操作.md)を正本とする。グローバル・数値・ローカルの順に詰め、グループ間だけ1セル空ける。UiModel::shortcutGuideとUiRenderer::presentで画面ごとの重複を除き、R等の物理キーの配送一覧も共用する。

履歴地図の再生速度は¼×・½×・1×・2×・4×。方向・速度はヘッダーの固定位置へ表示し、先頭／末尾でPAUSEにする。選択した間隔は読出し・地名・地図が準備できてから確保し、遅延時も点を飛ばさない。間隔はConfig.h、共有判定はLogReplay.h、操作受付と再生進行はLogBrowser.cppへ配置する。

TABは数値画面選択がある場所で次の有効な番号へ順送りする。トップは1→2→3→4→0→1、ログ閲覧は1→2→3→1。TABの案内は表示せず、Vは廃止する。物理TABはKeyboard.keysState().tabで押下エッジを検出し、HIDのKEY_TAB=0x2bをASCIIの＋として扱わない。
