# 起動モードとUSBストレージ

起動フラグによるモード切替とSDのUSB公開は実装済みである。USBメニューからのGPX・KML・CSV変換とSD所有権切替も実装し、詳細は[ログエクスポート仕様](10_ログエクスポート仕様.md)に集約する。

## 起動時の分岐

アプリケーションの起動モードはGPSロガー・USBストレージ・Wi-Fi管理の3種類とする。通常のGPSロガーモードにはLive Place・GPS記録・設定・ログ閲覧を含み、記録の開始／停止状態とは区別する。起動時にNVSのフラグを読み、その起動中に使うタスクとSDの所有者を決定する。

| 起動モード | 起動するアプリケーションタスク | SDの扱い |
|---|---|---|
| GPSロガー | App・UI・GPS・Storage | StorageがFAT32をマウントし、地図・辞書・ログを処理する |
| USBストレージ | App・UI・Storage | PC公開中は生セクタを公開する。エクスポートの端末操作中だけPC公開を止め、StorageがFatFsをマウントする |
| Wi-Fi管理 | App・UI・Storage | StorageがFAT32をマウントし、同じタスク上のWebサービスからファイルを操作する。GPS・MSCは開始しない |

USBのデバイス処理はTinyUSBのシステムタスクで実行する。通常モードは従来の4タスク・5キュー、USBモードはGPSタスクとそのキューを作らず、App・UI・Storageの3タスク・4キューとなる。専用の要求キューや一時ログバッファは増設しない。USBモードではGPS・地図・Wordbook・通常モードのログ閲覧を開始せず、データセットが欠けていても終了操作を行える。エクスポート対象の選択はUSBモード専用の画面とする。

全モードでUIタスクのM5本体・表示初期化完了を同期応答で確認してからStorageを起動する。USBモードでもSDのSPI初期化をUIの本体初期化と並行させない。USB画面を準備した後、Storageの初期化結果をUIへ反映する。

## 動作モード別の固定領域

GPS・USB・Wi-Fiは、専用App・UI・Storageタスクと専用の通信型を持つ独立アプリケーションとする。最上位のApplicationMemoryはアプリ全体をunionへ配置し、起動フラグを読んだ後に一つだけ構築する。固定予約は各アプリの最大値と管理領域の合計であり、USB型にGPSの地図・記録資源を含めない。稼働中の切替は行わない。詳細は[動作モード別メモリ構成設計](18_動作モード別メモリ構成設計.md)に従う。

## Wi-Fi管理モードの追加仕様

ファイル単位のアップロード・削除、ディレクトリ操作、テキスト表示・編集を行うWi-Fi管理モードは、[Wi-Fi管理モード仕様](19_Wi-Fi管理モード仕様.md)に定義する。基本のファイル管理を実装済みとし、tgz受信中展開は後続機能として追加する。GPS／USBとの排他と最上位モードunionを維持する。

## 永続フラグ

NVS名前空間`geoputer`の`boot_mode`キーへ、4バイトのレコードを保存する。内容は`M`、形式バージョン1、モード値、モード値と0xA5のXORとする。モード値は0がGPSロガー、1がUSBストレージ、2がWi-Fi管理。未設定はGPSロガーとし、不正・読取失敗でもGPSロガーへ戻してログへ記録する。

起動前の読取りを除き、フラグの書込みはStorageが行う。既存の`config`レコード、データセット番号・言語、記録間隔等は変更・消去しない。設定レコードの現行形式バージョン5と48バイトの長さも維持する。保存に失敗した場合は再起動せず、現在のモードとフラグを維持して失敗を表示する。

## GPSロガーからUSBストレージへ

設定のトップ階層に「システム設定」を置き、子画面に「モード」「GPS接続」「保存して再起動」「初期化」を並べる。初期化は既存の設定初期化画面を開き、SDフォーマットはストレージ操作に残す。モードはGPSロガー／USB／Wi-Fiを左右キーで直接編集する。項目を移動またはEnterで候補を確定し、未確定の変更はEscで取り消す。編集確定はUI内の候補確定であり、保存は行わない。GPS接続は現在Mesh Kit固定の読取専用で、外付けGPSは未実装とする。起動中に反映する動作設定・データセットはこの画面へ移さない。

「保存して再起動」で共通確認ダイアログを開き、「取消／再起動」を横並びに表示する。初期選択は取消、左右で選択、Enterで確定、Esc / Delで取消。確定時にUSBストレージのフラグ保存をStorageへ要求し、成功通知を受けてから再起動する。変更なし、Storage処理中、NVS利用不可、記録停止条件未達の場合は保存項目をグレーアウトして理由を示す。確認取消は候補を保持し、システム設定から設定トップへ戻ると候補を破棄する。

記録はSTOPPEDでなければ切り替えない。PAUSED・STARTING・RECORDING、Appの保留測位点、未保存レコード、開いているセッション、終了処理中は切替不可とし、先に記録を停止するよう表示する。AppとStorageでも再検証し、古い画面状態だけを根拠に再起動しない。モード切替の確認で記録を自動停止しない。先行するSD処理中は切替を無効にし、完了後に受け付け、使用中の地図・辞書を閉じてSDをアンマウントする。

次の起動ではUSB用のSD初期化だけを行う。PCにはカード全体をUSBマスストレージとして公開し、ログ取得、dataset.ini編集、GLC・Wordbookの入替えができる。

## USBストレージからGPSロガーへ

USBモードの入口は「ログを書き出す」「ロガーへ戻る」のメニューとする。「ロガーへ戻る」またはUSBメニューのEsc / Delで共通終了ダイアログを開く。「取消／終了」を左右で選択し、Enterで確定する。取消・Esc / Delではフラグを変えずUSBメニューへ戻る。0/1/2/3・F1・Dでは通常モードの別画面へ移動しない。起動直後に終了確認は開かない。PC公開中でも終了項目を有効とし、端末側の明示確認でUSB公開を停止して復帰できる。

終了確認には「PCの保存完了後に終了」／「Finish PC saves first」と表示する。PCでのコピー・編集・保存を完了してから端末の終了を確定する。Windows側をクイック削除に設定した運用では、PCの安全な取り外し操作を必須としない。PCの取り外し通知を受けると媒体を非公開にしてEJECTEDを表示するが、それだけではフラグ変更や再起動を行わない。

終了確定時は、実行中のUSBセクタ処理が終わるのを待ち、新規転送を止めてSDへ同期を要求する。その後GPSロガーのフラグを保存し、新しいUSBアクセスを止めて媒体を非公開にする。Storageから完了通知を受けたAppが再起動する。同期やフラグ保存に失敗した場合は現在のモードを維持し、再試行できる。PC内の未送信キャッシュは端末から同期できない。クイック削除以外のポリシーなどでPCの書込みキャッシュが有効な場合は、安全な取り外しを先に行う。端末側のSD同期だけでPCの未送信データまで保存できるとは扱わない。

USBモードで電源を切ってもフラグはUSBのままであり、次回もUSBモードで起動する。USBケーブルの抜去だけでは通常モードへ戻さない。画面の自動消灯も行わず、終了操作を常に可能にする。SD初期化に失敗した場合もエラーを表示し、終了ダイアログで戻れる。

通常モードへの復帰時はSDとデータセットを改めて検証し、変更された書式・地図・辞書を読み直す。USBモードより前のRAMキャッシュは再利用しない。

## USBモード内のログエクスポート

「ログを書き出す」では、対象ログと出力形式を選び、Storageが変換する。初期対応として設計する形式はGPX・KML・CSVとし、出力先は`/export/`、出力名は元のファイル名全体に`.gpx`・`.kml`・`.csv`を追加する。元の`.gps.dat`は保持する。

PC公開中だけ安全な取り外しを案内し、完了を確認してからUSB公開を停止してFatFsをマウントする。未接続・安全な取り外し済みなら案内を省略する。変換中のケーブル接続でもSDは公開せず、完了後にファイルを閉じ、同期・アンマウントを済ませてから再公開する。未接続なら接続待ちとする。この切替はUSBモード内で完結し、GPSの起動・NVSフラグの変更・再起動を行わない。詳細は[ログエクスポート仕様](10_ログエクスポート仕様.md)に集約する。

## USBとSDの実装

Arduino-ESP32のUSB-OTG / TinyUSBを使い、`ARDUINO_USB_MODE=0`とする。CDCは自動起動させず、アプリケーションが起動モードを読み、必要なクラスを登録してからUSBを開始する。全モードともUI・SDの初期化より先にUSBコントローラを初期化する。USBモードではその直後に切断状態とし、StorageのSD初期化と画面準備が終了してからPCへ接続する。初期化中の一時的な媒体なし状態をPCへ公開しない。SD初期化に失敗した場合もUSB接続と終了操作は可能にする。

USBシリアルは全モードで使用し、MSCクラスはUSBモードでだけ登録する。通常モードのUSBシリアル番号はMAC由来の既定値、USBモードは同じ値へ`-SD`を付け、異なるインターフェース構成をWindowsが同一機器の履歴として混在させない。再起動時はUSBを明示的に切断し、PCが取り外しを検出する時間を設けてから再起動する。WindowsでのCOM番号は従来のUSB Serial/JTAGから変わる場合がある。

SDのSPI配線と`Config.h`の`SdSpiHz = 25'000'000`（指定上限25MHz、現行ドライバーの実クロックは20MHz）は通常モードと共通とする。マウント・フォーマット・USB公開開始・再公開の全経路でこの定数を使う。PC公開状態では`sdcard_init`とブロックドライバの初期化を使い、`sdcard_mount`やFatFsのファイルAPIは呼ばない。端末操作状態への切替ではUSBセクタI/Oの停止と進行中I/Oの終了を確認し、FatFsの使用期間と分離する。MSCの読書きコールバック・所有権切替・終了処理を排他し、512バイトの作業領域を一つ持つ。部分セクタの書込みは既存内容を読んで対象部分だけを変更し、隣接データを維持する。要求全体の範囲を64ビットで検証し、範囲外ならSDへ触る前に失敗する。

USBの準備完了・取り外し・I/O異常はStorageが最新状態を保持し、通常のApp通知キューへ投機的に通知する。通知できないときも保持して再試行する。TinyUSBのコールバックからAppへ同期要求を送らず、UIやGPSのキューとも混在させない。

実装は`BootMode`、`ApplicationRuntime`、`apps/usb`、`task/storage/usb`、共用描画部品`apps/common/PanelRenderer`に配置する。[Espressif USB MSC API](https://docs.espressif.com/projects/arduino-esp32/en/latest/api/usb_msc.html)と、使用中のArduino-ESP32 2.0.17の実装を基準とする。
