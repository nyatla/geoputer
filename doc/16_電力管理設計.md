# 電力管理設計

## 1. 方針とレベル

動作設定の「省電力 / Power saving」からレベルを選択する。起動中に変更でき、既存の設定保存経路でNVSへ永続化する。初期値と旧設定からの移行値は1「しない」とし、オーディオを常時有効にした比較版の動作を維持する。

| レベル | 表示 | 方針 |
|---|---|---|
| 1 | しない / Off | 動作モードで使わない機器を固定停止。利用する機器の動的な電力管理はしない |
| 2 | 通常 / Normal | 上記に加え、利用状態に応じた電力管理を行う |
| 3 | 最大限 / Maximum | 当面は通常と同じ。将来の拡張用 |

USBは全レベルで現在の動作を維持する。既存の画面消灯・復帰やGPS／記録のユーザー操作も独立して維持する。LoRaの固定SLEEP・リセット保護、Wi-Fi／BLEを起動しない方針は変更しない。オーディオに電力管理を導入したことを理由に、GPSやSDを新たに休止しない。

## 2. モジュールと所有者

`application/power/PowerManager.h`はレベルと起動モードから機器方針を決める。方針の計算にはヒープもハードウェア操作も使用しない。Appが確定したレベルを既存のUI同期更新で渡し、UI内のPowerManagerが方針を反映する。App側の通知期限計算も同じ方針関数を使用する。

実機の操作は機器を所有するタスク内で実施する。オーディオの実体はUI所有の`power/AudioPower`と`hardware/AudioOutput`である。前者が電源・ミュート・復帰待ち、後者がROM音列・音量・通知期限を扱う。新たなタスク・キュー・画像領域は設けない。音声ライブラリ内部の再生ワーカーとDMAは起動時に一度だけ確保し、再生ごとに作り直さない。

GPSロガーモードではオーディオを利用可能とし、レベル1は常時有効、2・3は動的管理とする。USBストレージモードではオーディオを使わないため、全レベルでDAC・出力段を固定停止し、音声ワーカーを起動しない。USB通信・USB給電の制御は追加しない。

## 3. 通常レベルのオーディオ管理

ES8311全体を深いパワーダウンへ入れず、DACと出力段を待機停止する。RESET 0x00、SYSTEM 0x0D / 0x0E、クロック設定を再生ごとに変更しない。前の不安定な電源切替方式をそのまま戻さない。

待機停止は次の順とする。

1. 音声ドライバへ停止を指示する。
2. 非同期の再生バッファが解放されるまでUIループで待つ。
3. DMAに残る末尾データを考慮し、さらに20 ms待つ。
4. DACをソフトミュートし、出力段を無効にし、DACをパワーダウンする。
5. DAC・出力段レジスタの読戻しを確認してSTANDBYとする。

再生開始は次の順とする。

1. ソフトミュートしたまま、ROM上の無音PCMを音声ドライバへ渡す。
2. クロック始動のため40 ms待つ。
3. DAC・出力段を有効化し、読戻しを確認する。
4. 安定待ちとして80 ms待ち、ミュートを解除する。
5. 同じチャネルの無音PCMを通知音で置き換える。

各待ちは単調増加時刻の期限で管理し、UIタスクをsleepやbusy loopで塞がない。休符と繰返し間の短い待ちは同じ発音セッションとして電源を維持する。復帰途中で取消された場合も、停止とDMA待ちを経て待機停止する。停止待ち途中の再通知は、古い停止完了で新しい通知を電源断しないよう、復帰経路へ切り替える。

「しない」への切替では、待機停止中なら同じ復帰手順を経て有効に戻す。再生要求がなければ無音PCMを停止し、無音データを流し続けない。「通常」への切替では、再生中の音を中断せず、終了後に待機停止する。

ソフトミュートは[EspressifのES8311ドライバ](https://github.com/espressif/esp-adf/blob/master/components/esp_codec_dev/device/es8311/es8311.c)のDAC_REG31の扱いを参照する。DAC停止はM5UnifiedのSYSTEM_REG12 bit1、出力段はCardputer ADVのSYSTEM_REG13 bit4を使用し、その他の初期化値を保持する。I2Cや再生の失敗時は再生を停止し、可能な範囲でミュートし、エラーを記録する。エラー後は新しい音を開始せず、再起動で初期化し直す。

## 4. 通知期限

復帰待ちを音列の一部として消費しない。実際の音列は電源準備完了後に開始する。1回通知にはAppとUIで共通の500 msの準備予算を追加し、復帰中にAppが先に終了させることを防ぐ。UIは音列が1回終了した時点で再生を止めるため、余った準備予算の間に繰り返さない。

時間指定と「停止まで」の最大60秒は受付時刻からの上限を維持する。再通知でも最初の開始から60秒を延長しない。消音キー、音量、音種、境界判定方式を変更しない。

## 5. 設定保存とメモリ

NVSレコードは48バイトのまま形式バージョン5、項目数9とする。オフセット11の下位3 bitに共通音量0〜4、bit3〜4に省電力の選択番号0〜2（レベル1〜3）、上位3 bitはゼロを格納する。GPS接続、データセット、言語と既存項目の保存位置は変えない。旧v1〜v4を読み込み、省電力は「しない」を補う。旧v4の音量も維持する。予約値・値域外・チェックサム不一致を拒否する。

電力状態はUI内の固定メンバー、無音PCMはROM上の128バイト固定配列とする。電源切替のたびのヒープ確保・解放、音声ドライバの再作成、追加のバックバッファは行わない。レジスタ読戻しとログ上の停止確認は、消費電流の実測とは区別する。

## 6. 実機確認

2026-10-30、通常レベルで2〜3秒間隔の試聴を繰り返し、利用者が毎回発音し待機中も静かなことを確認した。ログでもクロック先行復帰・準備完了・DAC／出力段待機停止を確認した。消費電流は未測定である。[検証結果](検証/省電力レベルとオーディオ待機停止の検証.md)を参照する。
