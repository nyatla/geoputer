# ログプロパティと統計表示の設計

文書状態: 採用・実装（2026-10-27）。一覧→プロパティ→Enter→文字表示とし、Mの表示メニュー、Rの統計再計算、8件単位の分割集計を実装する。実測値と検証結果は[検証記録](検証/ログプロパティと統計表示の検証.md)に記載する。

## 1. 画面と操作

ファイル選択後は、選択メニューを持たない情報専用のプロパティ画面を開く。そこでEnterを押すと文字表示へ進む。その後のVによる文字/地図切替、地図のPによる再生/一時停止は現行の操作を維持する。

```text
LOGS → プロパティ → Enter → 文字表示 ← 1/2 → 地図表示
          │                    │              │
          └────────── M: ログ用ショートカット ─┘
                           │
                         統計
                           ↓
                     統計情報の別画面
```

| 画面 | 操作 | 動作 |
|---|---|---|
| 一覧 | Enter | 選択ファイルのプロパティへ |
| プロパティ | Enter | 文字表示へ。新しく選んだファイルは最初の点から |
| 文字/地図 | 1 / 2 | 同じ点で表示方法を切替 |
| 地図 | P | 再生/一時停止 |
| プロパティ・文字・地図 | M | ログ用ショートカットを開く |
| 文字/地図 | Esc / Del | プロパティへ。表示点を保持する |
| プロパティ | Esc / Del | 元の一覧・ページ・選択行へ |
| 統計情報 | Esc / Del | 呼出し元へ。計算中なら取消を要求する |
| 統計情報 | R | 明示的に再計算する |

同じファイル内の往復では表示点を保持する。プロパティからEnterで戻る場合は文字表示とし、新規ファイル選択だけ先頭へ戻す。Mを開くとリプレイを一時停止し、閉じても自動再生しない。

ショートカットは既存の中央ダイアログとChoiceDialog::openActionsを使い、横並びの「文字 / 地図 / 統計」、英語ではTEXT / MAP / STATSを表示する。左右で選択、Enterで決定、Esc/Delで取消とし、取消の選択項目は置かない。初期選択は統計とする。地図が使えない場合は地図だけを無効にする。形式不正など、処理できないことが既に分かる操作も無効にする。

## 2. プロパティに表示する基本情報

| 項目 | 内容 |
|---|---|
| ファイル名 | 一覧同様に末尾.gps.datを省略。必要なら折返し/スクロール |
| 記録件数 | サイズから得る保存済みの完全な32バイトスロット数 |
| ファイルサイズ | BまたはKiB/MiBで表示 |
| 開始日時 | 最初の測位点の日時、JST |
| 終了日時 | 最後の測位点の日時、JST |
| 経過時間 | 終了−開始。一時停止等の記録の空白も含む |

取得できない値は--とし、開始/終了の時刻が逆転している場合も経過時間を推測しない。全件の移動距離・最高速度・高度範囲はこの画面で計算しない。

既存のLogSummaryとReadLogSummaryを再利用する。現在の概要取得は512バイトのヘッダーと先頭/末尾の32バイトレコードを対象にし、全レコードを走査しない。ファイルシステムのメタデータ取得や末尾へのseekは別に発生するため、所要時間は実機で確認する。形式/ヘッダーと端点のエラーは基本情報に表示する。

一覧の件数表示は引き続き一覧走査時のstatだけから計算する。プロパティを開いた時点の保存済み範囲とは取得時点が違うため、記録中のファイルでは件数が増えている場合がある。

## 3. 要求したときだけ計算する統計

| 項目 | 集計内容 |
|---|---|
| 概算移動距離 | 隣接する記録点間の距離の合計 |
| 最高速度 | 速度項目を持つレコードの最大値 |
| 最低高度 | 高度項目を持つレコードの最小値 |
| 最高高度 | 高度項目を持つレコードの最大値 |
| 対象件数 | 計算開始時に確定した保存済み範囲 |
| 処理時間 | 要求の処理開始から完了までの実測経過時間 |

距離は記録点間を結んだ概算で、GPSの揺れや記録の空白を含む。現行の.gps.datには停止/再開の境界が保存されないため、本仕様では記録点間をそのまま接続し、記録されていない経路を復元しない。移動時間・停止時間の分類、平均速度、累積上昇/下降は本仕様に含めない。

速度・高度の欠損を0として混ぜず、有効な値が一つもなければ--を表示する。記録点が0/1件なら距離は0とし、最大/最小値は存在する項目だけを扱う。レコードのCRC・フラグ・値域は通常の読出しと同じ規則で確認し、破損時は該当点番号付きのエラーとして終える。途中までの値を全件の集計結果として確定しない。

統計画面は計算中もすぐに表示し、対象件数、処理済み件数、進捗バー、経過時間を示す。結果は完成後に埋める。通常のREADING表示は追加せず、実I/Oは既存のSDアイコンへ反映する。データセットや現在のGPS Fixは統計の計算条件にしない。

## 4. 結果の保持と再計算

結果は選択中ファイルに対して固定長の1件だけをRAMへ保持する。ファイル名・セッションID・対象バイト数・対象件数を結果に対応付ける。結果がない初回の3による統計表示だけ計算を開始し、結果がある間は再表示する。プロパティや文字/地図を開くだけでは全件計算を行わない。

Rを押したときだけ新しい保存済み範囲を取得して計算し直す。記録中のファイルでも自動再計算しない。結果には「対象N件」を残し、後から追記された点を含む最新集計であると誤表示しない。再計算中・失敗時に前回の値を新しい完成結果として表示しない。

別ファイルの選択、ログ画面群からの離脱、カードの取り外し/再マウント/初期化で保持結果を無効にする。統計用のファイルやNVSレコードは作らない。

## 5. タスクと通信

### UIとApp

UIは入力と表示を担当する。Mの選択やRは通常のUI操作通知でAppへ伝える。Appがファイル・表示点・呼出し元を保持し、統計画面を指定したうえでStorageへ要求する。計算開始前に旧地図ジョブの書込み権や、地名検索の借用領域の返却を終える。準備中もUIは応答し、旧結果は画面世代で排除する。

統計要求の同期戻り値は受付成否だけとし、走査完了を同期関数で待たない。受付後は既存のApp通知キューで進捗と終端結果を受ける。同期結果のタイムアウト時は、従来どおり同じ戻り値の回収を継続する。

### Storage

StorageWorkAreaのLogReaderに統計操作を追加し、地図生成と排他に扱う。Storageタスク内で固定量ずつ処理し、新しいタスク・キューを作らない。

8件/256バイトを1ステップとする。概要による事前確認後は同じFILで順次読み、1件ごとのopen/closeやseekを増やさない。記録中の対象は既存の保存済み読出しと同じ所有権で扱い、同じファイルを別の書込み主体から開かない。媒体の排他とLogWriterの保存済み読出しを再利用する。

処理区切り（最大32バッチまたは約2ms）で受信キュー・取消・ログ保存を処理する。64件リングが満杯になる場合やflush期限が来た場合は保存を優先し、その後に集計を続ける。GPS通知の処理とAppからRAMリングへの記録受付を止めない。

記録中は計算開始時点の保存済み上限を固定し、後から増える点は次回のRに回す。計算中の一時停止・記録終了、カードエラーでファイルの所有状態が変わる場合も、同じセッションと固定範囲を照合する。

### 進捗・終端・取消

進捗は約200ms間隔で最新値を通知し、レコードごとには送らない。キューが満杯なら最新進捗だけを保持して再送する。終端結果は通常の読出し結果と同様、受付されるまで同じ値を保持する。

取消は既存CancelLogReadと同じトークン照合方式を再利用する。現在のバッチを安全に終え、ファイルを閉じて終端を返す。UIは先に呼出し元へ戻せるが、Appは旧ジョブの終端回収まで同じ作業域を別の要求へ貸し出さない。画面を離れた後に来た結果を表示へ適用しない。統計結果を表示しているだけではStorageを処理中にしない。

## 6. メモリとモジュール

全件や経路の配列は保持せず、必要なのは小さな集計状態、固定バッチ、完成結果1件とする。結果は64バイトのPODとし、距離、最高速度、高度範囲、有効フラグ、処理件数、処理時間を収める。対象セッションとサイズは既存のLogSummaryで保持する。AppとUIには従来どおり独立した値コピーを渡す。

8件分256バイトは既存320バイトの読出し結果領域を使う。集計値64バイトに前回座標16バイトと開始時刻8バイトを加え、LogReaderは4,712→4,800バイトとなる。既存LogReaderのStatistics操作として実装し、結果unionのレコード領域を8件分の読出しに再利用する。FIL・パス・取消処理は共用し、StorageWorkAreaで地図生成と排他にする。ESP32-S3のELFで、通常ファームの静的RAMは95,064→95,512バイト（+448）、UI要求は1,304→1,424バイトと確認した。App通知816バイトと読出し結果504バイトは維持する。UI受信キューはxQueueCreateStaticで作成し、1枠の増分120バイトは上記の静的RAM増分448バイトに含まれる。キューのための追加ヒープ確保はなく、集計件数に比例する確保も行わない。

計算ループでvectorやstringを増やさない。パスとファイルの初回準備は既存のReader方式を再利用し、バッチごとの確保・解放を増やさない。地図へ戻る際は、必要なら画像を再生成し、以前の大きなラスタを統計のために保持し続けない。

| 対象 | 実装内容 |
|---|---|
| UiTypes / ScreenGroup | プロパティ・統計画面をログ画面群へ追加。旧選択メニューは復活させない |
| KeyBindings / ChoiceDialog / UiModel | MとR、3項目のログ用ショートカット、Enter/Escの遷移 |
| UiRenderer | 基本情報と統計の別表示、進捗・空値・エラー、共通SD/電池ヘッダー |
| LogBrowser / Application | 基本情報取得後はプロパティで待機し、Enterで初期点を要求。統計要求・進捗・結果・呼出し元を管理 |
| App側のLogStatistics制御 | 計算要求、キャンセル、結果1件の保持、再表示/再計算を分離する |
| 純粋なLogStatistics集計部 | GpsFixを受ける加算処理。SD/RTOS/UIに依存せず、距離・最大/最小を計算 |
| StorageのLogStatisticsJob | ファイルと保存済み範囲を所有し、固定バッチで復号・集計を進める |
| StorageWorkArea / StorageTask | 排他ジョブ、保存優先、取消、終端結果の保持 |
| LogReadTypes / TaskMessages | 固定長の統計結果と小さな進捗。既存返送union・通知キューに収まるか検証 |

Galuchat、Core、SDKや.gps.datの保存形式は変更しない。

## 7. 検証と計測

1. プロパティ画面、Enter→文字、Escの戻り先を復活させる。重い統計はまだ接続しない。
2. Mのショートカットと統計画面、R、進捗・取消の状態遷移を作る。
3. 純粋な集計部とStorageの分割ジョブを接続する。
4. 正常/欠損/0件/1件/CRC不正、時刻不明、日付変更線・同一点、画面離脱・古い結果、記録中の追記/一時停止/終了をホストで確認する。
5. 実機で所要時間・最大ステップ時間・最低空きヒープ・スタック余裕を計測する。

計算時間は[実機検証記録](検証/ログプロパティと統計表示の検証.md)に記載する。実ログに加えて1千・1万・10万点を対象に、読出しだけ、CRC/復号付き、統計付きの3条件を比較する。対象バイト数は512+32×Nである。距離計算・読出し・検証・全体時間を分け、初回と再実行、記録停止中と記録中を確認する。

1ステップが長ければバッチを小さくし、I/Oが支配的なら読み込み量を比較する。先に実測し、効果と常駐RAMの交換条件が明確な変更だけ採用する。プロパティを開く処理へ全件統計を戻さない。

## 8. 実装上の確定事項

LogStatisticsAccumulatorは固定長の純粋な集計器とし、LogReaderが保存済み範囲の固定、8件の読出し、全件のCRC・値域検証を行う。開始準備では概要と両端の点を検証し、通常ファイルは以降同じFILで連続読出しする。記録中はLogWriterのreadSavedを使い、そのセッションが閉じた場合はヘッダー・セッションID・サイズを再確認して独立FILで続行する。対象ファイルの追記は初回に固定した範囲へ含めない。

Storageは1ループで最大32バッチまたは約2msを処理し、集計中は1tick以上休止する。通知・受付・定期保存の処理へ戻ることを優先し、1バッチ内のSD待ちまでを2msに制限する意味ではない。途中の進捗は再送時点の最新値、終端結果は従来のStorageRepliesで配送まで保持する。

UIが持つ結果は現在の選択ファイルの1件だけであり、Rまたは再入場で必要な場合にだけ要求する。統計中の画面離脱はCancelLogReadで処理し、Appは結果を回収するまで要求識別子を画面資源の外に保持する。

統計の計算中は進捗表示のため自動消灯を延期し、完了後から設定の消灯時間を数える。Sキーによる明示的な消灯は受け付け、集計は継続する。
