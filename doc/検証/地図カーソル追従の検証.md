# 地図カーソル追従の検証

実施日: 2026-10-25

## 動作

地図の生成中心から左右上下それぞれ±32表示画素を含む範囲では、地図を固定してGPSカーソルだけを動かす。範囲はConfig.hのMapCursorRadiusで指定する。いずれかを超えた場合と倍率変更時は周期待ちをせず新しい現在地を中心に生成する。未完成の画像は描画せず、画像と倍率・地名・距離目盛りを一括で交換する。

AppはUIへのCommit成功後に完成画像の座標系を保存し、再生成判定に使用する。UIは自分が表示中のFrameInfoから同じMapTrackingの換算でカーソルを計算する。処理中にGPSが動いても旧画像の座標系で追従し、新画像の完了時にはその生成要求位置からの移動量を反映する。GPS喪失時は最後のカーソル位置を灰色で保持し、復帰位置が範囲内なら再読出ししない。

カーソルは文字より手前に描画する。地図領域はy=18〜118に制限し、ヘッダーとフッターへ描かない。元の配置では中心y=68、マーカーの下端y=78、地名背景y=79であり、地名との重なりを避けた下方向の移動余裕はほぼない。利用者の指定に従い、地名への重ね描きを許容する。地図領域外の位置は偽の端位置へ固定せず、カーソルを描かずに再生成を待つ。

地名と白い区域は生成地点に対応したままとし、カーソルだけが現在地へ追従する。128×128区域コードキャッシュとWordbookキャッシュ、地図の作業配列・境界画像は従来の構成を維持する。新しいキューやタスク、大きなキャッシュは追加していない。

## ホスト検証

- `tests/run_native.py`: 全倍率の±32画素の四隅・端、範囲外、緯度補正、異常座標を確認。既存のUI・GPS・記録・USB等の回帰試験も成功。
- `tests/run_map_scale.py`: 実Appで範囲内の新しいGPSサンプルが地図操作を増やさないこと、32.25画素の移動で即時に要求すること、旧画像の基準位置をCommitまで維持することを確認。再生成中の追加移動が新しい画像に対して4画素のオフセットとして反映されること、GPS喪失・復帰、倍率変更、古い完了通知の拒否も成功。
- `tools/render_map_view.py --scales 1 2 4`: 各倍率の完成・更新中・初回読出し中・未測位・読出しエラー・20画素移動・32画素移動・移動後のGPS喪失の計24シーンが成功。現在地マーカーの位置・色、地名前面への描画、その他の地名画素、倍率表示、上下罫線、4bit / RGB565一致を確認。

## 実機書込みと起動確認（2026-10-25）

MAC `70:af:09:df:46:d0`のCardputerへ、上記SHA-256のバイナリをアプリ領域`0x10000`だけに書き込み、ハッシュ照合が成功した。NVSとSDは消去していない。DISPLAY / TASKS / NVS / FAT32 / GPS UART / GALUCHAT DATAの6項目が成功し、通常起動・GPSの連続Fix（sample 1〜12）・地名更新を確認した。NMEA 190文の解析拒否は0で、観測中のパニックや再起動はなかった。シリアルキャプチャは終了しポートを解放した。

現在のdataset/01は162チャンク、区域コード66082のデータである。起動直後の128×128キャッシュ再構成は矩形本体104.663ms、Wordbook等を含む検索内部処理162.863ms。地図・地名の両ヒットでは内部処理0.086ms、SD・索引のI/Oは0だった。これは今回の地点の参考値であり、地図画面の生成時間や移動追従の実機計測ではない。
