# 表示時計・アクセス表示の検証

検証日: 2026-10-15  
対象: Cardputer ADV、Mesh Kit、240×135 px表示

## 1. 表示仕様

Live Placeの上段に8×8のASCIIで時刻、GPS状態、C / Rを表示する。時刻は(x=4, y=4)、GPS状態は(x=84, y=4)、Cは(x=212, y=4)、Rは(x=228, y=4)とする。CとRは文字自体を点灯し、キャッシュ参照中はCが緑、再読出し中はRが黄、通常は両方が暗灰となる。

時刻は初回の有効FixのUTCから日本時間へ合わせ、以後はUIの単調増加時刻で進める。未取得時は--:--:--とし、取得後はGPS喪失、Settings表示、消灯を経ても継続する。後続のGPS受信による再補正は導入しない。地名と対応座標の保持、アクセス表示の最低150ms点灯は維持する。

## 2. ホスト検証

`python3 tests/run_native.py`が成功した。表示時計は次の条件を確認した。

| 条件 | 結果 |
|---|---|
| GPS時刻の未取得、範囲外UTC | --:--:--を維持 |
| UTC 00:00:00の初回取得 | 日本時間09:00:00として開始 |
| 後続GPSサンプル | 初回の時刻合わせを上書きしない |
| GPS喪失後 | 単調増加時刻から秒を進める |
| Settings、消灯、Live Place復帰 | 時計を維持し、非表示中の時計再描画を抑制 |
| 日本時間・UTCの日付境界、32bit時刻の周回 | 正しく進行 |
| 秒表示の変化 | 描画を要求し、Appへ操作変更通知を送らない |

既存の通信、GPS、設定、Boot、地名保持、アクセス点灯時間のテストも成功した。

## 3. ビルドと実機

PlatformIOのcardputer-adv環境でビルドし、実機へ書き込んで4領域のハッシュ照合が成功した。固定RAMは38,304バイト、プログラム領域は1,480,485バイトだった。

再起動後はBootの6項目が成功し、GPSからの初回時刻取込みを`[UI] clock=10:46:49 JST (initial GPS time)`で確認した。12秒の取得ログ中、この初回取込みは1回だけだった。Live Placeへ遷移し、千葉県／習志野市の地名取得と初回MISS・後続HITを確認した。NMEAは180行、解析拒否は0だった。

ログは`.pio/build/cardputer-adv/clock_flash.log`と`clock_boot.log`に保存した。実機LCDの目視確認と、実機のGPS受信断を伴う時計継続確認は未実施であり、GPS喪失後の時計継続はホストテストで確認した。
