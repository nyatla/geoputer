# 全言語索引と索引保守の検証

検証日: 2026-10-22。対象はReverseGeoputerアプリの索引生成・部分更新・元データ突合と設定UI。

## 実装範囲

バイナリ形式version 1と固定名`_mapindex.dat`を維持し、INIで宣言された全言語のWordbook領域をASCII昇順で収録する。通常適用は、構造・CRCと元ファイルの識別情報が有効な既存領域をコピーし、欠落・変更された部分だけ生成する。言語だけの切替で元GLCを再走査しない。

設定→動作設定→データセットで、全体／地図／辞書を対象に再生成または検証を実行する。対象は保存済みのデータセット番号、辞書は全地名言語。確認ダイアログを経由し、要求受付の同期応答後にStorageが処理する。記録停止・未保存データの保存・セッション閉鎖完了を必要とする。保守はNVS保存・自動再起動を行わない。

元データ突合は、生成アルゴリズムの出力先を読取り専用の比較先へ切り替え、再計算したレコードと既存索引を照合する。仮置きヘッダーは最終値が確定した時点で比較し、実レコードは生成順に比較する。索引全体をRAMへ展開せず、検証用ファイルも作らない。全体検証と部分検証を分け、部分検証の対象外は検証済みの既存領域を使う。

再生成は`.tmp`へ出力し、構造・CRCと再生成部分の元データ突合、再利用部分との一致を確認した後で公開する。失敗時の旧索引復元は従来のトランザクション処理を共用する。地図・TI00・TT00・TM00などの段階、言語、段階内百分率・バー、経過時間を表示し、最終結果に所要時間を保持する。進捗通知は既存Appキューを使用し、最大約200ms間隔へ間引く。

## 実機と検証範囲

この変更の実機書込み、進捗表示の実画面確認、新方式での生成・突合の所要時間は未計測。以前の生成時間12秒／61秒は生成のみの参考値であり、今回の全体再生成はその後に元データ突合を行うため、同じ総時間とは扱わない。

突合する対象は索引の位置・件数・格納長などであり、圧縮本文や全地名の完全復号・全検索を保証しない。再帰深度等の異常値判定強化と、異常リセット後の自動退避は今回変更していない。Galuchatライブラリ・Core・SDKの変更も行っていない。

## データセットメニューへの統合

動作設定→データセットを、データセットを選択・索引を再生成・索引を検証の3項目を持つメニューへ変更した。メニュー表示にSD読出しを必要とせず、メタデータ不正・データセットエラー時も索引画面への入口を維持する。索引画面は使用中の番号と全言語を対象にし、一覧で閲覧した候補番号へは切り替えない。ストレージ操作の索引入口は移動し、カード操作4項目へ戻した。

再生成・検証を選ぶと、それぞれの実行項目を選択した状態で共通索引画面を開く。Esc / Delはデータセットメニューの同じ入口へ戻る。一覧の戻りもデータセットメニューへ変更し、その戻りは動作設定のデータセット項目へ戻す。確認・取消、対象選択、処理中の画面維持・消灯抑止は共用する。

データセットメニューへの統合後のnative試験は成功した。メタデータ不正時のI/Oなしの入口、再生成／検証の初期選択、共通確認・取消、対象選択、処理中の画面維持・消灯抑止、一覧・索引画面・動作設定への戻り先を確認した。追加項目の日本語グリフも確認した。
