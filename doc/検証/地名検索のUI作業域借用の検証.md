# 地名検索のUI作業域借用の検証

実施日: 2026-10-26
対象: 地名検索でUIの未使用backを作業域・結果格納域として利用する経路

## 実装

AppがBeginPlaceSearchでUIからアドレス・容量・貸出しIDを取得し、SearchPlaceへ渡す。UIは従来の固定画像2枚のうち未使用backを貸し出す。先頭4KiBは索引Reader、その後の整列済み領域はPlaceResult用とする。UIがplacement newで結果オブジェクトを構築し、Storageは指定された領域へ書く。UIの動的確保と追加の画像配列は設けない。

Storageは検索の間だけ索引FactoryへBorrowedReadBufferを結び付ける。GLC・Wordbookの索引読出しは順番に同じ4KiBを使い、全Readerの破棄後に借用指定を解除する。Storageの完了通知は要求・貸出しID、状態、区域コード、DatasetInfoを使用し、地名文字列は通知へコピーしない。既存の固定長通知型の文字列欄は使用しない。

Appの通知ハンドラは終了を記録するだけとし、通常ループのprocessPlaceで結果を確定する。別の同期要求を待機中に通知が来ても、同期要求を重ねて送らない。現在の表示へ適用できればCommitPlaceSearch、古い画面・ログ点・消灯中などの結果はDiscardPlaceSearchを送る。UIは地名を固定表示データへコピーしてから結果オブジェクトを破棄し、領域を再利用可能にする。Appの通常UIスナップショットも同じ結果に更新するため、後続の時計・GPS更新で古い地名へ戻らない。

画面切替は検索終了を待たずに実行できる。AppとUIの貸出し管理は画面用領域の外で保持し、Storageの終了通知までは返却しない。Storageキューが満杯で要求を送れなかった場合も取得済み領域を返却する。UI返却失敗時は状態を残して再試行する。地名検索と地図生成の貸出しは排他とし、表示中の地図frontは変更しない。

## ホスト検証

| 検証 | 結果 |
|---|---|
| tests/run_native.py | UI領域の整列・容量・結果格納と作業域の分離、地図表示との共存、画面切替、古いID、既存UI・GPS・ログ・USB回帰に合格 |
| tests/run_logger_app.py | 実際のAppでの要求・遅延確定、通常表示との整合、キュー満杯、返却失敗と再試行、画面切替後の完了、履歴地点の検索・移動中の古い結果の返却に合格 |
| tests/run_borrowed_place_files.py | ASan/UBSan付き。N03／estatの7地点問い合わせで、自己所有と借用の検索状態・区域コード・地名が一致。Factoryの借用復元と読出し例外後の返却に合格 |
| tests/run_map_scale.py | ASan/UBSan付き。既存の地図生成・縮尺・追従・取消と返却順序の回帰に合格 |
| tests/run_storage_work.py | Storageの作業領域切替、close失敗、100回の固定画像再利用に合格 |
| PlatformIO cardputer-adv | 通常ファームのビルド成功 |

実データ比較は初期のReader準備を終えてから、同じ7問い合わせを両経路へ送る。C++確保の要求回数・累計要求量を計測し、libc内部や実機ヒープのピークは含めない。

| データセット | C++確保回数、自己所有→借用 | 累計要求バイト、自己所有→借用 |
|---|---:|---:|
| N03 | 107 → 100 | 184,939 → 162,251 B |
| estat | 173 → 165 | 225,038 → 192,270 B |

索引の範囲が4KiB未満の場合は従来も必要量だけを確保していたため、削減量は常に確保回数×4KiBとはならない。地図・Wordbook本体の読出しバッファ、Reader本体・FIL、辞書の可変配列・文字列など、Storage側には動的確保が残る。今回で全廃したとは扱わない。Galuchat Core／SDK／同梱Galuchatの変更はない。

## ビルド容量

比較元は固定地図バッファ貸出しまでを含む通常ビルドとする。

| 項目 | 変更前 | 変更後 | 差 |
|---|---:|---:|---:|
| 静的RAM | 94,808 B | 95,040 B | +232 B |
| Flash使用量 | 1,226,613 B | 1,229,761 B | +3,148 B |

UIの画像領域は既存の2枚を共用し、索引作業用の4KiB領域を追加しない。実機のピークヒープ・所要時間の比較は今回未計測。

## 実機書込み

MAC `70:af:09:df:46:d0`のCardputerを照合し、生成した通常ファームをアプリ領域へ書き込んだ。書込み後のハッシュ照合と通常起動に成功した。ログでDISPLAY 240×135、4タスク／5キュー、NVS設定読込、SD FAT32、GPS UART、Galuchat OPEN OKを確認した。その後GPS FIXとなり、新しい貸出し経路で地名検索が完了した。

実機での全画面遷移の手動試験は未実施。画面切替・キュー満杯・返却再試行はホストで検証した。書込みログは初回USB再列挙中の一時的なポート切断を含むが、自動でROMへ移行して書込み・起動まで完了した。
