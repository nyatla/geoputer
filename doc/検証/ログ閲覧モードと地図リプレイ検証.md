# ログ閲覧モード・地図リプレイの検証

検証日: 2026-10-25（JST）。対象: ReverseGeoputer / Cardputer ADV。

本書は初版の検証記録。後続の＋／－・Pへの変更は[地図と再生キー割当の検証](地図と再生キー割当の検証.md)を参照する。

## 変更内容

ログ選択後の旧詳細メニューを、文字・地図・地図リプレイの3項目へ変更した。左右1点、上下10点、B/E先頭末尾、V表示切替、地図でSpace再生停止・Z倍率切替を実装した。同じファイル内では表示済み位置を引き継ぎ、別のファイルでは前の点を消す。地図には軌跡を蓄積せず、既存の±32画素追従と地名検索用キャッシュを使う。

再生は1点最低1秒とし、レコード・地名・地図の取得中は待機する。手動移動、V切替、Gダイアログ、消灯、離脱、末尾、読出し・地図エラーで停止する。現在のGPS受信・ロギングは別の状態として継続する。Galuchat本体、Core、SDK、記録ファイル形式、タスク・キュー数は変更していない。

## ホスト検証

- `python3 tests/run_native.py`: 同期通信、UI、設定、GPS、ログ形式・破損検出、キー、USB、エクスポート、フォントなどの既存検証を通過。新しい点送りと、データセットなしで文字だけ選べる条件を含む。
- `python3 tests/run_logger_app.py`: 実際のApplication・UiModel・LogWriterなどをホストのキュー接続で実行。過去の点がライブGPSに置き換わらないこと、GPS未測位でも履歴地図を生成できること、選択点を使う逆ジオコーディングとカーソル、同一セルの検索省略、10件境界、1秒の再生、末尾停止、破損停止、消灯・モーダルでの停止を確認。点送り後の古い地名結果は捨て、別のファイルを開いた時に古い点を表示しない。閲覧中にも実際のログ受付を行い、記録を継続できることを確認した。
- `python3 tests/run_map_scale.py`: 通常地図の倍率変更、取消、古い結果、転送途中の変更、同一Fix、未測位からの復帰、全行受信後の画像交換を通過。
- `python3 tools/render_log_browser.py`: 日本語・英語各28場面。実際の描画コードを使い、240×135画素、日英のフォント、ヘッダー・フッター、表示範囲、ダイアログを検査した。履歴地図のプレビューは描画検証用の区域パターンを使用する。

## 実機

MAC `70:af:09:df:46:d0`を照合し、アプリ領域0x10000だけを書き換えてハッシュ検証に成功した。NVS・SDを消去していない。再起動後、4タスク・5キュー、NVS読込、FAT32、GPS UART、データセットOPEN OK、GPS FIX、LivePlaceへの遷移をシリアルログで確認した。メインタスクのログ出力時の空きスタックは3,868バイト。

新しいログメニューを実機のキーで操作する試験は利用者による確認待ちであり、ホスト検証・実機起動確認と区別する。入口は4→ファイル選択→文字で見る / 地図で見る / 地図で再生。
