# 地図生成時の空きヒープ計測

更新日: 2026-10-24

地図生成中の実際の空きヒープ、最大連続空きブロックと、生成・転送後の回復を確認する。カーソル動作、画像形式、128キャッシュ、読出し方式は変更しない。

## 計測方法

`application/Config.h`の`MapHeapDiagnostics`をtrueにすると、既存のApp・Storage・UI処理から`[MAP-HEAP]`を出力する。新しいタスク・キュー・画像バッファは追加しない。計測関数は各値を取得した後にConsoleへ出力する。ホストでは出力しない。

| フィールド | 意味 |
|---|---|
| stage / token | 処理段階と同じ地図生成要求を結び付けるID |
| heap | MALLOC_CAP_8BITの現在の空き容量、バイト |
| min_boot | 同じcapabilityの起動以来の最小空き量。フレーム単位でリセットしない |
| largest | 同じcapabilityで現在確保可能な最大連続空きブロック、バイト |
| internal / internal_largest | INTERNALかつ8BITの現在空き量・最大連続空きブロック |
| stack_free | 計測を呼んだタスクの起動以来の残スタック最小値、バイト |
| bytes | source系の計測点では入力区域コード配列のバイト数。その他は0 |

全タスク共通のヒープを時点ごとに観測するため、同一要求内の差分にも他タスクの活動が含まれる。min_bootはアロケーターの累積値であり、各stageでの観測最小値とは区別する。Console出力自身の微小な一時使用も計測環境に含まれるため、この計測版の所要時間を診断なしの性能値と直接比較しない。

## 計測点

| stage | 状態 |
|---|---|
| read-begin | 読出し前。継続更新ではUIの前画像・受信用画像が残る |
| source-allocated | 区域コード配列を確保した直後 |
| source-read | readRectから復帰した直後。内部で開いた地図・索引のファイルセッションは終了済み |
| map-reader-closed | 外側の地図Readerオブジェクトと専用Factoryを破棄した後。入力配列は保持 |
| wordbook-read | 地名取得後。辞書Readerオブジェクトと結果文字列を保持するが、内部のページ読出しセッションは終了済み |
| source-ready | 読出し関数の一時データ解放後。入力配列のみを次段へ返す |
| render-begin | 境界画像も確保し、入力＋出力を保持する |
| render-done | 境界変換完了。入力区域コード配列を解放した後 |
| ui-begin | UIの受信画像を確保した後 |
| ui-commit | 全行の受信後、UIが表示画像を交換した後 |
| released | UIへの転送後にStorageの完成画像を解放した後 |
| ui-released / cancelled | 画面切替時のUI画像解放／Storage側要求の取消後 |

最初の1回と2回目にはUI画像が1枚ずつ増える。3回目以降の同じstageと、地図を離れた後の値を比較し、バッファの定常保持と継続的な減少を区別する。初回だけのキャッシュ確保を含めないため、Live Placeで128キャッシュ・地名LRUを温めてから地図を開く。

読出しの途中で確保・解放される一時領域はstage間に隠れる場合がある。初回地図処理で起動後の最低値を更新した場合は、min_bootも併せて余裕の評価に使う。全stageを網羅したフレーム固有の厳密なピークを取得する仕組みではない。


## 実機結果

MAC `70:af:09:df:46:d0`のCardputerへ、アプリ領域0x10000だけを書き込み、esptoolのハッシュ検証が成功した。SHA-256は`a5c7924e0e2c33e2db3f2f24ecaab5e2777770a2b5d8c7fb6f15f4d27da41036`。NVS・SDを消去していない。通常起動とGPS FIX、dataset/01の162チャンク、estatの「袖ケ浦三丁目」、128キャッシュと地名LRUのHITを確認した。

ユーザー操作で4から地図を開き、6回の生成・UI転送・Storageの解放を取得し、1でLive Placeへ戻るところまで記録した。入力区域コード配列は79,680バイト。以下は3〜6回目の定常更新での観測値である。

| 段階 | 空きヒープ（バイト） |
|---|---:|
| 地図を開く前・初回読出し直前 | 157,796 |
| 定常更新の読出し直前（UI画像2枚保持） | 145,644 |
| 区域コード配列の確保直後 | 65,600 |
| 読出し・地名取得の一時データ解放後 | 65,948 |
| 境界出力画像を確保した変換開始時 | 59,872 |
| 境界変換完了・入力配列解放後 | 139,568 |
| UI転送・Storage出力画像解放後 | 145,644 |
| 地図画面を離れてUI画像も解放した後 | 157,796 |

起動後最小空き量は、地図を開く前136,308バイトから、初回55,720バイト、2回目49,644バイト、3回目43,568バイト、以後43,564バイトへ更新された。最小値は約42.5KiB。読出し中のバッファ・復号用一時データの確保はreadRect内部で完結するため、復帰後のstageの空き量より小さい。この値は起動後の累積最小値であり、各要求で個別にリセットしたピークではない。

初回基準157,796バイトに対する最小値との差は114,232バイト（約111.6KiB）。この差には地図用画像、Reader・復号・文字列等の一時使用と、同時に動く他タスクの変動を含む。境界画像の2bit形式だけの容量を処理全体の使用量としない。

定常更新後の最大連続空きブロックは86,004〜88,052バイト（約84〜86KiB）で、次の入力配列79,680バイトとの差は約6〜8KiBだった。画面離脱後の最大連続空きブロックは100,340バイト、初回の読出し前は143,348バイトだった。総空き量の回復と、最大連続領域の回復を同一視しない。minimumを記録した厳密な瞬間の最大連続領域は取得していない。

3〜6回目の同じstageの総空き量は一定で、画面離脱後は地図を開く前の値へ戻った。この短い試験では継続的なヒープ減少を認めなかった。Storage残スタックは最小4,296バイト、UIは3,088バイト。panic・Backtrace・スタックカナリア・ヒープ破損のログは検出しなかった。長時間運用や別データセットでの最悪条件を保証する測定ではない。

`tests/run_native.py`とPlatformIOのcardputer-advビルドは成功した。静的RAMは81,880バイトで計測追加前と同じ、Flashは1,204,889バイト。診断ログはConfig.hのMapHeapDiagnostics=falseで無効にできる。実機には計測ログを有効にした通常ファームを残す。

ログ・集計JSON・書込み記録・ファームウェア・試験ログは`.pio/map-heap/`へ保存した。
