# データセット索引の生成・検証時間

計測日: 2026-10-22（JST）。Cardputer ADV、CPU 240MHz、SD SPI 4MHz、索引生成の読書きバッファ4KiB。製品と同じ`DatasetIndex.cpp`の生成関数と`DatasetIndex::validate()`を診断用コピーから呼び出した。Core・SDK・アプリ内Galuchatと製品ソースは変更していない。

## 条件と計測範囲

- SD上のN03・estatの各`dataset.ini`が指定するGLC・Wordbookを使用する。各データセットの生成は1回、生成した同一索引の検証は3回測定する。SDやファイルシステムのキャッシュは消去しない。
- 生成時間は、GLCとWordbookの索引作成、索引ヘッダー更新、索引全体のCRC追記、sync・closeまでを含む。入力データ全体の復号・完全性検査を行うものではない。
- 検証時間は、生成した索引のopenから全体の構造・CRC検証とcloseまでを含む。GLC・Wordbook本文全体の検証や起動後の検索時間ではない。通常適用で使う初回の値と、参考の3回の中央値を併記する。
- 元ファイルの識別情報取得と、生成・検証後の同一性照合は別に計測する。候補詳細の事前チェック、正式索引へのrename、NVS保存、再起動は時間外。GPS・UIタスクと製品のSDアクセス通知は継続する。
- 測定先は各フォルダの`_index_timing.tmp`。事前に存在する場合は上書きせず拒否する。生成・検証後に削除し、正式な`_mapindex.dat`、元データ、NVSのデータセット選択は変更しない。

## 確認と保存物

同じ診断処理をホストでも両データセットで実行し、生成・検証の成功、正式索引の内容維持、測定用ファイルの削除、既存の同名測定ファイルを保持して拒否する動作を確認した。ホスト時間を実機時間へ換算していない。

実機測定の終了後は通常ファームへ書き戻し、書込みハッシュ照合、通常起動、GPS測位と地名表示を確認した。測定のログは`.pio/index-generation-timing/device.log`、集計は`device-results.json`、ホスト確認は`host.log`、ソースハッシュは`diagnostic-sources.json`、書込み・起動確認は`flash.log`・`restore-flash.log`・`restore-boot.log`に保存する。

診断本体は`tests/performance/IndexGenerationBenchmark.h`と`IndexGenerationBenchmark.inc`に保存する。後者を診断用`DatasetIndex.cpp`のコピーへ追加して同一の内部生成処理を呼び出す。製品側へは組み込まない。
