# 全チャンクのブロック位置列挙時間

計測日: 2026-10-20。製品ソースの基準は`baf271e`。全GI01のブロック位置索引を初回起動時に作成する場合の判断材料として、全ブロックの開始位置と長さを一度ずつ読み出す時間を実機で測定した。位置の列挙・検証・ハッシュ集計を行う。全件のRAM保持、索引のファイル書込み、画像への展開は含まない。

## 対象と方法

Cardputer ADV（MAC `70:af:09:df:46:d0`）、CPU 240MHz、SD SPI 4MHz、Readerの先読み4096バイト。選択済みデータセットは`/sd/dataset/02/estat-r2ka-jgd2011-2020-grid-8192-10000.remap.wgsmapset.glc`、23,800,183バイトとする。

SDマウントとNVS設定読込みの後、通常のデータセット検証より前に、診断用WGSMapSet Readerの初期化を一度実行した。既存の初期化は各GI01のヘッダーを読んで本文全体をスキップするが、診断版ではこの一巡の中で各ブロックの位置を列挙する。事前にチャンク索引を作ってから、別の全走査を追加する方法ではない。

GLCH・必要ならLAYOを読み、GI01群は一つのファイルストリームで先頭から末尾へ順に処理する。ブロック先頭の絶対ファイル位置を取得し、既存の`skipBlock`で次の先頭へ進む。サイズ付きブロックは本文長で飛ばし、サイズを持たないブロックは内部構造を解析して末尾を求める。各ブロックの長さ・位置の単調性、各GI01の本文末尾、全ファイル末尾を検証する。

計測はFactoryの準備・ファイル操作・ヘッダー解析・ブロック位置の取得と検証・64bitハッシュ集計を含む。初期メタデータ用ReaderとGI01走査用ReaderのOpen/Closeを含み、それぞれ合計2回。チャンクごとのOpen/Closeはしない。Wordbook、画面描画、索引配列への格納、索引保存は対象外とする。進捗ログの出力呼出し時間だけを別途計測し、列挙時間から差し引く。GPS・UIタスクは継続するが、ReaderのSD/RG通知は無効とする。

## 実機結果

| 項目 | 値 |
|---|---:|
| 列挙時間（進捗ログ出力を除く） | 139.375981秒 |
| 実経過時間（進捗ログを含む） | 139.381441秒 |
| 進捗ログ出力 | 5,460 µs |
| GI01チャンク数 | 162 |
| ブロック数 | 23,679 |
| 本文長でスキップできたブロック | 16,652 |
| 内部解析が必要なブロック | 7,027 |
| fread取得量 | 17,599,060 B（16.784 MiB） |
| fread回数 / 時間 | 4,297回 / 53.506099秒 |
| fseek回数 / 時間 | 4,272回 / 85.642896秒 |
| Open / Close | 各2回 |
| 最初のブロック位置 | 1,627 B |
| 最後のブロック末尾 | 23,800,183 B（ファイル末尾と一致） |
| 位置・長さの64bitハッシュ | `344960485833343087` |
| 32bit開始位置配列の本体容量 | 94,716 B（92.50 KiB） |

32bit配列の容量はブロック開始位置だけの値であり、チャンクごとの参照情報、ブロック数、配列管理、メモリ確保の付随領域は含まない。今回の診断版は全配列を確保せず、位置と長さを順に検証・集計している。

デコーダへ渡したバイト数は78,912 B、先読みバッファ内でスキップした量は17,517,669 B、fseekで飛ばした量は6,203,606 Bだった。取得量はファイルAPIのfreadが返した量であり、物理SDセクタの転送量とは区別する。時間は割込み・他タスク実行・媒体待ちを含む経過時間である。

初回の全件列挙1回の実測であり、別のデータセット・SDや最大所要時間の保証ではない。SDマウント・NVS・Wordbookなどを含む起動全体の時間でもない。SPI転送やスキップ方式は既存の実装のままで、連続読出しへの変更や索引の永続化は実装していない。

## ホスト事前検証

同名のローカルデータセットを4・8・16KiBの各Readerで走査し、全23,679ブロックの位置・長さのハッシュ、GI01数、サイズ形式別件数、最終末尾の一致を確認した。実機でも同じハッシュだった。ホストの時間を実機時間へ換算しない。

## 生成物と復帰

診断コードは`.pio/block-index-bench/application`と`.pio/block-index-bench/include`の一時コピーだけへ追加した。製品のSDK・Reader・設定は変更していない。診断差分は`.pio/block-index-bench/diagnostic-source.patch`、ハーネスは`application/task/storage/galuchat/BlockIndexBenchmark.h`とする。

診断ファームは`.pio/block-index-bench/benchmark-firmware.bin`、SHA-256 `06c15eed6266c5f3166fe70dd371eddfa170085ae9afa023b4294e021712dba8`。ビルドは警告・エラーなく成功し、静的RAMは77664バイト、Flashは1133713バイトだった。対象MACを照合してアプリ領域へ書き込み、書込みハッシュ照合にも成功した。

生ログは`.pio/block-index-bench/device.log`、集計は`results.json`、ホスト検証は`host-results.log`へ保存した。試験後は製品ソースと4KiB設定で通常ファームをビルドし、アプリ領域だけへ書き戻した。MAC・書込みハッシュ照合に成功し、NVS・SDは消去していない。復帰後30秒のログでLoRa SLEEP、FAT32、GPS測位、Galuchat OPEN OK、Boot Ready、習志野市の地名表示とキャッシュヒットを確認した。通常検索は地図716800バイト・175回、シーク174回で、診断の全件列挙は実行されていない。復帰ログは`.pio/block-index-bench/restore-boot.log`、復帰用ファームは`restored-firmware.bin`、SHA-256は`1f8b633f8c3a8039340156a08dabfee5d5f40d9be03b1f8b8c2c0cfe07653df8`とする。
