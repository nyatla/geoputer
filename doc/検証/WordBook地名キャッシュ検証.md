# WordBook地名キャッシュ検証

検証日: 2026-10-16  
対象: WordBookCache、PlaceLookup、StorageTask  

## 1. 実装範囲

区域コードをキーに、UTF-8変換・整形済みの地名3階層を16件まで保持する。利用順のインデックス配列は16バイトで、使用した項目を先頭へ移し、満杯時は末尾を置き換える。LRUの判定に時刻・内部Tick・利用連番は使用しない。仕様は[システム構成設計6.2節](../04_システム構成設計.md#62-wordbookの地名キャッシュ)に従う。

キャッシュはStorage内のPlaceLookupのメンバーとして保持する。地名データ本体を並べ替えず、キャッシュへの追加で動的な領域確保を行わない。SDK内のトークンキャッシュは無効のままとし、third_partyのSDKは変更しない。

ヒット時は要求・Fixを今回の検索から結果へ設定し、地名だけをコピーする。ミス時は辞書読出し・文字コード変換・整形に成功した結果だけを登録する。Reader閉鎖時は登録内容と統計を無効化する。矩形の再構築・未測位・画面切替で地名を無効化しない。

## 2. ホスト単体検証

`python3 tests/run_native.py`を-Wall / -Wextra / -Werror、UndefinedBehaviorSanitizer付きで実行し、成功した。

- 空キャッシュ、コード0の非登録、UINT32_MAXの区域コードを確認した。
- 入力文字列と返却文字列を書き換えても、キャッシュ内の地名が変わらないことを確認した。
- 16件を登録後、古い登録項目を再利用し、17件目が登録時刻順ではなく利用順の末尾を置き換えることを確認した。
- 同じコードの再登録は地名を更新し、別項目の追出しや件数増加を起こさないことを確認した。
- clear後に旧項目を参照できず、件数とヒット・ミス統計がリセットされることを確認した。
- 29種類のコードへの10,000回の混合アクセスを、別のリストによる参照LRUと比較し、ヒット判定・地名・登録件数が一致した。

ホストでの`sizeof(WordBookCache)`は3,164バイト（約3.1KiB）。地名・コード・利用順・登録件数・統計を含む常設容量であり、ミス時のSDK読出しや文字変換用の一時領域は含まない。

`PLATFORMIO_CORE_DIR=/tmp/geoputer-pio-core /tmp/geoputer-pio-venv/bin/pio run -e cardputer-adv -j 4`は成功した。コンパイラの警告・エラーは検出していない。静的RAMは45,456 / 327,680バイト、Flashは1,052,113 / 3,342,336バイト。静的RAMの数値は実行中の空きヒープ・残スタックの計測値ではない。

## 5. 実機確認の扱い

この検証のSDアクセス数は、ホストで実装のObservedFileReaderとStorageObserverを使用して数えたものであり、SPIの電気的な計測ではない。

2026年10月16日、地名キャッシュを含む[Settings多言語化の通常ファームウェア](Settings多言語化検証.md#5-実機確認の扱い)を端末へ書き込み、ハッシュ照合と正常起動を確認した。実機ログでGPS更新、習志野市の地名取得、WordBookの初回MISS・登録1件から継続HITへの遷移を確認した。HIT時の例では検索全体が約724〜728µsであり、Storageの空きヒープは144,028バイト、最小ヒープ136,124バイト、残スタック7,428バイトを報告した。これらは起動後の短時間の観測値である。SD表示の目視、記録併用、長時間動作は未確認とする。

USBログでは`[WORDBOOK] HIT / MISS / NONE`、登録数/16、累計ヒット・ミスを出す。NONEは成功した地名結果がない場合とする。RGの画面仕様は矩形キャッシュの状態を示すままとし、地名キャッシュ専用の画面表示・タスク・キューは追加しない。
