# キーバインド変更検証

検証日: 2026-10-16  
対象: KeyBindings、UiTask、UiModel、UiRenderer  

## 1. 採用するキー

| 操作 | 物理キー |
|---|---|
| MENU | 2（Fn不要。Fn＋2も同じ操作） |
| 上 / 下 | `;` / `.`（Fn不要。従来のFn併用も可） |
| 左 / 右 | `,` / `/`（Fn不要。従来のFn併用も可） |
| 一時停止 | F1＝Fn＋1 |
| 決定 | Enter |
| キャンセル・戻る | Esc＝Fn＋バッククォート、またはDel |

左右の操作可能範囲はSettingsの値編集中とする。MENU・確認・一覧では上下で選び、Enterで決定する。画面消灯中の最初の押下は復帰だけに使用する。

## 2. 実装

[KeyBindings](../../application/task/ui/KeyBindings.h)で、M5Cardputerの物理キーのvalue_firstを論理操作へ変換する。MENUはUiKey::Menuとし、物理的なF2を前提とした名前を廃止する。

UiTaskは変換後の押下状態でエッジを検出するため、2や方向キーを押し続けたままFnを追加・解除しても新たな押下を生成しない。上下の長押しは400ms後から100ms間隔で反復する。DelとFn＋バッククォートは共通の取消状態として扱う。UIの操作保持・Appによる同期取得と画面指定の契約は維持する。

## 3. ホスト検証

`python3 tests/run_native.py`は-Wall / -Wextra / -WerrorとUndefinedBehaviorSanitizer付きで成功した。

- Fnなし・ありで2と4方向が同じ論理操作になることを確認した。
- 一時停止の1とEscのバッククォートはFnが必要であることを確認した。
- 2でMENUを要求し、`.` / `;`とEnterでSettingsへ進めることを確認した。
- Settingsの一覧状態では左右を無視し、値編集中だけ`/` / `,`で値を変更できることを確認した。
- Settingsで2を押しても画面を切り替えないことを確認した。
- 消灯中の最初の2はWakeだけとなり、復帰後の次の2でMENUを開くことを確認した。
- 既存のBoot・GPS・記録操作・設定保存・ライセンス閲覧の試験も成功した。

## 4. 画面・画像

操作ガイドを`2 MENU`へ変更し、x=188・y=124へ右寄せする。[Live Placeの実寸画像とプレビュー](../画面・操作/live-place/README.md)を実装のUiRendererから再生成した。

`python3 tools/render_live_place_layout.py`は文書用10状態と追加検証10状態で成功した。すべての状態で`2 MENU`をC64 ASCII 8ドットの字形と画素比較し、罫線・数値の境界・RG/SD・赤帯の検証も成功した。文書用の10枚と4倍プレビュー10枚は同名の旧画像を置き換え、旧キーガイドの画像は残さない。
