# ログパスの非所有化とスタック分離

検証日: 2026-10-28

## 実装範囲

LogWriterとLogReaderから、ルートとフルパスを保持するstd::stringを除去した。ファームウェアのログルートはConfig.hのLogDirectory（/sd/logs）に集約し、LogDirectory型がROM文字列を参照する。ホスト試験で別のルートを渡す場合は、Reader／Writerの寿命より長く呼出し元が保持する。

記録対象名は既存のLogSnapshot::name[48]、閲覧・統計・削除対象名はLogReadRequest::name[48]を使用し、別の名前配列を追加しない。フルパスはファイル操作時だけ終端込み256バイトのTemporaryPathへ構成する。上限は従来どおり255バイトとし、超過時は切り詰めない。通常の本体ルートと最大47バイトの名前では、終端込み57バイトに収まる。

保存・close失敗中は同じ名前を保持して再試行する。close成功後は保持対象としての所有を終了し、最後の名前は表示用スナップショットへ残す。一覧の記録中表示、記録中ファイルの読出し、削除保護はルートと名前を比較する。削除保護の大文字小文字を無視する比較を維持し、別ルートにある同名ファイルは区別する。

64件リング、10件単位の読出し、統計の8件単位処理、通知・世代・ジョブ切替の契約、ファイル形式と命名規則は変更していない。opendir／fopen等の内部確保は対象外とした。

## スタックの分離

LogDirectoryのopen・stat・削除・ファイルopenをnoinlineの関数とし、パス領域はその操作が返った時点で終了する。LogReader::readHeader、LogWriter::writeHeader、セッション重複確認のヘッダー読出しもnoinlineとし、各512バイトを処理中だけスタックへ置く。

ファイルopenの関数から戻ってからヘッダー処理を呼ぶ。パス領域を閲覧・統計のループ中まで保持せず、保存側でもファイル作成から戻ってからヘッダーを書き込む。FatFsへのopen中は正規パスとネイティブパスの短時間の重複があるが、その間にログの512バイトヘッダーは存在しない。保持済みファイルの読出しはハンドルを使い、パスを再構成しない。

通常ESP32ビルドの個別スタックフレームを、直前に保存したELFと比較した。

| 関数 | 変更前 | 変更後 |
|---|---:|---:|
| LogWriter::flush | 592 B | 80 B |
| LogWriter::createFile | 496 B | 144 B |
| LogWriter::sameSessionExists | 640 B | 96 B |
| LogReader::readTarget | 768 B | 256 B |
| LogReader::stepStatistics | 672 B | 160 B |
| LogReader::step | 160 B | 160 B |

新しいヘッダー読出しは576 B、ヘッダー書込みは560 B、セッションヘッダー照合は560 B。パス操作の関数は304〜336 Bとなった。統計の初期読出しでは、関連するアプリ側フレームの組合せが672 + 768 Bから160 + 256 + 576 Bとなり、パスを使う関数はヘッダー読出しより先に戻る。

これらは個別関数とその呼出し関係の静的確認であり、外部ライブラリを含む呼出し全体の最大値や実機ウォーターマークではない。タスクのスタック設定は増やしていない。

| StorageWorkArea | 1,800 B | 1,760 B | −40 B |
| LogSnapshot | 88 B | 88 B | 0 B |

表の型は内包する領域を含むため、各行を加算しない。LogDirectoryは8 Bの非所有参照となり、新しい常駐パスバッファは確保しない。実際のヒープ削減量は使用中のパス長とアロケータによって変わる。

## 検証

- 長いホスト用ルートで32ファイルを一覧化し、初回・繰返しともC++ newが0回で、同じ順序と件数になることを確認。
- 初回のファイル作成・保存、概要、測位点、統計読出しがC++ new 0回で成功。
- close失敗時の名前保持、同じファイルへの再試行、成功後の保持対象解除がC++ new 0回で動作し、表示用の名前と保存済みファイルが残ることを確認。
- 世代の古い解放通知、取消、未完了ジョブ・close失敗時の切替拒否、100回の固定領域切替を確認。
- 命名の日時・衝突・日時不明、保存失敗、リングの折返し、追記と読出し、統計、削除確認・記録中ファイルの別名保護、パス上限の既存試験が成功。
- Appの記録開始・一時停止・再開・停止、画面遷移・ログ閲覧・リプレイのホスト試験が成功。
- cardputer-advの通常ビルドが成功。補助の実機テストソースも新しいパス取得APIへ合わせた。

実行したランナーはrun_storage_work.py、run_native.py、run_logger_app.py。実機の書込み・動作試験は今回実施していない。
