# 所有者ごとの固定領域化6件の検証

実施日: 2026-10-26

## 実装

動的確保の頻度を減らすため、次の6件を実装した。タスク間の通信、処理順序、記録・索引のファイル形式、GaluchatライブラリのAPIは維持する。全画面共通の巨大な作業領域は新設せず、所有者ごとに配置する。

| 対象 | 配置と寿命 |
|---|---|
| 索引生成・検証のSource管理オブジェクト | Output内とgeneratePlanned内のoptional。Storageの既存スタックを使い、処理終了時に破棄する。Fileと4KiB読出しバッファは必要時の動的確保を維持する。 |
| dataset.iniの一時文字列 | 行・キー・値を既存行バッファのstring_viewで参照する。セクション名、言語一覧、返却するファイル名・説明・表示書式は所有する文字列へコピーする。 |
| 地名検索の2種類のReader本体 | PlaceLookupのoptionalメンバーへ配置する。全検査成功後に一時Readerを移し、失敗時の破棄と再設定時のresetは維持する。Reader内部の画素・Factory等は従来どおり。 |
| 文字描画用8×16の1bit画像 | PixelFontの20 B配列。UIループ内のRendererと同じ寿命で、既存UIスタック内に置く。M5GFXの末尾ガードと整列を含む。小さなパレットはライブラリが引き続き確保する。 |
| USBのMutex | UsbStorageがStaticSemaphore_tを所有し、xSemaphoreCreateMutexStaticで構築する。 |
| UIの240×135主画像 | UiTaskがUiFrameBufferを所有する。通常4bitで16,204 B、整列と末尾ガードを含む。グローバルApplication内に置き、UIスタックには載せない。UiCanvasは外部バッファを借用し、所有者より先に破棄する。 |

UIの既定色深度はConfig::UiColorDepthのままとする。16bitの比較描画と内部確保の経路も維持し、外部バッファを渡す場合は容量を検査する。設定言語IDの検査とUTF-8・地名書式の検査は、終端文字に依存しないビューに対応した。従来の言語IDのconst char*呼出しは維持する。

大きなFatFs FIL、SD読出しバッファ、区域コード画像、地図画像はスタックへ移していない。共有Factoryの所有権、画面間の資源切替手順も変更していない。

## 容量

PlatformIOの通常ビルド同士の比較。sizeofはESP32-S3用ツールチェーンで確認した。

| 項目 | 変更前 | 変更後 | 差 |
|---|---:|---:|---:|
| 静的RAM | 67,520 B | 84,112 B | ＋16,592 B |
| Flash使用量 | 1,221,245 B | 1,225,013 B | ＋3,768 B |
| PlaceLookup | 2,576 B | 2,888 B | ＋312 B |
| 索引Output | 32 B | 92 B | ＋60 B |

Sourceは60 B、StaticSemaphore_tは84 B。静的RAMの増加は、従来ヒープへ確保していた主画像と管理オブジェクトを所有者へ移した分であり、同量の総RAM増加を意味しない。一方、Reader未使用時もoptionalの領域を予約するため、未選択・USB時まで同じ量が節約されるわけではない。今回、変更後の実機ヒープ・処理時間は再計測していない。

## スタック

変更前の直近実機計測ログmemory-cleanup-after.logで、測定された最低未使用量はApp 2,572 B、UI 3,344 B、Storage 3,592 Bだった。uxTaskGetStackHighWaterMarkの値であり、各時点の単なる残量ではなく、その起動中に観測済みの最低未使用量を表す。全機能・全異常経路を網羅した保証値ではない。GPSの最低値は当該ログにない。

以下は変更前後のELFを逆アセンブルし、各関数のentry命令から求めた自身のフレームサイズ。呼出し先を含む実行時ピーク値ではない。

| 関数 | 変更前 | 変更後 | 差 |
|---|---:|---:|---:|
| UiTask::run | 2,272 B | 2,288 B | ＋16 B |
| PixelFont::begin | 32 B | 64 B | ＋32 B |
| PlaceLookup::open | 720 B | 864 B | ＋144 B |
| 索引generatePlanned | 976 B | 1,088 B | ＋112 B |
| readDatasetMetadata | 688 B | 688 B | 0 B |
| StorageTask::run | 1,008 B | 1,008 B | 0 B |
| UsbStorage::begin | 32 B | 32 B | 0 B |

今回の局所的な増分は前回の実測余裕に対して小さい。タスクの予約スタック容量は変更していない。変更後のHighWaterMarkを実測するまでは、前回の値から単純に増分を引いた数値を実測残量とは扱わない。

- tests/run_logger_app.py: 実Appの記録制御、文字・地図閲覧、再生、画面退出。
- tests/run_usb_export_lifecycle.py: USB変換の確保失敗・close失敗・結果保持・再公開。
- tests/run_dataset_index.py: N03実データと人工データの全言語生成・部分再生成・原データ照合・CRC・トランザクションとI/O失敗復旧。
- tests/run_map_files.py: 1/1・1/2・1/4の地図生成、地名検索、既存区域コードキャッシュの独立性。
- tools/render_log_browser.py: 日英計56場面。4bit・16bitと、内部確保・外部固定バッファの4通りが一致し、従来の112枚のPNGとも一致した。
- tools/render_map_view.py: 3倍率×8場面。4通りのバッファ・色深度の画素が一致し、同じN03入力で改修前を再描画した48枚のPNGとも一致した。
- PlatformIOのcardputer-adv通常ビルド、対象ソースのgit diff --check。

## 追加の一時文字列整理と実機書込み

2026-10-26、処理と所有権を単純に保つ範囲で、次の変更を追加した。

- LogWriterのセッション重複検査は、readdirの名前をstring_viewで参照する。次のreaddirまでに使い終え、一覧の名前コピーをなくす。保存中のパスは引き続き所有するstringとする。
- fatFsPathは返却するstringに必要容量を予約し、ドライブ番号・区切り・元パスを直接追記する。既存API、対応する長さ、UTF-8バイト列を維持し、substrと連結中の一時文字列をなくす。
- 索引のファイル名CRCはstring_viewの部分参照を受け取る。CRCの対象バイトと結果を変えず、マップ名・Wordbook名のコピーをなくす。
- Wordbookの文字コード指定は、定数の引用付きキーで検索し、元メタデータのビューを大文字小文字を無視して比較する。token_encodingの優先と空値時のtext_encodingへのフォールバックを維持する。
- dataset.iniの表示言語選択は定数または解析結果内のdefault_languageを参照する。結果を返すまで参照先を変更しない。行をまたいで保持するセクション名、言語一覧、返却する文字列は所有するstringを維持する。

パスの固定配列化、保持する言語IDの固定配列化、ObservedFileReader本体のスタック化は実施していない。ReaderFactoryのAPIや所有権は変更していない。

run_native.py、run_dataset_index.py（N03実データと人工データ）、run_logger_app.py、PlatformIO通常ビルドが成功した。2048文字のパス、最大ドライブ番号、31文字の言語IDへのフォールバック、文字コード名の混在ケース・空値・優先順位も確認した。

静的RAMは84,112 Bで変更なし。Flash使用量は1,225,013 Bから1,223,849 Bへ1,164 B減少した。ELFのentry命令による自身のフレームサイズは、LogWriter::sameSessionExistsが624→592 B、wordBookUsesUtf8が96→64 B、readDatasetMetadataが688→672 B。UIループ・地名検索初期化・索引生成のフレームサイズは前節の変更後と同じである。処理時間と全経路の実機スタック最低値の比較測定は行っていない。

前節の固定領域化6件を含む通常版を、MAC 70:af:09:df:46:d0のCardputerへ書き込んだ。書込み時のハッシュ検証と再起動後の240×135画面初期化、FAT32マウント、データセットOPEN OK、GPS FIX、地名検索成功をログで確認した。データセット01、習志野市袖ケ浦三丁目を取得した。

書込み済みfirmware.binのSHA-256は`0e368809ac4e8dcc9784854c34c0572f03306964b9431ce1f7ff14b37c0fcfe6`。ビルド・ホスト試験・書込みと起動のログ、ソースハッシュは.pio/string-cleanup-checksへ保存する。
