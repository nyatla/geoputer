# 区域コード画像の固定領域化

実施日: 2026-10-27。比較元はコミット0205819相当の `.pio/static-code-before/`、変更後は固定領域版。用途の説明と借用候補は[設計書](../14_Storage固定画像領域と作業領域の設計.md)を参照する。

## 実装

StorageCodeImagesをStorageTaskに内包し、地名判定用CodeCacheBuffer 64 KiBと地図用CodeImageBuffer 96 KiBを予約した。PlaceLookup/CachedMapReaderとMapSessionは借用参照へ変更し、配列のnew/deleteを除去した。容量不足時のヒープへの代替確保は行わない。

通常地図・ログ地図は別のメタデータを持ち、固定地図配列1枚を排他的に共有する。利用者切替時は他方を無効化する。CloseMapSession後も固定領域と有効な内容を保持し、要求条件が一致する新画面ではSDを読まず再描画する。地名判定の解像度と地図の縮小方法は変更していない。

## 実機ヒープ比較

Cardputer ADV、FAT32 SD、選択済みデータセット02・162チャンク。同じ仮想現在地（35.681641,140.027194）で、前→後→前→後の各2起動、各3周を実施した。メイン、1/1・1/4地図、ログ地図、ログ一覧、同じ929点ファイルのプロパティ・点表示・統計、メイン復帰を通過し、4起動とも3周を完了した。既存ログは読み取りだけで、設定保存はしていない。

前後に同じ1ms採取タスク（スタック2,048 B）と同じ472 Bの静的採取データを追加した。値はこの計測負荷込みの全タスク共通ヒープであり、Storageだけの私有ヒープの値ではない。観測対象は内部8bitヒープ。占有量は容量−空きとし、allocatorの管理情報を含む。

| 指標 | 変更前 B | 変更後 B |
|---|---:|---:|
| 計測版のヒープ容量 | 320,036 | 156,188 |
| 1ms観測・最低空き量 | 53,108 | 35,024 |
| 1ms観測・最大占有量 | 266,928 | 121,164 |
| allocatorの起動後最低空き量 | 53,028 | 34,516 |
| 低水位から求めた占有量 | 267,008 | 121,672 |
| 全区間の最小観測・最大連続領域 | 38,900 | 22,516 |

allocatorの低水位は起動からの履歴と複数領域の低水位を含み、区間ごとにリセットした瞬間値とは区別する。1msで捕捉できない短時間の確保があるので両方を示す。

定常状態（2・3周目）のスナップショット:

| 状態 | 変更前の空き B | 変更後の空き B | 変更後の最大連続 B |
|---|---:|---:|---:|
| メイン | 158,916–158,960 | 60,732 | 51,188 |
| 通常地図1/1 | 79,220–79,264 | 60,732 | 51,188 |
| 通常地図1/4 | 79,220–79,264 | 60,732 | 51,188 |
| ログ地図 | 79,220–79,264 | 60,732 | 51,188 |
| ログ点表示 | 158,840–158,884 | 60,656 | 51,188 |
| 統計結果 | 158,840–158,884 | 60,656 | 51,188 |
| 一巡後メイン | 158,916–158,960 | 60,732 | 51,188 |

メインでも地図保持中でも約59.3 KiBが空く。最低空きは約33.7 KiB、最小の最大連続領域は約22.0 KiBだった。メインでは未使用の地図領域も予約するため、以前の約155 KiBの空きは残らない。

ヒープから画像配列が消えたため、地図保持中に約80 KiBが出入りする状態もなくなった。ただし、ヒープ容量そのものを静的予約で約160 KiB減らしている。ヒープ占有量の減少を、そのまま総RAM消費の削減とは扱わない。

今回の有効地図は79,680 Bで、96 KiBとの差18,624 Bも常時予約する。そのため、生成時最低空き量は以前より約18 KiB少ない。画像のmalloc管理分が消える効果等があるため、単純な容量差と実測は数十〜数百B程度異なる。

固定化後の各起動では、3周ともメイン復帰後の占有量95,456 B・空き60,732 Bで一致した。今回の12周中、固定化後の2起動・計6周について、復帰後に増え続ける量はなかった。

## 所要時間

1起動につき9回の実地図読出しの合計は、変更前[2053, 2053] ms、変更後[2029, 2026] ms。平均は2053.0→2027.5 msだった。Readerのバッファ量、GLCの探索・展開・間引き方法は変更していない。この小規模比較を一般的な速度改善の証明とはしない。

## ホスト試験

- native回帰、実AppのGPS記録・ログ閲覧・UI操作。
- MapのASan/UBSan試験とStorage作業域試験。固定配列への参照維持、100回の排他切替で確保0、容量超過時のフォールバック禁止、新しい画面世代での再描画を確認。
- N03とestatの実データで、独立した地名キャッシュと地図の中心コード、1/1・1/2・1/4の間引き後コード列と境界画像を照合。
- 借用Reader試験で、索引用4 KiBの借用・返却、処理終了後のFactory解除、例外時の後始末を確認。

大きな配列はホスト試験側も明示的な固定バッファを渡す方式に変更し、製品に動的確保の互換フォールバックを残していない。実機では地図・ログ閲覧・統計の自動操作を前後各6周で確認した。実機の手動キー試験とは区別する。
