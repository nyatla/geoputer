# 一時パスの固定長化とスタック配置

## パスの規則

アプリ内の一時フルパスはStoragePath.hのTemporaryPathで統一する。Config.hのTemporaryPathBytesは256で、終端NULを含む。上限はUTF-8の255バイトであり、255文字ではない。SD表記とFatFs表記のどちらも上限を満たす必要がある。途中で切り詰めることはなく、上限超過や埋込みNULを検出した時点で失敗させる。

パス連結はstring_viewの組を固定配列へコピーし、FatFsのドライブ番号も局所文字配列で生成する。変換・連結にはヒープを使用しない。TemporaryPathはファイル操作を実行するスコープで保持し、そのc_str()を返却後まで保存しない。

## 適用範囲と寿命

地図生成・地名検索・ログ・索引・メタデータ確認・エクスポートのパス変換を固定長化した。データセットディレクトリ、INIへの連結、索引のtmp/dat/bakと公開・復旧用のパスも同じ型を使う。索引の保持パス３個はトランザクションの終了までスタック上に置く。renameの元・先は同時に必要なので、２個分の変換領域を使う。

選択中データセット、非同期のログ閲覧、書込み再試行、エクスポートのジョブ状態に保持するパスは、各所有者のstringとして維持する。SDKのFactory APIが所有するメタデータ確認用パスも維持する。これらの保持文字列やWordbookの可変配列・地名文字列までヒープから除去した変更ではない。

地図で使用していたNativePathBufferとUI backのパス用512バイト領域を廃止した。MapReadWorkspaceはReader用4,096バイトのみとし、地名検索のPlaceReadWorkspaceもReader用4,096バイトと結果領域を維持する。4KiBの読出しバッファはスタックへ移さず、UIから借りて索引・GLC・Wordbookで順に使う。

選択中のFileReadSourceはパス変換先を保持しない。パスを使うのはopen/stat等の呼出し中だけで、Reader本体やFILは変換領域を参照し続けない。上限超過は既存の検索・データセットエラーへ変換する。ログのbool型openはENAMETOOLONGを返し、一覧・エクスポートも既存のエラー状態へ遷移する。

## 検証

- １～３桁のドライブ番号で内容一致、両表記の上限直前／超過を確認。
- 日本語を含む255バイトのパスを完全なバイト列のまま扱い、追加１バイトは失敗することを確認。
- stdio／FatFs、診断無効／有効で借用Reader・固定FIL・スタックパスの正常処理がC++確保０回であることを確認。
- パス超過とI/O・デコーダー例外でFILと4KiBの借用を返却し、UI backの読出し領域外へ書き込まないことを確認。
- 長すぎるログディレクトリ、ログファイル、エクスポート先が、未処理例外ではなく既存の失敗結果になることを確認。
- N03とestatで地図の等倍／1/2／1/4と地名検索の結果が一致し、地図の借用経路のC++確保０回を確認。
- 索引生成・元データ突合・構造とCRC・公開失敗時の旧索引復旧を確認。
- 実アプリの設定・ログ記録／閲覧・画面切替・遅延結果・キャンセル・USB所有権・GPX/KML/CSV出力のホストテストを確認。

実機への書込み、変更後の実機スタック余裕・処理時間の再計測はこの変更では実施していない。

## ESP32ビルドとメモリ比較

通常ファームの変更前ELFと最終ビルドを比較した。

| 項目 | 変更前 | 変更後 |
|---|---:|---:|
| 静的RAM | 253,404 B | 253,380 B |
| Flash | 1,242,693 B | 1,241,801 B |
| FileReadSource本体 | 40 B | 32 B |
| PlaceLookup本体 | 2,928 B | 2,904 B |
| MapReadWorkspace | 4,608 B | 4,096 B |

パス変換先の参照をFileReadSourceから除き、静的RAMは24 B減少した。UI back自体は6,060 Bの画像として引き続き必要なので、借用レイアウトの512 B縮小を、そのまま物理メモリの解放とは数えない。TemporaryPath本体は256 B、Reader本体は88 B。StorageとUSBStorageのタスクスタックは12,288 Bを維持し、増設していない。

コンパイル結果の主な個別スタックフレームは次のとおり。

| 関数 | 変更前 | 変更後 |
|---|---:|---:|
| ReadFile::openRead | 80 B | 320 B |
| FileReadSource::inspectSource | 368 B | 608 B |
| readBoundaryMap | 512 B | 496 B |
| PlaceLookup::searchInto | 80 B | 80 B |
| DatasetIndex::apply | 656 B | 1,120 B |
| DatasetIndex::build | 320 B | 1,408 B |

索引生成は３本の保持パスもスタックへ移したため増分が大きい。代入で構築した時点では1,888 Bだったが、上限を事前確認して直接構築することで1,408 Bへ抑えた。長すぎるディレクトリではファイル操作や進捗通知を実行せずIndexFailedを返し、固定FILを借りないこともテストした。

表は各関数のフレームであり、呼出し全体の最大使用量ではない。通常のopen/stat用パスはそのファイル操作の終了時に寿命が終わり、4KiBのデータバッファをスタックへ積む変更はしていない。変更後の実機スタック余裕・空きヒープ・処理時間の数値は未計測である。
