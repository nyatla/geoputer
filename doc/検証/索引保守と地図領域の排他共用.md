# 索引保守と地図領域の排他共用

検証日: 2026-10-28

## 実装内容

設定からのデータセット適用・キャッシュ再生成・元データとの突合検証に、Storage所有の地図用96 KiBを貸す経路を追加した。通常地図・ログ地図のMapSessionを無効化して参照を外し、StorageMapMemoryのunionを地図配列からDatasetIndexWorkspaceへ切り替える。地名判定用64 KiBとUIの固定front/back画像は別のままとする。

未完了の地図／ログ読出し、未返却の地図結果、使用中のFIL、二重借用がある場合は開始しない。拒否時は保持地図を変更しない。StorageIndexLeaseが操作の寿命を管理し、成功・失敗・例外時にReader／OutputとFILを終了してから地図型を再構築し、MapSessionの参照を結び直す。validはfalseのまま戻すため、次の地図表示は再生成となる。検証で索引ファイルを書き換えない場合も、保持地図は無効になる。

## 作業領域

| 内容 | 容量 |
|---|---:|
| Source／Output共通の第1バッファ | 4,096 B |
| Source／Output共通の第2バッファ | 4,096 B |
| チャンク座標1,500件（int32 x/y） | 12,000 B |
| 合計 | 20,192 B |

DatasetIndexWorkが同時に生存するSource／Outputへ別々のバッファを貸す。生成では元データと書込み、突合検証では元データと比較索引を保持する。各Sourceの終了後に同じ領域を再利用し、3本目へ動的に退避しない。固定FILも従来の2枠を使う。座標は固定配列へ直接読み込み、作業領域全体や座標配列をタスクのスタックへ置かない。

INI解析、言語別辞書一覧、進捗の言語文字列等の動的確保は残る。作業領域を渡さないDatasetIndexは従来の自己確保する動作を維持する。通常の地名・地図読出しが借りるUIの4 KiBも変更しない。索引形式、CRC、全体再生成、元データとの照合、公開・ロールバックの仕様は同一である。

## ESP32ビルドとスタック

直前の通常ビルドELFを保存し、変更後のcardputer-advビルドと比較した。

| 項目 | 変更前 | 変更後 |
|---|---:|---:|
| 静的RAM | 253,532 B | 253,532 B |
| Flash | 1,240,901 B | 1,242,717 B |
| Application | 217,352 B | 217,352 B |
| StorageTask | 174,224 B | 174,224 B |
| StorageCodeImages | 163,840 B | 163,844 B |

役割管理で下位構造体は4 B増えたが、上位構造体の整列に収まり、全体の静的RAMは増えていない。StorageMapMemoryは管理込み98,308 B、DatasetIndexWorkは28 B、StorageIndexLeaseは40 B。20,192 Bのデータ本体はunion内にあり、後者2つは参照と貸出し状態だけを局所保持する。

個別関数のスタックフレームは、maintainDatasetIndexが576→640 B、applyDatasetSelectionが624→656 B、索引generateが1,376→1,408 B。buildは1,408 B、verifyAgainstDatasetは496 B、completeDatasetJobは1,072 Bで変化しない。座標12,000 Bやバッファ8,192 Bがフレームへ入っていないことを確認した。これらは個別フレームの静的確認であり、外部コードを含む最大使用量や実機ウォーターマークではない。

## 検証結果

- N03とestatで、自己確保版と借用版の生成索引がバイト単位で一致。再生成・突合検証・既存索引の適用で、4 KiBのC++ newが0回、単一の最大要求も4 KiB未満となることを確認。
- 固定座標配列へ書かれた先頭座標が生成された索引の座標と一致。最大1,500件の末尾にも配置可能で、2つのバッファが互いを上書きしないことを確認。
- 書込み・同期・close・公開の失敗時に、借用バッファとFILが返り、公開済み索引が維持されることを確認。同じ作業領域で再試行できる。
- 正常返却と例外時の地図型復元、古いMapSessionの無効化、参照の結び直し、地名判定配列の保持を確認。
- 未完了読出し、使用中FIL、読出し中の地図、完了したが未返却の地図結果、二重保守を拒否し、既存内容を無効化しないことを確認。
- 全言語、長い言語ID、破損・CRC・元データ変更、保存失敗時の復旧、未使用の一時ファイル、16／64 KiB境界、複数ブロック群の既存試験が成功。
- 通常ホスト試験、Appの記録・画面遷移試験、Storageの100回の固定領域切替、ESP32向けビルドが成功。

使用したランナーはrun_dataset_index.py（N03・estatと人工データ）、run_storage_work.py、run_native.py、run_logger_app.py。実機への書込み、処理時間比較、実機の空きヒープ／スタック計測は今回実施していない。
