# 索引保守のヒープ除去

検証日: 2026-10-29

## 変更

アプリの索引適用・再生成・元データとの突合検証から、全言語辞書情報のvector／文字列と、進捗言語名・4文字識別子のstringを除去した。INI解析は前段の固定出力を使用する。

全言語の情報はIndexBookTableへ最大16件保持する。1件は言語ID32 B、辞書名128 B、ファイル長・FAT時刻・ヘッダーCRC各4 Bで計172 B。16件2,752 Bと件数・整列分4 Bを合わせて2,756 Bとなる。DatasetIndexWorkspaceへ配置し、既存の地図用96 KiBとunionで共用する。新しい常設配列や、2.7 KiBのスタック配列は追加しない。

BookSourcesが表の借用を操作全体で管理し、正常終了・例外終了の両方で返す。DatasetIndexWork::inUseは表の占有も含む。二重貸出しは表を変更する前に拒否する。適用から全再生成へ進む時は先行する表を返してから借り直す。次の操作では件数を0へ戻し、少数言語の結果へ前回の行を混入させない。

進捗言語名はchar[32]、GLCH・GW00・GI01・LAYO等の照合はchar[4]を使う。SourceとOutputは従来の4 KiB×2本と固定FIL2枠を借りる。チャンク座標は従来どおり12,000 Bの固定配列を使用する。ファイル形式、言語の整列順序、生成・検証・公開・NVS保存・復旧の順序は変更しない。Core・SDKは変更していない。

作業領域を指定しない互換APIでは辞書表を自己確保する。正常なアプリ呼出しは必ず既存作業領域を渡す。破損検出・I/O失敗・不正な再入などの例外生成、標準IO・NVS等の内部確保は今回の「C++確保0件」の対象外とする。

## ヒープ比較

同じホスト試験コードで変更前後を比較した。対象区間はDatasetIndexの操作呼出し全体であり、C++のoperator new/new[]の回数と累計要求量を計数する。試験用のパス・INI・比較用データの作成は計数前に済ませ、進捗の受信側も固定領域を使う。renameの障害注入アダプタからも不要なstringを除き、試験自身の確保を混入させない。

| 条件 | 操作 | 変更前 回数／累計要求量 | 変更後 |
|---|---|---:|---:|
| 1言語 | 再生成 | 2回／97 B | 0回／0 B |
| 1言語 | 突合検証 | 2回／97 B | 0回／0 B |
| 1言語 | 正常な既存索引の適用 | 2回／97 B | 0回／0 B |
| 16言語・31 BのID・127 Bの辞書名 | 再生成 | 38回／5,072 B | 0回／0 B |
| 同上 | 突合検証 | 38回／5,072 B | 0回／0 B |
| 同上 | 正常な既存索引の適用 | 37回／5,040 B | 0回／0 B |
| 同上 | 索引なしからの適用・全生成 | 75回／10,112 B | 0回／0 B |

累計要求量はピークの同時使用量ではない。16言語の試験は同じ実Wordbookを複数の言語から参照する負荷条件で、INIの順序を逆にして索引の整列順序を確認する。N03とestat、両方の実データで変更後の確保0件を確認した。進捗通知を有効にし、最大長の言語IDを欠けずに返すことも検査する。

## スタック

コンパイラが生成した関数単体のフレームを比較した。呼出し先やOS・標準IOを含む最大スタック使用量、実機の高水位とは区別する。

| 関数 | 変更前 | 変更後 |
|---|---:|---:|
| 辞書情報の列挙（bookSources → readBookSources） | 1,584 B | 1,504 B |
| DatasetIndex::apply | 1,088 B | 1,104 B |
| DatasetIndex::build | 1,408 B | 1,408 B |
| DatasetIndex::verifyAgainstDataset | 480 B | 480 B |
| generate | 1,248 B | 1,232 B |
| StorageTask::maintainDatasetIndex | 1,024 B | 1,024 B |

辞書表全体をスタックへ載せず、列挙時の局所言語一覧も生成・TI00の再帰へ入る前に寿命を終える。新しい表を値返却・値コピーする経路は設けない。

## 検証結果

- `tests/run_dataset_index.py`をN03・estatで実行して成功。正常経路の確保0件を厳密に検査し、自己確保する互換経路と生成バイナリ全体が一致することを確認。
- 同試験で、書込み・同期・close・公開失敗時の借用返却と旧索引維持、失敗後の再利用、正常な適用で索引を書き直さないこと、CRC・構造・元データとの独立検証、全言語・長いID・合成データの境界を確認。
- 16件から1件への表の再利用、二重貸出し拒否、索引なしの適用からBuildへの移行を確認。
- `tests/run_storage_work.py`で、地図・索引用unionの型と寿命、2本のバッファ、固定FIL、失敗時の保持、100回の動的確保なしの切替を確認。
- `tests/run_borrowed_place_files.py`で、N03・estatの初期確認と各7点の検索が引き続きC++確保0件であること、結果一致・例外時返却を確認。
- `tests/run_native.py`の既存試験と、cardputer-advのビルドが成功。今回の変更ファイルの空白検査も成功。

実機への書込み、実機の処理時間・空きヒープ・スタック高水位の再計測は今回実施していない。
