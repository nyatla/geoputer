# App所有データセットセッションと固定ファイル名の検証

検証日: 2026-10-28

## 変更内容と所有関係

選択中の実行情報`SelectedDataset`をStorage所有からApp所有へ移した。AppはStorageより先にセッションを構築し、Storageの破棄後まで保持する。Storageは参照を借用し、既存の受付・完了通知の範囲内でセッションを更新する。AppとUIへの公開は既存の結果スナップショットを使い、処理中の内容を別タスクから直接読み書きしない。

本体のルートは`/sd/dataset/`で固定し、番号は整数0（未選択）または1〜99とする。使用中の地図名と選択言語のWordbook名を各128バイトの配列へ保持する。拡張子を含めUTF-8で127バイトまでとし、128バイト以上は拒否する。日本語もバイト数で数える。詳しい規則は[データセットメタデータ仕様](../08_データセットメタデータ仕様.md#22-地図名と辞書名の容量)に定義した。

ディレクトリとGLC・Wordbook・索引のフルパスはセッションに保存しない。FileReadSourceは番号・ファイル名・固定ルートを参照する非所有のパス情報を保持し、ファイル操作時に256バイトの一時パスへ組み立てる。Readerとその参照元を閉じてから名前を書き換える。索引名は固定の`_mapindex.dat`とし、INI形式・NVS形式・索引形式・SDK/coreは変更していない。

## ESP32向けビルドの比較

この変更の直前に保存したELFと、変更後のcardputer-adv通常ビルドを比較した。いずれも同じビルド設定を使用した。

| 項目 | 変更前 | 変更後 | 差 |
|---|---:|---:|---:|
| ファームの静的RAM | 253,380 B | 253,612 B | +232 B |
| Flash使用量 | 1,241,801 B | 1,243,833 B | +2,032 B |
| Application本体 | 217,200 B | 217,432 B | +232 B |
| StorageTask本体 | 174,656 B | 174,304 B | −352 B |
| SelectedDataset本体 | 416 B | 584 B | +168 B |
| PlaceLookup本体 | 2,904 B | 2,960 B | +56 B |
| FileReadSource本体 | 32 B | 48 B | +16 B |
| ObservedFileReader本体 | 88 B | 88 B | 0 B |
| UiData本体 | 1,392 B | 1,392 B | 0 B |

構造体の値は内包する領域を含むため、表の行を加算しない。Applicationの増分には所有場所の変更とパス情報の変更を含む。名前２つの固定配列は合計256バイトで、セッション全体は584バイトとなった。以前の概算で想定した言語や表示書式の固定長化は行っていない。

保持していたフルパス文字列のヒープ確保はなくなった。削減量はファイル名長とアロケータに依存するため、静的RAMの増分と相殺した実機の空きヒープ値は未計測。言語・表示書式、INI解析中の情報、Wordbook検索の配列・文字列等には動的確保が残る。

コンパイル結果の個別スタックフレームは、PlaceLookup::openが784→1,040 B、FileReadSource::inspectSourceが608→672 B、ReadFile::openReadが320→352 B、readBoundaryMapが496→576 Bとなった。一方、StorageTask::configureDatasetは416→64 Bとなった。これらは呼出し全体の最大使用量ではない。タスクのスタック設定は変更しておらず、変更後の実機ウォーターマークは未計測。

## 検証結果

以下のホスト検証とESP32向けビルドが成功した。

- 地図名・辞書名の127／128バイト境界、日本語UTF-8、未選択言語にある長すぎる辞書名を確認。超過時は切り詰めず、既存の名前を途中まで書き換えない。
- 番号1・99、固定索引名、FatFsドライブ番号、共通の255バイト一時パス制限を確認。パスの組立・変換単体は正常系でC++ヒープ確保０回。
- App、Storage、PlaceLookupが同じセッションを参照することを確認。
- 01→02の切替で地図名・辞書名・表示書式を変更し、旧Readerとキャッシュを破棄して再準備できることを確認。同じ番号の再適用、未選択への解除、失敗後の再準備も確認。
- N03で324点のキャッシュ検索と直接検索が一致。N03・estatの地名検索で通常経路と借用バッファ経路の結果が一致。
- N03・estatの地図生成で1/1・1/2・1/4の区域画像と境界画像が一致。借用経路の地図生成はC++ヒープ確保０回を維持し、完了・例外時の借用返却も成功。
- stdio／FatFs、診断有効／無効のReaderテスト、通常ホストテスト、Appの記録・画面遷移・借用管理テストが成功。

実行ランナーはrun_native.py、run_logger_app.py、run_borrowed_reader.py、run_place_files.py、run_borrowed_place_files.py、run_borrowed_map_files.py。実データはN03-20260101とestat-r2ka-jgd2011-2020を使用した。

SDへの読出し回数を増やす変更はなく、ファイル操作ごとの固定長パス組立が追加される。実機の処理時間比較とファーム書込みは今回実施していない。
