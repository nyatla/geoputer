# USBストレージモードの実装検証

2026-10-17。[起動モード・USBストレージ仕様](../09_起動モード・USBストレージ仕様.md)に従い、永続フラグによる起動分岐、動作設定の切替項目、共通終了ダイアログ、SDの生セクタ公開を実装した。

USBメニューと端末内変換を追加した版の検証は[ログエクスポート実装検証](ログエクスポート実装検証.md)へ分離する。本書の生成物・実機結果はSD公開版の記録として維持する。

## 実装範囲

通常起動は従来のApp・UI・GPS・Storage、USB起動はApp・UI・Storageとし、USB側ではGPSとFatFsのマウント・地図・辞書・ログ処理を開始しない。MSCインターフェースもUSB起動時だけ登録する。USBシリアルは両モードで使用するためUSB-OTG / TinyUSBへ移行した。

フラグは既存のconfigレコードとは別のNVSキーへ保存する。切替要求の同期受付だけでは再起動せず、Storageの保存成功通知後に再起動する。結果待機中に完了通知を取り込む場合にも操作IDを取り直さない。受付後のUI操作・自動消灯を抑止し、失敗時に再試行できる状態へ戻す。

USB読書きと終了を同じミューテックスで保護する。終了は進行中の転送完了とSD同期を待ち、フラグ保存が成功してから媒体を非公開にする。新しいUSB転送用の要求キューは追加せず、状態の変化をStorageから既存のApp通知キューへ送る。

## 実機確認の範囲

2026-10-17、当初の`b523755e…`版を実機へ書き込み、esptoolの書込み後ハッシュ検証に成功した。NVS・SDの内容は保持した。

通常起動のログで`mode=GPS LOGGER`、240×135表示、4タスク・5キュー、保存済み設定の読込み、SDのFAT32認識、GPS UART受信・FIX、GaluchatのOPEN OKを確認した。実SDのデータセットは172チャンクで、地名「千葉県 習志野市」の取得とキャッシュヒットも確認した。USBシリアルはCOM3として再認識された。ログは`.pio/usb-mode-boot.log`へ保存した。

その後のUSBモード切替では、Windowsでデバイス記述子の取得失敗が発生した。USBを先に初期化する中間版では複合デバイス・COM4を認識したが、SD容量とボリュームが確定しなかった。

最終版では、USBクラスを起動モードに応じて先に登録し、USBコントローラ初期化後は切断状態で待機する。UIタスクのM5本体初期化を同期応答で確認してからStorageとSDを初期化し、その結果を画面へ反映してからUSBを接続する。再起動前にも明示的にUSBを切断し、USBモードのシリアル番号には`-SD`を付けた。個々の変更の因果関係を分離する比較試験は行っていない。

最終版の書込み後ハッシュ検証に成功し、次の実機動作を確認した。

- Windowsが`GeoPuter SD Card`、シリアル`70AF09DF46D0-SD`、容量1,018,691,584バイト、MBRのオンラインディスクとして認識した。
- KドライブへFAT32として割り当てられた。Jドライブは接続前から存在する別の空媒体である。
- `dataset/01`のGLC・Wordbook・dataset.iniの一覧を取得でき、dataset.iniのSHA-256計算に成功した。
- 新規の一時ファイルへ4096バイトを書き込み、`Flush(true)`で同期して閉じ、再度開いて全バイトを照合した。試験用ファイルは削除した。既存のデータセットやログは編集していない。
- ユーザー操作によるUSB終了後、通常モードへの復帰とCOM3の再認識、GPSの継続したFIXを確認した。
- 通常モードから再びUSBへ切り替えた後も、COM5とKドライブのFAT32認識、dataset.iniの読出しに成功した。dataset.iniのSHA-256は試験前後で一致した。

USBモードのCDCはCOM5として認識したが、そのモードのConsole本文は今回の監視では取得できなかった。SDの実読書き確認はWindowsのディスク・ファイルAPIと端末表示に基づく。

USB構成の変更により、書込み後のUSBシリアルのCOM番号が従来から変わる可能性がある。ソフトウェアCDCのシリアルモニタはDTR・RTSの両方を有効にする設定とした。これらの実機経路をホストの配列試験や画素比較で確認済みとは扱わない。
