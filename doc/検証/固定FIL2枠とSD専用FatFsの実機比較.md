# 固定FIL2枠とSD専用FatFsの実機比較

2026-10-28。まずSDK標準FatFs＋固定FIL2枠をCardputer ADVで計測し、次にアプリ全体をSD専用FatFsへ切り替えて同じ条件で計測した。

## 結果

地図生成は全条件で増減が1%以内、estatの全索引生成は約+0.9%、元データ突合は約+0.1%だった。速度はほぼ同等で、地図画像のハッシュは全条件で一致した。N03の索引生成は単発計測で約−4.8%だが、確定した高速化効果とは扱わない。

メモリの余裕は増加した。estatの索引生成・突合中の最小空きヒープは42,792 Bから67,972 Bへ増え、最大連続空き領域の観測最小値も30,708 Bから55,284 Bへ増えた。固定FILだけでなく、ログ記録のFIL、VFSのFATFSとファイル枠も小さくなった効果を含む。

## 索引生成・検証とヒープ

時間は秒、ヒープはバイト。索引は各処理1回の計測値であり、統計的な誤差幅は評価していない。生成は一時ファイルの作成、レコード生成、ヘッダ補完、CRC追記、同期・閉鎖を含む。元データ突合は全レコード再計算と比較、生成前後の元ファイル識別情報の確認を含む。

| データセット | 処理 | SDK標準版 | SD専用版 | 増減 | SDK最小空きヒープ | SD最小空きヒープ |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| N03 | 全生成 | 4.656 | 4.431 | -4.84% | 42,288 | 67,928 |
| N03 | 構造・CRC | 0.020 | 0.019 | -4.85% | 48,288 | 73,432 |
| N03 | 元データ突合 | 4.174 | 4.229 | +1.34% | 42,288 | 67,928 |
| estat | 全生成 | 20.360 | 20.537 | +0.87% | 42,792 | 67,972 |
| estat | 構造・CRC | 0.035 | 0.033 | -4.47% | 48,216 | 73,396 |
| estat | 元データ突合 | 18.512 | 18.540 | +0.15% | 42,792 | 67,972 |

SDK版は試験前に取得済みの正式索引を維持し、`_fil_compare.tmp`を排他的に作成して生成・検証後に削除した。SD専用版も同じ方法を使用した。正式索引・元データ・NVS選択は変更していない。

## 比較条件とメモリの取り方

- ESP32-S3 / Cardputer ADV、Arduino-ESP32 2.0.17 / ESP-IDF 4.4.7、FatFs R0.13c。
- SDのSPIは25MHz指定、実クロック20MHz。Galuchatの先読みは4KiBのまま。
- dataset/01はN03（GLC 4,691,841 B）、dataset/02はestat（GLC 23,800,183 B）。いずれもINIで宣言されたWordbookを処理。
- 通常のApp・UI・GPS・Storageタスクを起動し、ログ停止・保持セッションなし・他のStorageジョブなしで自動計測。
- 両版ともStorageの共通固定FILを2枠使用。比較ファームの追加固定領域も両版で同じ6,112 B。SDK比較版の静的RAMは269,944 B、SD比較版は259,396 Bだった。
- 空きヒープと最大連続空き領域はMALLOC_CAP_8BITを使用し、SDアクセス境界などで観測した最小値。全命令・全mallocを追跡した厳密な瞬間最小値ではない。
- 比較ファームのヒープ値は通常版そのものの絶対値とは区別する。上表の静的RAMは、計測用処理を除いた通常版のビルド値。
- Storageタスクのスタック余裕は計測中両版とも3,132 B。共有FILをタスクスタックへ置く変更はしていない。

## SD専用版への接続

`Config.h`の`REVERSEGEOPUTER_SD_FATFS=1`を既定とした。0を指定するとSDK版の基準実装に戻してビルドできる。

`StorageFs.h`はアプリ名前空間内のネイティブ型・関数だけを選択し、SDK標準のグローバル型・関数・ヘッダを置き換えない。ArduinoのSDドライバはセクタI/Oとして使用し、SD専用FatFsと専用VFSが同じSDを管理する。SDK FatFsと同じ媒体を同時にマウントしない。

`StorageCard`に初期化・マウント・アンマウント・解放を集約し、通常モード、SDフォーマット経路、USBモードの端末側ファイル操作で使用する。USBのPC側アクセスは従来どおりrawセクタを使い、ローカルFatFsと排他にする。専用VFSはESP-IDF 4.4.7の公式実装を分離して使用し、stdio、stat、ディレクトリ操作も専用版へ接続した。

SD専用の実機比較では、VFS経由の排他的作成・書込み・セクタをまたぐ読出し・seek・fstat・fsync・close・日本語名へのrename・readdir・unlinkが成功した。ローカルを解除してrawで読出し、再マウントする所有切替も2回成功した。PCのUSBドライブを実際に再接続する試験とは区別する。

## 記録と再現

[生データCSV](固定FIL2枠とSD専用FatFsの実機比較.csv)はSDK版42件＋SD専用版42件。`backend`が実装、`round=0`が初回。計測用のソースはtests/performanceのFsComparisonBenchmark.h・FsIndexComparison.inc・FsStorageComparison.incに保存した。

```sh
python3 tests/performance/prepare_fs_comparison.py --output /tmp/rgp-fs-sdk --backend sdk
python3 tests/performance/prepare_fs_comparison.py --output /tmp/rgp-fs-sd --backend sd
# 各出力先で pio run -e cardputer-adv を実行する。
```

比較用bin・ELF・ソースの保存先は`.pio/twofil-comparison/`、実機ログは`.pio/borrow-layout-bench/twofil-sdk.log`と`twofil-sd.log`。
