# SD専用FatFsの実機性能比較

2026-10-28、Cardputer ADVの実SDで、SDK標準FatFsと512バイトセクタ専用のSD_FatFsを比較した。

## 結果

512バイト化による読出し量・転送回数の増加はなかった。最終版では通常のファイル読出しはほぼ同等だった。同一セクタ内の1バイト読出しを繰り返すケースでは約1.9%の増加が残るため、全操作が完全に同じ時間とはいえない。

estatのGLCを対象とした、初回を除く4回の中央値は次のとおり。時間はミリ秒、増減率は専用版 / 標準版 − 1。読出し回数とセクタ数は両版で一致した。

| 操作 | SDK標準版 | SD専用版 | 増減 | SD読出し回数 / セクタ数 |
| --- | ---: | ---: | ---: | ---: |
| 4KiB連続・512KiB | 294.238 | 294.507 | +0.09% | 133 / 1029 |
| 512B連続・512KiB | 532.558 | 533.979 | +0.27% | 1029 / 1029 |
| 1Bずれの4KiB連続・512KiB | 328.363 | 328.375 | +0.00% | 262 / 1030 |
| ランダム4KiB × 32回 | 241.656 | 241.023 | -0.26% | 376 / 558 |
| 同一セクタ内1B × 512回 | 33.758 | 34.387 | +1.86% | 4 / 4 |
| 境界をまたぐ17B × 128回 | 73.033 | 73.254 | +0.30% | 133 / 133 |

全6ファイルについて、ファイルごとの増減率を求めてその中央値を比較した結果は次のとおり。

| 操作 | 状態確認の重複除去前 | 重複除去後 |
| --- | ---: | ---: |
| 4KiB連続・512KiB | +1.19% | -0.12% |
| 512B連続・512KiB | +5.04% | +0.15% |
| 1Bずれの4KiB連続・512KiB | +1.89% | -0.18% |
| ランダム4KiB × 32回 | +2.65% | -0.04% |
| 同一セクタ内1B × 512回 | +2.30% | +1.87% |
| 境界をまたぐ17B × 128回 | +4.82% | +0.22% |

初回計測では専用版の接続層が`read`・`write`・`ioctl`直前に`disk_status`を追加実行していた。Arduino SDドライバの状態取得は実際にSDへコマンドを送るため、読出し回数に応じた遅延を生んでいた。FatFs本体の状態確認と重複するこの呼出しを除去した。転送中の取り外し、I/O障害、書込み保護はバックエンドの戻り値で検出する契約とし、ホストテストでも保護・失敗結果の伝達と状態取得の呼出し回数を確認した。

同一セクタ内の極小読出しで残る差については、専用版のコールバック・ロックなどの接続経路も異なるため、セクタバッファのサイズだけを原因と断定しない。このケースでもデータ読出し量の増加はない。

## 条件

- ESP32-S3 / Cardputer ADV、Arduino-ESP32 2.0.17 / ESP-IDF 4.4.7 / FatFs R0.13c。
- 同じSDカード、512バイトセクタ、FAT32。同じArduino SDドライバとSPI配線を使用。
- SPIは25MHz指定、実クロック20MHz。
- 標準版と専用版を同じファームにリンク。片方をアンマウントしてから他方をマウントし、同じ媒体を同時には管理しない。
- `dataset/01`のN03と`dataset/02`のestatにあるGLC・Wordbook・索引の計6ファイル。
- 6操作 × 5ラウンド × 2実装 × 6ファイル = 360試行。初回ラウンドを除く4回の中央値で比較。ラウンドごとにAB / BAの順序を交替。
- 連続読出しは最大512KiB、ランダム読出しはファイル全体から32か所を選択。同一セクタ内読出しは512回、境界読出しは最大128回。小さなファイルは長さに応じて短縮。
- `f_open`・`f_lseek`・`f_read`・`f_close`の合計時間を比較。マウント、CRC計算、ログ出力、待機はこの時間から除外。
- SPIドライバへ渡る`ff_disk_read`を計測し、転送回数・転送セクタ数も比較。
- 各ファイル・各操作で、両版および全ラウンドの読出しバイト数・CRC32・転送回数・セクタ数が一致。修正前後合わせて720試行が正常終了。
- 比較ファームではSD書込みを遮断し、書込み要求数は0。NVSも変更しない。
- GPS・UI・Storageの通常タスクを動かさず、ファイルI/Oを単独測定。地図生成全体・Wordbook検索全体・ログ書込みの性能は今回の測定対象に含めない。

| ID | 対象 | ファイルサイズ |
| --- | --- | ---: |
| 0 | N03 `_mapindex.dat` | 9,764 B |
| 1 | N03 GLC | 4,691,841 B |
| 2 | N03 Wordbook | 31,922 B |
| 3 | estat `_mapindex.dat` | 20,148 B |
| 4 | estat GLC | 23,800,183 B |
| 5 | estat Wordbook | 1,713,832 B |

## メモリと実機の復元

ESP32-S3で`FIL`は標準版4,136 B、専用版552 B。`FATFS`は標準版4,156 B、専用版568 Bだった。標準版は4096バイト領域を確保していても、このSDでは512バイトの1セクタをキャッシュする。専用版へ変えても8セクタ分のキャッシュを失うわけではない。

比較完了後は、計測前と同じ通常ファームへ戻した。アプリのSD接続先はSDK標準版のままで、専用版への移行は別作業。

| ファーム | SHA-256 |
| --- | --- |
| 状態確認の重複除去前 | `11c821f47b1d8aea53b948c71e97a3f32542cde8d7c7300399358f613511d24c` |
| 重複除去後 | `1d8ba0f5132dd1cf09257af5a498b9f00becf7f73dcbf1aa8cc86d3b5ec123e8` |
| 復元した通常版 | `531f87553e55ddc414499f327cd3fea01048e80bd75b11863bad2294e046f371` |

## 再現と記録

[比較サンプル](../../third_party/SD_FatFs/examples/cardputer_sd_benchmark/src/main.cpp)はCardputer ADV向け。書込み前に通常ファームを保存し、計測後に元へ戻す。

```sh
pio run -d third_party/SD_FatFs/examples/cardputer_sd_benchmark
python3 third_party/SD_FatFs/examples/cardputer_sd_benchmark/summarize.py DEVICE.log
```

[生データCSV](SD専用FatFsの実機比較.csv)と[中央値の集計CSV](SD専用FatFsの実機比較集計.csv)を保存した。`stage`が`before_status_cleanup`なら修正前、`after_status_cleanup`なら最終版。ラウンド0はウォームアップとして集計から除外している。

専用版のASan / UBSan付きホスト共存テストも、今回の変更後に両方のヘッダ順序で通過した。
