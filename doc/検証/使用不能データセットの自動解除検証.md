# 使用不能データセットの自動解除検証

検証日: 2026-10-23

## 対象と結果

使用中データセットの利用不能を検出した場合、原因を通知してNVSとRAM上の選択を未選択へ移す方式を実装した。定常状態は未選択と使用可能な選択済みに整理し、解除番号・原因・解除保存失敗を、その起動中だけ保持する診断情報へ分離する。正本は[メタデータ仕様8.3〜8.4節](../08_データセットメタデータ仕様.md#83-起動時の復元とエラー)とする。

ホスト回帰試験・実ファイル試験・Cardputer向けビルドが成功した。本変更の実機書込みと、実機での欠落・保存失敗の注入試験は行っていない。

## ホスト検証

`python3 tests/run_native.py`とN03の実ファイルを指定した`python3 tests/run_place_files.py`を実行した。警告をエラーとして扱い、UBSanと標準ライブラリのアサーションを有効にした。設定保存はPreferencesのホスト用バックエンド、地図・辞書・索引の試験は実際のファイルReaderを使用した。

| 対象 | 確認内容 |
|---|---|
| 自動解除 | SD利用不可、欠落、曖昧な構成、メタデータ・形式・文字コード不正、読出し失敗、上限超過、メモリ不足で番号0・空言語へ移る |
| 永続化 | 設定レコードを再読込みすると未選択となり、明るさ・記録間隔など無関係な設定と別のNVS名前空間を保持する |
| NVS保存失敗 | RAMは未選択へ退避し、NVSの旧選択と保存失敗フラグ・エラーを区別する |
| 反復抑止 | 解除後の同じ異常では再通知・NVS再書込みを行わない。NVS保存失敗後も書込みのループを作らない |
| 記録への影響 | 自動解除でログセッション・未保存64件の状態を変更しない。GPS未測位・区域なし・検索中などでは選択を解除しない |
| 表示 | 地名欄は未選択のまま、解除番号・原因の通知を5秒間表示する。期限満了で再描画し、消灯中の異常は復帰後に通知する |
| 保存失敗の表示 | NVS解除失敗の表示と、通常のSD問題を独立に判定する |
| キャッシュ欠落による起動失敗 | N03の有効な地図・辞書を配置して索引を置かず、prepareの失敗から選択解除・保存・Reader解放を行う |
| 次回起動 | 未選択を復元した後はprepare・searchでObserverのSDアクセス件数が増えず、画像キャッシュも保持しない |
| 復旧 | キャッシュを再生成しても保存選択は未選択のまま。明示的な再選択後はReader準備に成功する |
| 回帰 | 既存の候補検証失敗時の現用地名・キャッシュ保持、324点のキャッシュ／点検索比較、キュー・GPS・ログ・USB等の試験が成功する |

Storageが確認・検索で返した失敗だけを自動解除へ流し、候補の詳細・適用失敗では現在の有効な選択を維持する。使用中の番号に対するキャッシュ保守の失敗は自動解除し、別番号の保守失敗は現用選択に反映しない。USBへの正常な所有権移行は自動解除対象としない。

検出して結果として扱える読出し異常を対象とする。以前から検討中の不正データによる強制リセット対策や、圧縮本文の完全検証を追加した変更ではない。
