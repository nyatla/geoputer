# 画面群リソース整理の検証

確認日: 2026-10-25。比較元は画面専用UIデータの共用を適用した未コミット状態（UiData 1,248 B、静的RAM 67,752 B）とする。タスク・キュー構成、同期結果の必須回収、設定・ログ保存形式、Galuchat APIを維持する。

## 構造

ScreenGroupで共通画面・地図・ログ閲覧・設定・USBを分類した。メイン・GPS・MENU・Bootは共通画面として扱う。ログ一覧・詳細・測位点は同じ画面群とし、一覧名と選択位置を保持する。設定内のデータセット編集とライセンス位置も設定の局所状態としてまとめた。

| モジュール | 整理した資源 |
|---|---|
| ScreenGroup.h | 画面群の分類、送信用表示データの準備、不要な画面専用表示データの種別解除 |
| AppScreenResources.h | 地図転送・生成結果・表示アンカー・行位置・再試行と、ログ要求・10件キャッシュ・読出し位置・再試行を種別付きunionで共用 |
| UiScreenResources.h | 地図画像・カーソル、設定・データセット編集・ライセンス位置、USBのページと選択ファイルを名前付きの領域へ集約 |
| StorageScreenResources.h | Storage所有のMapBuildJobとLogReaderをまとめる。実I/O中の寿命は表示画面と独立して保持する |

UIの小さいメタデータは通常構造体に保持し、大きい画像バッファは地図表示時だけ確保する。Appの大きい値型の作業領域と、先行して共用したUiDataのログ／データセット表示データはunionで共用する。共通のGPS・記録・SD・NVS・時計・電池・入力時刻・確定待ち操作を画面専用領域へ移さない。128×128の区域コードキャッシュ、地名LRU、ログ書込みリングは共通の処理資源として維持した。

## 切替と非同期処理

Appは既存のUiRequest内へ次画面の表示データを準備し、UIの受付成功後に自身のリソースを切り替える。専用の追加一時バッファは作らない。拒否では元の画面・世代・作業データを維持する。UIは自身が所有する画像を解放し、各画面の局所状態を初期化する。

要求tokenと取消状態は共用領域の外に残す。地図画面を離れた後も古い地図ジョブを取り消せる。MapCompletedは地図用領域が有効かと取消状態を確認してから反映する。ログ結果はtoken・世代・取消・領域種別を照合し、古い結果を回収する際に現在の地図領域へ触れない。新しい地図要求は古いログ要求の終端結果を回収するまで待つ。Storageは受付済みジョブの資源を完了・取消まで保持し、タスク間の値コピー契約を維持する。

## メモリ

| 項目 | 変更前 | 変更後 |
|---|---:|---:|
| Appの地図作業データ | 個別メンバー | AppMapResources 672 B |
| Appのログ作業データ | 個別メンバー | AppLogResources 464 B |
| 二つの作業領域の保持 | 同時に予約 | 種別込みの共用領域680 B |
| UiModel | 1,640 B | 1,640 B |
| UiData / UiRequest | 1,248 B / 1,280 B | 変更なし |
| 通常ファームの静的RAM | 67,752 B | 67,304 B |
| 通常ファームのFlash使用量 | 1,214,685 B | 1,216,045 B |

作業領域単体では456 B小さくなる。周囲のアラインメントと構造体配置を含む通常ビルドでは448 B減った。先行するUI表示データ共用前の69,096 Bからは合計1,792 B減った。Flashは今回1,360 B増えた。値型のサイズはESP32-S3向けコンパイラのオブジェクトシンボルから確認した。実機の動的ヒープ・最大スタック使用量は再計測していない。
