# 実機動作とメモリ使用量

検証日: 2026-10-29

## 対象と書込み結果

Cardputer ADV／ESP32-S3実機で、選択言語・地名書式の固定長化、索引保守と地図領域の排他共用まで含む最新版を確認した。アプリ領域0x10000だけを書込み、esptoolのデータハッシュ照合に成功した。通常版でFAT32のSD、保存済みデータセット、GPS FIX、地名表示まで起動した。

計測には通常ソースのコピーへ診断出力と自動画面遷移を追加した一時ファームを使った。計測用の追加タスクは作らず、既存タスクのスタック残量を取得した。終了後は通常版を書き戻し、GPS FIX・地名表示・LivePlaceへの遷移を再確認した。NVSの設定変更、ログの記録・削除、索引の再生成は行っていない。

最終的に実機へ書き込んだ通常版firmware.binのSHA-256:

```
82dda79be3e357686d4f599d4070fec7b528824421a35adb85b6abe8ed6804d6
```

計測版のSHA-256:

```
91df428efbddeff4644d046c7a8bbdc89c89c0d940c518aeda1d4064a49ed539
```

## 動作確認

- 実GPSで受信・測位・時刻同期・逆ジオコーディングを確認した。
- 地図の1/1、1/2、1/4、位置変更による地名キャッシュ再構成、保持画像の再着色、通常地図とログ地図の切替、文字表示への復帰を確認した。自動試験の位置変更には実測位置を基準とする仮想座標を用いた。
- GPS、MENU、設定、ログ一覧への遷移を確認した。
- SD上の929点のログを開き、プロパティ、文字情報、地図表示、10点のスキップを確認した。保存ログは読取りだけに使用した。
- 選択中のデータセット02（estat、162チャンク）で、元データと索引の突合検証が成功した。所要時間は約21.0秒だった。
- 検証後に地図を再生成でき、借用した96 KiBが地図用途へ戻ることを確認した。
- 終了時のheap_caps_check_integrity_all(true)は成功し、リセット、スタック保護違反、ヒープ破損のログはなかった。GPS受信ログの最終値はNMEA 4,900、rejected 0、coalesced 0だった。

自動遷移は実キー入力ではないため、検証後の地図表示時に消灯タイマーが働いた。任意キーによる復帰後、地図再生成と試験終了まで成功した。消灯を抑える計測用コピーも準備したが、再書込み・再試験には使用していない。通常版の消灯仕様は変更していない。上記はシリアルログと描画処理の完了確認であり、全画面の目視・全キーの操作試験ではない。

## ビルド時の固定領域

| 項目 | 通常版 | 計測版 |
|---|---:|---:|
| 静的RAM | 253,740 B（247.8 KiB、77.4%） | 253,884 B |
| Flash使用量 | 1,242,305 B | 1,251,077 B |

計測版の静的RAM増分は144 Bで、自動試験の状態・座標等による。通常版のApplicationは217,560 B、内包するStorageTaskは174,224 B、SelectedDatasetは792 Bである。内包関係の行は加算しない。

Storageの固定画像領域は、地名判定用128×128×uint32の64 KiBと、地図区域コード用96 KiBである。索引保守は後者を共用し、4 KiB×2と最大12,000 Bの座標配列、合計20,192 Bを利用する。今回の書式固定化による通常版の静的RAM増分208 Bは、253,740 Bに含まれる。

## 実行時のヒープ

MALLOC_CAP_8BITの全体値を測定した。観測された総容量は162,196 Bで、内部RAMの値と一致していた。ビルドのRAM欄と実行時ヒープは対象領域・集計方法が異なるため、327,680 Bから静的RAMを引いた値をそのまま空きヒープとは扱わない。

| 状態 | 空きヒープ | 最大連続空き領域 |
|---|---:|---:|
| 起動完了・最初の地図を開く前 | 84,536 B | 73,716 B |
| 地図1/1の生成完了 | 84,060 B | 73,716 B |
| 地図1/2の生成完了 | 84,060 B | 73,716 B |
| 地図1/4の生成完了 | 84,060 B | 73,716 B |
| ログ一覧・プロパティ | 84,060 B | 73,716 B |
| ログ文字・ログ地図・点スキップ | 83,860 B | 73,716 B |
| 索引検証後・地図再生成後・試験終了時 | 83,860 B | 73,716 B |

起動後を通じた最小空きヒープは79,228 B（77.4 KiB）、終了時は83,860 B（81.9 KiB）だった。最大連続空き領域は各観測点で73,716 B（72.0 KiB）だった。後者は観測点の値であり、全時間の最小値を別途追跡したものではない。

地図縮尺の変更で64／96 KiBを追加確保する動きはなく、ログ表示後と索引検証後も同じ空き量へ戻った。起動直後との差676 Bについて、アプリ・標準IO・ドライバの割当元別の追跡は行っていない。今回の約4分の試験では、この差が継続的に増える傾向は見られなかった。起動時や索引保守に残るメタデータ等の動的確保がなくなったことを意味しない。

これらは計測版での値で、診断用144 Bとログ出力の影響を含む。通常版での全操作中の最小ヒープ値を直接測ったものではない。

## タスクのスタック

ESP-IDFのuxTaskGetStackHighWaterMarkはバイト単位で、タスク起動以来の最小残量を返す。計測版の全試験終了時の値を示す。

| タスク | 確保量 | 最小残量 | 観測上の最大使用量 |
|---|---:|---:|---:|
| App／loopTask | 8,192 B | 2,424 B | 5,768 B |
| UI | 8,192 B | 3,224 B | 4,968 B |
| GPS | 4,096 B | 2,392 B | 1,704 B |
| Storage | 12,288 B | 3,044 B | 9,244 B |

通常版へ戻した後の起動・LivePlace遷移時のApp最小残量は3,132 Bだった。計測版のAppには自動試験処理が入るため、その2,424 Bを通常版の操作全体の値とは扱わない。今回実行した地図・ログ閲覧・索引突合検証では各タスクに残量があり、スタック設定は変更していない。

測定の数値一覧は[実機メモリ計測CSV](20261029_実機メモリ計測.csv)に保存した。長時間運用、索引再生成、USBエクスポート、実GPSでの新規ログ保存は今回の試験対象に含めない。
