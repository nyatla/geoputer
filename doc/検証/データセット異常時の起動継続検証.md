# データセット異常時の起動継続検証

2026-10-21、採用仕様1.4をアプリへ反映した。GLC・Wordbookの形式とGaluchatのライブラリAPIは変更しない。

## 実装

Bootのデータセット専用停止と全面警告を廃止し、異常があっても通常の確認完了後にLive Placeへ進む。地名欄は日英の固定2行・地名フォントを使い、Fix喪失より原因表示を優先する。純粋なデータセット異常で赤帯を重複させず、GPS・記録・通常操作を維持する。

PlaceLookupは欠落・構成／形式不正・文字コード未対応・上限超過・メモリ不足・実検索の読出し失敗を保持し、Reader・矩形・辞書キャッシュを解放する。GPS要求やprepareの繰返しでは再オープンしない。明示的な再検証で世代を進め、Appは未完了の要求IDとデータセット世代を照合する。古い成功通知で使用不可を解除しない。

SD再マウント・フォーマット成功、同じ選択の適用成功後はCheckDatasetを要求し、検証成功後だけ検索可能へ戻す。候補の検証失敗では使用中のデータを変更しない。NVS保存失敗も再開の条件にしない。

## ホスト・描画の確認

- UBSan付きの既存ホスト試験で全データセット異常のBoot継続、直接設定操作、F1入口、非重複の赤帯、表示幅、世代による復旧と古い結果の拒否を確認した。
- 実ファイルで324件のキャッシュ／point結果一致を維持し、欠落・曖昧さ・破損・辞書消失・不正UTF-8・旧文字コードの失敗保持と、明示再検証後の復旧を確認した。
- ホストのメモリ確保を1回失敗させ、OutOfMemoryへの移行、繰返しのI/O抑止、明示再検証による復旧を確認した。ファームには故障注入を含まない。
- 9理由×日英×Fix有無の描画を検証し、地名領域がFix喪失で変わらないこと、4bppと16bppの一致、232px内の表示、GPS情報と操作の維持を確認した。

## 実機確認

Cardputer ADV（MAC: `70:af:09:df:46:d0`）へ通常ファームを書込み、45秒間の起動ログを確認した。

- バイナリ: `.pio/dataset-errors/firmware.bin`、1,131,696 bytes。
- SHA-256: `5af05fc4dc8511cda2670d6f0d3ed1e21f15fc926bed954a0e786b768f91fe73`。
- ビルド時の静的RAM: 77,536 bytes、Flash: 1,131,333 bytes。
- LoRa SLEEP、NVS読込、SDのFAT32マウント、4タスク・5キュー、GPS UART、162チャンクのデータセットOPEN OKを確認した。
- Boot完了は1回でLive Placeへ移行し、GPS Fix・地名取得を継続した。キャッシュヒット時は地図・辞書とも読出し／seekなし。パニック・アサート・予期しない再起動は検出されなかった。

ログは `.pio/dataset-errors/boot.log`、確認項目は同ディレクトリの `verification.json` に保存した。実機上のSDデータを破損させる試験と物理F1操作の試験は行っていない。異常条件とメンテナンス入口の確認はホスト・描画試験の結果であり、実機では通常起動を確認した。
