# トップ画面の直接切替

## 対象

Live Place、GPS Logger、Logs、Settingsトップで、1 / 2 / 3 / Escをそれぞれの固定の移動先とする。UIは変更要求を保持し、Appは現在の画面・ページ・世代と要求IDを確認した後、目的の画面を一度だけ指定する。途中でLive Placeを表示しない。

`ScreenNavigation.h`でトップ画面の判定を共有し、Settingsの子画面からの直接遷移はAppでも拒否する。Fn＋1は未割当のF1として維持し、物理1の保持中にFnを変更しても再発火させない。EscはFnの有無に依存しない。

## ホスト検証

`python3 tests/run_native.py`で、4画面間の全組合せ、現在画面へのキーの無操作、Appによる直接遷移の許可、記録状態の保持、一覧読込中の移動、下位画面・値編集中・確認中・削除実行中の抑止を確認した。メンテナンスでの通常画面への移動禁止、Escによる再起動確認、消灯中の復帰専用入力も確認した。

`render_live_place_layout.py`、`render_log_browser.py`、`render_settings_layout.py`で実装から240×135の画像を再生成し、字形・余白・罫線・ダイアログを検証した。英語・日本語のライセンス本文は同一の画素出力を維持する。

Live PlaceはP PAUSEを残して2:GPS / 3:LOG / ESC:SETを表示する。他のトップは1:LIVE / 2:GPS / 3:LOG / ESC:SETを表示する。ログ一覧のEnter / D案内はy=97へ移し、画面切替案内との重なりを避ける。

## 実機検証

MAC `70:af:09:df:46:d0` の実機へアプリ領域を書き込み、書込み後のハッシュ一致を確認した。再起動後、UI初期化、NVS復元、FAT32マウント、GPS FIX、データセット01の読込み、Live Placeへの遷移と地名取得を確認した。取得ログに例外・ウォッチドッグは見られない。

ビルド・書込み・起動ログとファームウェアは `.pio/screen-navigation/` に保存した。静的RAMは77,960バイト、Flash使用量は1,179,553バイト。物理キーによる各遷移の操作試験は未実施であり、ホスト試験と起動確認とは区別する。
