# Geoputer 画面・操作機能設計

文書状態: Draft 0.23

対象画面: 240 × 135 px、横向き  
入力: Cardputer ADV 56キーキーボード  

## 1. 文書の目的

本書は、Geoputerの画面一覧と、共通の情報設計、操作、状態遷移および表示ルールを定義する。各画面の詳細仕様と参考画像は、画面別ディレクトリへ配置する。

Geoputerの主役は道路地図ではなく「現在地の名前」と「地名の領域」である。限られた画面を地図アプリの縮小版として使わず、現在地を短時間で理解することへ表示資源を集中する。

製品の目的と利用体験は「[Geoputer コンセプト・利用体験概要設計](../01_コンセプト・利用体験概要設計.md)」、UIが参照する動作モードとデータは「[Geoputer システム構成設計](../04_システム構成設計.md)」を参照する。

UIとApplicationの役割、受信キューおよび表示更新の通信は「[Geoputer タスク構成設計](../06_タスク構成設計.md)」に従う。

### 1.1 現在の実装範囲

Boot、Live Place、GPS Logger、Settings、Logs、Log Detail、Log Pointを実装している。Live Placeの1/2/3からGPS Logger / Settings / Logsを直接開き、GPS Loggerで開始・再開・停止、Live Placeの0で一時停止を行う。記録操作は実際のSD保存へ接続済みであり、保存済み・未保存・バッファ使用数・欠落件数とエラーを表示する。通常ファームウェアの実GPSとキー操作による記録操作の通し確認は未完了とする。

Logsからファイル名一覧、詳細、測位点の閲覧が可能である。一覧のDは削除確認を開き、取消を初期選択として確定した削除だけをStorageへ要求する。保持中の記録ファイルは削除しない。削除中は操作と消灯を抑止し、完了後に一覧を更新する。Place Viewと距離・最高速度の全件集計は未実装とし、Place Viewへの入口は設けない。以下の画面一覧・状態遷移・受け入れ条件にはこれらの後続仕様を含む。GNSS PAUSE / ACTIVEの制御も未実装であり、現在は起動後にLive Placeへ進み、画面消灯・ログ停止・一時停止後もUART受信を継続する。詳細は[GPS Loggerの現行実装](gps-logger/README.md#5-現行実装)と[測位記録ファイル仕様](../07_測位記録ファイル仕様.md)を参照する。

## 2. UI設計原則

### 2.1 情報の優先順位

画面全体の情報優先順位は次のとおりとする。

1. 現在地名
2. GPS・ログ・SDの動作状態
3. 現在地周辺の領域
4. 速度、進行方位、高度、衛星数
5. 緯度・経度
6. 詳細なデバッグ情報

### 2.2 操作原則

- 電源投入時はGNSSをPAUSE、GPSログをSTOPPEDで開始し、その状態を明示する。
- 画面消灯中の最初のキーは画面復帰にのみ使用し、設定変更には使用しない。
- 左右キーはSettingsの値編集、共通確認ダイアログの選択、ライセンス情報のソフトウェア単位ジャンプに使用する。ダイアログでは左が取消、右が実行項目となる。上下キーは一覧・メニューの選択、Place Viewの縮尺変更に使用する。
- Enterは決定・OK、EscまたはDelはキャンセル・戻る。
- GPSログの一時停止・停止など、確認が必要な操作は一段階確認する。
- GPSログの開始・再開・停止はGPS Logger画面から行う。Live Placeの0は記録の一時停止に使用し、1/2/3でGPS記録・設定・ログ一覧を直接開く。
- GPSログがRECORDINGの場合は、画面遷移や画面消灯で記録を止めない。
- GPSログの一時停止は位置記録だけを止める。GPSデバイスをOFFにせず、GNSS ACTIVEとLatestFix更新を維持する。ログ停止後は、ほかに測位要求がなければGNSSをPAUSEへ戻す。
- データセット番号・地名用Wordbookの言語の変更は、GPSログの停止と未保存データの保存・セッション閉鎖が完了した後に限る。検証・NVS保存に成功してから再起動し、次の起動で適用する。PAUSEDは停止完了としない。起動時に選択済みデータセットを使用できなくても通常起動を継続し、地名2行へ原因を表示して逆ジオコーディングを停止する。

### 2.3 応答性

- 画面復帰後、100 ms程度を目標にフレームと最新状態を表示する。
- Galuchat検索は表示復帰をブロックせず、使用可能時の検索中状態を表示する。確定したデータセット異常は地名欄の原因表示を維持し、GPS更新・画面復帰では再検索しない。Live Placeの再検索では既存の地名と対応座標を保持する。RGはキャッシュ状態（未準備は暗灰、準備済みは緑、再構築中は黄）を継続表示し、SDはログ・地図・辞書を含む実アクセスで青く点灯する。
- 検索開始前に以前の有効な地名キャッシュがあれば、薄い表示または更新中マーク付きで先に表示する。
- キー入力に対する選択表示は、SDアクセスやGaluchat処理より優先する。
- 長い処理中も、GPSログの継続とEscによる画面離脱を可能にする。

## 3. 共通ビジュアルデザイン

### 3.1 画面グリッド

画面は原則として次の3領域で構成する。

```text
┌──────────────────────────────┐ y=0
│ Status bar / 16～18 px       │
├──────────────────────────────┤
│                              │
│ Main content / 約100 px      │
│                              │
├──────────────────────────────┤
│ Context / action / 16～18 px │
└──────────────────────────────┘ y=134
```

画面によって下部領域を省略し、Main contentを広げてもよい。左右の安全余白は4 px以上とする。Settingsは8ドットのタイトルを置くヘッダーを23 pxとし、本文は上端27 pxから20 px間隔の4行で表示する。

### 3.2 文字サイズ

すべての画面で8×8ドットと16×16ドットの2種類を持ち、文字種ではなく表示用途でサイズを選択する。

| 表示用途 | 固定セルサイズ | 対象 |
|---|---|---|
| 地名 | 16×16ドット（半角スペース8×16） | 都道府県、市区町村、町丁・小地域名、住所、データセット異常の固定2行表示 |
| Live Placeの速度・進行方位 | 16×16ドット | SPD / HDGの主数値、方位の°。ラベル・速度単位は8×8 |
| Live Placeの測位待ち | 16×16ドット | 地名欄の既存状態文字列`WAIT GPS FIX` |
| Settingsの主表示 | 日本語16×16 / 英語8×16 | メニュー項目、設定値、確認文、カード情報 |
| 補助表示・その他 | 8×8ドット | 画面タイトル、ライセンス本文、現在時刻、GPS状態、キーガイド、短い通知、座標、Settings以外の設定値 |

地名に含まれる英数字も16×16ドットとする。例えば「鷺沼2丁目1番1号」は日本語・数字とも16ドットずつ送る。Live Placeの速度・進行方位の主数値と方位の°も東雲16×16ドットとする。速度の小数点だけ元の東雲字形を使い、送り幅を8ドットへ詰める。SPD / HDGのラベルとkm/h、LAT / LON / ALT / SATの値は8×8ドットとする。GPS Loggerの操作・確認項目、Log Detailの操作項目、Settingsの項目・設定値・確認文・カード情報は、日本語モードでは東雲16×16、英語モードではAsciiFont8x16とする。日本語モードではログ詳細を測位点を見る / 再読込などの日本語表記とし、英語ラベルを全角ASCIIで代用しない。Logsのファイル名・概要数値・測位点データと、各画面のタイトル・補助表示は8×8とする。言語の選択値は日本語を16×16、Englishを8×16で表示し、文字高さを16ドットに揃える。16ドット部分は東雲の字形を使用し、英数字を8×8から2倍拡大しない。Settings画面群のタイトルとライセンス本文はASCIIの8×8ドットとする。補助表示・その他の日本語は8×8ドットとし、地名表示の16×16とライセンスの8×8は表示言語で変更しない。

日本語文字は線が潰れないビットマップのゴシック体を使用する。画面画像は240×135 pxの実寸で作成し、1画像ピクセルを1画面ドットへ対応させる。文字、罫線、アイコンは整数座標に配置し、アンチエイリアスを使用しない。拡大プレビューは最近傍法とし、実寸画像と区別する。[画像作成手順](画像作成手順.md)を参照する。

地名が表示幅を超える場合は固定サイズを維持したまま、末尾を省略する。選択中または一定時間後に横スクロールで全文を表示する。通常状態で常時流れるマーキー表示は避ける。

### 3.3 カラーパレット

| 色 | 用途 |
|---|---|
| 黒～濃紺 | 背景 |
| 白～明灰 | 通常文字 |
| シアン | 選択、現在位置、操作可能要素 |
| 緑 | REC、RGキャッシュ準備済み、正常完了 |
| 黄～アンバー | PAUSE、RGキャッシュ再構築中、注意 |
| 青 | SD実アクセス中 |
| 赤 | ERROR状態、GPS・SD等の問題を示す赤帯。帯内の文字は白 |
| 暗灰 | RG未準備、SDアクセスなし、無効操作 |

状態は色だけで伝えず、アイコンまたは短い文字を併記する。

```text
GPS●  正常Fix
GPS○  受信中・Fixなし
GPS‖  PAUSE
GPS×  UART受信なし
REC●  ログ記録中
PAUSE ログ一時停止
RG    緑=準備済み、黄=再構築中、暗灰=未準備
SD    青=実アクセス中、暗灰=アクセスなし
ERROR 問題の内容は赤帯の白文字
```

### 3.4 再描画

現行UIは4bit・16色パレットの全画面バッファを使用する。使用する9色のRGB565値とフォント・整数座標を維持し、UiCanvasが描画色をパレット番号へ変換する。色数だけを変更し、文字の拡大縮小や解像度の変更は行わない。画面形式は`Config.h`の`UiColorDepth`で指定し、16bitの参照描画とのピクセル比較で確認する。

- ステータスバーは1秒周期または状態変化時に更新する。
- Live Placeの速度・進行方位・高度・衛星数は新しい確定Fixで項目ごとの有効性に従って更新する。地名に対応する座標は地名検索のFixと一緒に更新する。
- 地名は検索完了時だけ更新し、毎秒検索しない。
- 状態・時計・操作の変更時に再描画を予約し、240×135の1枚のバックバッファを再構成してまとめて転送する。
- Place Viewのラスタは検索完了まで以前の画像を保持してよい。

Live Placeの上段は記録状態→時刻→RG→SD→電池の順とし、GPS:FIXと正常時SD OKを常設しない。住所は都道府県・市区町村と町名以降の2行とし、その下を左右パネルに分ける。左に16ドットの速度SPD・進行方位HDG、右に8ドットのLAT・LON・ALT・SATを置く。HDOPはメイン表示から外し、GPS取得・ログ記録には残す。RGはヒットごとに点滅せず、キャッシュを保持していればGPS喪失や画面切替後も緑とする。SDだけ短いI/Oを最低150ms表示する。配置の正本は[Live Place画面レイアウト仕様](live-place/レイアウト仕様.md)とする。

## 4. ナビゲーション構造

主要画面はLive Placeの数字1/2/3から直接開く。MENU画面は設けない。

```text
Live Place
├ 1 GPS Logger
├ 2 Settings
│  ├ 動作設定
│  ├ 動作モード
│  ├ ストレージ操作
│  ├ 初期化
│  ├ バージョン情報
│  └ ライセンス情報
└ 3 Logs
   └ Log Detail
      └ Log Point
```

| キー | 動作 |
|---|---|
| `0`（Fn不要） | Live PlaceでGPSログを一時停止確認（開始・再開・停止はGPS Logger） |
| `F1`（Fn＋1） | Bootの確認中・完了後にメンテナンスへ入る。地名欄の異常・メインの赤帯でも記録停止完了後に使用可 |
| `1`（Fn不要） | Live PlaceからGPS記録画面を直接開く。記録の開始・停止は実行しない |
| `2`（Fn不要） | Live Placeから設定画面を直接開く |
| `3`（Fn不要） | Live Placeからログ一覧を直接開く |
| `↑` / `↓`、または`;` / `.`（Fn不要） | 一覧・操作項目の選択、Place Viewの縮尺変更 |
| `←` / `→`、または`,` / `/`（Fn不要） | Settingsの編集状態で値を変更。他画面とSettingsの一覧状態では無効 |
| `D`（文字キー） | ログ一覧で選択ファイルの削除確認を開く。Delは戻る専用として区別する |
| `Enter` | 決定・OK、編集開始・保存 |
| `Esc` / `Del` | キャンセル・戻る |

Cardputerの方向操作は物理キー`;`＝上、`.`＝下、`,`＝左、`/`＝右を使用し、Fn併用も受け付ける。数字1/2/3の画面ショートカットはLive Place以外と確認中には作用しない。2/3はFn併用も同じ画面を開く。0はFn併用も同じ一時停止操作とする。1単独とFn＋1は別の操作とし、物理1を押したままFnを追加・解除しても新しい押下として扱わず、離して押し直してから次の操作を受け付ける。上下の長押しは400ms後から100ms間隔で反復する。画面消灯中の最初の押下は復帰だけに使い、同時に画面移動や設定変更を実行しない。

DelはFnなしで押せる戻る・キャンセルの代替キーとし、各画面でEscと記載する操作を同様に実行する。両キーを同時に押しても戻る操作を二重に発行せず、押し続けても階層を連続して戻らない。F1はFn＋1とし、Bootの確認中・完了後と、記録停止済みのメイン画面の異常からメンテナンスへ入る。記録操作は行わない。EscはFn＋バッククォートとする。

GPS Logger・Settingsの入口・LogsからのEsc / DelはLive Placeへ戻る。Log DetailはLogsへ、Log PointはLog Detailへ戻る。Settingsの子画面では一つ上の画面へ戻る。確認ダイアログ・設定編集中のEsc / Delはその操作を取り消し、元の画面へ戻る。

Live Placeの最下段はASCII 8×8で`0 PAUSE   1:GPS 2:SET 3:LOG`を表示する。画面選択の数字はシアン、説明はライトグレーとし、0の有効・無効は従来の記録状態に従う。27文字・216pxのため左右4pxの安全余白内に収まる。

Settingsの動作設定は本体NVSに保存する。ストレージ操作にはSDカード情報、再マウント、安全な取り外し、FAT32フォーマットを置く。初期化はGeoputerの設定だけを初期値へ戻し、SDカードのデータを消去しない。バージョン情報ではアプリの版・ビルド日時・Git情報を閲覧する。ライセンス情報はファームウェア内の読取専用データをASCIIの8×8ドット・1行29文字・9行表示で上下スクロールし、左右または`<` / `>`で前後のソフトウェアの先頭へジャンプして閲覧する。項目と確認手順は[Settings画面](settings/README.md)に従う。

## 5. 画面消灯と復帰

### 5.1 消灯

設定された時間キー操作がなければ、UIが最終入力時刻を含む消灯要求を保持し、UiContentChangedを通知する。AppがGetUiContentで現在内容を同期取得し、要求が有効であることを確認する。

1. UIが未確定の設定編集を取消または確認対象として扱う。
2. AppがUpdateUiContentでBACKGROUND_MODEと処理済みaction_idを指定する。
3. UIが指定を保持して同期結果を返し、タスク内でバックライトを消灯する。

GPSログがRECORDINGの場合は、GNSS ACTIVE、LatestFix更新、RAMログ追加および定期SD保存を継続する。PAUSEDの場合は記録だけを停止してGNSS ACTIVEを維持する。STOPPEDで測位要求がなければGNSSをPAUSEへ戻す。

### 5.2 復帰

画面消灯中の最初のキーは、UIが復帰操作として保持してUiContentChangedを通知する。AppはGetUiContentで復帰操作を同期取得する。

1. AppがSetUiScreenでVIEW_MODEとLive Place、処理済みaction_idを指定する。
2. UIが指定を保持して同期結果を返し、バックライトと画面を非同期に更新する。
3. AppがGNSS・GPSログ・SDの状態を集約し、UpdateUiContentで表示用データを渡す。
4. GNSSがPAUSEの場合はAppがACTIVEを同期要求する。
5. 直前の有効なFixと検索結果は前回位置として表示できる。
6. 新しい有効Fixを得たらAppがStorageへ検索要求を通知する。
7. 結果通知をAppが受け、UpdateUiContentで地名を渡す。UIが描画する。

復帰を発生させたキーは画面内操作へ引き継がない。処理済みの復帰操作と画面指定がUIへ反映されるまで次の確定操作を抑制する。

## 7. 通知とダイアログ

### 7.1 トースト通知

処理結果は画面下部へ2～3秒表示する。

```text
Log flushed
Settings saved
Galuchat data unavailable
```

トーストはGPS状態やREC表示を恒久的に隠さない。

### 7.2 確認ダイアログが必要な操作

- ログ削除
- Geoputerの設定初期化
- SDカードのFAT32フォーマット（ログ・GISデータを含む全データ消去）
- GPSログの一時停止
- GPSログの停止

選択を伴う確認はすべて[共通確認ダイアログ](共通確認ダイアログ.md)を使う。上記5操作とUSBモードへの切替・終了に適用する。背景を暗く残した中央ウインドウに上下1ドットの白線を引き、取消と操作を横並びにする。初期選択は取消、左で取消・右で実行項目を選択、Enterで確定、Esc / Delで取消とし、上下キーや画面ショートカットは受け付けない。

### 7.3 エラーバナー

SD書込み失敗・RAM満杯・GPS受信断等は、Live Place本文下部の赤地・白文字の帯に内容を表示し、トーストだけで消さない。最上段のERRORは問題の存在を示し、Appの記録要求・停止・一時停止状態とは分ける。RG/SDの枠色をエラー表示に代用しない。

Storageの同期受付エラーは戻り値、受付後の実保存エラーはStorageError通知からAppが把握する。Appがエラー種別・未保存件数・バッファ使用数と容量・欠落件数を集約し、先の同期結果を取得してからUpdateUiContentでUIへ渡す。UIは受け取った状態を自タスク内で描画する。

Live Placeでは赤帯に、GPS Loggerでは状態欄と件数表示に反映する。書込み・flush失敗はSD ERROR、RAM満杯の受付失敗はBUFFER FULLとして区別し、バッファ容量は64件とする。受付失敗だけで欠落したと表示しない。画面切替やGPS更新で保存エラーを消去せず、Appが対応する処理・媒体の回復を確認した状態を渡したときに更新する。


### 7.4 データセット異常の共通表示

使用中のデータセットの欠落・構成／形式不正・文字コード未対応・上限超過・メモリ不足・読出し失敗は、起動停止にせずLive Placeの地名2行に統一する。日本語・英語の固定文言、優先順位、逆ジオコーディング停止と明示操作による再検証は[データセットメタデータ仕様8.3〜8.4節](../08_データセットメタデータ仕様.md#83-起動時の復元とエラー)に従う。データセットだけの異常を赤帯・全面警告へ重複させず、Fix喪失で地名欄の原因を上書きしない。未選択候補の検証失敗はSettings内で表示して適用を拒否し、使用中データのエラーにしない。

この変更はコードと新しい日英の地名欄エラー画像へ反映済み。[検証結果](../検証/データセット異常時の起動継続検証.md)でホスト・描画・実機の確認範囲を区別する。

### 7.5 機能の利用条件と制約

[システム構成設計7節](../04_システム構成設計.md#7-エラー状態と機能の利用条件)を共通の判定基準とする。GPS Fixなしでは現在位置・地名の更新と新しい測位点の追加を制約し、設定やSD上の既存ログ操作を禁止しない。ログ開始・再開の受付と有効Fix待ちは分ける。SD利用不可でもGPS表示・NVS設定操作は継続し、データセット異常だけなら逆ジオコーディング以外の機能を維持する。

画面を開けることと、その画面の操作が成功することは別とする。必要条件を満たさない操作は理由を表示し、設定・復旧操作や元画面へ戻る経路を残す。SD書込みだけの失敗を読出し不能に拡大せず、保存済み・未保存・記録状態を別に表示する。バージョン・ライセンス情報はGPS Fix・SD・NVS保存なしで閲覧可能とする。エクスポートはUSBモード内でSDの所有権を取得して行う既存仕様を維持する。

## 8. 状態遷移

```text
                     key
        ┌────────────────────────────┐
        │                            v
┌────────────────┐            ┌──────────────┐
│BACKGROUND_MODE │<─ timeout ─│  VIEW_MODE   │
│LCD OFF         │            │  LCD ON      │
└────────────────┘            └──────────────┘
```

画面モードとGNSS・GPSログ状態は独立して遷移する。

```text
Power on: GNSS PAUSE / LOG STOPPED

GPS Logger Start:  GNSS ACTIVE → LOG STARTING → LOG RECORDING
Live Place 0:     記録追加停止 → 保存要求の同期受付 → LOG PAUSED（GNSS ACTIVEを維持）
GPS Logger Resume: 新しい有効Fix → LOG RECORDING
GPS Logger Stop:   記録追加停止 → 保存・終了要求の同期受付 → LOG STOPPED

LOG STOPPEDかつ測位要求なし → GNSS PAUSE
Live Place / Place View → GNSS ACTIVE
```

Galuchat検索は動作モードではなく、VIEW_MODE内の短命なジョブとして扱う。

```text
IDLE → QUEUED → READING → COMPLETE
                    └──→ ERROR
          Esc/画面遷移 → CANCEL_REQUESTED
```

Readerが安全に中断できない場合、画面表示だけを離脱し、現在の短い読込単位が終了した時点でジョブを破棄する。

## 9. UIが参照するモデルと操作内容

Appは表示する画面、表示モード、確定した設定、GPS・ログ・Storageなどの業務状態を所有する。UIは画面内の選択項目、ダイアログ操作、編集途中の値を所有する。

AppはGPS・Storageの通知を一度受信して表示データへ集約し、SetUiScreen / UpdateUiContentの同期メッセージでUIへ渡す。同期操作は指定・データ保持までとし、実際の描画とバックライト更新はUIタスク内で非同期に行う。表示更新で選択・編集状態を初期化しない。

```cpp
struct UIStatus {
    GPSStatus gps;
    LogStatus log;
    StorageStatus storage;
    GaluchatStatus galuchat;
    BatteryStatus battery;
};
```

ユーザー操作でUI内容が変わるとUiContentChangedをAppへ通知する。AppはGetUiContentで現在の選択・編集値・確定操作を同期取得し、業務操作を検証・実行する。

```text
UIタスク内でユーザー操作
  ↓
UiContentChanged → App
  ↓
App → GetUiContent（同期） → 操作内容取得
  ↓
AppがGPS・Storageの操作や画面遷移を判断
  ↓
App → SetUiScreen / UpdateUiContent（同期）
  ↓
UIが処理済み操作を反映し、非同期に描画
```

開始・停止・設定確定などの未処理操作はUIに1件保持し、Appの処理済みaction_idが反映されるまで次の確定操作で上書きしない。表示データ受信・再描画はUiContentChangedを発行する理由にしない。

同期結果取得のタイムアウトでも同じ要求の結果取得を続ける。通信と操作内容の詳細はタスク構成設計4.6節に従う。

## 10. UI受け入れ条件

- 電源投入時にGNSS PAUSEとGPSログSTOPPEDが表示される。
- 表示指定とデータ受渡しの同期完了後に、UIタスクが非同期で描画する。
- UiContentChangedを契機に操作内容を同期取得し、確定操作を1件保持して処理する。
- GPS Logger画面からGPSログを開始・再開・停止できる。
- Live Placeの0で記録だけを一時停止し、GNSS ACTIVEを維持する。
- Live Placeの1/2/3でGPS記録・設定・ログ一覧を直接開け、各入口からEsc / DelでLive Placeへ戻れる。
- GPSログ開始時にGNSSがACTIVEとなり、有効Fix取得後にRECORDINGへ移行する。
- GPSログがRECORDINGの場合は画面消灯中も記録が継続する。
- GPSログがPAUSEDの場合は画面消灯中もGNSS ACTIVEを維持する。STOPPEDで測位要求がなくなるとGNSSがPAUSEへ戻る。
- 任意キーでLive Placeへ復帰する。
- 復帰キーが設定変更として処理されない。
- 有効Fixがあれば地名検索中表示を経て地名が表示される。
- Fixなし、Galuchatデータなし、SDエラーを互いに区別できる。
- 左右キーはSettingsの値編集、共通確認ダイアログ、ライセンス情報のソフトウェア単位ジャンプで動作する。Escはキャンセル、Enterは決定として動作する。
- Place Viewで現在位置、現在領域、周辺領域および縮尺を識別できる。
- GPS Logger画面の表示中はGaluchat検索を行わない。
- GPS接続モードを選択でき、再起動後は選択したGPSを使用する。
- Settingsの4メニューを2階層で操作し、子画面からEscで入口へ戻れる。
- SDが利用できなくてもNVS設定を読込み・保存でき、NVS保存失敗とSDエラーを区別できる。
- 設定初期化とSDフォーマットは確認後だけ実行し、互いの保存媒体のデータを変更しない。
- SD未挿入でもOSS・フォントのライセンス本文をスクロールして閲覧できる。
- 15秒無操作の初期設定で画面が消灯する。
- 長い一覧処理またはGaluchat処理中もGPSログを失わない。

## USBストレージの起動モード

起動前にNVSのフラグを読み、GPSロガーを含む通常起動とUSBストレージ起動を分ける。設定のトップ階層に「動作モード」を置き、記録停止完了後に切替確認からフラグ保存・再起動を要求する。USB起動ではGPS・GISを開始しない。PC公開中は端末側のSDファイル操作を行わない。USB専用画面から共通終了ダイアログを開き、PCでの保存完了後、終了の確定でSD同期・公開停止・GPSロガーのフラグ保存・再起動を行う。PC公開中でも終了は選択可能とする。USB画面と終了確認は自動消灯しない。

USB起動時は「ログを書き出す」「ロガーへ戻る」のメニューを表示する。書き出しはログ選択→GPX・KML・CSVの形式選択→変換→完了の順とし、PC公開中だけ安全な取り外し案内を挟む。未接続・安全な取り外し済みは案内を省略する。USBモード内で公開を止めてStorageが変換し、完了後にSDを再公開する。出力先と命名は[ログエクスポート仕様](../10_ログエクスポート仕様.md)、画面は[エクスポート画面](usb-storage/export-proposal/README.md)を正本とする。変換中は取消・モード終了を受け付けず、同名出力を上書きしない。

画面仕様は[USBストレージ](usb-storage/README.md)、起動・排他・保存の契約は[起動モード・USBストレージ仕様](../09_起動モード・USBストレージ仕様.md)に従う。

メンテナンスではSettingsを使用し、自動の位置検索・記録開始・画面消灯を抑止する。入口のEsc / Delは通常画面へ直接戻さず、取消を初期選択とする再起動確認を開く。[Bootの復旧経路](boot/README.md#5-f1によるメンテナンス起動)に従う。
