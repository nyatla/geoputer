# Geoputer Boot画面

文書状態: 採用仕様 1.0（データセット異常時の起動継続は実装反映済み）
対象画面: 240 × 135 px、横向き  
入力: Cardputer ADV 56キーキーボード  

[画面・操作機能設計（共通仕様・画面一覧）](../02_画面・操作機能設計.md)

## 1. 目的と表示

起動時に各機能の準備状況を表示し、利用できない機能と理由を確認できるようにする。現在の実装段階では6項目を表示する。

データセットが使用できない場合も、以下のチェック一覧で理由を示した後にLive Placeへ進む。通常起動を続けることと、逆ジオコーディングが使用可能であることを区別する。原因・地名欄の文言・再検証条件は[データセット異常時の共通仕様](../../08_データセットメタデータ仕様.md#83-起動時の復元とエラー)を正本とする。

```text
GEOPUTER            STARTUP
------------------------------
[+] DISPLAY        240X135
[+] TASKS/QUEUES    4T/5Q
[+] NVS SETTINGS    LOADED
[!] SD CARD         NO CARD
[+] GPS UART        UART OK
[!] GALUCHAT DATA   NO SD
GPS:MESH  DATASET:01
------------------------------
ESC MAINT          ENTER START
```

文字はタイトルを含め8×8ドット、アンチエイリアスなしとする。ヘッダー下の罫線はy=22、チェック行はy=29から14px間隔の6行、GPS接続・データセット番号はy=110、フッター上の罫線はy=118とする。項目名と結果は別の列に配置し、結果の略称は9文字までとする。

| 項目 | 確認内容 | 主な結果 |
|---|---|---|
| DISPLAY | UIの240×135描画領域とフォントの準備 | 240X135 |
| TASKS/QUEUES | App・UI・GPS・Storageの4タスクと5キューの準備 | 4T/5Q、TASK ERR |
| NVS SETTINGS | 保存領域の準備、設定レコードの読込み・形式・検査値 | LOADED、DEFAULT、INVALID、NVS ERROR |
| SD CARD | カードの認識、マウントとFAT32判定 | FAT32、NO CARD、NOT FAT32、SD ERROR |
| GPS UART | Mesh KitのUART受信準備 | UART OK、UART ERR |
| GALUCHAT DATA | 保存済み番号・言語のファイル検出、Reader生成、ヘッダー・辞書形式・文字コード確認 | OPEN OK、NO SD、MISSING、CONFIG、VERSION、ENCODING、DATA ERR、TOO LARGE、NO MEMORY |

Galuchatの確認はGPS Fixを要求しない。データをRAMへ全展開せず、検索用のReaderを準備する。OPEN OKは起動時に必要な読出し準備の成功を表し、地図・辞書の全領域の走査や全地名の復号を完了した意味ではない。実検索中の読込異常はLive Placeへ別途表示する。

GPS UARTの成功は受信設定の準備までであり、GPS機器からのNMEA受信や測位成功を意味しない。GPS MODEはチェック行にせず、現段階の固定値MESHを補助表示する。GPS待機操作は起動チェックの対象にせず、通常起動では受信を開始する。GPSログはSTOPPEDのまま開始する。

## 2. 状態と色

| 表示 | 状態 | 色 |
|---|---|---|
| [.] | 未確認 | 暗灰 |
| [~] | 確認中 | シアン |
| [+] | 準備成功 | 緑 |
| [!] | 機能制限・確認を実施できない | 黄 |
| [X] | 準備・検証失敗 | 赤 |

NVS設定領域とSDの準備結果は分離する。SD未挿入・マウント失敗でもNVSの設定読込みを行う。設定が未保存の場合は初期値を使用し、DEFAULTとして正常表示する。設定が不正・読込不能ならエラーを表示し、初期値で継続する。データセット未選択の場合、GALUCHAT DATAは正常完了のNONEとし、INI・GLC・Wordbook・索引を読まない。データセット選択済みでSDが使用できない場合、Storageの確認経路でNO SDを通知して選択を解除する。データセット固有の欠落・破損・キャッシュ欠落でも原因を表示し、NVSとRAMの選択を未選択へ更新する。解除のNVS保存失敗はNVSチェックにも反映する。下部に解除番号と原因・NONEを表示して起動を継続する。

## 3. 完了と操作

確認中はCHECKING...とESC MAINTを表示し、Escによるメンテナンス要求を除いて画面遷移・設定操作・無操作消灯を行わない。すべての確認結果が揃った時点で起動確認を完了し、各チェック行の成功・警告・失敗を保持してENTER STARTを表示する。データセットの警告・失敗も確認完了として扱う。

完了後は通常2秒、警告・失敗がある場合は5秒表示し、Live Placeへ自動遷移する。Enterは完了後だけLive Placeへの遷移要求として受け付ける。2・Esc・Del・上下左右ではBootを抜けない。Live Placeの無操作期限はBootを抜けた後から数える。

SD・NVS・GPS・Galuchatの障害は機能ごとに扱い、UIとAppが操作可能なら利用可能な機能で起動を継続する。画面やUIの準備に失敗してチェック画面そのものを表示できない場合は、シリアルログへ初期化失敗を出して停止する。処理自体の異常リセットは画面上の通常エラーと区別し、Escによる読込み前の退避経路を用意する。

機能ごとの必要条件と複数障害時の制約は[システム構成設計7節](../../04_システム構成設計.md#7-エラー状態と機能の利用条件)に従う。GPS Fixなしは起動完了の待ち条件にせず、設定・既存ログの利用を禁止しない。SD利用不可でも有効FixがあればGPS情報を表示し、NVSが利用可能なら通常設定を保存できる。NVS設定が未保存ならDEFAULT、不正・復元失敗ならエラーと初期値適用を区別する。チェック行の赤・黄を理由に設定専用画面へ固定しない。

### 3.1 データセットが使用できない場合

NVSの番号と言語を復元して検証する。ディレクトリ・INI・GLC・言語セクション・Wordbookの欠落、不正なデータ、文字コード未対応、チャンク上限超過、メモリ不足、読出し失敗のいずれも通常起動の停止理由にしない。SDが利用不可ならSDのチェック行に媒体の理由を、GALUCHAT DATAにはNO SDを表示し、ファイル欠落と誤認しない。

すべての確認結果が揃った後は5秒表示し、期限満了またはEnterでLive Placeへ進む。Escは確認中・完了後ともメンテナンスを要求できる。データセット専用のSTARTUP ERROR画面や、上限超過・メモリ不足だけの全面警告は新仕様では使用しない。

Live Placeの地名2行へ原因を表示し、逆ジオコーディングを使用不可として保持する。GPS・設定・ログ閲覧を利用可能な範囲で継続し、SDが使えればGPSログを開始できる。SD利用不可の場合はログ保存も不可として別途表示する。選択番号・言語を別候補に自動変更せず、利用者が再マウント・適用・再起動を行った場合だけ再検証する。

## 4. タスク連携

Appが確認結果を集約し、SetUiScreen / UpdateUiContentでBootの値コピーをUIへ渡す。UIは描画とEnter・Esc操作を担当し、初期化・SD・NVS・Galuchat読出しを直接実行しない。

NVS読込みはLoadSettings、Galuchat読出し準備はCheckDatasetの通知でStorageへ要求し、ReadCompleted / ReadFailedで結果を受け取る。未投入の要求だけを再試行し、投入済み要求を重複実行しない。通常起動の受付期間後はGPS受信を開始し、Boot表示中も継続する。

## 5. Escによるメンテナンス起動

Esc（物理バッククォート、Fn不要）はBootの確認中・完了後にメンテナンスを要求する。チェックに警告・失敗がある場合も同じ操作とし、データセット専用の起動停止画面は設けない。電源投入時から押し続けたEscは、最初のBoot画面を受け取る前でもUIが保持する。USBストレージとしての起動は、このキーで変更しない。記録の一時停止は起動後のGPS画面またはGで行う。

ADVでは、UI所有のアプリ側Readerがキーボードチップの行列をGPIOとして一度走査し、リセット前から保持されたキーの現在状態を復元する。古いイベントは行列走査を停止した状態で破棄し、復元後はキーパッド動作へ戻す。通常入力はFIFOをポーリングし、初期化前から割込みが発生済みでも新たな割込みエッジを要求しない。外部ライブラリ本体は変更しない。

UIはボード・キーボードの準備直後、最初のApp要求を処理する前に物理バッククォートを走査する。押されていればFnなしでもEscとして保持し、Boot指定への応答時点でメンテナンス要求を用意する。Appは最初のUI内容をSD初期化前に確認し、直ちにSettingsへ移る。NVS設定復元や1500msの受付期間の完了を待たない。画面タイトルは`MAINTENANCE`とし、GPS開始とCheckDatasetの投入を省く。押しっぱなしを新しいEsc押下として扱わず、メンテナンスへ移った直後に終了確認を開かない。

メンテナンス表示後もStorageの初期化・SDマウントとNVS設定の読込みは進める。初期化・復元中はStorageを処理中として表示し、保存・媒体操作を受け付けない。設定の読込み後に保存済み言語などを反映する。読み込んだ選択が不正でも、メンテナンス中は自動で地図本文を開かない。

通常起動にはNVS設定の読込み後の`config::BootMaintenanceWindowMs`（1500ms）を残し、Boot画面でEscを押してもメンテナンスへ入れる。UIの操作要求を起動処理より優先する。Delは通常画面の戻る・取消として維持し、起動時とLive Placeでメンテナンスを選ぶキーにはしない。F1は未割当とする。

受付期間を過ぎた通常起動ではGPS UARTを初期化し、データセット選択済みの場合にGaluchatを準備する。未選択ではGaluchatのファイルを開かず、GPS表示と記録を利用可能な状態で起動する。Bootのフッターには常に`ESC MAINT`を表示し、確認中は`CHECKING...`、完了後は`ENTER START`を併記する。チェック結果が異常でもこのフッターを維持する。

メンテナンスは専用の実行状態として既存の設定画面を使い、入口タイトルを`MAINTENANCE`とする。自動消灯、Live Placeへの自動遷移、位置検索、GPS記録開始を行わない。設定変更、SD操作、データセット選択、USBモードへの切替は既存の処理を使用する。地図が使用不能でもその警告画面で設定を覆わない。設定入口でEsc / Delを押すと共通確認ダイアログを開き、取消／再起動を左右で選ぶ。再起動は取消を初期選択とし、Storageの処理中は実行を拒否する。子画面のEsc / Delは従来どおり一つ上へ戻る。

通常起動後のEscは障害の有無にかかわらずMENUを開く。MENU→0 設定、またはトップの0から復旧操作を行える。自動読込み前に退避するメンテナンス起動は、Escを押しながら起動・リセット、またはBoot画面中のEscを使用する。明示的なGPS停止はGPS画面と共通Gで行い、MENU・画面切替では記録状態を変えない。

すでに開始したStorageの読込みは強制中断しない。初期化中にEscを押した場合は新規の自動処理を止めて設定へ移るが、進行中の読込みはStorageが完了するまで所有する。読込み自体でクラッシュする場合は、次の起動時からEscを保持し、読込み前の経路を使用する。起動後に入った場合、すでに開始済みのGPS UART受信は継続するが記録・位置検索は行わない。

Escの入口、受付期間、メンテナンス状態、確認付き再起動に加え、データセット異常時の起動継続・地名欄表示への統一・再読込み抑止を実装した。索引保存・再生成は設定のデータセット再適用から利用できる。再生成・検証は動作設定→データセットから対象を選んで実行でき、起動・検索は保存索引を利用する。

## 事前索引の扱い

[事前索引ファイル仕様](../../11_データセット事前索引ファイル仕様.md)の `_mapindex.dat` は、データセット・地名用言語の適用または明示再生成時に作成する。通常起動・再マウントでは既存索引を検証するだけで、欠落・不正・不一致は地名欄のデータセットエラーとして起動を継続する。Escメンテナンスからの設定操作・通常のEscによる設定操作は維持する。

同じ選択の再適用でも生成できるようにし、生成には記録停止・未保存データの保存・セッション閉鎖完了を必要とする。生成・検証が成功するまで使用可能へ戻さず、切替のNVS保存・Reader切替も確定しない。適用・同じ選択の再適用による生成を実装している。生成中は適用中の表示を維持し、生成失敗・設定保存失敗・索引復元失敗を表示する。復元失敗では退避ファイルを残し、再適用で元データから生成し直す。通常起動では索引を必須とし、欠落・不正・元GLC不一致は既存のDATA ERRと地名欄の読込失敗表示へ接続する。Escメンテナンスまたは通常設定で同じ選択を再適用して生成できる。チャンク配列はRAMへ保持せず、画像ミス時に保存索引をSeek＆Readする。ブロック群からの復号再開はアプリ内Galuchatの追加APIで実装済みである。Wordbook索引も利用し、選択言語領域の欠落・元Wordbook不一致はDATA ERRとして扱う。再生成・検証は動作設定→データセットのキャッシュ操作から実行する。
