# 起動モードとUSBストレージ

起動フラグによるモード切替とSDのUSB公開は実装済みである。USBメニューからのGPX・KML・CSV変換とSD所有権切替も実装し、詳細は[ログエクスポート仕様](10_ログエクスポート仕様.md)に集約する。

## 起動時の分岐

アプリケーションの起動モードはGPSロガーとUSBストレージの2種類とする。通常のGPSロガーモードにはLive Place・GPS記録・設定・ログ閲覧を含み、記録の開始／停止状態とは区別する。起動時にNVSのフラグを読み、その起動中に使うタスクとSDの所有者を決定する。

| 起動モード | 起動するアプリケーションタスク | SDの扱い |
|---|---|---|
| GPSロガー | App・UI・GPS・Storage | StorageがFAT32をマウントし、地図・辞書・ログを処理する |
| USBストレージ | App・UI・Storage | PC公開中は生セクタを公開する。エクスポートの端末操作中だけPC公開を止め、StorageがFatFsをマウントする |

USBのデバイス処理はTinyUSBのシステムタスクで実行する。通常モードは従来の4タスク・5キュー、USBモードはGPSタスクとそのキューを作らず、App・UI・Storageの3タスク・4キューとなる。専用の要求キューや一時ログバッファは増設しない。USBモードではGPS・地図・Wordbook・通常モードのログ閲覧を開始せず、データセットが欠けていても終了操作を行える。エクスポート対象の選択はUSBモード専用の画面とする。

両モードでUIタスクのM5本体・表示初期化完了を同期応答で確認してからStorageを起動する。USBモードでもSDのSPI初期化をUIの本体初期化と並行させない。USB画面を準備した後、Storageの初期化結果をUIへ反映する。

## 永続フラグ

NVS名前空間`geoputer`の`boot_mode`キーへ、4バイトのレコードを保存する。内容は`M`、形式バージョン1、モード値、モード値と0xA5のXORとする。モード値は0がGPSロガー、1がUSBストレージ。未設定はGPSロガーとし、不正・読取失敗でもGPSロガーへ戻してログへ記録する。

起動前の読取りを除き、フラグの書込みはStorageが行う。既存の`config`レコード、データセット番号・言語、記録間隔等は変更・消去しない。設定レコードの形式バージョン3と48バイトの長さも維持する。保存に失敗した場合は再起動せず、現在のモードとフラグを維持して失敗を表示する。

## GPSロガーからUSBストレージへ

設定のトップ階層に「動作モード」を置く。現在値は日本語ではGPSロガー、英語ではGPS logger。これは通常設定レコードのフィールドではなく、起動フラグを変更する制御項目とする。動作設定の次に並べ、Enterで切替確認を開く。動作設定の一覧には含めない。

Enterで共通確認ダイアログを開き、「取消／切替」を横並びに表示する。初期選択は取消、左右で選択、Enterで確定、Esc / Delで取消。確定時にUSBストレージのフラグ保存をStorageへ要求し、成功通知を受けてから再起動する。

記録はSTOPPEDでなければ切り替えない。PAUSED・STARTING・RECORDING、Appの保留測位点、未保存レコード、開いているセッション、終了処理中は切替不可とし、先に記録を停止するよう表示する。AppとStorageでも再検証し、古い画面状態だけを根拠に再起動しない。モード切替の確認で記録を自動停止しない。先行するSD処理があれば完了後に受け付け、使用中の地図・辞書を閉じてSDをアンマウントする。

次の起動ではUSB用のSD初期化だけを行う。PCにはカード全体をUSBマスストレージとして公開し、ログ取得、dataset.ini編集、GLC・Wordbookの入替えができる。

## USBストレージからGPSロガーへ

USBモードの入口は「ログを書き出す」「ロガーへ戻る」のメニューとする。「ロガーへ戻る」またはUSBメニューのEsc / Delで共通終了ダイアログを開く。「取消／終了」を左右で選択し、Enterで確定する。取消・Esc / Delではフラグを変えずUSBメニューへ戻る。1/2/3・F1・Dでは通常モードの別画面へ移動しない。起動直後に終了確認は開かない。PC公開中でも終了項目を有効とし、端末側の明示確認でUSB公開を停止して復帰できる。

終了確認には「PCの保存完了後に終了」／「Finish PC saves first」と表示する。PCでのコピー・編集・保存を完了してから端末の終了を確定する。Windows側をクイック削除に設定した運用では、PCの安全な取り外し操作を必須としない。PCの取り外し通知を受けると媒体を非公開にしてEJECTEDを表示するが、それだけではフラグ変更や再起動を行わない。

終了確定時は、実行中のUSBセクタ処理が終わるのを待ち、新規転送を止めてSDへ同期を要求する。その後GPSロガーのフラグを保存し、新しいUSBアクセスを止めて媒体を非公開にする。Storageから完了通知を受けたAppが再起動する。同期やフラグ保存に失敗した場合は現在のモードを維持し、再試行できる。PC内の未送信キャッシュは端末から同期できない。クイック削除以外のポリシーなどでPCの書込みキャッシュが有効な場合は、安全な取り外しを先に行う。端末側のSD同期だけでPCの未送信データまで保存できるとは扱わない。

USBモードで電源を切ってもフラグはUSBのままであり、次回もUSBモードで起動する。USBケーブルの抜去だけでは通常モードへ戻さない。画面の自動消灯も行わず、終了操作を常に可能にする。SD初期化に失敗した場合もエラーを表示し、終了ダイアログで戻れる。

通常モードへの復帰時はSDとデータセットを改めて検証し、変更された書式・地図・辞書を読み直す。USBモードより前のRAMキャッシュは再利用しない。

## USBモード内のログエクスポート

「ログを書き出す」では、対象ログと出力形式を選び、Storageが変換する。初期対応として設計する形式はGPX・KML・CSVとし、出力先は`/export/`、出力名は元のファイル名全体に`.gpx`・`.kml`・`.csv`を追加する。元の`.gps.dat`は保持する。

PC公開中だけ安全な取り外しを案内し、完了を確認してからUSB公開を停止してFatFsをマウントする。未接続・安全な取り外し済みなら案内を省略する。変換中のケーブル接続でもSDは公開せず、完了後にファイルを閉じ、同期・アンマウントを済ませてから再公開する。未接続なら接続待ちとする。この切替はUSBモード内で完結し、GPSの起動・NVSフラグの変更・再起動を行わない。詳細は[ログエクスポート仕様](10_ログエクスポート仕様.md)に集約する。

## USBとSDの実装

Arduino-ESP32のUSB-OTG / TinyUSBを使い、`ARDUINO_USB_MODE=0`とする。CDCは自動起動させず、アプリケーションが起動モードを読み、必要なクラスを登録してからUSBを開始する。両モードともUI・SDの初期化より先にUSBコントローラを初期化する。USBモードではその直後に切断状態とし、StorageのSD初期化と画面準備が終了してからPCへ接続する。初期化中の一時的な媒体なし状態をPCへ公開しない。SD初期化に失敗した場合もUSB接続と終了操作は可能にする。

USBシリアルは両モードで使用し、MSCクラスはUSBモードでだけ登録する。通常モードのUSBシリアル番号はMAC由来の既定値、USBモードは同じ値へ`-SD`を付け、異なるインターフェース構成をWindowsが同一機器の履歴として混在させない。再起動時はUSBを明示的に切断し、PCが取り外しを検出する時間を設けてから再起動する。WindowsでのCOM番号は従来のUSB Serial/JTAGから変わる場合がある。

SDのSPI配線・4MHz設定は通常モードと共通とする。PC公開状態では`sdcard_init`とブロックドライバの初期化を使い、`sdcard_mount`やFatFsのファイルAPIは呼ばない。端末操作状態への切替ではUSBセクタI/Oの停止と進行中I/Oの終了を確認し、FatFsの使用期間と分離する。MSCの読書きコールバック・所有権切替・終了処理を排他し、512バイトの作業領域を一つ持つ。部分セクタの書込みは既存内容を読んで対象部分だけを変更し、隣接データを維持する。要求全体の範囲を64ビットで検証し、範囲外ならSDへ触る前に失敗する。

USBの準備完了・取り外し・I/O異常はStorageが最新状態を保持し、通常のApp通知キューへ投機的に通知する。通知できないときも保持して再試行する。TinyUSBのコールバックからAppへ同期要求を送らず、UIやGPSのキューとも混在させない。

実装は`BootMode`、`OperatingMode`、`task/storage/usb`、共通UiModel / UiRendererに配置する。[Espressif USB MSC API](https://docs.espressif.com/projects/arduino-esp32/en/latest/api/usb_msc.html)と、使用中のArduino-ESP32 2.0.17の実装を基準とする。
