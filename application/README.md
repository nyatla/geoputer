# Geoputer Application

Application・UI・GPS座標受信・Storageを実装する。ApplicationはArduinoの`setup()` / `loop()`が実行されるメインタスクで動作し、UI・GPS・StorageをFreeRTOSの別タスクとして起動する。GPSがUARTとNMEA解析、StorageがNVS設定とSDを所有し、Appが各タスクの結果・通知を集約してUIへ表示データを渡す。

```text
application/
  main.cpp                 メインタスクの入口
  Application.h/.cpp       全体状態、通知受信、UI・GPS・Storageの同期操作
  Config.h                 UI色深度・SD予約枠・チャンク上限・GISキャッシュ・検索周期
  LogBrowser.cpp           一覧・詳細・測位点の要求、結果照合、10件キャッシュ
  Settings.h/.cpp          設定の初期値・値域検証・NVSレコード符号化
  BootStatus.h             起動チェックの状態・表示略称・完了判定
  TaskMessages.h           固定長メッセージと同期結果
  task/ui/
    UiTask.h/.cpp          UI受信ループ、キー入力、通知・結果返送
    UiModel.h/.cpp         選択状態、未処理確定操作、画面指定の保持
    UiRenderer.h/.cpp      メイン画面とSettingsの描画
    UiCanvas.h             RGB565描画色と4bit・16色パレット画像の対応
    PixelFont.h/.cpp       8×8・16×16ドットの固定セル描画
    Shinonome.h/.cpp       東雲16ドット字形のFlash参照
    UiTypes.h              画面・操作・表示データの値型
    KeyBindings.h          1/2/3の画面選択・方向操作と物理キーの対応
    LivePlaceLayout.h      画面の領域・GPS数値と未取得表示
    PlacePresentation.h    Storageの2行住所の受取りと検索中の表示保持
    LicenseText.h/.cpp      Flash内のライセンス本文（生成済み）
    SettingsLayout.h        設定画面のグリッドと表示範囲
    SettingsText.h/.cpp     設定画面の日英表示・単位・確認文・処理通知
  task/gps/
    GpsTask.h/.cpp         UART受信、同期操作、サンプル・状態通知
    GpsReceiver.h/.cpp     同時刻の統合、Fixの有効性、受信断判定
    NmeaParser.h/.cpp      GGA/RMCの座標・日時・速度・方位・衛星・HDOP解析
    GpsTime.h              UTC暦とJSTファイル名時刻の変換
    GpsTypes.h             座標と受信状態の固定長の値型
  task/storage/
    StorageTask.h/.cpp     NVS・SDの受信ループ、同期受付、非同期実処理
    SettingsStore.h/.cpp   PreferencesによるNVS設定保存・復元
    StorageTypes.h        設定保存・カード・操作状態の値型
    PlaceTypes.h          検索座標・地名結果・読出し状態の値型
    PlaceSearchFlow.h     App側の検索間隔と未完了要求の管理
    StorageActivity.h      RG状態・SD実I/Oの観測
    log/
      LogWriter.h/.cpp     排他付き64件リング、保存範囲の保持、失敗時の同一位置再試行
      LogReader.h/.cpp     6件の一覧、概要、最大10件の読出しと検証
      LogReadTypes.h       閲覧要求・固定長結果・表示状態
      LogFormat.h          512バイトヘッダーと32バイトレコード・CRC32
      LogFile.h            ESP32のFatFs / ホストstdioのランダムアクセス
    galuchat/
      PlaceLookup.h/.cpp  SDKのファイルReader、データ検出、地名検索
      CachedMapReader.h/.cpp 128×128・32bitの矩形キャッシュと点検索

      TextEncoding.h/.cpp UTF-8検証と%書式による2行への整形
  utils/

    Task.h                 受信キュー1つを所有するサブタスク基底クラス
```

現在は4タスク・5キューとする。ApplicationQueueは8件、AppReturnQueueは1件、UIQueue・GPSQueue・StorageQueueは各1件。UIは8192バイト・優先度1、GPSは4096バイト・優先度2、Storageは12288バイト・優先度1をスタック容量と優先度の初期値とし、実機で計測して調整する。未取得の同期要求は全体で1件だけとし、結果取得のタイムアウト後も同じ要求を待つ。Appは通知からUIの操作内容を取得し、画面指定と処理済みIDを返す。UIは描画前に同期結果を返し、結果キューが満杯なら完成済みの結果を保持して再投入する。GPSも同じ戻り値キューを使い、返送の再試行中もUART受信を続ける。

同期戻り値の共通ヘッダー・初期状態は`utils/SyncClient.h`の`prepareSyncReturn`で、各タスクが所有する戻り値へ直接設定する。追加の転送用フレームは作らず、満杯時に完成済み結果を保持して再送する方式は維持する。Storageの未処理ジョブは`JobKind`で一種類だけ保持し、設定読出し・地名検索・データセット検査・データセット操作・設定保存や媒体操作を区別する。完了通知は送信できるまで別に保持する。USB移行とデータセット変更で共通するロガー停止条件は`log/LogTypes.h`の`loggerStopped`へ集約し、Appの未受付点・制御操作等の追加条件は各呼出し側で確認する。

## ビルド

リポジトリのルートでPlatformIO Coreを使う。

PlatformIOが未導入の場合は、プロジェクト内の仮想環境へ導入する。

```bash
python3 -m venv .venv
.venv/bin/pip install platformio==6.2.0
.venv/bin/pio run -e cardputer-adv
```

PlatformIOがPATHにある場合は次のコマンドでビルドする。

```bash
pio run -e cardputer-adv
```

生成物は`.pio/build/cardputer-adv/firmware.bin`。書き込みには同じ環境で`pio run -e cardputer-adv -t upload`を使用する。書き込み先の接続・識別を確認してから実行する。

## 現在の操作とGPS接続

- 起動後はBoot画面で6項目の確認結果を表示する。データセット欠落を含む警告・失敗も確認完了として扱い、完了後は通常2秒、問題があれば5秒でLive Placeへ進み、Enterでも進める。GPS受信はメンテナンス受付後、Bootの表示中から開始する。
- Live Place・GPS Logger・Logs・Settingsのトップ間は、1＝Live Place、2＝GPS Logger、3＝Logs、Esc（Fnなしも可）＝Settingsで直接切り替える。同じ画面のキーは何もしない。下位階層・値編集中・確認中・削除実行中は画面ショートカットを無効にし、Esc / Delは取消・一段戻る操作とする。メンテナンスとUSBモードでは通常画面への切替を行わない。 MENU画面は設けない。Delは各トップからLive Placeへ戻る従来操作を維持する。
- GPS LOGGERのSTARTで新しい有効Fixから記録する。メイン画面の0（Fn不要）は一時停止確認、GPS LOGGERのRESUMEは再開、STOPは終了確認。いずれも記録だけを制御し、GPSデバイスの電源は変更しない。
- 動作設定ではEnterで編集、左右キーで候補変更、Enterで確定、EscまたはDelで取消。DelはFnなしで使用できる。Cardputerの実キーは画面選択が1/2/3、上が`;`、下が`.`、左が`,`、右が`/`で、すべてFnなしで使用できる。2/3と方向操作はFn併用でも同じ操作となる。1単独とFn＋1は別の機能とし、押し続けたままFnを変更しても再発火しない。Escは物理バッククォート（Fn不要）、決定はEnter、一時停止はPとする。F1（Fn＋1）は未割当とする。左右はSettingsの値編集中、共通確認ダイアログ、ライセンス情報のソフトウェア単位ジャンプで有効とする。確認では左が取消、右が実行項目の選択となる。
- 無操作で設定時間後に画面を消灯する。最初のキーはLive Placeへの復帰だけに使い、同時に画面操作を実行しない。GPS受信は消灯中も継続する。
- 測位前は`NO FIX`、有効NMEAが3秒以上届かない場合は`NO GPS`とし、座標を`--`にする。受信が続いていても有効座標が3秒以上更新されなければ`NO FIX`に戻す。
- GPS受信はSettings表示中も継続する。Live Placeの表示中は有効FixからSD上の選択済みデータセットを検索し、地名を16×16ドットで表示する。起動時のログはSTOPPED。記録中は画面消灯・Settings表示を経ても新しいFixの採用と保存を継続する。

接続は[Mesh Kitの標準接続](https://docs.m5stack.com/en/arduino/projects/cap/cap_lora868)を使用し、UART1のRX=G15、TX=G13、115200 bps・8N1とする。受信バッファは2048バイトとし、5ms周期で最大1024バイトを取り出す。GPIOと通信速度は現在の実装では固定であり、設定画面から変更しない。LoRaの送受信は初期化しない。GPS・USBの両モードでsetupの先頭からNRST=G3をLOWに保持し、StorageのSPI初期化後にGetStatusとSetSleep(0)だけを送って内部のcold SLEEPへ移す。成功時はNSS=G5とNRST=G3をHIGHに保持して不用意な復帰を防ぎ、失敗時はリセット保持へ戻す。起動ログは`[LORA] SLEEP`または`[LORA] RESET HELD`とする。個別電源断ではなく、GPSの給電・受信は継続する。

Live Placeのヘッダーには現在時刻を8×8のASCIIでHH:MM:SS表示する。GPSから最初の有効FixとUTC時刻を得た時点でUIの表示時計を合わせ、日本時間（UTC+9）へ変換する。以降はUIタスクの単調増加時刻で進め、GPS受信断・Fix喪失・Settings表示・消灯を経ても継続する。未取得時は--:--:--とし、再起動後は改めてGPS時刻を待つ。この段階は初回の時刻合わせだけを行い、GPSの各受信で時計を再設定しない。ログ用の測位UTCとは独立した表示時計とする。

GPSの同期操作は`StartGpsReception`と`GetGpsStatus`とする。前者の成功はUART受信の準備完了を表し、有効Fixを待たない。GNSSの休止・復帰コマンドや電源状態の確認は行わず、最終設計の`InitializeGps` / `SetGnssState`の完了を代用しない。通常起動のメンテナンス受付後から受信し、START前は記録に採用しない。GNSS PAUSE制御の導入は別工程とする。

GGAとRMCをチェックサム付きで解析し、GP・GNなどのトーカーに依存せず度分表記を符号付き十進度へ変換する。同一UTC時刻の情報は80msの統合待機または次時刻の到着で1サンプルに確定し、どちらかが無効なら有効位置として扱わない。破損行・範囲外座標は採用しない。受信断やFix喪失では有効フラグと表示座標を消去する。

通知は`GpsSampleReady` / `GpsStatusChanged`としてApplicationQueueへ投機的送信する。満杯時は最新のスナップショットを保持して再試行し、途中の表示更新が統合された件数を数える。現在は画面表示用であり、全サンプル保存の保証は行わない。AppはGPSの共通revisionで古い通知と同期結果を除外し、同期待ち中の通知では表示データの更新予約だけを行う。同期結果の取得後に`UpdateUiContent`を送り、UI自身が描画する。

USBシリアル（115200 bps）には状態変化と有効座標を出力する。5秒ごとの`RX` / `NMEA` / `rejected`は、UART到着・有効行の受信・破損行の切り分けに使用する。`coalesced`は通知待ち中に統合された更新数とする。`NO FIX`が続く場合はGPSアンテナから空が見える場所で測位を確認する。

16×16の地名・GPS測位待ちは、英数字と日本語を東雲16ドットに統一する。GPS Logger・ログ詳細の操作項目とSettingsの主表示は、日本語モードを日本語表記の東雲16×16、英語モードをM5GFXのAsciiFont8x16とする。言語名は日本語を16×16、Englishを8×16で表示する。東雲16ドット部分のASCII英数字には全角字形を使い、該当する全角記号がない場合だけ同じ東雲の8×16字形をセル中央へ置く。8×8字形の2倍拡大は行わない。未収録文字は東雲の白四角で表示する。8×8のASCIIはM5GFXの`Font8x8C64`、補助表示の日本語は`lgfxJapanGothic_8`を使用する。描画は1ビット字形から整数座標へ行い、アンチエイリアスを使用しない。東雲の固定ソース・ライセンス・変換手順は[third_party/shinonome](../third_party/shinonome/README.md)に保持し、`python3 tools/prepare_shinonome.py`でFlash上の読取専用字形表を生成する。

Live Placeの最下段は`P PAUSE 2:GPS 3:LOG ESC:SET`とし、画面選択の数字とESCをシアン、説明をライトグレーで表示する。他のトップは`1:LIVE 2:GPS 3:LOG ESC:SET`を表示する。ログ一覧からファイル名一覧、詳細、測位点を閲覧できる。ログ一覧のDで削除確認を開き、取消を初期選択として削除を実行できる。Delは戻る操作として維持し、一覧の案内は`[ENTER] OPEN    [D] DELETE`とする。記録・保存・終了処理中の対象はUIとStorageで保護する。Place Viewは未実装のため表示しない。[Boot画面](../doc/画面・操作/boot/README.md)はAppが集約した初期化結果を表示する。通信契約は[タスク構成設計](../doc/06_タスク構成設計.md)に従う。

BootのチェックはDISPLAY、TASKS/QUEUES、NVS SETTINGS、SD CARD、GPS UART、GALUCHAT DATAの6項目。NVS設定の未保存はDEFAULTとして正常扱いとし、SD未認識と混同しない。GaluchatはGPS Fixを待たずにCheckDataset通知で保存済み番号・言語のファイル・ヘッダー・辞書形式・文字コードを確認する。設定未保存時・初期化後は未選択とし、GALUCHAT DATAは正常のNONEを表示してデータファイルを開かない。未確認・確認中・成功・警告・失敗を色と記号で区別する。Boot表示中は無操作消灯を行わず、完了前のEnter・数字キー・Delではチェックを中断しない。Escは初期化完了を待たずメンテナンスへ入る。UART OKは受信準備の成功であり、測位成功やGNSS PAUSEを意味しない。

## Galuchatのファイル読出し

FAT32のSDカードの`/dataset/01/`〜`/dataset/99/`に、`dataset.ini`、WGSMapSet/3（`.glc`）、言語別GisWordBook/0（`.giswordbook`）を配置する。INIのファイル名指定を使い、余分なGLC・辞書があっても自動選択しない。初回は未選択で起動するため、設定→動作設定→データセット→データセットを選択から番号と言語を選び、「適用する」で即時反映する。選択一覧の先頭にある未選択を確認して、NVSを未選択へ戻せる。未選択でもGPS表示・ログ記録は利用できる。[配置用INI例](../examples/sd/dataset/01/dataset.ini)のファイル名は、実際に配置するファイル名へ合わせる。

データセット切替用の`dataset.ini`は[データセットメタデータ仕様](../doc/08_データセットメタデータ仕様.md)で定義する。UTF-8の行単位のINIで、言語別のタイトル・説明・Wordbookと共通のGLCを指定する。解像度・格納範囲・チャンク数はGLCから取得する。切替対応版では01〜99から番号と言語を選択し、ログの停止・保存・閉鎖完了後に検証・NVS保存後にReaderを切り替えて即時反映する。起動時に選択先が見つからない場合は原因を通知して未選択へ移し、通常画面へ進む。メタデータの読取りと切替は実装済み。[実装検証](../doc/検証/データセット切替実装検証.md)にホスト試験を記録する。UTF-8専用化、メニュー遷移のスタック削減、UIの休止処理を含む修正版を実機へ書込み済み。SD上のINIとファイル名を合わせた後、地名取得に成功した。旧版ではデータセット適用後の再起動と切替先の復元を確認し、最終版で切替済みデータの読出し・MENU・SETTINGS・戻る操作を90秒間監視した。[メニュー遷移修正の検証](../doc/検証/メニュー遷移リセット修正検証.md)に結果を記録する。

```text
SDカード直下/
└ dataset/
  └ 01/
    ├ dataset.ini
    ├ 任意名.glc
    └ 任意名.giswordbook
```

Wordbookと`dataset.ini`、タスク間メッセージ、UIの文字列はUTF-8に統一する。Wordbook内部の`token_encoding`を優先し、未指定または空の場合は`text_encoding`を参照する。値は大文字・小文字を区別せず`utf8`または`utf-8`だけを受け付ける。文字コードの未指定・未対応や不正なUTF-8は`ENCODING ERROR`とし、端末内で文字コード変換は行わない。SJIS（CP932）版やUTF-16版のWordbookは使用できない。既存のSDカードでは、同じGLCに対応するUTF-8版Wordbookへ置き換え、INIの`wordbook`をそのファイル名へ変更する。ファイル名やメタデータだけの変更では文字コードを変換できない。[UTF-8統一の検証結果](../doc/検証/UTF-8統一検証.md)に実ファイル試験と容量を記録する。

Storageがマウント済みの`/sd`をSDK互換の`ObservedFileReaderFactory`から読む。実際のopen・seek・バッファ補充・closeだけをSDアクセスとして観測し、バッファ内の1バイト参照は対象外にする。先読み量は用途別とし、地図の初期化・チャンク索引構築とWordbookは4KiB、地図の矩形取得は16KiBを使用する。WordBookのSDK内トークンキャッシュは無効とし、データ全体のRAM展開は行わない。スキップがバッファ内なら位置だけを進め、バッファ外に残る距離が`FileReadThroughSkipBytes`以下なら通常のバッファ補充で読み流す。初期値は4096バイトで、0は従来どおりバッファ外を常にfseekする。長い距離はfseekを維持し、読み流した後の先読み余剰は次の読出しに再利用する。読み流し専用の追加バッファは確保せず、地図とWordbookの両方に適用する。読み流しでは実際のfreadを観測し、RAM上のスキップはI/Oとして数えない。SDKのReaderを基準とする[third_party/galuchat](../third_party/galuchat/README.md)を使用し、現在はチャンク範囲Readerの試作差分をアプリ内だけに保持する。coreとSDKは変更しない。C++17と例外処理を有効にする。

アプリの`FileReadOptions`でバッファ容量と読み流し閾値を独立して指定する。汎用の既定値はともに4096バイト。容量0はファイルI/Oの前に拒否する。`ObservedFileReaderFactory::setReadOptions`は以後に生成するReaderだけへ作用し、生成済みReaderの容量・閾値は維持する。Storageが地図の索引構築完了後にFactoryを矩形用へ切り替える。Readerが生存中の再確保や追加のキャッシュ・索引は行わない。アプリ限定試作では、範囲指定時に先読みバッファをチャンク全体長までに抑え、freadの補充をチャンク末尾までに制限する。矩形取得用16KiBでは先読みバッファ容量が従来4KiBに対しReader一つあたり12KiB増えるが、初期化の同時2 Readerは合計8KiBを維持する。[用途別先読み量の実機比較](../doc/検証/用途別先読み量の実機比較.md)に条件と結果を記録する。

WordBookの地名検索はアプリ側のWordBookCacheで包む。32bit区域コードとUTF-8検証・書式展開済みの地名2行（各64バイト）を16件まで固定長で保持する。利用順だけを16バイトのインデックス配列で管理するLRUとし、時刻・内部Tickは使わない。ヒット時は辞書読出しとUTF-8検証・整形を省き、ミス時に成功した結果だけを登録する。今回の座標・時刻・要求世代は毎回の要求から結果へ設定する。

地名キャッシュは矩形の再構築・GPS喪失・画面切替では保持し、PlaceLookupのclose、SD媒体操作、Reader再オープンで消去する。矩形と地名がともにヒットした検索ではSDを読まない。RGは従来どおり矩形の状態、SDはログ等も含めた実I/Oを表示する。実装と検証は[WordBook地名キャッシュ検証](../doc/検証/WordBook地名キャッシュ検証.md)を参照する。

区域コードの取得は`CachedMapReader`で包み、最初の点検索時に128×128の`uint32_t`画像1枚（64KiB）を確保する。経度・緯度はSDKと同じ解像度と丸め方で整数座標へ変換する。範囲内は画像の値を返し、初回または範囲外では取得点をセル(64,64)とする矩形をアプリの`DiskIndexedMapReader`で読み直す。保存索引のチャンク情報を1件ずつ読み、対象チャンクの群情報を1件ずつ確認し、必要な群へ直接移動して追加APIの`readRectFromBlockRange()`で復号する。群を持たない16KiB未満のチャンクは既存の`readRectWithoutTail()`を使用する。原点は`(ix-64, iy-64)`、幅・高さは128、範囲の上端は含まない。区域なしのコード0も有効なキャッシュ値とする。

アプリは`DiskIndexedMapReader`を使用し、保存索引から対象チャンクを選ぶ。`MaxDatasetChunks`（1500）は索引読込み前に確認する。SDKの`GaluchatWGSMapSet3IndexedReader`は今回の比較試験の旧方式だけに使用し、製品側でRAMチャンク索引を作らない。従来の`GaluchatWGSMapSet3Reader`と既存APIは変更しない。矩形取得では最後に必要なブロックの処理を完了した時点で停止し、後続ブロックの走査とGI01全体長の一致の検証を省く。必要ブロック内の復号・バイト境界整列・RAWS/LZSSの終端検証は維持する。チャンクごとに独立したReaderを閉じるため、次のチャンクに備えた末尾への移動は行わない。保存チャンク索引と既存の画像キャッシュを使用する。保存ファイル内のブロック群索引も使用し、群ごとに復号範囲を制限する。同じチャンクの複数群はファイルとバッファを使い回し、追加画像は作らない。

読出し先のアダプターは32bitの範囲を検証し、複数地図が重なる場合は先に取得した非ゼロ値を保持する。これによりSDKの点検索の優先順を維持する。SDKの矩形読出しは通常後の非ゼロ値で上書きするため、標準のRasterViewをそのまま使わず、このアダプターへ直接書き込む。64bitの中間画像は作らない。

再構成開始時にキャッシュを無効化し、矩形全体の読出し成功後に原点と有効状態を確定する。途中の読込・確保・コード値域エラーは検索失敗として返し、部分的な画像を参照しない。同じReaderの範囲内では画面復帰後も再利用する。SD再マウント・取り外し・フォーマットおよびReaderの閉鎖時は画像を解放し、別のデータセットへ持ち越さない。BootのCheckDatasetでは画像を確保しない。

Appは`SearchPlace`通知に要求ID・画面世代・Fixのコピーを付ける。Storageは結果を`ReadCompleted` / `ReadFailed`で返す。結果は`StorageReadKind::Place`で設定読出しと区別し、通知キュー満杯時も保持する。新しい検索は未完了要求がない場合だけ行い、通常は新しいGPSサンプルに対して最短5秒間隔とする。Settings表示中と画面消灯中は新しい検索を開始しない。

RGは矩形キャッシュの実状態を示し、未準備は暗灰、構築中は黄、有効な矩形を保持していれば検索間隔中やGPS喪失・画面切替後も緑を維持する。SDはログ・地図・WordBook・媒体操作の実I/Oで青く点灯し、RAM受付・キャッシュ参照・文字変換・NVS保存では点灯しない。状態の正本はStorageで、`RgCacheStateChanged` / `SdAccessChanged`をAppが最新revisionで統合しUIへ渡す。キュー満杯時は最新状態を保持し、表示通知を待ってI/Oを遅らせない。SDだけ最低150ms表示し、同じアクセスIDの再送で再点灯しない。

[メイン画面](../doc/画面・操作/live-place/README.md)は採用仕様1.3のレイアウトを実装し、上段に記録状態・JST時刻・RG・SD・電池、本文に東雲16ドットの住所2行、左に大きな速度・進行方位、右にLAT / LON / ALT / SAT、下段に記録時間・64件バッファ、問題発生時は赤地白文字の原因を表示する。電池残量はUIがM5Unifiedから5秒ごとに取得し、取得不能は--%、充電状態が不明なら充電中と表示しない。

地名と表示座標は同じ検索Fixを使う。再検索中は前の表示を保持し、結果確定時に一緒に差し替える。Fix喪失時は旧地名・座標を消し、WAIT GPS FIXを16ドット表示する。キャッシュとSDの実状態はGPS喪失で消去しない。画面世代が古い結果、Fix喪失前の検索結果は適用しない。Storageがdataset.iniのdisplay_line1 / display_line2を展開し、完成した2行をキャッシュ・通知する。Appは再整形しない。各行は232ドット以内、半角スペースは8×16、その他は16×16とし、超過時はUTF-8境界を保って...で省略する。

SD未認識、ファイル不足、候補重複、区域なし、文字コード異常、データ読込異常を区別して表示する。SDカードは起動前に挿入する。起動後に挿入・交換した場合はSettingsのストレージ操作で再マウントする。SDデータの異常でGPS受信やNVS設定保存を止めない。

速度・方位の主数値は東雲16ドット、ラベル・速度単位・右側の詳細値はASCII 8ドットとする。SPD / HDGは左上ラベル、左右・上下の均等分割、SPD / HDG間の横線は左端から中央縦線までとする。速度は低速時に整数m/h、1〜100km/h未満は小数1桁km/h、100km/h以上は整数km/hへ切り替える。数字16ドット・小数点の送り幅8ドットで3桁までを収め、単位の位置を固定する。方位はGPSの進行方位を整数度へ丸め、360°は0°とする。ALTはGGAの海抜高度を小数1桁のメートルで表示する。項目ごとの未取得やFix喪失は--にし、HDOPはメイン表示だけから外してGPS取得・ログ記録には残す。

## GPSログの保存

Appは新しい有効Fixを設定間隔で採用し、StorageTask::tryAppendLogを通常の関数として呼ぶ。この関数はAppタスク上で排他付き64件リングへコピーし、受付結果とLogSnapshotを返す。要求・戻り値キューやSD処理の完了を待たず、他の同期要求の結果待ち中にGPS通知を処理する場合も追加できる。成功はRAM受付であり、永続化完了ではない。OpenLogSession / FlushLog / CloseLogSessionは引き続き同期メッセージとする。Storageは満杯・設定時間経過・一時停止・停止で実保存を行う。FatFsのf_sync成功後に保存件数を進め、LogWrittenを通知する。保存失敗はStorageError（Log種別）で通知し、受け付けた全レコードを保持して5秒間隔で同じ位置へ書き直す。

記録間隔は1・5・10秒（初期値1秒）、SD保存間隔は1・5・10・30・60秒（初期値10秒）から設定する。保存期限はバッファが空から非空になった時点を基準に判定する。長いGIS処理の分割は未実装であり、その実行中や先行する結果返送待ちの間もRAMに空きがあれば追加できるが、実保存とキュー経由の制御受付は遅れ得る。

レコード本体は`records[64][32]`、連番は`sample_seqs[64]`に分離し、合計2,304バイトを維持する。Storageは保存対象を固定してからロックを解放し、リングの最大2連続区間を直接writeしてf_syncする。成功時にその対象だけを解放し、保存中に追加された点は残す。失敗時は同じ対象・同じファイル位置を保持して再試行する。保存中の分も64件へ含め、二重バッファやSD保存用の全件スタックコピーは作らない。符号化には32バイトのローカル領域、ヘッダー生成には従来どおり512バイトを使用する。ESP32の排他区間は状態・添字・コピーに限定し、変換・CRC計算・SD・キュー待ちを含めない。

満杯の間の新規受付は失敗とする。Appは未受付の採用点を1件保持して再要求し、その間に保持できなかった新しい採用対象点だけを欠落件数へ加算する。一時停止・停止の確定操作は新規採用を止め、保持中の点が受付済みになってから、その境界のflush / closeを要求する。SD障害が継続して境界が受付不能なら操作はWAITのまま待ち、未保存点を破棄しない。

未受付点の再要求は1秒間隔とする。セッション終了もLogWritten / StorageErrorとStorageSnapshotで通知し、open=false・closing=falseで終了を確認する。終了専用の通知は設けない。ログ保存通知は元の同期要求IDを引き継がず、AppはStorageのrevisionで古い媒体状態を除外し、LogSnapshot自身のrevisionで直接受付後の件数・保存状態が古い通知へ戻らないようにする。終了処理中や未保存データの保持中は、新規セッションを受け付けない。ファイルの作成・seek・書込み・sync・closeの失敗は共通のLogError::Ioとして通知する。

SD直下のlogsへ、最初の採用点のJSTからYYYYMMDD_HHMMSS_n.gps.datを作る。日時不明はundated_<session16桁>_n.gps.datとする。排他的な新規作成で既存ファイルを上書きせず、同じ秒は連番を進める。512バイトヘッダー・32バイト測位レコードをリトルエンディアンとCRC32で符号化する。ファイル形式の正本は[測位記録ファイル仕様](../doc/07_測位記録ファイル仕様.md)。有効点のないセッションは空ファイルを作らない。一時停止・再開では同一セッションを継続し、停止後の次回開始は別ファイルにする。

ログの保存・未保存・欠落・最終保存の状態はGPS LOGGERで確認する。ログが開いているか未保存データがある間は、再マウント・取り外し・フォーマットを拒否する。NVS設定の保存は使用できる。ログ一覧・概要・最大10件単位の非同期読出しと閲覧画面は実装済み。距離・最高速度の全件集計、GNSSの休止・復帰制御、長いGIS処理の分割は後続実装とする。GPS通知は最新値へ統合する方式であり、全GNSSサンプルを無条件に保存する保証は行わない。

## 設定・ストレージ・ライセンス

Settingsは動作設定、システム設定、ストレージ操作、バージョン情報、ライセンス情報の5メニューとし、4行ずつスクロール表示する。項目・値・確認文・カード情報は日本語を東雲16×16、英語をAsciiFont8x16とし、タイトルとライセンス本文はASCIIの8×8ドットとする。GPS状態・キーガイド・短い通知も8×8ドットとする。動作設定は項目名をx=20で左寄せ、値を実描画幅に応じて右端x=236へ右寄せする。4行表示で全6項目へスクロールし、カード容量等はカード情報パネルを開いて表示する。動作設定の先頭に表示言語（日本語 / English、初期値日本語）を置き、表示言語・GPSログ間隔・SD保存間隔・消灯時間・輝度を編集してNVSへ保存できる。表示言語はEnter確定後、Appが適用した時点で同じ画面・選択位置のまま反映する。輝度・消灯時間も即時反映する。ログ間隔はAppのFix採用間隔、SD保存間隔はStorageの未保存データの期限へ反映する。データセットは一覧・詳細・地名用言語の選択を開く。システム設定にはモード編集・Mesh Kit固定のGPS接続（外付けGPS未対応）・保存して再起動・初期化を置く。初期化画面から戻るとシステム設定の同じ項目へ戻り、確認後だけ実行する。GPS接続は動作設定から除く。

NVSの名前空間は`geoputer`、キーは`config`。48バイトのレコードへ識別子、形式バージョン3、7項目、Wordbook言語、検査値を保存し、長さ・形式・値域・検査値を検証してから使用する。設定が未保存なら初期値を使用し、不正・読込障害は設定エラーとして表示する。旧バージョン1・2の16バイト設定を読み、他項目を維持してデータセットだけ01・INIの既定言語へ移行する。次の保存でバージョン3へ移行する。保存形式の詳細は[Settings画面仕様](../doc/画面・操作/settings/README.md#7-nvsの形式と旧設定の引継ぎ)に従う。SD未挿入でも設定を読み書きできる。SaveSettingsは設定のコピーを保持した時点で同期結果を返し、実保存成功はSettingsWritten、失敗はStorageErrorで通知する。LoadSettingsは通知で要求し、ReadCompleted / ReadFailedで復元結果を返す。完了通知はキュー満杯時も保持して再投入し、実処理を二重実行しない。

SDはLCDと別のSPI（FSPI、SCK=G40、MISO=G39、MOSI=G14、CS=G12）を4MHzで使用し、未使用LoRaのNSS=G5をHIGHに保つ。ストレージ操作画面にはカード状態、カード容量、FAT種別、総容量・空き容量、再マウント、安全な取り外し、FAT32フォーマットを用意する。FAT32以外は利用対象外として表示する。SD操作はOperateStorageの同期受付後にStorageが実行し、StorageOperationCompleted / StorageErrorで結果を通知する。

フォーマットは端末上の確認画面で取消からOKへ選び直して確定した場合だけ実行し、カード全体をFAT32の単一ボリュームとして作成する。マウント失敗時の自動フォーマットは行わない。設定初期化も別の確認画面を経てGeoputerの初期値をNVSへ保存する操作とし、SDデータや他ライブラリのNVS領域を消去しない。

ライセンス情報はSDとNVSを使わず、Flash内の本文を上下キーでスクロールして閲覧する。上下キーを押し続けると連続スクロールする。配布元と本文は[ライセンス一覧](../third_party/licenses/manifest.json)に保持し、`python3 tools/prepare_licenses.py`で29文字幅・9行表示の8ドットASCII本文を再生成する。IPAの許諾文は公式の英語本文を使い、東雲は原文を保存したうえで英訳を掲載する。

ホスト側の通信・UI状態・GPS解析・NVS設定テストは、リポジトリのルートで`python3 tests/run_native.py`を実行する。チェックサム、座標変換、無効Fix、同時刻の統合、古いサンプルの除外、受信断、UTC日付境界、タイマー周回とUI操作の保持、設定の保存・復元・破損検出・保存失敗、編集取消、2階層の戻り操作、フォーマット・初期化の確認、消灯・復帰を確認する。書き込み後は、USBシリアルのNMEA受信状況、LCDの実座標と1 / 2 / 3 / Escによるトップ間の直接遷移を実機で確認する。

USBログの取得には、pyserialを導入したPythonで`python tests/capture_serial.py COM6 --seconds 30`を使用する。COM6は実機の接続先へ置き換える。esptool 4.9を同じPython環境へ導入すれば`--reset`で起動ログを取得でき、`--output ファイル名`で受信ログを保存できる。USB切断時は取得を終了し、それまでのログを保存する。

Galuchatの実ファイル検証は、同じ組の日本向けWGSMapSetとUTF-8のWordbookを指定して`python3 tests/run_place_files.py <mapset.glc> <names.giswordbook>`を実行する。習志野市庁舎・皇居付近の繰り返し検索、未収録座標、ファイル不足・重複・破損・修復後の再読込みを検証する。キャッシュは元の点検索との324点の比較、矩形境界、コード0、負座標、地図重なり、32bit値域、読込み途中の失敗と復旧、ヒット時に地図読出しセッションを作らないことを検証する。

検証手順と結果は[Galuchat矩形キャッシュ検証](../doc/検証/Galuchat矩形キャッシュ検証.md)、[表示時計・アクセス表示検証](../doc/検証/表示時計・アクセス表示検証.md)、[東雲フォント・Settings文字サイズ検証](../doc/検証/東雲フォント・Settings文字サイズ検証.md)を参照する。

USBログの`[CACHE]`はHIT / MISS / INVALID、画像容量、累計ヒット・ミス・再構成件数と検索全体の所要時間（マイクロ秒）を出す。所要時間には地名キャッシュの検索、ミス時のWordBook読出し・表示用変換も含む。`[WORDBOOK]`は地名キャッシュのHIT / MISS、登録数/16と累計ヒット・ミスを出し、地名結果が成功しなかった場合はNONEとする。辞書統計はReader閉鎖時にリセットする。`[GIS]`のheap / min_heap / largestは現在空きヒープ、起動以降の最小空きヒープ、現在の最大連続空き領域をバイト単位で示す。

`[READ-TIME]`は検索全体・Reader準備・地図検索・SDKの128×128矩形読出し本体・辞書検索・文字変換を別々に計測する。`[READ-IO]`は地図と辞書のファイルAPI時間、読出し量、read / seek / open / close回数を示す。`[MAP-IO-TIME]` / `[BOOK-IO-TIME]`はfreadとfseek、fopen / fclose / statの時間を個別に示す。各検索でリセットし、ヒット時に前回の読出し時間を表示しない。内数の関係と実機結果は[Galuchat読出し時間計測](../doc/検証/Galuchat読出し時間計測.md)を参照する。

## ログ閲覧

各トップ画面の`3`でLOGSを開く。ファイルをEnterで開くと詳細を表示し、「測位点を見る」で1点ずつ閲覧できる。上 / `;`が前、下 / `.`が次、Esc / Delが戻る。消灯中の最初のキーは復帰だけに使う。

一覧は6件ずつ、詳細はファイル名・端点のJST日時・スロット数・バイト数を表示する。測位点は保存済みのGPS値を表示し、逆ジオコーディングは行わない。Appが10件の生レコード320バイトを保持し、UIへ現在の1点を渡す。Storageの同期結果は受付成否だけを返し、読出し結果はトークン・画面世代付きの固定長通知として値コピーする。結果バッファプールと解放通知は使用しない。

記録中の閲覧でもRAM受付を続け、SD読書きはStorageTaskが直列化する。先行分の保存後に取得した保存済み上限を固定し、新しい記録は詳細の「再読込」で反映する。読出しは元ファイルを変更せず、破損点の番号も詰めない。操作と検証範囲は[Logs](../doc/画面・操作/logs/README.md)、[詳細・測位点](../doc/画面・操作/log-detail/README.md)、[ログビューア検証](../doc/検証/ログビューア検証.md)を参照する。

フォントと動作設定の配置変更・検証は[UIフォント・設定配置検証](../doc/検証/UIフォント・設定配置検証.md)を参照する。

## Galuchatのリソース設定とチャンク索引

ビルド時のGIS設定は`application/Config.h`へ集約する。`MaxDatasetChunks`は1500（上限を含む）、`MapCacheSide`は128、`FileReadBufferBytes`・`MapInitReadBufferBytes`・`WordBookReadBufferBytes`・`FileReadThroughSkipBytes`は4096、`MapRectReadBufferBytes`は16384、`IndexReadBufferBytes`は4096、`WordBookCacheEntries`は16、`PlaceSearchIntervalMs`は5000とする。利用者が画面から変更する設定の候補・初期値は引き続き`Settings.h` / `Settings.cpp`で管理する。

通常起動では保存索引の全体検証と元GLCHの照合を行い、チャンク配列をRAMへ保持しない。矩形検索時は交差するチャンクだけを開く。起動時・Reader再オープン時にチャンク数を確認し、1501以上は保存索引の検証とGI01の読出しへ進まず利用不可とする。逐次探索へ戻さない。上限超過とメモリ確保失敗はGPS更新によって再試行せず、Readerの明示的な閉鎖・SD再マウント後に再確認する。GPS受信とログ記録は継続する。

起動チェックでは`TOO LARGE` / `NO MEMORY`を表示する。起動を継続し、原因を通知して未選択へ移り、逆ジオコーディングを停止する。全面警告を閉じる操作は要求しない。同じ制限を選択済みデータと切替候補へ適用する。`[DATASET]`ログにチャンク数・設定上限・状態を記録する。

## メモリ削減後の描画と通信

`Config.h`の`UiColorDepth = 4`で16色パレットの全画面バッファを使用する。現在の9色・240×135の解像度・字形・一括転送を維持し、RGB565色から番号への変換はUiCanvasに集約する。値16は従来のRGB565参照描画とし、プレビュー生成時に両者のRGBピクセルが一致することを確認する。SDのVFS予約枠は`SdMaxOpenFiles = 3`とし、2本を同時に開く地図初期化へ1本の余裕を持たせる。

キューは用途ごとにUiRequest（1056 B）/ GpsRequest（16 B）/ StorageRequest（144 B）/ AppNotification（664 B）/ ReturnMessage（280 B）を使用する。UI更新以外のキューや結果保持領域へUIデータ全体を予約しない。Appの2キュー・サブタスクの各1キューと件数、同期結果の必須回収、値コピーによる所有権を維持する。起動ログの`[MEMORY]`に各型のサイズとSD枠・色深度を記録する。

実装・実測・検証範囲は[メモリ削減実装検証](../doc/検証/メモリ削減実装検証.md)にまとめる。

### 起動モードとUSBストレージ

通常モードの設定→システム設定でモードをUSBに編集し、「保存して再起動」で確認すると、Storageが独立したNVSキーboot_modeを保存し、成功通知後にAppが再起動する。記録停止・未保存データの保存・セッション閉鎖が完了していることが必要。USBモードではGPSを起動せず、PC公開中はSDをFatFsへマウントしない。PC公開中でも終了ダイアログの終了を選択できる。PCのコピー・編集・保存を完了して確定すると、実行中I/Oの終了・SD同期・フラグ保存・USB公開停止後に通常モードへ再起動する。Windowsのクイック削除で運用する場合はPCの安全な取り外しを必須としない。PCの未送信キャッシュを端末から同期する機能ではない。

USB-OTG/TinyUSBへ移行し、CDCを手動開始する。アプリケーションログはutils/ConsoleのUSBCDCへ出力し、MSCはUSB起動時だけ登録する。シリアルモニタは115200bps、DTR/RTSとも有効とし、USB Serial/JTAGを使っていた従来のCOM番号から変わる場合がある。NVSのconfigレコード・SD上のログ形式は維持する。[詳細仕様](../doc/09_起動モード・USBストレージ仕様.md)。

USBメニューの「ログを書き出す」から、保存済みログをGPX・KML・CSVへ変換できる。[エクスポート仕様](../doc/10_ログエクスポート仕様.md)に従う。出力は`/export/<元のファイル名全体>.<形式の拡張子>`とする。PC公開中だけ安全な取り外しを待ち、USB公開を止めてFatFs操作へ切り替え、閉鎖・同期・アンマウント後に再公開する。変換はStorageの`task/storage/export/LogExporter`が10点ずつ進め、2048バイトのバッファを使う。関連定数は`Config.h`に置く。同名出力は上書きせず、破損・不完全末尾・0件のログはエラーとする。変換中の取消は提供しない。実装と試験の範囲は[実装検証](../doc/検証/ログエクスポート実装検証.md)を参照する。

ライセンス本文は上下で1行スクロールし、左右キーまたはライセンス閲覧中の`<` / `>`（Shift+, / Shift+.）で前後のソフトウェアの名称行へジャンプする。名称が表示の先頭へ来るようにし、先頭・末尾で折り返さない。`tools/prepare_licenses.py`はマニフェストの掲載項目から本文と先頭位置を同時生成する。

設定の「バージョン情報 / About」ではReverseGeoputerの版・JSTビルド日時・Git情報を確認できる。製品名と版は`Version.h`を正本とし、初期版は`0.1.0-dev`とする。PlatformIOのpre-build hookがビルドディレクトリの`generated/BuildMetadata.h`へ日時とGitの短縮ハッシュを生成する。未コミット変更は`+dirty`、Gitが取得できない場合は`unknown`と表示する。Enter / Esc / Delで同じメニュー項目へ戻る。ライセンス本文は別の項目として維持する。

## メンテナンス起動

Cardputer ADVではアプリ側の`hardware/AdvKeyboardReader`をUIが所有する。初期化時にGPIOによる物理マトリクス走査で押下状態を復元し、通常時はTCA8418のFIFOをポーリングする。MCUリセット前からキーを保持していてイベントが残っていない場合も検出し、重複pressで状態を二重追加しない。キーボード更新はUIが明示的に1回ずつ実行し、M5Cardputer側の自動更新と重複させない。

Bootの確認中・完了後、および異常表示中のLive PlaceでEsc（物理バッククォート、Fn不要）を押すと、メンテナンス状態で設定画面を開く。電源投入時からの押しっぱなしも保持し、UIはAppへの最初の応答前にキーを走査する。起動時にEscが押されていれば、AppはSD初期化・NVS復元の完了を待たずメンテナンスを表示し、設定復元だけを継続する。復元中の保存操作は無効にする。通常起動には設定読込み後の1500ms受付期間（`config::BootMaintenanceWindowMs`）も残し、GPS・地図の自動初期化前に退避できる。メイン画面のエラー時も、記録と保存の終了後はEscで入れる。通常のEscによる設定操作は継続する。

メンテナンスでは自動位置検索・記録開始・消灯を抑止する。設定入口のEsc / Delは共通の取消／再起動確認となる。設定変更・SD操作・データセット選択・USB切替は既存処理を使う。開始済みのStorage処理は強制中断しないため、読込みでクラッシュする場合は次回起動からEscを保持する。保存索引はデータセットの再適用で生成できる。起動・検索では保存チャンク索引を利用する。独立した再生成・元データ突合は動作設定→データセットから実行する。[Boot仕様](../doc/画面・操作/boot/README.md#5-escによるメンテナンス起動)を参照する。

## 障害時の機能制約

[システム構成設計7節](../doc/04_システム構成設計.md#7-エラー状態と機能の利用条件)を正本とする。有効GPS Fixなしでは地名更新・新しい測位点の追加だけを止め、設定・SD操作・既存ログの利用は各機能の必要条件で判断する。開始・再開は次の有効Fix待ちとなり、記録中のFix喪失はセッションや記録要求を解除しない。SD利用不可ではログ・地名機能を利用できないが、GPS表示とNVS設定操作を継続する。データセット異常だけなら逆ジオコーディングを停止し、ログは利用可能なSDと有効Fixに従って記録する。

SD全体の利用不可、書込みだけの失敗、NVSの設定復元失敗・保存失敗は別に扱う。ログ閲覧・削除・USBモードでのエクスポートは現在のGPS Fixやデータセットを必要としない。版・ライセンスの表示データはファームウェア内にあり、SD・GPS・NVS保存に依存しない。UI・Appを準備できない初期化失敗だけは通常操作の開始前に停止する。

## データセット異常時の起動継続

[データセットメタデータ仕様8.3〜8.5節](../doc/08_データセットメタデータ仕様.md#83-起動時の復元とエラー)に従い、使用中の欠落・破損・文字コード未対応・上限超過・メモリ不足・読出し失敗・SD利用不可では、原因を通知してNVSとRAMを未選択へ移す。地名欄は未選択とし、GPSと利用可能なログ機能を継続する。解除理由はその起動中の診断へ残し、キャッシュ保守後も利用者が改めて選択するまで検索を再開しない。

欠落時の起動停止と上限超過・メモリ不足の全面警告は廃止した。PlaceLookupはすべてのデータセット失敗を保持し、Reader・画像・辞書キャッシュを解放する。明示的なCheckDataset／configureで検証世代を進め、Appは要求IDと世代を照合して古い成功によるエラー解除を防ぐ。Boot・地名欄・再読込み抑止の[検証結果](../doc/検証/データセット異常時の起動継続検証.md)を参照する。

## データセット事前索引（生成・チャンク読出し実装済み）

[事前索引ファイル仕様](../doc/11_データセット事前索引ファイル仕様.md)に従い、適用・再適用時に`/dataset/NN/_mapindex.dat`を生成する。GLCとINIに宣言された全言語のWordbookを収録し、有効な既存領域は再利用する。生成・構造CRC検証・同期・公開後にNVSを保存し、失敗時は旧索引を復元する。生成設定は`Config.h`へ集約する。

データセットの「適用する」は検証・索引確定・NVS保存後にReaderとキャッシュを入れ替え、CheckDatasetの再確認後に検索を再開する。ログ停止・保存・閉鎖完了を必要とするが、再起動は行わない。システム設定のモード候補はUI内で保持し、編集確定や確認取消ではNVSへ書き込まない。

通常起動・明示再検証では索引全体の構造・CRCと元GLCHの識別情報を照合する。索引なし・破損・元GLC不一致はデータセットエラーとし、GPS・SDログは各機能の条件に従って継続する。Escメンテナンスまたは設定のデータセット再適用で生成できる。候補表示は索引を必要とせず、元データを検証する。

`DiskIndexedMapReader`は共通ヘッダーと全体範囲だけを保持する。画像キャッシュのミス時は索引を1回開き、チャンク情報40バイトを順に読む。交差しないチャンクの群情報はskipし、交差するチャンクの群情報16バイトを1件ずつ確認して、必要な群だけ保存位置から復号する。マップ索引領域の末尾で先読みを止め、毎検索の全体CRCは行わない。128×128画像・地名LRUは維持し、画像ヒット時は地図用の索引・GLCを開かない。地名LRUがミスする場合はWordbook用の索引を別に開く。`[INDEX-IO]`と`[INDEX-IO-TIME]`は両方の索引I/Oの合計を記録し、`[READ-IO]`のmap/bookは元GLC・元Wordbookだけを記録する。

ブロック群の途中再開はアプリ内Galuchatの追加APIで実装した。索引ファイル形式は変更せず、既存索引をそのまま使う。WordbookもDiskIndexedWordBookReaderで保存済みTI00・TT00・TM00索引を利用する。選択言語と元Wordbookの識別情報を起動時に照合し、地名キャッシュのミスごとに索引を前方向へ1回読み、対象枝・ページ・断片を直接取得する。Core・SDKへは今回の追加APIを反映していない。前段実装の実機比較は[保存チャンク索引の比較](../doc/検証/保存チャンク索引の性能比較.md)、現在の群索引の利用・試験は[保存ブロック群索引の検証](../doc/検証/保存ブロック群索引の検証.md)と[保存Wordbook索引の検証](../doc/検証/保存Wordbook索引の検証.md)に記す。

保存索引は地図とINIの全地名言語のWordbookを1ファイルへ収録する。適用時は有効な領域を再利用し、設定→動作設定→データセットのキャッシュ再生成・キャッシュ検証で、対象番号を選び地図と全言語Wordbookを一括処理する。通常起動の軽い確認と、明示操作による元データの全走査突合を区別する。詳細は[データセット事前索引ファイル仕様11節](../doc/11_データセット事前索引ファイル仕様.md#11-索引保守と全言語の利用)に従う。

データセットメニューは「データセットを選択」「キャッシュ再生成」「キャッシュ検証」の3項目とする。キャッシュ操作は対象の番号一覧→共通確認→進捗・結果の順に進み、地図と全言語Wordbookを一括処理する。対象を通常利用に適用せずに保守でき、使用中が未選択でも操作できる。既知の実行不能条件は項目をグレーアウトして理由を示し、試行が必要なI/O・破損・不一致などは処理結果で表示する。

使用中のデータセットが欠落・破損・キャッシュ欠落・SD利用不可などで使用不能と判明した場合、StorageはNVSを番号0・空言語へ更新し、Readerとキャッシュを解放する。NVS保存失敗でもRAM上は未選択とし、保存失敗を通知する。解除番号と原因は5秒間の通知と、その起動中のデータセット設定に残す。新しい候補の検証失敗では現在の有効な選択を維持する。自動解除はGPSの記録状態を変更せず、復旧後も利用者が改めて選択するまで地名検索を再開しない。
